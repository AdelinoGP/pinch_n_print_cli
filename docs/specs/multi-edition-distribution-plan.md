## Approved scope (verbatim intent)

Phases 1–3 of ADR-0057's delivery plan. Phase 4 (platform builds: aarch64
matrix, iOS AOT, browser research) is explicitly deferred — no packet.

1. DEV-094 completion — batched host-service bridges: wire the wasm32 arms of
   the SDK polygon-op and mesh-query wrappers to the already-declared WIT
   batched host services (per ADR-0049 and its 2026-08-05 amendment; today
   only `log*` has its wasm32 bridge arm). Includes migrating the measured hot
   consumers (`classic-perimeters`, `support-planner`) onto the wrappers where
   they call `slicer_core::polygon_ops` directly, and fuel/wall-clock
   before/after evidence per ADR-0055 methodology.
2. Integrated-module infrastructure per ADR-0056: `#[slicer_module]` native
   adapter emission; integrated-module registration as search tier 5
   (manifest via `include_str!` through the same ingestion pipeline;
   first-root-wins dedup unchanged); dispatch routing behind the ADR-0005
   runner-trait seam; `--no-integrated-modules` flag; provenance-aware
   duplicate-id diagnostic ("external module X shadows integrated module X");
   provenance surfaced in `pnp_cli module` listing/diagnose.
3. Hybrid pilot: `classic-perimeters`, `arachne-perimeters`,
   `support-planner` compiled as integrated modules; per-module parity
   contract tests running identical inputs through both dispatch paths
   asserting structural invariants (ADR-0042) plus tolerance-based IR
   comparison (byte-equality explicitly NOT the gate — DEV-093, ULP drift);
   residual divergence filed in `docs/DEVIATION_LOG.md`. Integrated modules
   stay single-threaded internally (ADR-0056 §5). The Hybrid integrated set is
   a dist-config list seeded with these three modules and finalized by
   profiling inside this packet.
4. Editions in xtask: `cargo xtask dist` gains the edition dimension
   (Developer/Hybrid/Integrated per ADR-0057's table); disjointness invariant
   enforced (an edition never stages an external copy of a module it
   integrates); CI builds and verifies the edition artifacts (CI currently
   never runs dist at all).

Hard constraints carried into every packet: canonical parity discipline per
`CLAUDE.md` Test Discipline; guest-WASM staleness rules apply to the wasm
twins of integrated modules; snake_case config keys; symbol-name citations
only.

All six rows are `generated` — i.e. the spec directory exists and is authored.
That is a *queue* status and is distinct from each packet's own frontmatter,
where all six read `status: draft`; none is activated.

Each was independently run through the preflight symbol-existence gate (S0–S8)
on 2026-08-07. The first pass returned four BLOCKED (200, 201, 202, 203) and two
PASS; every finding was fixed and the four were re-gated to PASS. Treat "the gate
passed" as a fact with a date, not a permanent property — re-run `--preflight`
before activating any packet, since the tree these packets are pinned against
keeps moving.

The plan file and all six packet directories should be **committed together**.

**Phase 4 (deferred, no packet):** platform builds — aarch64 matrix, iOS AOT
(`cwasm` precompilation or Pulley, since iOS forbids JIT), browser/library
embedding (additionally requires `host-algos` — rayon, boostvoronoi — to build
for wasm32 hosts; unresolved research).

**Also unscheduled:** ADR-0057's Integrated edition is defined as "every core
module integrated". Packet 204 pilots three; packet 205 deliberately makes
`cargo xtask dist --edition integrated` fail loudly with a named list until
coverage is complete, rather than shipping an artifact that calls itself
Integrated while tier-shadowing the remainder. A follow-on packet (205a+)
integrates sixteen modules, and packet 205b completes the transports for the
two remaining transport-blocked modules — mechanically repeating 204's
registration-plus-parity-gate pattern per module — before that edition builds.
