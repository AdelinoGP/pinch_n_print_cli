### Known accelerated-host build trap (measured 2026-10-31)

On this machine the accelerated host build can fail in `libmimalloc-sys` with
`cl.exe` exit 2 and an empty stderr. Root cause, isolated by reproduction:
cargo hands `cc` a **verbatim** `\\?\D:\…` `OUT_DIR` for the accelerated target
dir, and `cl.exe` mishandles that path (`mimalloc.h` missing on one run,
`\\mimalloc-static.cc` on the next). Building the same target dir through a
**relative** `CARGO_TARGET_DIR` (the same shim contract `xtask dist` uses)
compiles cleanly, after which `xtask dist` finds the artifacts and stages:

```bash
export CARGO_TARGET_DIR=target/dist-host-accelerated
export RUSTC="$PWD/target/accelerated-driver/rustc-shim.exe"
export PNP_XTASK_EXE="$PWD/target/debug/xtask.exe"
export PNP_XTASK_WORKSPACE_ROOT="$PWD"
export PNP_ACCELERATED=1
export PNP_ACCELERATED_MODE=host-release
cargo build -p pnp-cli --release
cargo xtask dist --accelerated --edition developer   # no-op build + staging
```

No source or codegen input differs between the two invocations; only the
absolute path cargo embeds in the artifact.

## The pins this take adds

The 2026-10-31 ruling ("pinned back") fixes the three OrcaSlicer 2.5 defaults
that flipped away from the 2.4-era matched job:

| key | pin | 2.5 default |
| --- | --- | --- |
| `enable_arc_fitting` | 0 (`disabled`) | enabled |
| `elefant_foot_compensation` | 0 | 0.15 |
| `brim_width` | 0 | 5 |

`Test-OrcaEvidence` (`run_scoreboard.ps1`) asserts each resolved value in every
Orca run's own G-code appendix and rejects the t98 filament-default signature
(`filament_density = 0`, `filament_max_volumetric_speed = 2`,
`first_layer_temperature = 200`) outright, so a future install or preset bump
fails the batch instead of drifting silently.

## Reduce

```powershell
# the rig's own per-run dump + gap table
pwsh -NoProfile -Command "& 'docs/specs/perf-vs-orca/evidence/matched-pair/summarize_scoreboard.ps1' -BatchIds 't103-benchy','t103-base-classic-off','t103-base-arachne-off','t103-base-classic-on','t103-base-arachne-on'" > SUMMARY.txt

# the scoreboard tables, park bound and summary.json
python analyze.py > TABLES.txt
```

`SUMMARY.txt` is the summarizer's output as recorded (96 rows / 72 measured,
starvation flags, medians, section counts). `TABLES.txt` is `analyze.py`'s
output (the SCOREBOARD tables, the pins, the brim asymmetry and the
park bound). The ledger CSVs in this directory are the five batch
`scoreboard-rows.csv` files copied verbatim; the raw capture trees stay under
the gitignored `target/matched-pair/<BatchId>/`.

## Verify from the committed set only

```bash
python verify.py
python verify.py --self-test
```

`verify.py` re-derives every median, gap ratio, group shape, park bound, pin
assertion, filament-leg record, output flag, the brim asymmetry and the
ordinary == accelerated byte identity from the committed row CSVs. It never
reads the raw capture tree. `--self-test` runs 13 negative controls (wall
median, CPU median, gap ratio, park bound, sample count, starvation flag,
degraded flag, byte identity, each of the three pins, the filament default
signature, and the brim asymmetry) and requires every one to be detected.
