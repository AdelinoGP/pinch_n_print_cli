# Reproducing the t82 fairness-key parity audit

Checkout-only verification (no OrcaSlicer, no fixtures, no build):

```bash
python docs/specs/perf-vs-orca/evidence/t82-fairness-key-audit/verify.py --self-test
```

Exit 0 means every headline count re-derives from the committed artefacts and
all nine negative controls were rejected.

Re-derive the mechanical join (no judgement) and then merge the curated
adjudication:

```bash
python docs/specs/perf-vs-orca/evidence/t82-fairness-key-audit/classify.py
python docs/specs/perf-vs-orca/evidence/t82-fairness-key-audit/merge_verdicts.py
```

`classify.py` joins the appendices against the upstream reference, the verified
gap inventory, the PnP registry and the matched configs; `merge_verdicts.py`
adds the `scope` / `bucket` / `verdict` columns and exits non-zero while any row
is still unclassified.

Regenerate the Orca side (needs OrcaSlicer installed, the two fixture STLs under
`tmp/`, and nothing else):

```bash
pwsh -NoProfile -File docs/specs/perf-vs-orca/evidence/t82-fairness-key-audit/run_orca_appendix.ps1
```

That rewrites `appendix/*.txt` and `runs.json` and leaves the raw G-code under
`target/t82-key-audit/` (never committed). The eight runs total roughly two
minutes on the dev machine; the base cells dominate.

## Artefacts

| file | what it is |
|---|---|
| `appendix/*.txt` | the eight resolved-config appendices, one `key = value` per line |
| `runs.json` | per-run exit code, wall, G-code bytes, appendix key count, derived config path |
| `key-table.csv` | one row per resolved key — the completeness artifact |
| `summary.json` | the bucket counts the write-up quotes, regenerated by `merge_verdicts.py` |
| `verdicts.json` | the curated adjudication, one entry per non-mechanical classification |
| `classify.py` | mechanical join, no judgement |
| `merge_verdicts.py` | adjudication merge, fails on gaps |
| `verify.py` | checkout-only verifier + negative controls |
| `run_orca_appendix.ps1` | Orca runner |

## Measurement notes

- The appendix is parsed with the same `^\s*;?\s*(key)\s*=\s*(value)$` shape the
  matched-pair rig uses. G-code comments outside that shape are ignored.
- The runner records 622 captured lines per cell; parsing yields **618 distinct
  keys**, because three keys are emitted twice (`curr_bed_type`,
  `wipe_tower_x`, `wipe_tower_y` — a process copy and a machine copy with
  identical values). The parser keeps the later copy; `runs.json` records the
  pre-dedupe line count.- `runs.json` records `appendix_keys` before that dedupe; `verify.py` only
  asserts it is at least 500.
