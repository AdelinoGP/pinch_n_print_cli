# t59 — PrePass::Slice flat-bridge closing: representation analysis verdict

Ticket: [PrePass::Slice flat-bridge closing reduction](../../issues/59-prep-slice-flat-bridge-closing-reduction.md)
(wayfinder map [Slice performance vs OrcaSlicer](../../map.md)).
Take: 2026-10-14, first frontier ticket in order on map resumption.

## Verdict

**(b) No representation-safe reduction of the enclosure closing is
established; the closing call is irreducible without changing output.**

`assemble_flat_bridge_areas` (`crates/slicer-core/src/algos/prepass_slice.rs`)
computes `closed = closing_ex(&support, 12 mm, Miter)` and consumes the result
**only** as a per-component boolean (`intersection(component, refilled)` area ≥
10 % of the component). On the real matched layers that boolean is decided by
**offset-cleanup artifacts generated by degenerate near-zero-area sliver paths
in `support`** — the output of `difference(&region.polygons, &unsupported_region)`.
Re-emitting the *same point set* through a normalized path list (a clip against
a containing box, or `union_ex`) changes the closing's output by tens of mm² and
flips gate verdicts on **92 of 239 benchy layers (38.5 %)** and **320 of 469
base layers (68.2 %)**. Every candidate reduction measured — this take's
local-closing shape plus the previously recorded shapes — either changes the
input path list, the call sequence, or the offset configuration, and therefore
fails representation identity. No production edit; no timing campaign.

The candidate's **cost ceiling was measured anyway**: the refuted local shape is
only ~12 % cheaper than the full closing, because the flat-bridge components'
bounding box covers ~half the support bbox on every call. The closing is not a
"recompute less geometry" problem at the scale the ticket hoped.

## Method

Temporary probe harness (`probe.patch`): a `--features host-algos` test that,
per fixture (`tmp/3dbenchy.stl`, `tmp/base.stl`; heavy, gitignored), reproduces
the production inputs of the flat-bridge branch exactly —

- bed placement as `pnp_cli` does for STLs (`place_bare_mesh_on_bed`,
  `crates/slicer-model-io/src/loader.rs`; default bed from
  `ResolvedConfig::bed_shape`),
- the production layer-top schedule (`layer_top_zs`,
  `crates/slicer-config/src/resolution.rs`; 240 benchy / 495 base layers — the
  layer counts the 2026-10-09 refresh measured),
- `execute_mesh_analysis` + `batch_bottom_surface_footprints` +
  `batch_slice_objects_by_layer` (`crates/slicer-core/src/algos/`),
- `region.polygons = apply_slice_closing_radius(raw, 0.049)` (the
  `slice_closing_radius` default consumed by
  `execute_prepass_slice_single_layer_with_cache`,
  `crates/slicer-core/src/algos/prepass_slice.rs`),
  `unsupported = difference(current_raw, prev_raw)`,
- then calls `assemble_flat_bridge_areas` on a region reconstructed exactly as
  `execute_prepass_slice_single_layer_impl` builds it.

**Reconstruction fidelity was asserted, not assumed**: on sampled layers of
both fixtures (and on both drilled layers) the reconstruction's
`bridge_areas`/`is_bridge` are byte-equal to the real entry point's output
(`execute_prepass_slice_single_layer_with_cache`).

The probe is temporary; the raw captures live (gitignored) under `target/t59/`;
the reducer `reduce_t59.py` regenerates `reduced/`; `verify.py` exits 0 against
the in-repo reduced set alone.

## Deliverable 1 — consumers and the representation each needs

**The closing result (`closed` / `refilled`) itself** has exactly one consumer:
the per-component fraction gate inside `assemble_flat_bridge_areas`. The
reported geometry is the untouched component (`component.clone()`); the closing
geometry is discarded. So the closing only needs to reproduce the exact gate
booleans — but exactly.

**The gate's output** (components appended to `region.bridge_areas`; `is_bridge`)
is consumed with exact integer geometry by:

- `gate_bridge_areas_by_unsupported_span` + `update_external_bridge_orientation`
  (`crates/slicer-runtime/src/slice_postprocess_prepass.rs`): subtracts the
  lower layer's committed `infill_areas`; clears everything when the layer
  below is absent; derives `bridge_orientation_deg` from the gated geometry.
- `sync_perimeter_infill_areas_into_slice`
  (`crates/slicer-runtime/src/region_partition.rs`): `bridge =
  intersection(bridge_areas, wall_inset)`, then
  `sparse_infill_area = difference(wall_inset, bridge ∪ bottom ∪ top)` — the
  bridge components are material-excluded from sparse infill and the committed
  `bridge_areas` become the clipped set.
- Guests via the SDK views: `wave-overhangs`
  (`modules/core-modules/wave-overhangs/src/lib.rs`; external bridge =
  `bridge_areas − internal_bridge_areas` → `BridgeInfill`), `classic-perimeters`
  (per-vertex `is_bridge` containment through
  `crates/slicer-core/src/perimeter_spatial.rs`), `gyroid-infill`
  (`modules/core-modules/gyroid-infill/src/lib.rs`; fill precedence).
- The visual-debug SliceIR typed capture (`crates/pnp-cli/src/visual_debug.rs`)
  serializes `bridge_areas` verbatim.

Every consumer needs the exact emitted polygon list; hence representation
identity at the region level is the binding oracle (as the ticket states).

## Deliverable 2 — candidate refutation, with mechanism

### Candidate shape tested (this take)

`local_closing_candidate` (probe): one closing over `support` clipped to the
union bbox of `flat_bridge` padded by `2R + 1 mm` (R = 12 mm), then the same
per-component gate. Exactness argument (point sets): for a point `p` in a
component, membership in `closed` depends only on support within `2R` of `p`.
Measured across every real layer of both fixtures:

| fixture | closing calls | verdict flips | flip rate |
| --- | ---: | ---: | ---: |
| benchy | 239 | 92 | 38.5 % |
| base | 469 | 320 | 68.2 % |

**Refuted** — not representation-identical. The failure is not boundary
jitter: single components flip from 0.99 to 0.05 or 0.0 to 1.0.

### Mechanism (why the whole family fails) — drilled layers

The drill (both fixtures; `reduced/mechanism.json`) decomposes one layer's
closing under four input path lists of the *same point set*:

`support` = one large piece **plus a population of degenerate sliver paths**:

| layer | support paths | of which slivers (<0.001 mm²) | large piece | sliver max extent |
| --- | ---: | ---: | ---: | --- |
| benchy 161 | 73 | 72 | 116.642 mm², 1180 pts | 1.934 × 0.108 mm |
| base 8 | 75 | 74 | 72.084 mm², 471 pts | 0.609 × 0.464 mm |

Closing output by input path list (mm²):

| variant | benchy 161 | base 8 |
| --- | ---: | ---: |
| raw production path list | **325.304** | **31.536** |
| same point set via `intersection` (normalized) | 215.4 | 72.1 |
| same point set via `union_ex` (normalized) | 215.381 | 72.053 |
| large piece only (slivers removed) | 127.902 | 73.170 |
| support area itself | 116.6 | 72.1 |

Two independent normalizations of the same point set agree with each other and
differ hugely from the raw production path list — so the divergence is caused
by **path-list identity, not by geometry**: the mitered offsets of the sliver
paths (miter limit `ORCA_MORPH_MITER_LIMIT` = 3.0 in `morph_pass`,
`crates/slicer-core/src/polygon_ops.rs`) fold back into spikes whose NonZero
union cleanup reshapes the result. On base layer 8 the raw-path-list closing is
even **smaller than its own input point set** (31.5 mm² vs 72.1 mm²): the
artifacts carve area away. (Recorded as the current canonical behaviour this
gate consumes — not asserted to be a defect.)

The gate reads exactly this artifact field: on benchy 161, component 0 measures
fraction 0.988 raw vs 0.049 normalized; component 1 0.336 vs 0.0. On base 8,
component 18 measures 0.114 raw vs 0.0 normalized; component 13 0.0 vs 1.0.
Any reduction that alters the input path list, the call sequence, or the
offset configuration moves the artifact field and flips such verdicts.

### The skip family is empty, and the baseline gate is knife-edge

- **Far-rejection guards have zero hits**: across all real layers, **0 of
  3,266** benchy components and **0 of 11,685** base components have their bbox
  expanded by R disjoint from the support bbox (the conservative
  "provably no overlap" test). (Corroborates the ticket-27 record: the earlier
  per-component bbox guard "skipped none of its 240 calls".)
- **The gate decisions themselves sit at numerical knife-edges in the
  baseline**: the minimum `|fraction − 0.1|` is 4e-5 (benchy) and 2.4e-4
  (base); 13 / 63 components are within 0.02 of the threshold. Only an
  identical computation is safe.
- The previously recorded shapes stand refuted and are not revived:
  `refilled`-elimination (ticket 27: 105 vs 104 polygons on benchy layer 1),
  same-direction-collinearity cleanup (~2 %, inside noise), per-component bbox
  guard (0 hits).

### Cost ceiling of the refuted shape (measured, attribution only)

Local shape total time vs full closing total, accumulated in-process across
all call layers:

| fixture | global closing (sum) | local clip + closing (sum) | local/full |
| --- | ---: | ---: | ---: |
| benchy | 19.416 s | 17.109 s | 0.881 |
| base | 403.713 s | 353.676 s | 0.876 |

So even an exact local closing would save ≈12 % of the closing's accumulated
thread-time — because the flat-bridge bbox covers ~half the support bbox on
every call (box/support bbox area ratio: mean 0.519 benchy, 0.494 base). The
2026-10-09 refresh's host table (closing_ex 389.5 s accumulated / 470 calls on
base-classic-on) remains the current scale of the call; an ~12 % cut of it is
far below what would lift a cell, and it cannot be had safely.

## Scope and disclosures

- The probe measures the **host `PrePass::Slice` builtin**
  (`commit_slice_builtin` / `execute_prepass_slice_all_layers`,
  `crates/slicer-runtime/src/builtins/prepass_slice_producer.rs`). On the
  matched configs the stage's inputs and the two consumed config keys
  (`slice_closing_radius`, `flat_bridge_closing_join`) are identical across the
  generator and support cells, and the stage is host-side (identical in
  ordinary and accelerated editions); the scan therefore covers all four
  matched cells per fixture without re-running them.
- All timings are **single-run in-process accumulated thread-time
  (attribution only)** — never wall claims, never a speed verdict. The
  standing paired ordinary + accelerated A/B was not run: no candidate
  survived representation identity, so the gate's precondition ("Only after
  (a) may the standing paired A/B run") is not met.
- Machine: Windows dev host; release build; `RAYON_NUM_THREADS` default. The
  probe ran no uninstrumented campaign and touched no production default.
- Fixture placement note: the probe places the STLs on the default bed exactly
  as `pnp_cli` does for the matched runs; benchy lands at x≈116 mm, base at
  x≈117–134 mm on the layer rows cited (the bed-centred coordinates).
