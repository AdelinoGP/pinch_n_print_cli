# t55 body-union cases — corpus format v1

Generated by `../../t55-to-cases.py` from all four cases in each of
`t55-body-union/{ordinary,accelerated}-{base,benchy}-specimens.jsonl`.
All inputs are retained, including mode-identical duplicates. `manifest.json`
records source checksums, layers, case counts and output bytes.

Site 550 = tree-support body union. Opcode 2 = union. Subject is the first
`carved`, role 0 ExPolygon; clips are all remaining ExPolygons. Every contour
and hole is retained in input order, without reorientation, matching
`expolygon_to_paths` and `clip_polygons` in
`crates/slicer-core/src/polygon_ops.rs`, and the measured call in
`docs/specs/perf-vs-orca/evidence/t55-body-union/harness.rs::run`.

## Shared argument map (drivers hardcode this map)

* Offset opcode 0: arg 1 = delta f64 bits; 2 = join enum (0 Square,
  1 Bevel, 2 Round, 3 Miter); 3 = end enum (0 Polygon, 1 Joined,
  2 Butt, 3 Square, 4 Round); 4 = miter limit f64 bits. These are required.
  Optional arg 5 = arc tolerance f64 bits (absent means engine default 0).
* Boolean opcodes 1 Difference, 2 Union, 3 Intersection, 4 Xor:
  required arg 10 = fill rule (0 EvenOdd, 1 NonZero, 2 Positive, 3 Negative).
* Optional arg 7 = preserve_collinear (0/1; boolean default 1, offset default 0);
  optional arg 8 = reverse_solution (0/1, default 0).
* Other argument IDs are rejected, not silently ignored. A capture using a
  different map must be translated explicitly before replay.

All numbers are ASCII integer tokens. `#` starts a comment until newline.
`case site layer opcode [call_index]` is one line; other records are
`arg id u64`, `subj npaths`, `clip npaths`, `end`. Geometry after subj/clip
is framed as, per ExPolygon/path: nrings, then per ring: npts, then x y pairs.
Geometry may span lines. Boolean cases require both subj and clip records.
Offsets require subj and must not carry clip. Each case ends with `end`.
Coordinates are signed i64 in production integer units; no scaling is done.

Compatibility note: the preliminary harness used fill-rule arg 6 and numeric
site IDs. Before final measurement it was aligned to `corpus/t68sites/README.md`
(as authored by `../../reduce.py`): fill-rule arg 10, and site IDs may be named
ASCII tokens such as A or RP1. This README records that v1 clarification.
Drivers emit `site` as a JSON string, including numeric site token "550".
All other numeric fields remain integer tokens. Arg 6 is not accepted.
