## Scope

1. **Exact `tree-support` renderer fast paths (`TS-1` + `TS-2`):**
   - **`TS-1a` (`crates/slicer-sdk/src/traits.rs::PaintRegionLayerView::paint_policy_for`):** before calling `region_covers_expoly(&region.polygons, expoly)` for a `SliceIR` region, check whether `region.segment_annotations` contains any non-`None` `PaintSemantic::SupportBlocker` or `PaintSemantic::SupportEnforcer` annotation (using the exact same predicate as `crates/slicer-core/src/paint_policy.rs::support_eligibility`, e.g., a shared `has_support_paint` helper). When absent, skip `region_covers_expoly` immediately. **Exactness:** when a region has no support-paint annotations, `support_eligibility` always returns `DefaultEligible`, which has no effect on `blocked`/`enforced`; regions WITH paint annotations still execute `region_covers_expoly` unchanged (including non-convex vertex probes and blocker > enforcer precedence).
   - **`TS-1b` (`modules/core-modules/tree-support/src/lib.rs::skeleton_wall_count`):** precompute the contour bounding box and each hole's bounding box once per `expoly` (in units), and check `if count <= best { continue; }` **before** running the point-in-expolygon test (skips `99.1–99.2 %` of points in `O(1)`).
   - **`TS-2` (`modules/core-modules/tree-support/src/lib.rs::TreeSupport::run_support`):** bypass the redundant in-guest `slicer_core::polygon_ops::union_ex(&regions)` **only when provably safe**: `regularized.is_some()` (already disjoint output of `slicer_core::support_regularize::regularize_entry_roles`) OR `regions.len() <= 1` OR the polygons in `regions` are **pairwise bounding-box disjoint** (using a tight exact bbox-disjointness helper, since `modules/core-modules/tree-support-planner/src/lib.rs` can append regions via `role.regions.extend(incoming_role.regions)` on multi-entry merges). Keep `union_ex(&regions)` whenever any two polygons in `regions` have overlapping bounding boxes on an unregularized entry.
2. **Exact `infill-linker` + `clipper2-rust` open-subject tagging and metadata/connect acceleration (`IL-1` + `IL-2` + `IL-3`):**
   - **`IL-1` (`vendor/clipper2-rust/src/engine.rs`, `engine_fns.rs`, `lib.rs` + `crates/slicer-core/src/polygon_ops.rs::PreparedPolylineClip::clip_batched`):** add `source_id: u32` to `LocalMinima` and `OutRec` (default `0`, zero overhead on existing APIs), plus `Clipper64::add_open_subject_tagged(&mut self, path: &Path64, source_id: u32)` and `Clipper64::execute_open_tagged(&mut self, clip_type: ClipType, fill_rule: FillRule) -> Result<Vec<(u32, Path64)>, ClipperError>` (propagating `local_min.source_id` in `start_open_path` and `add_local_min_poly`). Wire `PreparedPolylineClip::clip_batched` to use `add_open_subject_tagged` / `execute_open_tagged` to assign every output open polyline directly to its originating subject index, eliminating `attributed_runs` geometric re-attribution and per-subject ambiguity repairs.    - **`IL-2` (`modules/core-modules/infill-linker/src/orchestrate.rs`):** skip building `source_segments` in `link_paths_without_offset` when the caller does not need them (`link_region_group` discards them; `link_union_group` keeps them when called), and precompute once per source `ExtrusionPath3D` whether all `path.points` share uniform metadata (`z, width, flow_factor, overhang_quartile, dist_to_top_mm, overhang_distance_mm`) so `point_with_metadata` runs in `O(1)` when uniform and falls back to the exact nearest-point scan when metadata varies along a path.
   - **`IL-3` (`modules/core-modules/infill-linker/src/graph.rs` & `connect.rs`):** precompute per-ring bounding boxes, per-edge bounding boxes, edge squared lengths, and cumulative arc lengths once in `BoundaryInfillGraph::new`; prune non-matching rings and edges by current best squared distance in `project_on_ring` / `BoundaryInfillGraph::project` (exact squared-distance bound before any `hypot`); and in `nearest_pair_candidates`, exploit the existing `arc_position` sort order on each ring (scanning forward modulo ring perimeter until directed arc distance exceeds `max_walk_distance`, preserving exact tie-breaking and candidate ordering).
