# Design: 204-hybrid-pilot-parity

## Controlling Code Paths

- Primary code path: `crates/slicer-integrated-modules/src/lib.rs`'s `integrated_registrations()` and `native_entries()` (both **FORWARD-DEP**, created by packets 201/202 returning empty collections); the dual-dispatch seam formed by `WasmRuntimeDispatcher` (`crates/slicer-wasm-host/src/dispatch.rs`) driving two `CompiledModuleLive` values (`crates/slicer-wasm-host/src/binding.rs`) through `LayerStageRunner::run_stage` / `PrepassStageRunner::run_stage` (`crates/slicer-wasm-host/src/traits.rs`).
- Neighboring tests/fixtures: `crates/slicer-runtime/tests/common/perimeter_harness.rs` (six public items at authoring: `WallGenerator`, `PerimeterCapturingLayerStageRunner`, `PerimeterHarnessError`, `run_pipeline_capturing_perimeters`, `AlignedCoverageMeasurement`, `align_coverage_measurements`), `crates/slicer-runtime/tests/common/dispatch_fixture.rs` (`DispatchFixture`, `DispatchFixtureBuilder`, `for_stage`), `crates/slicer-runtime/tests/common/support_wedge.rs`, and the existing ADR-0042 corpus in `crates/slicer-runtime/tests/arachne_structural_invariants.rs` (its `symmetric_coverage_ratio` / `coverage_predicate` / `assert_capture_is_structural` are the model for the new comparator's shape, not its import source — that file is a Cargo-autodiscovered standalone test binary with no library surface).
- OrcaSlicer comparison: none. This packet compares PnP's native path against PnP's own wasm path; there is no canonical C++ equivalent of a dispatch-path split. No `OrcaSlicer Reference Obligations` section exists in `packet.spec.md` or `requirements.md` for that reason.

## Architecture Constraints

- **Byte-equality is not the gate (ADR-0056 Decision item 4).** The comparator asserts structural invariants plus a `1e-3` mm coordinate tolerance. It must never compare `f32`/`f64` bit patterns, and it must never be relaxed to make a red parity test green — a red parity test removes its module from `dist/editions.toml`'s `hybrid.integrated_modules` (`requirements.md` §Step Completion Expectations), it does not relax the assertion.
- **Single-threaded module logic on both paths (ADR-0056 Decision item 5).** Integrated modules must not gain internal parallelism; parallelism comes from batched host services (ADR-0049/DEV-094) and host-side layer fan-out. Enforced cheaply by AC-9's static negative check over the three crates' `Cargo.toml` and `src/**`. Verified at authoring: none of the three declares `rayon` today (the only `rayon` hits under `modules/core-modules/` are transitive entries in `wit-guest/Cargo.lock` files, which AC-9's `src/`-and-`Cargo.toml`-scoped greps correctly ignore).
- **Feature unification is what makes `arachne-perimeters` native-capable, and it is load-bearing.** `modules/core-modules/arachne-perimeters/Cargo.toml` takes `slicer-core` with `default-features = false`, and its wall generation calls `slicer_sdk::host::generate_arachne_walls`, whose `#[cfg(not(target_arch = "wasm32"))]` arm calls `slicer_core::arachne::pipeline::run_arachne_pipeline` and therefore needs `host-algos`. That feature arrives through `crates/slicer-sdk/Cargo.toml`'s `[target.'cfg(not(target_arch = "wasm32"))'.dependencies] slicer-core = { features = ["host-algos"] }` (verified present at authoring; packet 202 AC-5 locks it). Cargo unifies features per crate across a build, so the module's own `default-features = false` does **not** subtract it. Consequence: `crates/slicer-integrated-modules/` must NOT be built with `--no-default-features` in a way that severs `slicer-sdk`, and any future no-wasm host that drops `slicer-sdk`'s native arm silently breaks native arachne. AC-6 asserts the native path actually produced walls precisely because a compile-time success would not prove the feature reached it.
- **`classic-perimeters` runs its polygon math in-guest today** (`slicer-core` with default features). Its native arm therefore calls the same `slicer_core::polygon_ops` code the guest calls, compiled for the host — the expected divergence class is codegen/libm ULP drift, not algorithmic. `support-planner` takes no `slicer-core` dependency at all and reaches geometry through `slicer_sdk::host_batch::batch_offset` / `OffsetRequest`, so its native path exercises the host-service arm directly rather than a bridged one; that asymmetry is the reason its parity test asserts on harvested `SupportPlanIR` rather than on polygon output.
- **File-overlap hazard with packet 200 (sequencing).** Packet 200 (generated, unimplemented, queue row 1) migrates geometry call sites *inside* `modules/core-modules/classic-perimeters/src/lib.rs` onto `slicer_sdk::host` wrappers. This packet's classic-perimeters surface is disjoint by construction: `src/lib.rs` is on the out-of-bounds list and no step may edit it. The queue order (200 before 204) is the assumed sequencing, and it matters for the *measurement*, not the edit: the AC-8 profiling and the AC-3 parity baseline must be taken against the post-200 tree, because 200 moves classic-perimeters' `offset`/`difference_ex` work from in-guest to host-side and that materially changes both the wall-clock share justifying Hybrid membership and the native-vs-wasm divergence surface. If 204 is implemented before 200, the implementer MUST record that in the AC-8 evidence block and re-run the profiling after 200 lands.
<!-- snippet: wasm-staleness -->
- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and, if `STALE:` is reported, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.
<!-- snippet: coord-system -->
- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.
- No public schema/version constant is bumped and no struct gains a field in a crate with existing struct-literal sites; the only new structs (`EditionSpec`) and new fields (entries in the two registry vectors) are net-new with no pre-existing literal sites. Blast-radius discipline therefore does not bind, and no step carries a struct-literal sweep.

## Code Change Surface

- **Selected approach:** register-then-gate-then-finalize. (1) Add the three pilot modules to the 201/202 registry crate behind per-module cargo features. (2) Author a *shared, self-tested* structural comparator before any subject test, then one parity contract test per module reusing packet 202's demonstrated seam. (3) Express the Hybrid set as a committed TOML config with an `xtask`-side validating reader, finalized by an ADR-0055 profiling run.
- **Exact functions, traits, manifests, tests, and fixtures:**
  - `crates/slicer-integrated-modules/Cargo.toml` — three `[dependencies]` entries marked `optional = true` with path `../../modules/core-modules/<name>`, plus `[features]` `classic-perimeters = ["dep:classic-perimeters"]` and the two counterparts (feature names = module directory names, per 201's convention).
  - `crates/slicer-integrated-modules/src/lib.rs` — `integrated_registrations()` gains three `#[cfg(feature = "...")]` push blocks building `IntegratedModuleRegistration { manifest_toml: include_str!("../../../modules/core-modules/<name>/<name>.toml"), origin_label: "integrated://<name>" }`; `native_entries()` gains three `#[cfg(feature = "...")]` push blocks of `(ModuleId::from("com.core.<name>"), <Type>::__slicer_native_entry())` — note `ModuleId` is a **type alias** (`pub type ModuleId = String;` in `crates/slicer-ir/src/slice_ir.rs`), not a newtype struct, so `ModuleId::from(&str)` is `String::from` and no constructor needs importing. The `#[slicer_module]`-annotated types are `ClassicPerimeters` (impl `LayerModule`), `ArachnePerimeters` (impl `LayerModule`), `SupportPlanner` (impl `PrepassModule`) — verified in the tree at authoring.

Returns `Err(String)` naming the first violated invariant; the test wrappers `unwrap` it so the failure message is the diagnosis.

The entry key is the **full triple** including `global_layer_index`; `z` is inside the compared tuple. See `packet.spec.md` AC-5 for why both are load-bearing.

Unregistered files compile to nothing and report a false pass — preflight S7.
  - `crates/slicer-runtime/tests/integration/main.rs` — one `mod hybrid_pilot_external_override_tdd;` line.
  - `dist/editions.toml` (new file, new directory) — leading `# evidence:` comment block, `schema_version = 1`, then `[edition.developer]`, `[edition.hybrid]`, `[edition.integrated]`, each with `integrate_all` and `integrated_modules`.
  - `xtask/src/editions.rs` (new) + `mod editions;` in `xtask/src/main.rs` — `pub const EDITIONS_CONFIG_PATH: &str = "dist/editions.toml";`, `pub struct EditionSpec`, `pub fn load_editions(ws_root: &Path) -> Result<BTreeMap<String, EditionSpec>, String>`. Parsed with the already-present `toml = "0.8"` dependency via `toml::Table` — **no new xtask dependency**. Validation: every name in every `integrated_modules` must equal the file stem of a `build_guests::discover_guests(ws_root)` spec whose `tree == GuestTree::Core`; otherwise `Err(format!("{EDITIONS_CONFIG_PATH}: unknown module '{name}'"))`. Unit tests live in `#[cfg(test)] mod tests` inside the same file, because `xtask` has no `[lib]` target and an integration test could not reach `load_editions`.
  - `docs/01_system_architecture.md` §"Producing the tier-4 layout: `cargo xtask dist`" (heading located at line 982 at authoring; re-locate by heading text before editing).
- **Rejected alternatives and reasons:**
  - *Hardcode the Hybrid set as a Rust `const HYBRID_MODULES: &[&str]`.* Rejected: ADR-0057 requires "a dist-configuration list, not a hardcoded constant", and 205 must be able to change an edition's membership without a code change.
  - *Put the editions list inside `crates/slicer-integrated-modules/Cargo.toml` as a feature group (`hybrid = [...]`).* Rejected: a cargo feature group cannot express the **complement** (which modules a Hybrid edition still stages externally), which is exactly what 205's disjointness invariant needs; and it would not be readable by `xtask` without parsing a manifest.
  - *Put the reader in `crates/slicer-schema`.* Rejected: wrong home — that crate owns WIT and manifest schema, not distribution packaging. `xtask` already owns `discover_guests` and `dist`, which is the validation oracle and the consumer.
  - *Add `xtask/tests/editions_tdd.rs`.* Rejected: `xtask` is a binary-only crate; an integration test cannot import its modules. In-file `#[cfg(test)]` unit tests reach `load_editions` and run under `cargo test -p xtask`.
  - *Write one combined parity test parameterized over all three modules.* Rejected: a single test that fails cannot tell you which module diverged, and `requirements.md`'s one-module-at-a-time rule needs each module's gate to be independently red or green.
  - *Reuse `arachne_structural_invariants.rs`'s helpers by importing them.* Rejected: that file is a standalone Cargo-autodiscovered integration-test binary (`crates/slicer-runtime/Cargo.toml` declares no `[[test]]` sections at all — every test binary in that crate is autodiscovered from `tests/`), so it has no importable library surface and its helpers are private to it. The new comparator lives in `tests/common/` where both the `contract` and `integration` binaries can mount it.
  - *Compare final G-code instead of stage commits.* Rejected: G-code folds in seam placement, path optimization, and emission, so a divergence there cannot be attributed to the dispatch path under test.

## Gaps Inherited from Packet 202 (recorded at 202 closure, 2026-08-10)

Packet 202 closed with the native dispatch seam live and the never-silent rule enforced (AC-N2). The following 202-closure gaps bound what this packet's parity gate can and cannot exercise; none blocks the three pilots, but each is a recorded limit:

1. **Stage transports that fail LOUDLY on the native path.** 202's `marshal/native.rs` completes the commit for the layer infill/perimeter/support stages, prepass, finalization, and the postpass **text** variant. The native path returns a fatal error — never a silent skip — for `Layer::SlicePostProcess`, `Layer::PathOptimization`, seam stages, the layer `paint_segmentation` arm, and the postpass **gcode** variant (completing gcode postpass needs a runner-command mutation surface that 202's seam does not expose; that is a later packet). The three pilots dispatch only `Layer::Perimeters` (×2) and `PrePass::SupportGeometry`, which are fully committed — but a parity test must never route a pilot through the loud-error stages, and any future pilot on those stages needs the transport completed first.
2. **View-leg approximation points to audit in the parity gate.** 202's request builders hardcode values for fields the envelope cannot carry: `effective_layer_height.unwrap_or(0.2)` and `scoring_width: 0.4` in `crates/slicer-wasm-host/src/marshal/native.rs` (the input-view leg is exactly the dual leg this packet's gate audits). If a parity fixture's inputs traverse these fields, divergence at those points is expected and must be triaged as an envelope-coverage gap, not a module defect.
3. **Instrumentation zeros on native dispatches.** Native calls return empty `last_*`/`take_*` captures (ModuleAccessAudit/profiling see zeros) — documented at 202. AC-8's methodology is unaffected (fuel is a wasm-guest counter by ADR-0055; wall-clock is process-level), but if this packet's evidence needs per-module native reads, that is new work, not a fixture tweak.
4. **Native log capture deferred.** `slicer_sdk::host::log*` native arms bypass the dispatcher's capture channel (code comment in tree); no AC depends on it. If 204's profiling runs need native module logs, route them into `last_log_messages` as follow-up work.
5. **Workspace shape change.** The four sdk-* test-guests became workspace members (crate-type `cdylib, rlib`) and `cargo xtask build-guests` discovers test-guests by path pattern, not the old `[workspace]` sentinel. The parity seam file `native_dispatch_parity_seam_tdd.rs` landed and is the reuse template for Steps 4–6 — re-derive its exact construction shape by dispatch (its final form may differ from the authoring-time quote).

## Locked Assumptions and Invariants

- **Locked:** the Hybrid integrated set lives in `dist/editions.toml` and nowhere else; any consumer (packet 205 included) reads it through `xtask::editions::load_editions`. A second source of truth for edition membership is a design defect.
- **Locked:** names in `integrated_modules` are module **directory** names — simultaneously the `slicer-integrated-modules` cargo feature name, the `modules/core-modules/<name>` directory, and the `<name>.wasm` / `<name>.toml` stem `xtask dist` stages. This three-way identity is what lets 205 derive both the cargo feature list and the disjoint external set from one list. It is validated by `load_editions` (AC-7, AC-N1).
- **Locked:** parity is certified by structural invariants plus tolerance, never by byte-equality and never by a stored snapshot of PnP's own output (ADR-0042 rejects self-captured baselines as oracles; ADR-0056 Decision item 4 rejects byte-equality).
- **Locked:** integrated modules stay single-threaded internally until a separate per-module decision with a deterministic merge (ADR-0056 Decision item 5).
- **Reversible:** every pilot module is behind an off-by-default cargo feature. A build with no pilot feature enabled is byte-identical in behavior to the pre-packet tree, so the integration is revertible without a code change.

## Risks and Tradeoffs

- **The comparator could be authored too loosely and certify a broken native path.** This is ADR-0042's central failure mode. Mitigated structurally: the comparator's own self-tests land and pass *before* any subject test — AC-N2/AC-N3 for the layer family and **AC-N6 for the prepass family**, so neither comparator ships unproven. AC-N3 requires rejection of the D5 dropped-loop class; AC-N6 requires rejection of a dropped `SupportPlanEntry`, a dropped `branch_segment`, a dropped point, and — the sharpest case — an entry whose `global_layer_index` differs while `(object_id, region_id)` match, which is the discriminator proving the entry key is the full triple rather than a layer-collapsing pair. Residual risk: an invariant not in the ADR's list could still be violated silently.
- **Arachne's native path may legitimately diverge more than the others**, because its wasm arm routes through the `generate-arachne-walls` host service while its native arm calls `run_arachne_pipeline` in-process — nominally the same code, but the WIT round-trip re-encodes coordinates. If the `1e-3` mm tolerance proves too tight there, the correct response is to *widen the coordinate tolerance for that module with a measured maximum per-point delta and a recorded rationale* and file a DEVIATION_LOG row, never to drop an invariant — and never past the absolute `coord_mm` ceiling of **`1e-2` mm**. The ceiling exists because widening is otherwise unbounded: two “next order of magnitude” steps reach `1e-1` mm, which is larger than nozzle-scale features (a 0.4 mm nozzle emits ~0.45 mm beads), making the coordinate gate inert while still looking green. A divergence that needs more than `1e-2` mm is a defect, not drift: the module is dropped from `hybrid.integrated_modules` and the divergence is filed. The same ceiling binds the prepass comparator.
- **The AC-8 profiling could show one of the three seeded modules does not merit Hybrid membership.** That is a legitimate outcome, not a failure: ADR-0057 says the set is "seeded" and "finalized by profiling". The list shrinks and the evidence block records why. The parity test for a dropped module still ships (its feature still exists), so a later packet can re-add it without re-deriving the gate.
- **A stale wasm twin silently invalidates every parity result.** A stale guest compared against a fresh native path produces a divergence that looks like a real defect. Mitigated by the freshness gate immediately before each parity run.
- **Sequencing with packet 200** — covered under Architecture Constraints. The tradeoff accepted: if 204 runs first, the AC-8 numbers must be re-taken later; the parity gate itself remains valid because it compares the two paths of whatever tree exists.
- **The `xtask` reader adds a validation that will fail loudly if a module directory is renamed.** Accepted deliberately: a silent mismatch would ship an edition that both integrates and externally stages the same module — the exact shadowing ADR-0056 warns negates the edition.
