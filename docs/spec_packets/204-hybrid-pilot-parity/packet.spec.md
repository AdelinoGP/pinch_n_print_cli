# Packet Contract: 204-hybrid-pilot-parity

## Goal

Ship `classic-perimeters`, `arachne-perimeters`, and `support-planner` as integrated modules — registered through packet 201's registry and packet 202's native-entry table behind their per-module cargo features — gated by per-module dual-dispatch parity contract tests that assert ADR-0042 structural invariants plus tolerance-based IR comparison, and record the profiling-finalized Hybrid integrated set as a committed dist-config list at `dist/editions.toml`.

## Scope Boundaries

This packet wires three already-native module crates into `crates/slicer-integrated-modules/` (features, `integrated_registrations()`, `native_entries()`), adds three parity contract tests plus one shared invariant helper under `crates/slicer-runtime/tests/`, and creates `dist/editions.toml` with an `xtask` reader/validator. It does **not** change dispatch routing, macro emission, marshalling, the CLI surface, or `cargo xtask dist` itself (202, 203, and 205 respectively), and it does not touch the geometry call sites inside `modules/core-modules/classic-perimeters/src/lib.rs` (packet 200 owns those).

## Prerequisites and Blockers

- Depends on: `201-integrated-module-registry-tier5` and `202-native-adapter-and-dispatch`, both `implemented` as of 2026-08-10 (202 closed with the FORWARD-DEP shapes below verified in the tree: `IntegratedModuleRegistration`, `integrated_registrations()`, `native_entries() -> Vec<(ModuleId, NativeStageEntry)>`, `ModuleProvenance`, `load_live_modules_for_plan_with_integrated(..., native_entries)`, `slicer_sdk::native::NativeStageEntry`, `__slicer_native_entry()`, `CompiledModuleLive.native_entry` / `with_native_entry`, the crate `crates/slicer-integrated-modules/` itself, and the parity-seam pattern in `crates/slicer-runtime/tests/contract/native_dispatch_parity_seam_tdd.rs`). Minor landed deltas vs the authoring quotes: the loader takes `native_entries: &[(ModuleId, NativeStageEntry)]` (slice, not Vec); `NativeStageEntry` derives `Clone, Copy`; the four sdk-* test-guests are now workspace members. Known 202-closure gaps that bound this packet's scope are recorded in `design.md` §"Gaps Inherited from Packet 202". Packet 203 is **not** required.

- Unblocks: 205 (`cargo xtask dist` edition dimension consumes `dist/editions.toml`).
- Activation blockers: 201 and 202 must be `implemented` first. See `design.md` §Open Questions for `[FWD]` items.

## Acceptance Criteria

State ACs only here; `requirements.md` references their IDs.

- **AC-1. Given** `slicer-integrated-modules` built with all three pilot features enabled, **when** `integrated_registrations()` is called, **then** it returns exactly 3 registrations whose embedded `manifest_toml` values carry `module.id` values `com.core.classic-perimeters`, `com.core.arachne-perimeters`, `com.core.support-planner`, with `origin_label` values `integrated://classic-perimeters`, `integrated://arachne-perimeters`, `integrated://support-planner` (201's origin-label convention). | `cargo test -p slicer-integrated-modules --features classic-perimeters,arachne-perimeters,support-planner hybrid_pilot_registrations_are_exactly_three`
- **AC-2. Given** the same three features, **when** `native_entries()` is called, **then** it returns exactly 3 `(ModuleId, NativeStageEntry)` pairs in which `com.core.classic-perimeters` and `com.core.arachne-perimeters` carry `NativeStageEntry::Layer(..)` and `com.core.support-planner` carries `NativeStageEntry::Prepass(..)`, matching each module's declared `[stage] id` (`Layer::Perimeters`, `Layer::Perimeters`, `PrePass::SupportGeometry`). | `cargo test -p slicer-integrated-modules --features classic-perimeters,arachne-perimeters,support-planner hybrid_pilot_native_entry_families_match_stage_ids`
- **AC-3. Given** one `WasmRuntimeDispatcher` and two `CompiledModuleLive` values for `com.core.classic-perimeters` — native (`native_entry: Some(ClassicPerimeters::__slicer_native_entry())`, `wasm_component: None`) and wasm (`native_entry: None`, `wasm_component: Some(..)`) — driven on a byte-identical `LayerStageInput` and `ConfigView`, **when** `LayerStageRunner::run_stage` runs on both, **then** both return `Ok(Some(LayerStageCommit))` and `assert_parity_structural` passes: equal region count, equal loop count per region, equal loop nesting depth sequence, equal per-loop point count, equal `ExtrusionRole` sequence, every loop closed within `1e-3` mm, no self-intersection, and per-point coordinate agreement within `1e-3` mm — **float byte-equality is not asserted** (ADR-0056 Decision item 4). | `mkdir -p target && cargo test -p slicer-runtime --test contract -- integrated_parity_classic_perimeters 2>&1 | tee target/test-output.log && rg -q "^test result: ok" target/test-output.log`
- **AC-4. Given** the same dual-dispatch construction for `com.core.arachne-perimeters`, **when** both paths run on a byte-identical `LayerStageInput`, **then** both return `Ok(Some(LayerStageCommit))`, `assert_parity_structural` passes with the same invariant set as AC-3, and additionally the bead-count sequence per loop is equal between the two paths and no bead width exceeds `2.0 ×` the resolved `optimal_width` on either path (ADR-0042's D4 invariant). | `mkdir -p target && cargo test -p slicer-runtime --test contract -- integrated_parity_arachne_perimeters 2>&1 | tee target/test-output.log && rg -q "^test result: ok" target/test-output.log`
- **AC-5. Given** one `WasmRuntimeDispatcher` and two `CompiledModuleLive` values for `com.core.support-planner` on a byte-identical `PrepassStageInput` carrying the shared support-wedge fixture, **when** `PrepassStageRunner::run_stage` runs on both, **then** both return `Ok(PrepassStageOutput::SupportPlan(..))` whose `SupportPlanIR` agree structurally at every nesting level of the real shape (`SupportPlanIR.entries: Vec<SupportPlanEntry>` → `SupportPlanEntry.branch_segments: Vec<ExtrusionPath3D>` → `ExtrusionPath3D.points: Vec<Point3WithWidth>`, all in `crates/slicer-ir/src/slice_ir.rs`): equal `entries` count; equal key set over the **full triple** `(global_layer_index: i32, object_id: ObjectId, region_id: RegionId)`; per matched entry, equal `branch_segments` count; per matched segment, equal `points` count and equal `role`; per matched point, `(x, y, z, width)` agreement within `1e-3` mm. The layer index is part of the key because `SupportPlanIR.entries`' own doc comment states multiple entries may share `(layer, object)`, and keying on `(object_id, region_id)` alone would collapse every layer into one bucket — a wasm path that dropped an entire layer's branches would still pass. `z` is compared for the same reason: it is the last physical layer discriminator. | `mkdir -p target && cargo test -p slicer-runtime --test contract -- integrated_parity_support_planner 2>&1 | tee target/test-output.log && rg -q "^test result: ok" target/test-output.log`
- **AC-6. Given** `arachne-perimeters` compiled into the host (it declares `slicer-core` with `default-features = false`, so its native arachne arm depends on `host-algos` arriving through `slicer-sdk`'s `cfg(not(target_arch = "wasm32"))` dependency), **when** the native path of AC-4 runs, **then** it emits a non-empty wall set — impossible unless `slicer_sdk::host::generate_arachne_walls`' native arm reached `slicer_core::arachne::pipeline::run_arachne_pipeline` — and `crates/slicer-integrated-modules/Cargo.toml` gates the `arachne-perimeters` dependency behind a feature of the same name rather than enabling it unconditionally. | `sh -c 'rg -q "arachne-perimeters" crates/slicer-integrated-modules/Cargo.toml && rg -U -q "\[features\][^\[]*arachne-perimeters" crates/slicer-integrated-modules/Cargo.toml && (rg -q "host::generate_arachne_walls" modules/core-modules/arachne-perimeters/src/lib.rs || rg -q "slicer_sdk::host::generate_arachne_walls" modules/core-modules/arachne-perimeters/src/lib.rs || rg -q "\bgenerate_arachne_walls\(" modules/core-modules/arachne-perimeters/src/lib.rs) && echo PASS'`
- **AC-7. Given** the committed dist-config list at `dist/editions.toml`, **when** `xtask`'s `load_editions` reads it, **then** it returns three editions keyed `developer`, `hybrid`, `integrated`; `hybrid.integrated_modules` equals the profiling-finalized set as a list of module **directory** names (each name equal to a `modules/core-modules/<name>` directory, a `slicer-integrated-modules` cargo feature, and a staged `<name>.wasm` stem); `developer.integrated_modules` is empty with `integrate_all = false`; `integrated.integrate_all = true`. | `cargo test -p xtask editions_config_declares_three_editions`
- **AC-8. Given** the ADR-0055 `--profile` methodology applied to a release binary, **when** the packet closes, **then** `dist/editions.toml` carries a leading `# evidence:` comment block recording, for each of the three seeded modules, **both** ADR-0055 signals: the measured per-module **guest fuel** (the ADR's *primary* signal). Fuel must be sampled on the **external/wasm** build: ADR-0055 states verbatim that "native code is not metered", so a natively-dispatched module reports zero by construction. (The ADR's only statement about a host call not burning fuel is scoped to the profile *mark* — "Because the mark is a host call, it burns no fuel" — so "host calls consume no fuel" in general is an inference from the ADR's fuel definition, not ADR text. Either way the conclusion holds: fuel is a wasm-guest instruction counter. The ADR predates integrated modules and does not discuss them.) **and** the measured per-module **wall-clock share** (the ADR's *secondary* signal, taken profiling-off per ADR-0055's "absolute timings come from a profiling-off run" caveat), plus the model, the exact command, and the run-to-run spread. The `hybrid.integrated_modules` list must match that evidence. | `sh -c 'rg -q "^# *evidence:" dist/editions.toml && rg -qi "fuel" dist/editions.toml && rg -qi "wall-clock" dist/editions.toml && rg -q "extruder_idler|benchy" dist/editions.toml && rg -q "run-to-run spread" dist/editions.toml && echo PASS'`
- **AC-9. Given** ADR-0056 Decision item 5 (integrated modules stay single-threaded internally), **when** the three pilot module crates are inspected, **then** none of `modules/core-modules/{classic-perimeters,arachne-perimeters,support-planner}/Cargo.toml` declares a `rayon` dependency in either the inline (`rayon = ...`) or table (`[dependencies.rayon]`) form, and none of their `src/**` files uses `par_iter`, `par_bridge`, `par_chunks`, or `rayon::`. | `sh -c 'for m in classic-perimeters arachne-perimeters support-planner; do rg -q "^(rayon|\[dependencies\.rayon\]|\[target\..*dependencies\.rayon\])" modules/core-modules/$m/Cargo.toml && { echo "FAIL rayon dep: $m"; exit 1; }; rg -q "par_iter|par_bridge|par_chunks|rayon::" modules/core-modules/$m/src/ && { echo "FAIL rayon use: $m"; exit 1; }; done; echo PASS'`

## Negative Test Cases

- **AC-N1. Given** an `dist/editions.toml` whose `hybrid.integrated_modules` names `not-a-module`, **when** `load_editions` runs, **then** it returns `Err` whose message contains both `not-a-module` and `dist/editions.toml` — an unknown module directory name is never silently ignored, because a silently-dropped name would ship an edition that stages an external copy of a module it believed integrated (ADR-0056 disjointness consequence). | `cargo test -p xtask editions_config_rejects_unknown_module_name`
- **AC-N2. Given** the parity comparator `assert_parity_structural`, **when** it is handed two commits that are structurally identical but whose every coordinate differs by `1e-6` mm (a ULP-scale perturbation of the kind wasm32-vs-native libm drift produces), **then** it returns `Ok(())` — proving the gate is tolerance-based and not byte-equality (ADR-0056 Decision item 4, DEV-093). | `cargo test -p slicer-runtime --test contract -- parity_comparator_accepts_ulp_perturbation`
- **AC-N3. Given** the same layer-family comparator, **when** it is handed two commits where the second is missing one closed loop (the ADR-0042 D5 geometry-dropping failure class) and, separately, two commits whose loop point counts differ, **then** it returns `Err` in both cases with a message naming the differing invariant — proving the invariants are not vacuous and cannot be satisfied by dropped geometry. | `cargo test -p slicer-runtime --test contract -- parity_comparator_rejects_dropped_loop`
- **AC-N4. Given** an external `com.core.classic-perimeters` on a disk search root plus the integrated registration and native-entry table from AC-1/AC-2, **when** `load_live_modules_for_plan_with_integrated` builds bindings, **then** that module's `LiveModuleBinding` has `native_entry: None` and `wasm_component: Some(..)` — the pilot integration never bypasses a user's external override. (Note: `load_live_modules_for_plan_with_integrated` in `crates/slicer-wasm-host/src/execution_plan_live.rs` is the **live-binding** layer and is a different function from `load_modules_from_roots_with_integrated` in `crates/slicer-scheduler/src/manifest.rs`, which is the **manifest-ingestion/dedup** layer. This AC asserts on the former's `LiveModuleBinding` output; dedup itself is packet 201's contract.) | `cargo test -p slicer-runtime --test integration hybrid_pilot_external_override_forces_wasm`
- **AC-N5 (doc grep).** Given the doc edits below, both greps pass. | `sh -c 'rg -q "dist/editions.toml" docs/01_system_architecture.md && rg -q "integrated_modules" docs/01_system_architecture.md && echo PASS'`
- **AC-N6. Given** the prepass-family comparator `assert_prepass_parity_structural`, **when** it is handed two `SupportPlanIR` values that differ in exactly one of four ways — (a) the second is missing one whole `SupportPlanEntry`, (b) the second has an entry whose `global_layer_index` differs while `(object_id, region_id)` match, (c) the second is missing one `ExtrusionPath3D` from one entry's `branch_segments`, (d) the second has a segment with one fewer `Point3WithWidth` — **then** it returns `Err` in all four cases naming the differing level. Case (b) is the specific discriminator proving the key is the full triple and not `(object_id, region_id)`; case (a) is ADR-0042's D5 dropped-geometry class at prepass scope. | `cargo test -p slicer-runtime --test contract -- parity_comparator_rejects_dropped_support_entry`
