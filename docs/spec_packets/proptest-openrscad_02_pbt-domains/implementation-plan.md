# Implementation Plan: pbt-domains

Do not start until `proptest-openrscad_01_pbt-foundation` is implemented and its feature, `PropertyRun`, `CaseGuard`, registry and context contracts have been rechecked against disk. New symbols/files in this plan are planned, not present at authoring. Steps leave default and property-enabled targets compiling. The spec defines `C`, `P`, feature gates and mandatory `target/test-output.log` capture; inspect/archive that file before the next test invocation.

## Step 1: Recheck the foundation and add compiling helper targets

- Objective: consume the real predecessor surface and prepare registered, feature-gated test homes without changing production contracts.
- Surface: `crates/slicer-sdk/src/test_support/property_testing/mod.rs` from the predecessor; new `domains`, `oracles`, `regression` submodules beneath it; new `crates/slicer-sdk/tests/property_domains.rs` and `crates/slicer-sdk/tests/property_domain_contracts.rs`; `crates/slicer-sdk/Cargo.toml` target registrations and property-only dependencies if needed; `test-properties.toml` predecessor schema.
- Approach: use exactly the export names/shapes in the spec. Add error/type declarations and compile witnesses first; do not add live registry records for nonexistent executable tests. Read actual prerequisite status/exports and current canonical fixture/coordinate/test-quality docs. No new feature beyond `property_testing`; no property/engine default, production guest manifest, normal-dependency cycle or SUT visibility widening.
- Fallout: new test-support types have no preexisting literal sites. `GeometryBounds` and `GeometryDomain` need safe documented `Default` bases for later FRU; test literals of watched helper/IR types follow `docs/21_data_defaults_and_fixtures.md`. No IR/WIT/schema/default changes.
- Verify: `cargo check -p slicer-sdk --all-targets --features property_testing`; `cargo check -p slicer-sdk --all-targets`; predecessor `property_harness` target with mandatory test-log wrapper.
- Done when: disabled builds remain clean and both new targets really appear in feature-enabled Cargo metadata/discovery; compile witnesses are labeled as such, not counted as correctness properties.

## Step 2: Implement scalar, graph, IR and permutation domains with independent small models

- Objective: support the cheap data-model owner packets without waiting for geometry or an engine.
- Surface: the new `domains` scalar/config/ID/graph/IR exports under `crates/slicer-sdk/src/test_support/property_testing/`; its `oracles::{graph_reachability,graph_cycle_remainder,first_missing_anchor,is_permutation,locked_groups_are_contiguous}`; deterministic `domain_scalar_edges_and_config_types`, `domain_graph_models_and_cycle_tail`, `domain_ir_anchors_permutations_and_layers` and malformed-bound controls in `crates/slicer-sdk/tests/property_domain_contracts.rs`; initial three executable generative functions named in the spec in `crates/slicer-sdk/tests/property_domains.rs`.
- Approach: construct DAGs from unique nodes/forward edges and cycles with a retained downstream tail. Use independent nonempty-path enumeration for reachability/cycle remainders. Build IR with existing fixture bases and fresh per-layer IDs, choose explicit matching roles, and keep config scalar domains separate from cross-field validity. Include deterministic IEEE/ID/empty/extreme-anchor witnesses. Preserve valid/dangling/cycle/malformed/lock modes during all shrinks.
- Surface integration: replace only the local strategy/oracle in `crates/slicer-ir/tests/property_ir.rs::proptest_ir_travel_anchors_membership` with shared `anchor_cases`/`first_missing_anchor`; keep the `H-IR-ANCHORS` registry ID, actual validator invocation, first-missing-ID check and foundation bounds keys unchanged. Do not recast allocator/sentinel rules as membership-validation behavior.
- Verify: `C`; feature-enabled SDK check; `cargo xtask test --summary --properties --property H-IR-ANCHORS --tier routine`. Before live profiles for the new D-records, use controlled subprocess contexts for pilot/probe execution exactly as in foundation.
- Done when: cheap strategies/models fail deliberate counterexamples, all semantic witnesses survive simplify/complicate, shared anchor adoption still proves the actual library validator, and no malformed raw graph is accidentally passed to a validated scheduler contract.

## Step 3: Prove exact integer geometry predicates before using them to certify inputs

- Objective: build independently justified validity and full-segment inclusion machinery for small bounded cases.
- Surface: the new `oracles::{orientation,signed_area2,segment_relation,validate_ring,point_in_region,segment_in_region,validate_geometry}` under `crates/slicer-sdk/src/test_support/property_testing/` plus supporting private functions; scalar-to-grid collapse and exact predicate tests in `crates/slicer-sdk/tests/property_domain_contracts.rs`; optional numeric dependency wiring in root/SDK manifests and lockfile when selected.
- Approach: use original elementary geometry, not Clipper/geo/production validators. Derive checked orientation/area bounds. Partition segments at every rational intersection and inspect every open interval and endpoint, with explicit strict/inclusive/tangent/overlap behavior. Choose checked bounded rationals only with a complete intermediate proof; otherwise use optional exact rational/big-integer internals. Keep public return types unchanged. Implement ring adjacency exceptions, disjoint strict holes, winding and component relationships without a repair step.
- Verify: `C`, especially `domain_exact_predicates_counterexamples` and `domain_rejects_invalid_bounds_and_witness_loss`. Check documented hand-worked orientation/area values, concave and hole-crossing cases defeating vertex/single-midpoint checks, touching boundaries, quantization collapse and arithmetic overflow. Run default/property-enabled dependency graph checker from foundation if dependencies change.
- Done when: independently worked fixtures falsify common broken predicates, overflow cannot masquerade as a valid result, and the exact oracle's dependency overlap and arithmetic/units proofs are documented. Do not begin certifying random valid geometry before this gate is green.

## Step 4: Add bounded topology families and protocol-correct shrinking

- Objective: expose real diverse geometry and meaningful structurally smaller failures without claiming unrestricted polygon generality.
- Surface: `GeometryBounds`, `GeometryDomain`, `GeometryCase`, `GeometryStrategy`, `GeometryValueTree`, `geometry_cases`, `geometry_complexity`, `line_segments`, `InvalidGeometryKind`/case/strategy under the new `crates/slicer-sdk/src/test_support/property_testing/domains/`; topology/shrink tests in `crates/slicer-sdk/tests/property_domain_contracts.rs`; `proptest_direct_geometry_domains` in `crates/slicer-sdk/tests/property_domains.rs`.
- Approach: start with parameterized deterministic catalog families (convex, concave, proven non-star-shaped orthogonal notch, multiple holes/disconnected outers, narrow-neck/corridor, gap/short-edge and one-unit/almost-collinear cases). Add optional vertices, holes/components and translation/dimension parameters so structural shrinking is demonstrable. Validate each generated/current candidate with Step 3 predicates; reject impossible requests at construction. Use actual ValueTree rollback protocol, bounded candidate retries and lexicographic complexity. Allow removal only above minima; keep class/invalid witness. Do not use an unchecked generic vertex-deletion shrinker or a rejection-only "general" generator.
- Fallout: safe helper defaults permit FRU, but live measured profile bounds are explicit; update helper test literals in this step rather than weakening the literal gate. No production IR field or version changes.
- Verify: `C`, including `domain_geometry_topology_witnesses`, `domain_shrink_protocol_preserves_witnesses`, `domain_known_failures_shrink_structurally`, false-return/repeated-complicate transitions, and `domain_exhaustion_is_not_success`. Probes begin with explicit nonminimal cases and assert both nonempty populations and actual complexity reduction.
- Done when: every declared topology class has coordinate-level independent evidence; all exposed valid shrink states stay valid; removable structure shrinks and required structure remains; exhaustion is distinguishable from pass. The evidence states these are bounded families, not a completed hybrid/general generator.

## Step 5: Analytical mesh and transform families with separate oracles

- Objective: supply small mesh stimuli and independent structural/analytical checks for later mesh/I-O properties.
- Surface: `SolidKind`, `MeshCase`, `analytical_meshes`, `RigidTransformCase`, `rigid_transforms`, `InvalidMeshKind`, `invalid_meshes`; `oracles::{validate_indexed_mesh,mesh_signed_volume_mm3}`; `domain_analytical_mesh_oracles` and `proptest_direct_mesh_domains`.
- Approach: indexed boxes/prisms use positive dyadic mm dimensions; independently expected bounds/volume come from dimensions. Validate finite coordinates, flat index triples, triangle degeneracy and opposite closed-edge incidence; compare signed tetrahedron-sum volume against dimensional geometry with a derived mm³ error bound. Build explicit column-major identity/quarter-turn/translation matrices, never `Transform3d::default()`. Independent transform observations are coordinate sign/swaps plus translation, not the same matrix helper. Keep malformed families separate and fault-preserving through shrink.
- Verify: `C`; property-enabled SDK check; controlled `D-MESH` pilot context after its callback exists. Include invalid index/stream/finite/degenerate records, translated/quarter-turned solids and checked excessive-bound rejection.
- Done when: mesh metadata and geometry agree by independent calculations, no finite-intermediate assumption is unproved, and limitations (no arbitrary 3D self-intersection certificate or arbitrary-rotation invariance) are explicit.

## Step 6: Compile concrete regression fixtures and connect failure artifacts

- Objective: make generated failures usable as named, readable, RNG/evaluator-independent regressions.
- Surface: the new `regression::{ConcreteInput,format_regression_fixture}` under `crates/slicer-sdk/src/test_support/property_testing/`; target-local diagnostics integration in the foundation helper; `domain_regression_fixture_compiles_and_preserves_bits` and fixture compilation support in `crates/slicer-sdk/tests/property_domain_contracts.rs`.
- Approach: output a fixture statement block, not an assertion-free generated test. Escape string/comments/identifiers, preserve float bits (signed zero, infinities, NaN payload), all IDs/topology and flat indices, use safe fixture bases/FRU for watched IR structs. The named owner regression must add an actual independent assertion to the production SUT and name the root cause/previous input. Do not commit a fake SUT regression solely to demonstrate the formatter.
- Verify: `C` compiles/evaluates emitted representative statements in a native temporary fixture build, retaining compiler output; use a feature `test`-only fixture dependency graph where SDK bases are referenced and prove no Proptest RNG/context/engine is needed. Any Cargo test invocation inside probes must route combined output into/append to `target/test-output.log`; a plain compile/run probe is not a hidden unlogged test suite. Re-run source/artifact replay probes and check no source-adjacent seed history is created.
- Done when: reconstructed concrete data/bit patterns match, malicious/empty metadata cannot corrupt a fixture, and target artifacts include readable root-cause/input material rather than seeds alone. A string snapshot is not accepted as compilation evidence.

Verify the existing foundation Windows routine job discovers and executes the new records, not a copied CI list. Record direct G-GEOMETRY proof and remaining scripted/general-geometry obligations for `pbt-scripted`.
- Verify: `C`, `P` routine/extended, `H-IR-ANCHORS`, then full selected registry routine/extended commands, reading/archiving combined logs between runs; foundation harness/xtask negative probes; default and feature-enabled build/check/clippy, literal/test-quality and guest freshness gates in the spec. An unavailable CI execution is a closure gap, not a source-inspection pass.
