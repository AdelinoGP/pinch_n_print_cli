# Implementation Plan: pbt-ci-closure

This is an authoring-only packet. Re-read the approved source plan and both files of every predecessor, then start complete closure only after #1–#16 are `implemented`; `generated` is not implementation. A blocked SCAD/scripted branch permits an accurately labeled partial direct audit, not implementation/closure of this packet. Do not edit other packet artifacts or the source queue. No step below assumes a test, CI job, feature, profile or evidence file exists before its prerequisite lands.

All `C1`, `C2`, `X`, `CHAIN-runtime`, `CHAIN-core`, `GCODE`, `SPEED`, `BRIM`, `SCAD-*`, `P-*`, `R-*` and `GRAPH` aliases are the exact commands and target/feature/filter rules in `packet.spec.md` § Verification. Every plain Cargo test uses its status-preserving tee wrapper; archive/read `target/test-output.log` before the next run. Registry and guest-dependent runs go through `cargo xtask test`, without a second Cargo-test process hiding its status. Every step leaves the default workspace build and its selected feature configuration compiling.
