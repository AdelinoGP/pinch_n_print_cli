# PBT CI and Rollout Closure

## Goal

Close the approved Proptest/OpenRSCAD rollout only when its complete property inventory, measured Windows execution, SCAD obligations, dependency boundaries, contributor handoff and repository acceptance gates have independently verifiable evidence.

## Why

`docs/specs/proptest-openrscad-adoption.md` § G-ROLLOUT requires all selected families to be accounted for, actual Windows CI and manual extended execution, dependency isolation, documentation and a complete evidence ledger. Earlier packets own and incrementally wire their routine properties; this packet audits and completes that wiring, not retroactive permission for an earlier family to omit it. A compiled test, a registry row, an upstream Windows build, a green unrelated test or an authoring preflight is not execution evidence.

At authoring the approved queue recorded #1–#16 as generated and their packet front matter as `draft`: generated means authored, not implemented. At that point the tree had no property registry, property runner, SCAD adapter or Windows jobs; re-derive their state at implementation rather than treating this authoring snapshot as current. All names and files explicitly identified as prerequisite or new below are planned; no profile, feasibility result, build, test or CI pass is claimed here.

## Scope

- In: audit every predecessor charter, registry identity, exact target and feature, measured tier, executed-property event, evidence document, handoff, forward item and defect/regression; finish registry-driven CI/discovery, Windows manual dispatch and failure-artifact wiring; prove replay and production/guest dependency isolation; provide the final evidence ledger, contributor handoff and the explicit gated final workspace acceptance in Verification.
- In: focused corrections to the existing property runner, its registry/discovery, test fixtures and CI wiring needed to make that audit fail closed. Add only the private xtask tests specified below. Preserve normal test passthrough, existing guest/CLI freshness and quarantine policy.
- Out: implementing an earlier family, SCAD adapter/importer, broad geometry generator or additional randomized guest/pipeline campaign; new SDK/production APIs; loosening profiles, assertions, tolerances, feature gates or tests to obtain a pass; a wholesale migration of existing Ubuntu jobs; scheduled runs. Family fixes and any required blocking follow-up are owned by the appropriate predecessor/follow-up work, not silently absorbed here.
