## Problem Statement

Packet P13 (Support / Support — owner `support-planner`) is the next uncovered slice of the OrcaSlicer FFF feature-gap queue (`05-asset-packet-list.md` §P13 — 12 keys, Tier A). Authoring-time re-derivation against the tree (the map's "re-derive, don't trust" rule) finds the 12 keys in four states, none matching the tier table's uniform "Tier A plumbing, owner support-planner" row:

- **Six keys are already wired and canonical-faithful** — `support_object_xy_distance` (declared 0.35 / [0, 10] in both planner manifests, consumed by both planners), `support_threshold_angle` (host typed 30.0, consumed by the overhang analysis, declared in `traditional-support-planner.toml`), `support_style` (canonical 7-value enum declared in `tree-support-planner.toml`, string form in `traditional-support.toml`, consumed by the tree planner and by `traditional-support`'s snug branch), `support_type` (the raw-config family selector — functional end-to-end but declared in **no** module manifest), `support_expansion` (host typed 0.0, consumed as the overhang Step-6 XY expansion), `support_threshold_overlap` (host typed `ResolvedFloatOrPercent{50.0, true}`, consumed on the zero-angle branch).
- **One key is wireable with a genuinely missing input** — `enforce_support_layers`: the decision point exists (`force_support = params.layer_id < params.enforce_support_layers` in `slicer-core`'s `overhang_annotation.rs`, with geometry arms already in `support_overhang_detection_tdd.rs`), but `resolve_contact_params` (`crates/slicer-runtime/src/builtins/support_analysis_producer.rs`) hardcodes `enforce_support_layers: 0` with the comment "New bridge / sharp-tail / enforce / layer-index knobs have no production config source yet". The plumbing is one field read.
- **Five keys have no decision point in this tree** — `raft_first_layer_expansion` (zero occurrences anywhere under `crates/` + `modules/`; no `ResolvedConfig` field), and `support_bottom_z_distance` / `support_critical_regions_only` / `support_object_first_layer_gap` / `support_remove_small_overhang` (host-typed `ResolvedConfig` fields with canonical defaults, emitted to the CONFIG_BLOCK via `SUPPORT_CONFIG_DEFAULTS` where applicable, but with zero production read sites). These are re-adjudicated **declared-with-gap** (packet 259/260/261 pattern): declared with canonical types/defaults/bounds in the owner manifests, unread, pinned non-perturbing.

The owner correction re-derived at authoring: the tier table's `support-planner` claim is held by `tree-support-planner` and `traditional-support-planner` (and that is where `support_object_xy_distance` rides, and where raft-family keys ride per packet 261), but the overhang-analysis decision points for `support_threshold_angle` / `support_threshold_overlap` / `support_expansion` / `enforce_support_layers` live in the **host** (`slicer-runtime::builtins::support_analysis_producer` + `slicer-core::algos::overhang_annotation`), the family selection for `support_type` lives in the **scheduler** (`select_support_family`, `execution_plan.rs`), and the five with-gap keys have no live decision point anywhere (canonical consumers recorded in §Per-Key Canonical Evidence). The packet declares the family-agnostic support-analysis keys in both planner manifests (the `support_object_xy_distance` "both families read one key" pattern) and records the correction.

User rulings: none required — every port default already equals the canonical default (verified per key below), and the five with-gap declarations are canonical-bounds net-new (no declared-bounds divergence is created — the single exception, `support_expansion` min 0.0, mirrors the port's own host-side `>= 0` bound from `docs/config/host-keys.toml` and is recorded, not invented).

### Wiring notes (port-specific decisions the canonical reads forced)

- **The one true wiring: `enforce_support_layers`.** The decision point is real and tested (`SupportContactParams.enforce_support_layers` + the `force_support` branch; arms `enforce_support_layers_forces_full_contacts_in_leading_layers` and `enforce_support_layers_beyond_model_changes_nothing` already exist in `slicer-core/tests/support_overhang_detection_tdd.rs`). The producer comment claiming "no production config source yet" becomes false. The typed CLI-bound `u32` field is the only read needed (`extension_float` would be wrong — the producer's own doc comment warns that extensions lookups silently ignore configured values for CLI-bound keys; `support_threshold_angle` at `resolve_contact_params` is read the same typed way). Default 0 → `force_support` never true → default-path identity (AC-3 + AC-N1 both assert). Canonical's tree-family enforced-layer offset is `-0.15 × extrusion_width` (a different mechanism from the normal-family `lower_layer_offset = 0`); the port has one branch and it is the normal-family one — recorded as a divergence note, not implemented (tree-family fidelity is Tier B+ geometry).
- **`support_type` gets its first manifest home.** The family selector is functional today via raw config (scheduler `select_support_family` reads the raw map before typed resolution; both planners' `canonical_support_family`; the producer's `support_family()`); the absence of a manifest declaration means no enum bounds enforcement and no module-table row. Declaring the canonical 4-value enum in both planner manifests (same-key-in-two-modules pattern, `support_object_xy_distance` precedent) makes the global raw-config path reject unknown spellings (AC-4, `TypeMismatch`) — canonical-faithful strictness (Orca's parser rejects unknown enum values). The per-object metadata path (`loader.rs` object-metadata coercion) and per-region claim matching keep their existing tolerant fallback (`canonical_support_family` prefix-match → traditional); the asymmetry is recorded as a divergence note, not silently extended.
- **`support_style` type correction on the traditional side.** Canonical declares one 7-value enum whose cross-family styles are rejected at `SupportParameters` construction; `traditional-support.toml`'s string declaration is the type divergence. Upgrading to the enum matches `tree-support-planner.toml`'s declaration and the canonical type; the `snug` read site is value-based and unaffected. The 238b packet owns the tree-family style semantics; this packet only aligns the declaration type.
- **Declared-with-gap keys are unread.** None of the five with-gap keys (nor the four wired-but-declared additions) is read in any module's `src/lib.rs`; AC-N1 pins byte-identical planner output with all nine manifest-declared keys set explicitly vs absent. This is the packet 259/260/261 pattern; the canonical consumers are recorded so future geometry packets can consume the declarations.
- **Host keys stay host-keyed.** The eight host-typed keys keep their `ResolvedConfig` fields and `docs/config/host-keys.toml` entries (defaults already canonical); the manifest declarations add reachability/bounds/doc rows without moving the host read sites. `support_threshold_angle`'s host+manifest dual presence is the precedent.
