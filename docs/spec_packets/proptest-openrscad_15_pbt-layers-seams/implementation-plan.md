# Implementation Plan: pbt-layers-seams

Implement only after packets #1 and #2 have `status: implemented` and their actual exports, registry schema, feature behavior and runner semantics have been checked. The approved queue authorizes this scope; its `generated` status is not implementation. All tests and helpers remain private to their owners unless a focused, independently confirmed fix requires an existing production seam. No workspace test is required.

Every plain Cargo test command below is run under Bash after `set -euo pipefail` and `mkdir -p target`, with its shown `2>&1 | tee target/test-output.log`; inspect/archive the log before the next test. In PowerShell retain the native `$LASTEXITCODE` across `Tee-Object`. Registry runs use `cargo xtask test` as written, which owns combined logging, context and child status. Registry ID-to-package, lib target, feature and exact test filters are fixed by the table in `packet.spec.md`; do not append incompatible Cargo selectors to property mode. For each newly added record, use a valid provisional registry profile for Windows pilots, explicitly mark those results as non-completion in the evidence, and then commit measured profiles and rerun the exact selectors. Do not bypass #1's context or reduce an accepted profile through an override. Pilot profiles are not completion evidence until measured, reviewed and recorded.
