# Design: 212-extra-perimeters-parity

## Controlling Code Paths

- Primary code path: `arachne_params_from_config` (`modules/core-modules/arachne-perimeters/src/lib.rs`) — specifically its `max_bead_count` derivation, which today reads `max_bead_count_explicit = config.get_int("max_bead_count")` and `wall_count = config.get_int("wall_count").map(|v| v.max(0) as u32).unwrap_or(3)`, then matches: `Some(v) if v > 0 => v as u32` (explicit override) else `_ => (2 * wall_count).max(1)` (auto-derive). The auto-derive arm is the single line this packet changes.
- Ordering neighbours in `run_perimeters` (same file), all downstream of the `arachne_params_from_config(config, layer_index == 0)?` call and therefore automatically composed with the fix: the DEV-125 `alternate_extra_wall` block that does `params.max_bead_count += 2` under the `layer_index % 2 == 1 && !spiral_vase && sparse_infill_density > 0.0` guard, and the `only_one_wall_first_layer` clamp that does `params.max_bead_count = 2` when `is_bottom_layer`. The clamp is placed after the bump so it wins; both continue to win over `extra_perimeters` for free, matching classic's ordering.
- Derived caps inside the per-region loop of `run_perimeters` — `base_max_bead_count` is captured from `params.max_bead_count` inside that loop, and the top-surface / fallback / second-pass paths derive `2`, `base_max_bead_count + 2`, and `base_max_bead_count` from it. All inherit the fold with no edit.
- Mirror side (READ-ONLY): `run_perimeters` (`modules/core-modules/classic-perimeters/src/lib.rs`), where `let extra_perimeters = _config.get_int("extra_perimeters").unwrap_or(0).max(0) as u32; let base_wall_count = base_wall_count + extra_perimeters;` sits immediately before the DEV-125 guard and before the `only_one_wall_first_layer` clamp. This is the ordering the arachne side must reproduce.
- Manifests: `[config.schema.extra_perimeters]` exists in `modules/core-modules/classic-perimeters/classic-perimeters.toml` (`type = "int"`, `default = 0`, `min = 0`, `max = 10`, `group = "Walls"`) and is absent from `modules/core-modules/arachne-perimeters/arachne-perimeters.toml`, whose `[config.schema]` declares `wall_count` and `max_bead_count` but not `extra_perimeters`.
- Neighbouring tests/fixtures: `crates/slicer-runtime/tests/integration/extra_perimeters_config_tdd.rs` (classic-only today; two tests), `crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs` (`ARACHNE_FALLBACKS` + `assert_exhaustive_reconcile`), `modules/core-modules/arachne-perimeters/tests/alternate_extra_wall_tdd.rs` (the measured `emitted == max_bead_count / 2` mapping and the 20 mm / 1.0 mm-bead fixture this packet reuses).
- OrcaSlicer comparison: see `requirements.md` §OrcaSlicer Reference Obligations; do not repeat delegation rules.

## Architecture Constraints

- `ConfigView::from_declared` (`crates/slicer-ir/src/slice_ir.rs`) copies only keys present in the module's declared set. A read of an undeclared key returns `None` on every live slice, so the manifest registration and the code read MUST land in the same step or the fix is dead in production while passing every direct-invocation test (direct-invocation tests build a `ConfigView` via `ConfigViewBuilder`, bypassing `from_declared` entirely — this is exactly the blind spot that made `extra_perimeters` look wired).
- `docs/15_config_keys_reference.md`'s config-key tables are GENERATED by `cargo xtask gen-config-docs` and `docs/07_implementation_status.md`'s Open Deviation Map by `cargo xtask check-deviations` (which also VERIFIES the doc-15 sections under `--check`) and CI fails on drift via `--check`. They must be regenerated, never hand-edited.
- `crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs` is exhaustive by enumeration with set-equality in BOTH directions: adding `[config.schema.extra_perimeters]` to the arachne manifest without adding `("extra_perimeters", Int(0))` to `ARACHNE_FALLBACKS` fails the suite, and vice versa. This is a mandatory part of this packet's blast radius, budgeted into Step 2.

- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and, if `STALE:` is reported, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.
- Config key strings in Rust and in manifest section headers are snake_case. The key is `extra_perimeters`, never `extra-perimeters`, and it is distinct from the already-registered `extra_perimeters_on_overhangs`.
- No new struct field and no public schema/version constant is introduced, so the struct-literal blast-radius rule does not fire. The only enumeration-style blast radius is `ARACHNE_FALLBACKS`, handled above.

## Code Change Surface

- **Selected approach — (iii) stage the two divergences: fix the read gap now, re-file the modelling divergence as its own deviation.** Concretely: register `extra_perimeters` in the arachne manifest and change `arachne_params_from_config`'s auto-derive arm from `(2 * wall_count).max(1)` to a `2 * (wall_count + extra_perimeters)` form, where `extra_perimeters` is read with `config.get_int("extra_perimeters").unwrap_or(0).max(0) as u32` — the identical read expression classic uses, so the two generators cannot drift on clamping or defaulting.

  The choice is decided by evidence, not by convenience:
  - `Surface::extra_perimeters` (`Surface.hpp`) is `unsigned short`, zero-initialised in every constructor. Its only in-code writer is `PrintObject::make_perimeters` (`PrintObject.cpp`), whose per-region loop body the BBS patch short-circuits with a bare `continue`; the only other write is `from_json(const json&, Surface&)` (`Print.cpp`). Upstream the field is in practice always `0`. Porting a per-`Surface` model would faithfully reproduce a dead code path.
  - PnP cannot express per-region config at this seam without an IR/WIT change: `SliceRegionView` (`crates/slicer-sdk/src/views.rs`) has no `config_id`, and `LayerModule::run_perimeters` takes one layer-wide `&ConfigView` for the entire `&[SliceRegionView]` slice. Half (b) is a different packet's shape entirely.
  - Half (a) is a live, silent, user-visible data loss today. Leaving it open to avoid "entrenching" a divergence whose canonical counterpart is dead code inverts the cost.

  Entrenchment is mitigated, not ignored: DEV-132's status records half (a) closed and cites a newly-allocated `DEV-###` carrying half (b) forward with the evidence above, so the modelling divergence remains a tracked open row rather than being absorbed into a "closed" label.
- **Exact functions, manifests, tests, and fixtures:**
  - `arachne_params_from_config` (`modules/core-modules/arachne-perimeters/src/lib.rs`): add the `extra_perimeters` read next to the existing `wall_count` read; change only the `_ =>` arm of the `max_bead_count` match. Update the adjacent comment block (which currently explains the auto-derive as "`2 * wall_count`") to state `2 * (wall_count + extra_perimeters)` and cite `WallToolPaths::generate`'s `max_bead_count = 2 * inset_count` together with `process_arachne`'s `WallToolPaths(..., coord_t(loop_number + 1), ...)`.
  - `modules/core-modules/arachne-perimeters/arachne-perimeters.toml`: new `[config.schema.extra_perimeters]` block copied from `classic-perimeters.toml` (`type`/`default`/`min`/`max`/`display`/`group`) with an arachne-specific `description`.
  - `crates/slicer-runtime/tests/integration/extra_perimeters_config_tdd.rs`: add `arachne_extra_perimeters_bonus_adds_to_wall_count`, `arachne_extra_perimeters_zero_is_noop`, `extra_perimeters_survives_wall_generator_switch`, `arachne_explicit_max_bead_count_override_ignores_extra_perimeters`, `arachne_extra_perimeters_composes_with_alternate_extra_wall`, plus a shared 20 mm / 1.0 mm-bead fixture. The two existing classic tests (`extra_perimeters_bonus_adds_to_wall_count`, `extra_perimeters_zero_is_noop`) keep their current fixture and assertions untouched.
  - `crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs`: one row `("extra_perimeters", Int(0)), // get_int(..).unwrap_or(0).max(0)` in `ARACHNE_FALLBACKS`.
  - `docs/DEVIATION_LOG.md`, `docs/07_implementation_status.md`, `docs/15_config_keys_reference.md` (last two partly regenerated).
- **Rejected alternatives and reasons:**
  - *(i) Mirror the key and say nothing about the modelling divergence.* Rejected: it silently retires DEV-132 including half (b), which is a real (if low-value) divergence and must stay tracked.
  - *(ii) Migrate to a per-`Surface`/per-region model now.* Rejected on the two grounded facts above: the canonical writer is dead, and PnP would need an IR field, WIT marshalling, and per-region config resolution — far beyond one coherent remediation slice, in service of a field upstream never sets.
  - *Fold `extra_perimeters` into the explicit-`max_bead_count` arm too.* Rejected: `max_bead_count`'s own manifest `description` documents a positive value as an advanced override "honoured verbatim", and `alternate_extra_wall_tdd.rs` depends on that contract. Pinned by AC-N1 and AC-N3.
  - *Apply the bonus as a post-hoc wall-count mutation after the beading stack.* Rejected: canonical folds it into `inset_count` **before** `WallToolPaths` is constructed, and the existing `alternate_extra_wall` port already established `params.max_bead_count` as the correct seam.
  - *Put the new tests in a new file under `modules/core-modules/arachne-perimeters/tests/`.* Rejected: the cross-generator equality case (AC-3) needs BOTH modules, and `slicer-runtime` already dev-depends on both while `arachne-perimeters` does not depend on `classic-perimeters`.

## Data and Contract Notes

- IR/manifest contracts: one new `[config.schema.extra_perimeters]` entry in `arachne-perimeters.toml`. `ConfigView` is a flat `HashMap<String, ConfigValue>` filtered by the declared set; no IR struct changes. No `min-ir-schema` / `max-ir-schema` bump — the manifest's `[compatibility]` block is untouched.
- WIT boundary: none. `ConfigView` marshalling is key-agnostic; no `crates/slicer-schema/wit/**` edit, so no bindgen invalidation beyond the module's own source.
- Determinism/scheduler constraints: `max_bead_count` is a pure function of config; the fold introduces no ordering, no floating-point, and no host call. The `2 * (wall_count + extra_perimeters)` product keeps `max_bead_count` EVEN, which `LimitedBeadingStrategy` requires — an odd cap triggers its warning and its odd-centre `compute` branch dumps the surplus region thickness into one wide centre bead. This evenness invariant is the reason the bonus is applied as `2 * (a + b)` rather than as a separate `+extra` addend.

## Locked Assumptions and Invariants

- **Locked:** `max_bead_count`'s auto-derive branch stays EVEN for every non-degenerate input. Any future change to this derivation must preserve `max_bead_count % 2 == 0`, per `LimitedBeadingStrategy`'s odd-cap behaviour documented in `arachne-perimeters.toml`'s `[config.schema.max_bead_count].description`. **Carve-out:** the pre-existing `.max(1)` floor on that arm yields the odd value `1` when `wall_count == 0 && extra_perimeters == 0`. This hole predates the packet (`(2 * wall_count).max(1)` had it identically) and is preserved unchanged; it is unreachable through a validated config because `[config.schema.wall_count]` declares `min = 1`.
- **Locked:** a positive explicit `max_bead_count` is honoured verbatim and is NOT adjusted by `extra_perimeters`. Pinned by AC-N1; `alternate_extra_wall_tdd.rs` depends on it.
- **Locked:** the `extra_perimeters` fold happens inside `arachne_params_from_config`, hence strictly before the `alternate_extra_wall` `+= 2` bump and before the `only_one_wall_first_layer` clamp — mirroring classic, where the addition sits before the DEV-125 guard and the clamp still wins on the first printed layer.
- **Not locked / reversible:** the behaviour change is fully reversible by leaving `extra_perimeters` at its `0` default, which is the manifest default and the code fallback; a default-config slice produces byte-identical output to today.

## Risks and Tradeoffs

- **Behaviour moves for users who already set `extra_perimeters` while running arachne.** That is the point of the packet, but it means arachne goldens or parity fixtures that happen to carry a non-zero `extra_perimeters` will shift. Mitigation: the key defaults to `0` everywhere and no existing arachne fixture sets it (verified: zero `extra_perimeters` occurrences under `modules/core-modules/arachne-perimeters/src/` and the only manifest hits were `extra_perimeters_on_overhangs`). If `cargo check`/`clippy`/the targeted tests are green and a broader golden still moves, that is a genuine finding to report, not a fixture to re-record.
- **The `emitted == max_bead_count / 2` mapping is empirical, not structural.** It was measured for `LimitedBeadingStrategy`'s filtered sentinel pair on one specific fixture. Step 1 re-measures on the fixture it actually uses before pinning literals. If the measurement disagrees with AC-1/AC-2/AC-N1/AC-N2, escalate as `[BLOCK]` — never relax the assertion to match the observation.
- **Registering a key makes it user-visible in `config-schema` output and doc 15.** Accepted: that is the intended parity outcome — the same key must mean the same thing under either `wall_generator`.
- **Half (b) survives as an open deviation.** Accepted and explicit. The tradeoff is a tracked, evidence-carrying open row versus building per-region IR plumbing for a canonical field that upstream never sets.
