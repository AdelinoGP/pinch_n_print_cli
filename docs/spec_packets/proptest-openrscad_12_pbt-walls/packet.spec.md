# Classic-perimeter and fuzzy-skin kernel properties

## Goal

Add bounded, independently-oracled property tests for `ClassicPerimeters::emit_walls` and `apply_fuzzy_skin`, with deterministic negative controls, required nonempty witnesses, and measured Windows routine/extended profiles, without changing production visibility or duplicating the Arachne coverage owned by packet 10.

## Why

The approved source is `docs/specs/proptest-openrscad-adoption.md`, especially §§5–7, 11 and G-FAMILY, and queue row 12. Its classic-perimeters obligation is role-appropriate closure, parallel metadata alignment, and valid wall bands/degenerate behavior under documented offset/width preconditions, explicitly **not** a universal wall count. Its fuzzy-skin obligation is seeded repeatability, preservation of unselected spans and metadata, and independently measured displacement from the corresponding source segment with a derived tolerance.

The current coverage is fixture-based: `classic_perimeters_tdd`, `wall_closure_tdd`, `classic_perimeters_concave_tdd`, `boundary_paint_tdd`, `fuzzy_skin_tdd` and `closed_loop_tdd`. Those tests establish important single examples, including a single-edge closing-displacement check, but they do not exercise a generated bounded domain, a derived displacement envelope, or a shrink that keeps the selected/unselected or gate mode. This packet adds those properties beside the private kernels, where `emit_walls` and `apply_fuzzy_skin` are reachable without widening production APIs.

Arachne host and module coverage belongs to `proptest-openrscad_10_pbt-arachne`. This packet only links that packet: it does not call `run_arachne_pipeline`, `build_walls`, `classify_line` or `commit_wall_sequence`, and claims no H-ARACHNE or M-ARACHNE credit. `proptest-openrscad_09_pbt-geometry` is optional coordination only; no H-BOOL/H-OFFSET/H-MESH export is consumed and its implementation is not a queue dependency.

## Scope

- In: `classic-perimeters` and `fuzzy-skin` owner-local `property_testing` features; private `src/property_tests.rs` modules with stacked `#[cfg(test)]` and owner-feature gates; direct bounded strategies for wall bands, polygon cases, fuzzy spans and fuzzy parameters; independent local oracles; required nonempty witnesses; deterministic oracle-mutation and degenerate/failure controls; manual FRU/waiver review of the scanner-invisible module test files; five registry records with measured routine/extended profiles; Windows execution evidence; focused canonical-correct fixes and named concrete regressions only if a property confirms a SUT defect.
- Out: production visibility changes; new SDK/shared strategy or oracle exports; IR/WIT/schema/config changes; Arachne host or module properties (owned by packet 10); SCAD, OpenRSCAD or scripted recipes; a randomized module-entrypoint/E2E quota; universal wall-count, all-LoopType-closure, containment or metadata-preservation claims; region-chain or `(priority, name)` identity changes (packet 11); workspace test runs; changes to other packets or the queue.

## Design notes

### Grounded kernels, callers and existing preconditions

- `ClassicPerimeters::emit_walls` (`modules/core-modules/classic-perimeters/src/lib.rs`) is private and is called from five sites in `ClassicPerimeters::run_perimeters` (overhang top/non-top, top-surface top/non-top, and the full-region path). It receives `&mut PerimeterOutputBuilder`, `wall_count`, `emit_outer`, `emit_inner`, the outer/inner wall widths, `layer_height`, the `PerimeterSpatialContext`, and `PathAnnotationMode`; it returns `Result<(), ModuleError>`. The tests call this real private method directly. Existing `classic_perimeters_tdd`, `wall_closure_tdd`, `classic_perimeters_concave_tdd` and `boundary_paint_tdd` remain the entrypoint/example coverage and are not counted as property coverage.
- `apply_fuzzy_skin` (`modules/core-modules/fuzzy-skin/src/lib.rs`) is a private free function; `FuzzySkinModule::run_wall_postprocess` is its sole production caller. It receives an `ExtrusionPath3D`, `WallFeatureFlags` slice, `WidthProfile`, `apply_to_all`, `thickness`, `point_distance`, `layer_index` and `wall_index`, and returns `(Vec<Point3WithWidth>, Vec<WallFeatureFlags>, Vec<f32>)`. The tests call the real private function directly. `fuzzy_skin_tdd` and `closed_loop_tdd` remain entrypoint/example coverage.
- `WallLoop` has `perimeter_index`, `loop_type`, `path`, `width_profile`, `feature_flags` and `boundary_type`. `ExtrusionPath3D` has `points`, `role`, `speed_factor`, `tool_index` and `order_lock`. `Point3WithWidth` has `x`, `y`, `z`, `width`, `flow_factor`, `overhang_quartile`, `dist_to_top_mm` and `overhang_distance_mm`. `WallFeatureFlags` has `tool_index`, `fuzzy_skin`, `is_bridge`, `is_thin_wall`, `skip_ironing` and `custom`. These are the fields asserted below; no field is added and no schema version changes.
- `ExtrusionPath3D::is_closed` compares only the first and last XY coordinates and requires at least two points. `expolygon_to_path3d_indexed` emits one point per ring vertex and appends a clone of the first, so an ordinary classic wall is closed by explicit repeat; `mirror_first_to_last` copies the first feature flag onto the closing repeat. `width_profile.widths` is built to the same point count. These are the closure and parallelism contracts, not a claim that every `LoopType` is closed.
- `line_width_to_spacing` returns `width - layer_height * (1 - PI / 4)` and rejects a nonpositive spacing. `emit_walls` maps that rejection to `ModuleError::fatal(ERR_NEGATIVE_SPACING, ...)`; `ERR_NEGATIVE_SPACING` is the module's private constant `1`. The valid property domain constructs widths above the positive-spacing threshold; a deterministic control exercises the rejection path.
- `emit_walls` first calls `remove_small_and_small_holes` with `DEGENERATE_MIN_AREA_SQ_UNITS = 1.0` and `0.0` hole area, so a `<3`-vertex or zero-area input contour is dropped before offsetting. The band loop stops when an inset result is empty; therefore the **computed** band indices are a prefix of `0..wall_count`, and the **emitted** set is that prefix filtered by `emit_outer`/`emit_inner`. The actual number of bands is geometry-dependent; no criterion requires the configured wall count on a shape too small to hold it.
- `PerimeterOutputBuilder::new` is unbounded and exposes `wall_loops()`, `infill_areas()` and `seam_candidates()`. The foundation's `CaseGuard` provides per-case log/mesh/ID isolation and capture sinks, but its perimeter sink is a `PerimeterOutputCapture`, not a `PerimeterOutputBuilder`; each generated or shrink invocation therefore creates a fresh local `PerimeterOutputBuilder`. The guard is still used through `PropertyRun::check` so state does not leak between cases; the local builder is never shared across cases.
- The new tests are private unit modules (`src/property_tests.rs`), not `tests/**` integration targets, because both kernels are private and production visibility must not be widened for tests. The module declaration uses stacked separate attributes:

  ```rust
  #[cfg(test)]
  #[cfg(feature = "property_testing")]
  mod property_tests;
  ```

  Add an empty owner `property_testing = []` feature to each module `Cargo.toml`. The module feature only controls compilation of the test module; the actual harness/proptest dependency comes from the existing dev-dependency on `slicer-sdk` upgraded to `features = ["test", "property_testing"]` plus workspace-managed `proptest` as a dev-dependency. No normal dependency, default feature, guest manifest or production build gains Proptest or the property support.
- The classic geometry domain maps `Convex`/`Concave` to `min_components = 1, min_holes = 0`, `Holed` to `min_holes = 1`, and `Disconnected` to `min_components = 2`, with `BoundaryRule::Strict` and the registry bounds; an impossible minimum or an oversized bound is rejected before sampling, not narrowed. Every generated case is passed through `validate_geometry` before the SUT.
- The shared inputs and oracles come only from #1/#2. `geometry_cases` supplies bounded `Convex`, `Concave`, `Holed` and `Disconnected` cases; `validate_geometry` independently certifies each generated case before the SUT runs. The classic oracle additionally checks exact integer-derived output metadata and the fuzzy oracle checks span matching and measured displacement. No new `slicer-sdk` export is requested; no Arachne or wall/fuzzy strategy is added to the shared surface.
- Neither kernel accepts a region chain. The tests construct no `RegionKey`, `variant_chain` or `(priority, name)` sequence. Packet 11's shared ordered identity is therefore untouched; if a later fixture introduces a chain, it must preserve that identity and this packet makes no contrary claim.
- This packet's fuzzy properties deliberately do not claim that every field of every output point is preserved. Inserted samples are synthetic: the source currently supplies the segment-start flag and profile width while interpolating the point width/flow, and it resets overhang metadata on inserted samples. The asserted contract is exact preservation for unselected input spans and original endpoints, plus a measured displacement bound for inserted samples. Any stronger preservation claim requires a separate source/canonical decision.
- Mode selectors use one `prop::sample::select(vec![...]).no_shrink()` strategy, never a `prop_oneof!` of `Just` mode arms. Verified in the proptest 1.11 API/source: `prop_union` says a union's `ValueTree::simplify` can switch to an earlier arm when the originally chosen arm cannot shrink further; `Strategy::no_shrink` wraps a single selector and its `NoShrink` value tree returns `false` from both `simplify` and `complicate`; `prop_ind_flat_map` does not shrink the input that selects the derived strategy; `TestRunner::deterministic` exists for protocol probes. The classic emit mode, `variant_fuzzy`, fuzzy `apply_to_all` and open/closed topology use no-shrink selectors. Local private `ClassTag`, `EmitMode`, `ApplyToAllMode` and `TopologyMode` enums derive `Clone, Copy, Debug, PartialEq, Eq` (the `select` element bound is `Clone + Debug + 'static`). The classic topology class is selected by a no-shrink `ClassTag` selector and `prop_ind_flat_map` into the matching prebuilt #2 `geometry_cases` strategy; all four class strategies are constructed and validated before the selector is built, so the closure cannot fail or fall back during generation. It is not a `prop_oneof!` over class strategies, because the outer union's `simplify` could switch topology. Fixed prefixes are `Just` components outside any union and remain fixed. Ordinary generated geometry, counts, point vectors, widths and thickness/point_distance remain shrinkable.
- Owned shrink probes use `TestRunner::deterministic()`, `Strategy::new_tree` and `ValueTree::{current,simplify,complicate}`. They call both directions, assert the no-shrink modes, the #2 topology and the fixed prefix remain unchanged, assert each current classic geometry still passes `validate_geometry`, and require at least one ordinary value to change; the classic probe runs once for each of the four class tags. A `simplify`/`complicate` sequence that only returns `false` is a probe failure, not a pass. SUT-output violations are reported with `TestCaseError::fail`, never `TestCaseError::Reject`, `prop_filter` or a silent skip; only construction-time bound/domain rejection may fail before sampling.

### M-CLASSIC-WALL-STRUCTURE — role, closure and metadata alignment

- Owner/test: `classic-perimeters` / `classic_perimeters` lib / `property_tests::proptest_classic_wall_structure`; registry ID `M-CLASSIC-WALL-STRUCTURE`.
- Contract: every ordinary `Outer`/`Inner` wall emitted by the tested no-medial-axis path is a closed loop with an explicit XY closing repeat; its `perimeter_index` is the band that produced it; its role, loop type, speed factor and widths are the band's role/width metadata; its point, width-profile and feature-flag arrays are parallel; and its per-point z, flow and annotation fields are the documented defaults of this fixture.
- Domain: #2 `geometry_cases` over `Convex`, `Concave`, `Holed` and `Disconnected`, with integer-unit coordinates bounded by `max_abs_units`, vertices/holes/components bounded by the registry, and each case independently accepted by `validate_geometry`. The call uses empty `segment_annotations`, an empty `PerimeterSpatialContext` (no boundary/overhang/bridge inputs) and `PathAnnotationMode::Unconsumed`, so the expected flags/annotation defaults are the documented no-paint fixture. Wall count is `1..=max_wall_count`; outer/inner widths and layer height are finite positive canonical-unit values above the `line_width_to_spacing` threshold; `emit_outer`/`emit_inner` come from one `prop::sample::select(vec![Both, OuterOnly, InnerOnly]).no_shrink()` mode selector; `variant_fuzzy` comes from `prop::sample::select(vec![false, true]).no_shrink()`. Empty output is permitted for a small generated shape; the property observes a nonempty population through a local in-process counter and the deterministic witness below.
- Strategy: construction-first per-class `geometry_cases` selected by a no-shrink `ClassTag` selector plus `prop_ind_flat_map` (not a `prop_oneof!` over class strategies, which could switch topology during shrinking), plus bounded scalar tuples. No blanket `Arbitrary` on IR types and no `prop_filter` as the only generator. The deterministic witness is a 20 mm square with both emit gates enabled, `wall_count = 3`, outer width 0.4 mm, inner width 0.4 mm and layer height 0.2 mm, exercised in both `variant_fuzzy` modes. It must emit bands `{0,1,2}` and a nonempty wall population.
- Oracle: local `classic_structure_oracle` reads the actual `WallLoop`s returned by `emit_walls`. For each wall it checks `perimeter_index < wall_count`; band 0 maps exactly to `LoopType::Outer`/`ExtrusionRole::OuterWall`/`outer_speed_factor` and band >0 to `LoopType::Inner`/`ExtrusionRole::InnerWall`/`inner_speed_factor`; `points.len() == width_profile.widths.len() == feature_flags.len()`, `points.len() >= 4`, `path.is_closed()` and first/last points are bit-identical; every consecutive XY pair is distinct; every point has finite `x/y/z/width/flow`, `z == fixture z`, `width == band width`, `flow_factor == 1.0`, `overhang_quartile == None`, `dist_to_top_mm == 0.0` and `overhang_distance_mm == None`; every `width_profile.widths[i] == band width`; every feature flag equals `WallFeatureFlags { fuzzy_skin: variant_fuzzy, ..Default::default() }`; the closing width and flag mirror the first; `tool_index` and `order_lock` are `None`. The oracle does not call a production validator or reconstruct the offset.
- Tolerance: exact f32 equality for copied widths, z, flags and the closing point; no numeric epsilon is used for structure. Finiteness is checked before comparisons.
- Shrinking: the selected topology class is a no-shrink selector; #2's per-class geometry tree preserves the declared topology and required components/holes. The emit mode and `variant_fuzzy` use no-shrink selectors and cannot flip; wall count and ordinary scalar values may shrink to other valid values, with the deterministic witnesses covering both fuzzy modes and the capacity case. A wall that loses its closing repeat or a required band is a failure, not a valid shrink; a confirmed mode-specific defect gets a concrete regression.
- Execution: routine and extended in-process profiles with `timeout_ms = 0`; no fork or timeout is selected for this native kernel. The actual cases/bounds/rejection limits are measured before registration.
- Failure record: retain context, concrete geometry, wall/band index and the failing field; classify SUT, generator/oracle or contract. A confirmed SUT defect gets a named RNG/context-independent concrete regression.
- Acceptance: the property executes through `PropertyRun::check`, the deterministic witness and generated nonempty counter both pass, `classic_structure_oracle_rejects_mutations` proves the oracle rejects missing closure, a changed band/role/width/flag/z/speed and a nonfinite coordinate, and `classic_shrink_preserves_emit_mode_and_topology` proves the no-shrink emit/`variant_fuzzy` modes and the fixed topology survive `simplify`/`complicate` while an ordinary scalar changes.

### M-CLASSIC-BAND-SELECTION — gates, valid bands and degeneracy

- Owner/test: `classic-perimeters` / `classic_perimeters` lib / `property_tests::proptest_classic_band_selection`; registry ID `M-CLASSIC-BAND-SELECTION`.
- Contract: `emit_outer`/`emit_inner` select exactly the corresponding ordinary roles; when at least one band is emitted, the emitted band indices are `{ i in 0..=max_emitted : allowed(i) }`, where `allowed(0) = emit_outer` and `allowed(i>0) = emit_inner`; `wall_count` is an upper bound, not a promised count; a shape too small for the request emits fewer bands; degenerate input contours emit no walls; a nonpositive spacing is a fatal `ERR_NEGATIVE_SPACING` error, never a silent clamp; `emit_inner == false` emits no infill areas; `emit_outer == false` emits no seam candidates.
- Domain: the same bounded geometry and width/height domain as `M-CLASSIC-WALL-STRUCTURE`, with `wall_count` spanning `1..=max_wall_count` and the three emit modes. The deterministic degeneracy witnesses are a 2-point contour, a 3-point collinear contour and an empty polygon list; the capacity witness is a 1 mm square with `wall_count = 10`, outer/inner width 0.4 mm and layer height 0.2 mm, which must emit at least one ordinary band and fewer than 10 bands after execution establishes the actual count. If that exact square is empty, use the smallest documented shape that produces a nonempty band and record the count.
- Strategy: reuse the construction-first geometry/scalar families, including the no-shrink topology-class selector and `prop_ind_flat_map` from Step 3; select the three emit modes with one `prop::sample::select(vec![Both, OuterOnly, InnerOnly]).no_shrink()` strategy rather than a union of `Just` arms, so neither `simplify` nor `complicate` can switch the mode. Required witnesses are executed deterministically outside random chance.
- Oracle: local `classic_band_oracle` first runs the structure oracle, then checks the allowed-prefix rule over the collected band set, rejects any `perimeter_index >= wall_count`, rejects a missing allowed index below the maximum emitted index, and checks the infill/seam gate implications. It never compares the number of emitted bands or walls to `wall_count`.
- Tolerance: exact integer band indices and boolean gates; no geometry tolerance.
- Shrinking: the emit mode is a no-shrink selector and cannot flip; the requested wall count may shrink to a smaller valid request. A smaller geometry may legitimately emit fewer bands, but it may not introduce a band outside `0..wall_count` or break the allowed-prefix rule. Degenerate cases are separate deterministic inputs, not a shrink target that silently changes the mode.
- Execution: routine and extended in-process profiles, measured.
- Failure record: retain the requested count, emit mode, actual band set and the first violating index; a capacity difference is not a failure unless the allowed-prefix/gate contract is broken.
- Acceptance: the property runs through the harness; the capacity witness emits at least one and fewer than the requested ten bands and still satisfies the oracle; the 2-point/collinear/empty witnesses emit no walls/infill/seams; `emit_outer=false` emits no outer roles or seam candidates; `emit_inner=false` emits no inner roles or infill; `classic_negative_spacing_is_fatal` observes `ModuleError.code == ERR_NEGATIVE_SPACING` with `fatal == true`; `classic_property_domains_reject_unsafe_bounds` asserts the exact `DomainError` variants for missing/oversized/impossible/invalid bounds; and `classic_band_oracle_and_degenerate_cases` proves the oracle rejects an injected band gap and a gate violation.

### M-FUZZY-REPEATABILITY — deterministic seeded output

- Owner/test: `fuzzy-skin` / `fuzzy_skin` lib / `property_tests::proptest_fuzzy_repeatability`; registry ID `M-FUZZY-REPEATABILITY`.
- Contract: `apply_fuzzy_skin` is deterministic for identical inputs. Its internal seed is derived from `layer_index` and `wall_index`; the Proptest runner seed controls case sampling, not the SUT's perturbation stream. Two calls with the same case produce bit-identical points, feature flags and widths.
- Domain: bounded paths of 3..=`max_points` canonical-unit points (including zero-length consecutive points in the generated tail), per-point flags and positive widths, `apply_to_all` from `prop::sample::select(vec![false, true]).no_shrink()`, open/closed topology from a second `select(...).no_shrink()` selector, positive finite thickness/point_distance, and arbitrary `u32` layer/wall indices. Every generated case carries a `Just` non-collapsing leading segment so a selected nonzero span is always present; the deterministic witness is the closed 5-point square with mixed flags described under `M-FUZZY-SPAN-PRESERVATION`. A `<2`-point path is a separate deterministic identity control, not a generated mixed case.
- Strategy: construction-first vectors; duplicate consecutive points are allowed as a documented degenerate mode; no rejection filter is needed for determinism.
- Oracle: local `fuzzy_repeatability_oracle` compares every point field by float bits (including signed zero), every `WallFeatureFlags` value and every width by bits. NaN is outside the valid domain; a single changed bit is a failure.
- Tolerance: none; bitwise equality is the contract for identical inputs.
- Shrinking: the layer/wall indices are part of the case; `apply_to_all` is a no-shrink selector and cannot flip. Generated per-point flags may shrink as valid inputs; the deterministic mixed witness and any confirmed concrete regression carry the specific selected/unselected failure.
- Execution: routine/extended in-process.
- Failure record: retain both argument tuples and the first differing point/flag/width; a mismatch is a SUT or harness defect, not a reason to relax to approximate equality.
- Acceptance: the property runs through the harness; `fuzzy_repeatability_control` proves the bitwise comparator rejects a one-bit mutation and that a changed `layer_index` changes a multi-sample witness while each seed still repeats exactly; `fuzzy_shrink_preserves_modes_and_fixed_prefix` proves the no-shrink `apply_to_all`/open-closed modes and the fixed prefix survive `simplify`/`complicate` while an ordinary tail value changes. This is a determinism pin, not a correctness claim; mark it with the `docs/22_test_quality.md` determinism waiver in the test source.

### M-FUZZY-SPAN-PRESERVATION — unselected spans and endpoint metadata

- Owner/test: `fuzzy-skin` / `fuzzy_skin` lib / `property_tests::proptest_fuzzy_span_preservation`; registry ID `M-FUZZY-SPAN-PRESERVATION`.
- Contract: every input list entry in the declared domain is consumed exactly once and in order in the output; an unselected segment (neither `apply_to_all` nor its start flag is `fuzzy_skin`) contributes no inserted sample and preserves its endpoint point, flag and profile width exactly; a selected nonzero-length segment contributes at least one inserted sample; a selected zero-length segment contributes none and otherwise copies through; output point/flag/width arrays are parallel. The packet does not claim preservation of synthetic inserted-sample overhang/flow metadata.
- Domain: the repeatability domain, with at least one mixed `true`/`false` flag witness, one `apply_to_all=true` witness, one all-flags-false `apply_to_all=false` witness and one closed path with an explicit final repeat. When `apply_to_all=false`, every generated case carries a `Just` following segment whose start flag is false (a fixed prefix outside any union), so the selected/unselected contrast survives shrinking; when `apply_to_all=true`, every segment is selected by definition. The deterministic 5-point square uses flags `[true, false, true, true, true]`, widths `[0.4, 0.5, 0.4, 0.45, 0.4]`, thickness 0.3 mm and point_distance 0.8 mm; segment 1 is unselected and segment 3 is the closing edge.
- Strategy: per-point `fuzzy_skin` booleans and other metadata varied; the fixed leading selected segment and, when `apply_to_all=false`, the following unselected segment are `Just` prefixes; `apply_to_all` and open/closed topology are `prop::sample::select(...).no_shrink()` selectors. The deterministic witnesses cover the mixed, all-selected (`apply_to_all=true`) and all-unselected (all flags false, `apply_to_all=false`, exact copy) modes. The required mixed witness is deterministic.
- Oracle: local `match_fuzzy_output` consumes the output in order. It matches the first input point, then for each segment either requires the next output point to be the exact endpoint (unselected or zero-length) with no insertion, or scans inserted samples until the exact endpoint (selected nonzero) and requires at least one. It checks inserted flags equal one of the segment endpoints' flags and inserted profile widths equal one of the endpoint profile widths exactly; it does not assert inserted `Point3WithWidth.width`. It rejects extra output points, a missing endpoint, an inserted point in an unselected span and any changed endpoint metadata.
- Tolerance: bitwise equality for unselected original points/flags/widths and for the inserted profile flag/width selection; no width epsilon. The displacement property carries the derived geometric tolerance.
- Shrinking: `apply_to_all` and open/closed topology are no-shrink selectors and cannot flip; the leading selected segment is a fixed `Just` prefix, and when `apply_to_all=false` the following unselected segment is also fixed. Per-segment flags in the generated tail, the remaining points and widths shrink as valid inputs; the deterministic mixed witness and any confirmed concrete regression carry the specific selected/unselected failure. A shrink that removes the fixed prefix or changes a fixed-prefix flag is not a valid shrink of this family.
- Execution: routine/extended in-process.
- Failure record: retain the input path, flag vector, widths and the first mismatched output index; classify SUT versus matcher.
- Acceptance: the property runs through the harness; `fuzzy_required_witnesses_are_nonempty` proves the mixed closed witness has inserted samples only on selected spans and preserves segment 1, the same closed square with `apply_to_all = true` inserts on every nonzero segment, and the same square with all flags false and `apply_to_all = false` is an exact copy; `fuzzy_span_oracle_rejects_mutations` rejects a moved unselected point, an extra point in an unselected span and a selected span with all samples removed; `fuzzy_disabled_parameters_are_identity` proves nonpositive/nonfinite thickness or point_distance and a `<2`-point path return exact copies; `fuzzy_shrink_preserves_modes_and_fixed_prefix` proves the modes and fixed selected/unselected prefix survive while the generated tail shrinks.

### M-FUZZY-DISPLACEMENT — independently measured offset from the source segment

- Owner/test: `fuzzy-skin` / `fuzzy_skin` lib / `property_tests::proptest_fuzzy_displacement`; registry ID `M-FUZZY-DISPLACEMENT`.
- Contract: each inserted sample lies on the perpendicular offset of its corresponding source segment with a signed displacement whose magnitude is at most `thickness` (within a derived f32 error envelope), and its longitudinal projection lies within the source segment (within the derived longitudinal envelope). The source segment is identified by output order, not by the SUT's internal RNG or a copied implementation.
- Domain: the span-preservation domain, with finite positive thickness and point_distance bounded by the registry, coordinates bounded by `max_abs_mm_units`, and the fixed `Just` selected nonzero leading segment (outside any union) so at least one inserted sample exists independently of random chance; `apply_to_all` and open/closed topology remain no-shrink selectors. Zero-length selected segments are excluded from displacement assertions because they legitimately produce no sample.
- Strategy: construction-first path/parameter families; the oracle measures in widened `f64` from the f32 inputs, so the SUT's f32 arithmetic is the only source of the envelope.
- Oracle: local `match_fuzzy_output` returns `InsertedSample { segment_index, output_index, point }`. For each sample, `fuzzy_measure_displacement` computes in f64 the perpendicular distance `d` from the point to the infinite source line and the projection parameter `t` on the segment. The property asserts `d.is_finite()`, `0 <= d <= thickness + fuzzy_displacement_tolerance(max_abs_mm, thickness)`, and `-tol_t <= t <= 1 + tol_t` with `tol_t = tolerance / seg_len + 8 * f64::EPSILON`. The deterministic closed witness must have at least one sample on the closing edge and a strictly positive maximum `d`.
- Tolerance: `fuzzy_displacement_tolerance` is a local helper of the form `K * f32::EPSILON * (max_abs_mm + thickness_mm + 1.0)`, where `K` is derived from the actual f32 operation sequence (`dx/dy`, `seg_len`, `perp`, `base`, `displacement`, final add) and the oracle's f64 cross/dot measurement, and the derivation is recorded in the evidence. It is not tuned to observed output and does not claim universal containment of the displaced point in the source region.
- Shrinking: `apply_to_all` and open/closed topology are no-shrink selectors and cannot flip; the fixed leading selected segment and its source-segment correspondence survive; the remaining path/parameters shrink as valid inputs. The deterministic closed witness and any confirmed concrete regression carry a closing-edge sample; a shrink that removes the fixed prefix is not a valid shrink of this family.
- Execution: routine/extended in-process.
- Failure record: retain input points, segment index, inserted point, measured `d`/`t`, tolerance and the derivation; a failure is classified as SUT, generator/oracle or contract before any fix.
- Acceptance: the property runs through the harness; the deterministic witness proves positive displacement on the closing edge within tolerance; `fuzzy_displacement_oracle_rejects_mutations` rejects a displacement above `thickness + tolerance`, a point beyond the segment's longitudinal span, and a point attributed to the wrong orthogonal segment; `fuzzy_shrink_preserves_modes_and_fixed_prefix` proves the leading selected segment and no-shrink modes survive. The tolerance derivation and `K` are recorded in evidence; no observed-output epsilon is introduced.

### Shrinking, negative controls and defect lifecycle

- The selected topology class is a no-shrink selector; #2's per-class geometry strategy/shrink retains the declared topology and required holes/components. Local classic cases keep the emit mode and `variant_fuzzy` as no-shrink selectors; wall count and ordinary scalar values may shrink to other valid values. Fuzzy cases keep `apply_to_all` and open/closed topology as no-shrink selectors and the leading selected (plus, when `apply_to_all=false`, following unselected) fixed `Just` prefix; per-segment flags and ordinary generated values shrink as valid inputs. Any confirmed mode-specific defect gets a concrete regression.
- Required witnesses are deterministic direct calls in addition to fresh generated exploration: the 20 mm/3-band classic square, the 1 mm/10-band capacity square, the 2-point/collinear/empty degenerates, the mixed-span closed fuzzy square, the closing-edge displacement sample and the invalid-parameter identity cases. A property that observes zero nonempty generated cases fails its local counter; a deterministic witness that produces no expected population fails its direct assertion.
- Each oracle has a deterministic mutation control. The control starts from a real SUT output and changes one contract field (closure, band, role, width, flag, z, speed, coordinate, unselected point, inserted-sample displacement or longitudinal position); the oracle must reject it. A control that accepts the mutation is a test failure, not a waiver.
- On failure, retain the context/artifact required by #1 first, reproduce the concrete input, then classify SUT, generator, oracle or contract. A confirmed SUT defect receives a focused canonical-correct fix and a named concrete regression that runs without Proptest RNG or `PNP_PROPERTY_CONTEXT` and names the root cause and formerly failing input. Seeds are diagnostic artifacts, not committed regression history. Do not relax an oracle, narrow the domain, add an ignore, or re-record a baseline to obtain a pass. If no defect is confirmed, the evidence says so; a larger unresolved defect blocks the affected family.
