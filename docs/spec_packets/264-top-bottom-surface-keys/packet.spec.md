# Packet Contract: top-bottom-surface-keys

## Goal

Make all four OrcaSlicer top/bottom surface keys drive real decision points in this port. `top_surface_density` / `bottom_surface_density` become the divisor of the exposed-surface solid line spacing in `rectilinear-infill` (replacing the hardcoded `SOLID_DENSITY`), including canonical's `density <= 0` top-surface skip. `top_surface_pattern` / `bottom_surface_pattern` stop being module identity and become a value→claim-holder mapping resolved in `resolve_global_config`: each of canonical's eight enum values names a module holding `claim:top-fill` / `claim:bottom-fill`, and this packet ships the six fillers the tree does not have yet (`monotonicline-infill`, `alignedrectilinear-infill`, `concentric-infill`, `hilbert-curve-infill`, `archimedean-chords-infill`, `octagram-spiral-infill`), extends packet 262b's `monotonic-infill` to hold `claim:bottom-fill`, and routes `rectilinear` to the existing `rectilinear-infill`. Every value the user can type resolves to a filler that actually differs in output; no value is declared and left unread.

## Scope Boundaries

The packet creates six core-module crates (crate, manifest, `wit-guest/`, tests, guest `.wasm`), adds the pattern→holder derivation to `resolve_global_config` and `apply_overlay` (`crates/slicer-scheduler/src/config_resolution.rs`), adds the two density fields and their spacing wire to `rectilinear-infill` (`RectilinearInfill`'s `LayerModule::from_config` impl, `RectilinearInfill::run_infill`), appends `claim:bottom-fill` to `monotonic-infill.toml` plus the bottom-role emission arm in that module, registers the six modules in the root `Cargo.toml`, the integrated registry (`crates/slicer-integrated-modules/{Cargo.toml,src/lib.rs}`) and `crates/pnp-cli/Cargo.toml`'s passthrough features, and documents the two selection keys in `docs/04_host_scheduler.md` § Claim Resolution. It does **not** add a WIT interface, bump an IR schema, or add a `ResolvedConfig` field — `top_fill_holder` and `bottom_fill_holder` already exist in the `declare_resolved_config!` block (`crates/slicer-ir/src/resolved_config.rs`, both `String`, both defaulting to `"rectilinear-infill"`), and `claim:top-fill` / `claim:bottom-fill` already exist in `docs/03_wit_and_manifest.md` § Known claim IDs. It does not port canonical's top-surface *expansion* pass (`PrintObject.cpp` `detect_surfaces_type`, `PerimeterGenerator.cpp` `top_fill_replaces_inner_walls`), the `GCode.cpp` `_needSAFC` / `retract` pattern reads, the bridge-fallback coupling in `group_fills`, or the gyroid opt-in solid path (ADR-0027). It touches `ORCA_CONFIG_PADDING` (`crates/slicer-gcode/src/serialize.rs`) **not at all** — the previous revision's `top_surface_pattern` padding-twin correction is deleted from this packet's scope under map Authoring rule 2.
