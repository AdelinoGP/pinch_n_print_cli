# Design: 253-part-cooling-fan-scale-and-cooling-keys

## Controlling Code Paths

- Primary code path: `modules/core-modules/part-cooling/src/lib.rs` — `PartCooling::from_config` (reads 4 keys today via `config.get`), `layer_fan_speed`, `cooling_decision_for_event`, `run_finalization` (emits via `FinalizationOutputBuilder::push_fan_speed` → `GCodeCommand::FanSpeed`, and `push_annotation` → `LayerAnnotationKind::Raw`).
- Neighboring tests/fixtures: `modules/core-modules/part-cooling/tests/part_cooling_tdd.rs` (5 behavioural tests), `tests/cooling_config_schema_tdd.rs` (3 schema tests), `tests/slicer_module_binding_tdd.rs`; `crates/slicer-runtime/tests/integration/gcode_part_cooling_emission_tdd.rs` (annotation→G-code emission), `tests/contract/integrated_parity_part_cooling_tdd.rs`; `crates/slicer-sdk/src/traits.rs` `push_fan_speed` (value 0 → `Raw("M107")`, else `Raw("M106 S{v}")`).
- OrcaSlicer comparison: see `requirements.md` §OrcaSlicer Reference Obligations; do not repeat delegation rules.

## Architecture Constraints

- **Config keys are snake_case** (repo rule); new keys follow Orca's spelling exactly — this packet never invents a key name.
<!-- snippet: coord-system -->
- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.
- **Schemas:** manifest `[config.schema]` edits flow through `read_config_schema` (`crates/slicer-scheduler/src/manifest.rs`) into `ConfigBoundsIndex::from_modules`; bounds/enum enforcement then happens host-side in `ConfigBoundsIndex::check` (`crates/slicer-scheduler/src/config_resolution.rs`) with zero host code change — the keys ride the `extensions` bucket of `ResolvedConfig` (untyped), merged by `to_config_map` (`crates/slicer-ir/src/resolved_config.rs`), pre-filtered per module by `ConfigView::from_declared` (`crates/slicer-ir/src/slice_ir.rs`). No typed `ResolvedConfig` field is added.
- **One key, one reader.** `ConfigBoundsIndex::from_modules` walks every module's schema and merging bounds across modules is supported, so co-declaration is *possible* — but this packet does not use it. Each key is declared in exactly the module that reads it: 15 in `part-cooling`, 4 (plus the supporting `chamber_temperature`) in `machine-gcode-emit`. A declaration in a module that never calls `config.get` on the key is the declaration-only disposition map rule 1 prohibits.
- **`machine-gcode-emit` can emit lines no template contains.** `substitute_placeholders` renders `[key]` references inside user templates (arbitrary lookup over `ConfigView::keys()`, warn-and-pass on an unresolved key, single-pass, **no conditionals**), but the module also writes non-template commands during `reemit_command` (the `ExtrusionMode` to `M82`/`M83` bridge). The header/footer emission uses the latter capability at the `PrintStart` prepend and `PrintEnd` append, not the placeholder path — the four keys are canonically emitted by `GCode::_do_export`, not resolved by the placeholder parser.
- **The percent→S conversion is shared:** implement exactly one helper, `percent_to_fan_s(p: i64) -> u8` = `floor(255.5 × p / 100)` — canonical `GCodeWriter::set_fan`'s `(unsigned int)(255.5 * speed / 100.0)`. Both the primary channel and the `P2` auxiliary channel use it. `overhang_fan_speed`'s existing percent scale is unaffected (it already stores percent and multiplies by the fan max), but its product with `fan_max_speed` must switch to percent×percent before conversion.

## Code Change Surface

- Selected approach: deepen `PartCooling` and `MachineGcodeEmit` in place (no new module, no WIT/IR change). Ownership follows the reader, not the ticket: the four header/footer keys are declared **only** in `machine-gcode-emit`, because `part-cooling` never reads them and a declaration without a read is precisely what map rule 1 prohibits.
  1. **Manifests.** `part-cooling.toml`: re-key the 2 scale keys to percent (`type = "float"`, default 100/20, min 0, max 100); add the 13 remaining P01 keys with Orca defaults/bounds; add the threshold enum (`values = ["0%", "10%", "25%", "50%", "75%", "95%"]`, default `"95%"`); widen `internal_bridge_fan_speed`/`ironing_fan_speed`/`support_material_interface_fan_speed` to `min = -1, max = 100`; and add the role base-speed keys the slowdown stage reads (names/defaults copied from `slicer_ir::feedrate::SPEED_KEYS` and `docs/config/host-keys.toml` `[speeds]`) — 8 declared today becomes 21 P01-and-cooling keys plus the speed block. `machine-gcode-emit.toml`: add `activate_air_filtration`, `activate_chamber_temp_control`, `during_print_exhaust_fan_speed`, `complete_print_exhaust_fan_speed`, `chamber_temperature` — 14 declared today becomes 19.
  2. **Percent normalization:** every site that turns a fan percent into an S-value calls the shared `percent_to_fan_s`; defaults 100/20 produce S255/S51 — the module's default-path bytes (`M106 S255`, `M107`) are unchanged, keeping existing fixtures honest.
  3. **Fan curve:** `PartCooling` grows the config fields and per-layer decision implementing the canonical branch chain (base = `R ? min : 0`; `T < S` → max; `S ≤ T < F` → `t = (T − S)/(F − S)`, speed = `floor(t·min + (1−t)·max + 0.5)` in percent; `T ≥ F` → base; ramp `factor = (idx+1−C)/(L−C)` multiplied and clamped only when `idx+1 < L`). Layer time `T` is derived per-layer in `run_finalization` from the view's entities (path length ÷ feedrate; `speed_factor` profiles honored), not guessed from scheduling data.
  4. **Role-fan selection:** per-layer role scan replaces today's `BridgeInfill`-only bump: `BridgeInfill`/`InternalBridgeInfill`/`SupportInterface`/`Ironing` map to their keys with canonical precedence and `-1` fallbacks (`internal_bridge` → `overhang_fan_speed`; the other two disabled at `-1`).
  5. **Threshold:** `overhang_fan_threshold` classifies whether an entity's `overhang_quartile` bands (map: 10%→quartile ≥1, 25%→≥2, 50%→≥3, 75%→4) or bridge/external-perimeter roles qualify it for the overhang fan.
  6. **Time-domain:** kickstart/speedup re-time rising `M106`s to an earlier entity boundary using the same per-entity time model; gated by `fan_speedup_overhangs`; emitted as `Raw` annotations ahead of the demanding entity.
  7. **Auxiliary channel:** with `auxiliary_fan`, each qualifying layer gains a `Raw("M106 P2 S{n}")` (via `percent_to_additional_fan_s`) and the final layer gains `Raw("M106 P2 S0")`.
  8. **Layer-time slowdown stage** (new, in `PartCooling::run_finalization`): estimate each layer's print time from `LayerCollectionView::ordered_entities` (path length divided by `base_speed(role) * speed_factor`, the same time model the fan curve uses so the two agree by construction); when `slow_down_for_layer_cooling` is true and the estimate is below `slow_down_layer_time`, scale the adjustable entities by a single layer factor `target_time_ratio`, floored per entity at `(slow_down_min_speed / base_speed(role)).max(0.05)`; `dont_slow_down_outer_wall` removes `ExtrusionRole::OuterWall` from the adjustable set (canonical `CoolingBuffer::parse_layer_gcode` clearing `adjust_external`). Written through `FinalizationOutputBuilder::modify_entity` + `EntityMutation::SetSpeedFactor`. Travel moves are not adjusted, matching canonical.
  9. **Header/footer emission** (new, in `MachineGcodeEmit::run_gcode_postprocess`): at the `PrintStart` prepend, `push_raw("M191 S{chamber_temperature}")` **before** the rendered `machine_start_gcode` when `activate_chamber_temp_control && chamber_temperature > 0` and the rendered template contains no leading `M141`/`M191` line (port of canonical `GCode.cpp`'s static `custom_gcode_sets_temperature`), then the rendered template, then `Raw("M106 P3 S{n}")` when `activate_air_filtration`. At the `PrintEnd` append: the rendered `machine_end_gcode`, then `Raw("M141 S0")`, then `Raw("M106 P3 S{n}")` — canonical `_do_export`'s chamber-off-then-exhaust order. Conversions use `percent_to_exhaust_fan_s`.
- Exact functions, traits, manifests, tests, and fixtures: `PartCooling::from_config` plus new private helpers (`percent_to_fan_s`, `percent_to_additional_fan_s`, one shared layer-time estimator used by both the curve and the slowdown stage, `base_speed(role, config)`, role-fan selector, threshold classifier, re-timer, slowdown scaler); `MachineGcodeEmit::run_gcode_postprocess` plus `percent_to_exhaust_fan_s` and the `custom_gcode_sets_temperature` port; `FinalizationModule::run_finalization` orchestration unchanged in shape. New test files: `part-cooling/tests/cooling_curve_parity_tdd.rs`, `part-cooling/tests/layer_slowdown_parity_tdd.rs`, `machine-gcode-emit/tests/exhaust_and_chamber_emission_tdd.rs`; `crates/slicer-scheduler/tests/config_bounds_enforcement_tdd.rs` extended; fixture updates limited to restating raw-byte expectations in percent terms.
- Rejected alternatives and reasons:
  - New dedicated `exhaust-fan` / `air-filtration` modules: rejected — canonically these are header/footer emission features and `machine-gcode-emit` already owns the `PrintStart`/`PrintEnd` sites; a new module would invent a stage this tree's DAG does not have and would race the existing module for the same two insertion points.
  - Declaring the four header/footer keys in `part-cooling` as well ("co-declaration"): rejected — `part-cooling` has no reason to read them, and a declaration without a read is the declaration-only disposition map rule 1 prohibits. An earlier draft of this packet did exactly that and called placeholder reachability the deliverable; canonical grounding this session showed the keys are emitted directly by `GCode::_do_export`, not resolved through the placeholder parser (only `during_print_exhaust_fan_speed` is *additionally* published, as `during_print_exhaust_fan_speed_num`).
  - Adding an SDK/host accessor so guests can read `slicer_ir::feedrate::FeedrateConfig` instead of re-declaring `*_speed` keys: rejected **for this packet** — it would be a new host function across the WIT boundary, which this packet is not authorized to add (see `[FWD]` below). The duplication is taken knowingly as DIV-D.
  - Implementing the slowdown as a `PostPass::GCodePostProcess` rewriter over the final `GCodeCommand` stream (which would give the emitter's exact time model rather than a guest estimate): rejected — it would move a cooling decision out of the cooling module into a text-stream rewriter that must re-emit every command or silently drop it, and it would split the fan decision and the slowdown decision across two stages with two different time models.
  - Typed `ResolvedConfig` fields for the new keys: rejected — the extensions bucket already delivers values into the module `ConfigView`; typed fields are for host-side *decisions*, which (except the curve) none of these keys feed.
  - Converting at config-resolution time (storing S-values in config): rejected — Orca's percent must survive to templates/placeholders raw (AC-8 pins raw percents in templates); conversion belongs at emission.
  - Porting `FanMover` verbatim as a gcode-line post-filter over serialized G-code: rejected — this tree's guest modules decide before emission from IR views; re-implementing the same re-timing at the annotation level is strictly smaller and testable without a textual G-code rewriter.

### Tier, claims, and carriers (map rule 4 / rule 1)

- **Tier: B.** This packet builds decision points that do not exist today (the fan curve, the layer-time slowdown stage, the header/footer emission), but it builds all of them **inside existing owners at their correct seams** — `part-cooling` at `PostPass::LayerFinalization`, `machine-gcode-emit` at `PostPass::GCodePostProcess`. No new module, so it is not Tier C; no key here is mere plumbing into a pre-existing decision point, so it is not Tier A. The ticket's "17 Tier A + 2 Tier B" framing is superseded — the map/ticket update is listed in the session report.
- **Claims held: none, and correctly none.** Both owners carry `[claims] holds = []` / `requires = []` today and keep it. Map rule 4's claim-holder shape fires on *cross-module algorithm selection* — an Orca enum whose values are separate implementations resolved through `*_fill_holder` / `module_overrides`. Nothing in this packet is that: `overhang_fan_threshold` is a threshold one module compares against, and the fan/slowdown branches are one module branching internally over behaviour it implements itself (the rule's own trigger test, `seam_position`/`support_style` category). Turning a fan curve into claim holders would fragment one decision across modules for no selection benefit.
- **Which existing mechanism carries the new data:**
  - Fan decisions, the `P2` channel, and the kickstart/speedup re-timing ride `LayerAnnotation` / `LayerAnnotationKind::Raw` through `FinalizationOutputBuilder::push_fan_speed` and `push_annotation` — already the module's output surface.
  - The slowdown stage rides `FinalizationOutputBuilder::modify_entity` with `EntityMutation::SetSpeedFactor`, applied in `FinalizationOutputBuilder::apply_to` onto `ExtrusionPath3D::speed_factor`, and resolved at emission by `DefaultGCodeEmitter::resolve_feedrate` (`crates/slicer-gcode/src/emit.rs`). `overhang-classifier-default` already writes speeds through this exact path (its `SetPointSpeedFactors` use), so the mechanism is proven, not invented.
  - The header/footer lines ride `machine-gcode-emit`'s own `PrintStart` prepend / `PrintEnd` append steps in `run_gcode_postprocess`, emitted through `GcodeOutputBuilder::push_raw` (`crates/slicer-sdk/src/postpass_builders.rs`) alongside the rendered templates — not through `push_fan_speed`, which is hardwired to the primary `M106 S` channel. The module already writes non-template commands there (the `ExtrusionMode` -> `M82`/`M83` bridge in `reemit_command`), so synthesized lines are an existing capability, not a new seam.
  - Every new key rides the untyped `extensions` bucket of `ResolvedConfig` into the owner's `ConfigView`. **No WIT interface, no IR schema bump, no typed `ResolvedConfig` field, no new host function** — verified this session against `crates/slicer-sdk/src/traits.rs` and `crates/slicer-ir/src/slice_ir.rs`.

### Recorded divergences from canonical (rule 4: improvements and forced simplifications, never gaps)

`DIV-A`..`DIV-E` are **design-local labels for this packet only** — they are not `docs/DEVIATION_LOG.md` IDs and must not be greped for there. Per ticket 02, a `DEVIATION_LOG.md` row is filed only after the human has been asked and signed off; Step 9 surfaces these, it never self-files them.

- **DIV-A — per-filament gating collapses to two global bools.** Canonical guards the exhaust/chamber emissions with a printer-level `support_air_filtration` bool AND per-filament `activate_air_filtration` / `activate_air_filtration_during_print` / `activate_air_filtration_on_completion` / `activate_chamber_temp_control`, reduced with `max`/OR across active extruders (`GCode.cpp::_do_export`). This port has no per-filament profile model — the map's Tier-D fog — so `activate_air_filtration` alone gates both exhaust emissions and `activate_chamber_temp_control` alone gates both chamber emissions. Rationale: the extra four canonical keys are per-filament by construction; declaring them global would be a lie about their semantics, and the collapsed gate is behaviourally identical on the single-filament configurations this port supports today. When the per-filament fog clears, the reduction is reinstated by adding the vector keys, not by changing this packet's decision point.
- **DIV-B — three fan converters, kept distinct.** Canonical uses three different roundings for the three fan channels (`GCodeWriter::set_fan` `255.5 * p / 100`; `set_additional_fan` `255.0 * p / 100`; `set_exhaust_fan` `p / 100.0 * 255`). This is almost certainly canonical accident rather than intent, but the port reproduces all three exactly and pins the disagreement with a test (AC-2), because a viewer diffing PnP output against Orca output would flag a one-unit S difference as a parity break. This is a *deliberate* non-improvement, recorded so a future reader does not "clean it up".
- **DIV-C — annotation-level re-timing instead of a G-code text filter.** Canonical `FanMover` re-times rising fan commands by rewriting serialized G-code lines. This port decides before emission from IR views and re-times at the annotation level. Strictly smaller, testable without a textual rewriter, and identical in observable output.
- **DIV-D — guest-side role base-speed table (duplication, recorded as a risk).** The slowdown stage needs each role's base speed in mm/s to turn `slow_down_min_speed` into a factor. `slicer_ir::feedrate::FeedrateConfig` and `DefaultGCodeEmitter::resolve_feedrate` are native-only: `crates/slicer-sdk/src/host.rs` exposes no speed accessor, and `LayerCollectionView` carries no speed table. So `part-cooling` re-declares the `*_speed` keys it needs in its own `[config.schema]` and hand-rolls a private `base_speed(role, config)` mapping — exactly the precedent `overhang-classifier-default` set (its private `base_speed` and `speed` helpers are crate-private and not importable). Key names and defaults are copied from `slicer_ir::feedrate::SPEED_KEYS` and `docs/config/host-keys.toml` `[speeds]`, which are the single sources of truth. The duplication risk is real and is filed as `[FWD]` below.
- **ADR-0052 conformance (S8).** ADR-0052 fixes the per-point carrier as `EntitySpeedProfile { entity_id, factors: Vec<f32> }` of *factors* against the per-role base speed, in an `entity_id`-keyed side table, with the `clamp(0.05, 5.0)` staying in `DefaultGCodeEmitter::resolve_feedrate`. This packet **conforms**: it writes whole-entity `EntityMutation::SetSpeedFactor` (the pre-existing `path.speed_factor` path the ADR describes as the status quo), on the same factor scale, and changes neither the carrier shape nor the clamp location. It does not amend the ADR and needs no amendment deviation.
- **DIV-E — the min-speed floor is computed, not clamped into.** `DefaultGCodeEmitter::resolve_feedrate` clamps factors to `0.05..=5.0` (ADR-0052). The guest therefore computes `factor_floor = (slow_down_min_speed / base_speed).max(0.05)` itself rather than relying on the host clamp, so a `slow_down_min_speed` below `0.05 * base` is honoured as the clamp value knowingly rather than silently.

## Risks and Tradeoffs

- **Per-point vs per-layer granularity:** canonical `check_overhang_fan` compares per-extrusion-point overlap; PnP classifies per entity using quartile bands — a documented approximation (quartile bands are themselves an overhang-degree quantization). Behaviour converges as thresholds map to bands; exact per-point overlap equality is NOT claimed.
- **Layer-time estimation** from path length ÷ feedrate ignores accelerations/retractions; canonical's estimate has the same class of simplification at this layer. Documented as estimate semantics.
- The `-1` sentinel keys are declared `int` with `min = -1` — module code must read `i32`/`i64` (not `u8`) or the sentinel wraps; the curve tests pin the fallback explicitly (AC-4).
- Fixture churn: raw-byte assertions in three existing files must be restated in percent terms without weakening (Step Completion Expectations in `requirements.md`); any mid-scale expectation must be re-derived through `floor(255.5 × p / 100)` (50% → `floor(127.75)` = **S127**, never eyeballed), and the overhang bump at defaults stays S255 (100% × 100%).
- **Slowdown vs fan-curve time model:** both use the same guest-side layer-time estimate by construction (one helper, called twice). If they were allowed to diverge, a layer could be slowed for cooling while the fan curve still read it as fast. Step 7 must reuse Step 4's estimator rather than write a second one; the invariant is asserted directly.
- **Slowdown interacts with `overhang-classifier-default`,** which also writes speed mutations at `PostPass::LayerFinalization` (via `SetPointSpeedFactors`). Per ADR-0052 upsert semantics, whichever module runs later wins for an entity it touches; `part-cooling` uses whole-entity `SetSpeedFactor` while the classifier uses per-point profiles, and the two carriers are read independently by `resolve_feedrate` (an absent profile row falls back to `ExtrusionPath3D::speed_factor`). Step 7 must verify the composition, not assume it — a per-point profile written by the classifier would otherwise shadow the cooling slowdown for that entity.
- **The synthesized header/footer lines change default-config output only when the two bools are on** — both default false, so the default G-code stream is unchanged. That is an intentional identity, asserted as the *negative* half of AC-8/AC-8b, never as the evidence that the keys work.

## Context Cost Estimate

- Aggregate: `M`
- Largest step: `M` (Step 4 fan-curve port + its invariant suite; Step 7's slowdown stage is the same size). Nine atomic steps — the packet is broad but every step is S or M, which is what keeps the aggregate at `M` rather than `L`.
- Highest-risk dispatch and required return format: the CoolingBuffer re-verification — `SNIPPETS` capped at 3/30 lines; anything larger is rejected and re-dispatched narrower.

## Open Questions

- `[FWD]` Guest-side duplication of the emitter's role -> base-speed table (DIV-D). `slicer_ir::feedrate::FeedrateConfig` / `DefaultGCodeEmitter::resolve_feedrate` are native-only and the SDK exposes no speed accessor, so `part-cooling` must hand-roll a match that stays consistent with the emitter's by convention alone. The right long-term answer is a host-side accessor or an SDK-shared table, which is a **new host function across the WIT boundary** and therefore out of this packet's authorization. Filed here so the next packet that needs a base speed does not re-derive the problem. No activation blocker: the duplication is testable (a test asserting the guest table and `SPEED_KEYS` name the same keys) and localized.

Resolvable at Step 6 by reading `ConfigBoundsIndex` / `ConfigValue` enum handling; no activation blocker.
- `[FWD]` Whether `check_overhang_fan`'s `0%` -> external-perimeter arm should also cover `ThinWall` sub-roles PnP may split later — pinned to `OuterWall` for now, which is this tree's external-wall role. Resolvable at Step 6; no activation blocker.

Consequence: the slowdown trigger point differs from Orca's on layers dominated by short segments. Recorded rather than hidden; AC-10 asserts the stage's own model self-consistently (mutations move the *estimate* to the target), not byte parity with Orca. Resolvable only by a host-provided layer-time input, which is a new surface and out of scope.
