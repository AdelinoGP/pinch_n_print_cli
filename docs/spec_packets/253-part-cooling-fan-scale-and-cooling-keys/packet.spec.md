# Packet Contract: 253-part-cooling-fan-scale-and-cooling-keys

This packet was authored per the useful grounding in `requirements.md` §Verified Grounding; all symbol paths below were verified against the current tree at authoring time.

## Goal

Implement OrcaSlicer's 19-key cooling surface as behaviour, split across its two real owners: in `part-cooling`, percent-normalize `fan_max_speed`/`fan_min_speed` to Orca's 0–100 scale, port the canonical fan-decision chain (layer-time interpolation, full-fan ramp, stop/start suppression, role-based fan speeds, overhang-threshold enum, time-domain fan speedup/kickstart) **and** the canonical layer-time slowdown stage that `dont_slow_down_outer_wall` gates; in `machine-gcode-emit`, synthesize the canonical chamber-temperature and exhaust-fan lines at the `PrintStart`/`PrintEnd` injection sites. Every key in this packet drives a decision point that exists when the packet closes — no key is declared without a consumer.

## Scope Boundaries

Fifteen of the 19 P01 keys are declared and consumed in `modules/core-modules/part-cooling/`; the four header/footer keys are declared and consumed in `modules/core-modules/machine-gcode-emit/` — the module that owns the `PrintStart`/`PrintEnd` injection sites and therefore the only honest owner of a header/footer emission. They are **not** co-declared into `part-cooling`, which does not read them. The supporting key `chamber_temperature` is declared alongside them because `activate_chamber_temp_control` has no behaviour without it. No host-crate changes, no WIT change, no IR schema bump, no new module, no `ResolvedConfig` field: the layer-slowdown stage rides the existing `FinalizationOutputBuilder::modify_entity` / `EntityMutation::SetSpeedFactor` surface that `overhang-classifier-default` already uses. Full lists in `requirements.md`.
