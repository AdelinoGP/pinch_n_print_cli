# Arachne host and perimeter-kernel property contracts

## Goal

Complete H-ARACHNE and the Arachne perimeter module's classification, wall-conversion and sequence properties with independently justified, feature-enabled tests, canonical-correct fixes, concrete regressions and measured Windows execution.

## Why

The approved `docs/specs/proptest-openrscad-adoption.md` §§3, 5–7, 10–13 and queue row 10 require host structural/beading/graph properties and module-owned kernel properties. The algorithm is shared: `run_arachne_pipeline` (`crates/slicer-core/src/arachne/pipeline.rs`) owns the host pipeline, while `build_walls`, `classify_line` and `commit_wall_sequence` (`modules/core-modules/arachne-perimeters/src/lib.rs`) own distinct conversion, labeling and commitment behavior. A module test that merely calls the host must not be credited as a second algorithm property.

Source inspection reveals a concrete alignment risk worth testing, not an executed failure: `build_walls` captures widths and feature flags before a possible `path.points.reverse()`, and its winding branch checks point count rather than `line.is_closed`. Unequal widths and asymmetric flags can expose an index mismatch hidden by uniform fixtures. Open lines and zero-width inner-contour markers are legitimate; do not generalize an all-closed or all-positive-width fixture into a universal Arachne contract.

The authoring source audit also found two concrete parity discrepancies requiring implementation-time reproduction: local widening currently branches on thickness alone, whereas both inspected canonical trees gate single-bead widening on the requested count as well; local pre-stitch maximum emission closes a micro-loop that canonical leaves open. These are source observations, not measured test results; investigate the real caller and fix canonical-correct behavior rather than preserving a contradictory fixture.

## Scope

- In: the assigned H-ARACHNE host pipeline, distributed/limited/widening beading and skeletal-graph kernel properties; the three named private module kernels; a focused canonical/source contract audit; direct bounded domains, independently derived models, non-vacuous witnesses and negative controls; owner-local tests and registry charters; measured Windows routine/extended and incremental PR execution; focused canonical-correct fixes and concrete regressions for confirmed defects.
- Out: classic perimeters/fuzzy skin, unrelated module families, general Clipper/Voronoi correctness, SCAD, a live OrcaSlicer differential harness, a broad randomized guest or full-pipeline campaign, new public production visibility, IR/WIT/schema changes, and unproven universal wall-count, shape-preservation, closure, width-cap or parity claims. Larger defects that prevent an assigned charter remain blocking fix work, not a waived family.

- `docs/spec_packets/proptest-openrscad_02_pbt-domains/` (**draft at authoring**): planned `slicer_sdk::test_support::property_testing::domains::{DomainError, GeometryBounds, GeometryDomain, GeometryCase, TopologyClass, BoundaryRule, geometry_cases}` and sibling `oracles::{validate_geometry, signed_area2, point_in_region, PointLocation}`; `regression::{ConcreteInput, format_regression_fixture}` only supports its documented scalar, graph, layer, geometry and mesh variants. Its generic `SmallGraph` is not a skeletal half-edge graph; construct/inspect the real graph instead. No assumed Arachne-specific exported generator exists.
- Transitive #1, `docs/spec_packets/proptest-openrscad_01_pbt-foundation/` (**draft at authoring**): exact planned `PropertyRun::{new,bound,check}`, `CaseGuard`, `test-properties.toml` registry, profile/context/events/artifacts and `cargo xtask test --properties` selectors. Implementation and closure wait for both prerequisites to be implemented; recheck their actual exports and shapes against disk first. Queue status `generated` is not implementation.

## Design notes

### Production boundaries, features and deliberately limited contracts

- `slicer-core` has `default = []`; `skeletal_trapezoidation` (`crates/slicer-core/src/lib.rs`) and `arachne::{pipeline,generate_toolpaths}` (`crates/slicer-core/src/arachne/mod.rs`) require `host-algos`. `beading` itself is ungated. Existing standalone `arachne_pipeline`, `arachne_invariants`, `arachne_beading_propagation_delta_bound` and `arachne_construction_epilogue` targets are auto-discovered without Cargo `required-features`, but their **source files** each use `#![cfg(feature = "host-algos")]`: a bare run may silently execute zero tests. `beading_distributed` and `beading_limited` are explicit standalone targets without a required feature. Always select and verify `host-algos` for graph/pipeline baselines.
- `arachne-perimeters` is a root workspace package. Its Cargo lib target is `arachne_perimeters`; native `slicer-sdk` depends on core with `host-algos`, although the module's direct core dependency disables defaults. Test the private kernels in a new feature-gated unit-test module, not by making them public. Both production `run_perimeters` and the one-wall-top path call `build_walls` and `commit_wall_sequence`; `build_walls` calls `classify_line`. Existing entrypoint examples are wiring evidence, not replacements for kernel properties.
- Add new empty owner selection features `slicer-core/property_testing` and `arachne-perimeters/property_testing`, workspace Proptest **dev** dependencies, and SDK `property_testing` **dev** dependencies following the predecessor's pattern. Add standalone `property_arachne` and `property_arachne_contracts` targets to `crates/slicer-core/Cargo.toml`, each with `required-features = ["host-algos", "property_testing"]` and matching source-level gates. Register `property_tests` in the module's `src/lib.rs` with stacked separate `#[cfg(test)]` and `#[cfg(feature = "property_testing")]` attributes on the module declaration, and put its planned tests in new `src/property_tests.rs`. Retain the stacked form as the required declaration: `#[cfg(test)]` confines the module to test builds and `#[cfg(feature = "property_testing")]` makes the properties opt-in; this is a compilation/readability choice, not a scanning mechanism. **No automated literal-scanner coverage follows from either form.** `collect_enforced_files` (`xtask/src/check_literals.rs`) collects `crates/*/tests`, `crates/*/benches`, `crates/*/src` (inline `#[cfg(test)]` subtrees) and `modules/core-modules/*/tests`; it never collects `modules/core-modules/*/src`, and `LiteralVisitor::visit_item_mod` does not follow an out-of-line `mod property_tests;` into `src/property_tests.rs`. `cargo xtask check-literals` therefore cannot see this file (`docs/21_data_defaults_and_fixtures.md` §7.1). The implementation must manually review the new `src/property_tests.rs` and any helper file or inline test code this packet adds under the module's `src/**` for exhaustive literals of watched types, and use FRU or an `// exhaustive: <reason>` waiver per `docs/21_data_defaults_and_fixtures.md` §§1, 3, 4; the review, the re-derived watched-type names and the outcome go into the evidence file. No relocation is planned: the scanner-covered `tests/**` location is an integration test without access to private `classify_line`, `build_walls` and `commit_wall_sequence`, no simpler `#[path]`-based placement with the same access was verified, and the packet must not widen production visibility solely for tests. Relocate only if implementation verifies such a placement and records it in the evidence. A lib target cannot have `required-features` without gating production: use the source gate and verify discovery instead. Preserve default normal/build/guest graphs; explicitly record that the owners' dev graphs may acquire Proptest even when an owner property is not selected.
- `ExtrusionLine` contains `junctions`, `inset_idx`, `is_odd`, `is_closed`; each `ExtrusionJunction` contains `p` and `perimeter_index` (`crates/slicer-ir/src/slice_ir.rs`). `ExtrusionPath3D::is_closed` requires a repeated first/last XY point. `WallLoop.path.points`, `width_profile.widths` and `feature_flags` are parallel **by point**, not merely equal in length. `run_arachne_pipeline` returns `(printable_lines, inner_contour)`, not one vector: `separate_out_inner_contour` (`crates/slicer-core/src/arachne/separate_inner_contour.rs`) classifies a marker by its **first** zero-width junction. Do not apply printable-width assertions to marker lines or assume every later printable junction has strictly positive width.
- `SkeletalTrapezoidationGraph::from_polygons` (`crates/slicer-core/src/skeletal_trapezoidation/graph.rs`) finalizes compacted indices. Its implementation permits `NO_INDEX` for absent `twin`, `next` or `prev`, despite broader comments about twins; test bounds and reciprocity **when present**, not universal twin presence. `distance_to_boundary` can have an uncomputed NaN sentinel: do not require every vertex radius to be finite. Immediately after construction the two beading side tables are vertex-parallel; do not silently generalize this construction-stage condition across arbitrary mutations.
- ADR-0011 (`docs/adr/0011-perimeter-module-owns-wall-sequencing.md`) makes a region's committed wall sequence authoritative. Assert an exact mode order only for the controlled single-outer wall batch below; test separate region batches independently, never globally sort by `perimeter_index`. ADR-0023 (`docs/adr/0023-arachne-port-strategy.md`) sets the segment-Voronoi/preprocessing boundary. Do not feed overlapping/T-junction or invalid geometry to a kernel that promises no such validation.

### Shared domain, oracle and evidence rules

Use #2's `geometry_cases` and `validate_geometry` with independently verified winding, topology and bounded arithmetic; locally construct bounded Arachne-specific parameter/line/half-edge cases without advertising them as shared exports. Bounds are registry `u64`s: checked conversion precedes arithmetic, allocation and narrowing. Prove bounds for coordinates, area, f32/f64 conversion, bead-count arithmetic and intermediate products, including every `max_beads + 1` calculation. Use construction-first shapes, not a rejection-only strategy. Explicitly exercise valid convex/concave, holed, disconnected, thin and near-degenerate witnesses where supported; preserve required witnesses on every `simplify`/`complicate` state. Distinguish a valid tiny feature removed by documented preprocessing (`EmptyAfterPreprocess` where applicable) from an unexpected failure on the separately defined guaranteed-output domain. Neither an empty result nor a rejected/exhausted generator proves output properties.

Parameter domains use finite positive bead spacing/widths and layer height, a nonzero bounded distribution count, bounded finite transition inputs and positive even limited caps. Couple the generated thickness/count to each property branch rather than feeding arbitrary parameters to `compute`. Geometry is integer units; extrusion junctions are f32 millimeters. Use exact comparisons for indices, booleans, order and constructed dyadic values where proven. Otherwise derive dimensionally correct absolute/relative rounding envelopes from the chosen f32/f64 operations and bounds before testing; record reference arithmetic error. Never tune an epsilon to the observed output or assume integer→f32→integer is an exact identity.

Before generalizing, inspect the actual canonical equivalents and their caller preconditions; record the source revision, file/function, conditions, intentional PnP distinctions and any fixture conflicts in the evidence file. In particular the stale `transition_dist = 4.0` comment in `arachne_invariants` is not a current failure report, and `build_propagated_graph` in that test omits stages now present in the real orchestrator: its output is not automatically the graph used by `run_arachne_pipeline`. Execute existing feature-enabled baselines and inspect logs at implementation. Protected parity/self-captured tests stay unchanged in strength; verify canonical behavior before any fixture correction. No actual C++ port is pre-authorized as necessary; if a focused fix translates upstream logic into a new Rust file, include the standard attribution header and original source path from `docs/ORCASLICER_ATTRIBUTION.md`.

Each charter below is a separate semantic property, with owner/test, contract, domain, strategy, independent oracle and dependency overlap, tolerance, shrink/witness policy, measured execution/isolation, failure artifact and acceptance documented in `docs/testing/properties.md`. Every property calls the named real SUT through #1 `PropertyRun::new`, `bound`, `check` and per-invocation `CaseGuard`. Record required deterministic witnesses outside random chance, and require an actual observed population before iterating assertions. Helper/negative-control evidence is not credited as a production property.

### H-ARACHNE-BEADING — analytic bead and sentinel cases

`proptest_arachne_beading_relations` calls `DistributedBeadingStrategy::{new,compute}` through `BeadingStrategy` (`crates/slicer-core/src/beading/distributed.rs` and `crates/slicer-core/src/beading/mod.rs`), plus `LimitedBeadingStrategy::{new,compute}` (`crates/slicer-core/src/beading/limited.rs`) and `WideningBeadingStrategy::{new,compute}` (`crates/slicer-core/src/beading/widening.rs`). Generate bounded positive dyadic width `w`, thickness `t`, nonzero distribution radius and counts with zero, one, two and multiple-bead witnesses. For the distributed zero-bead case assert empty parallel arrays and `left_over = t`; for one and two beads compare to independently derived full-thickness or equal-halves and center positions. For `n >= 3` use `t = n*w`: all widths are `w`, locations are `(i + 1/2)*w`, and `left_over = 0`, within a pre-derived error envelope. This analytical equal-spacing special case is not a copied distribution implementation or a claim about arbitrary deficits.

For the limited decorator, use cap `2k >= 2`, a distributed parent and positive width `w`. At the cap use `t = 2k*w`: independently expect `2k` real beads of width `w`, centers `(i + 1/2)*w`, one zero-width marker at `k*w`, and zero leftover. For requested count `cap + 1`, use `t > cap*w`: the `2k` real beads retain width `w`; the left-half centers are `(i + 1/2)*w` for `i < k` and the right-half centers mirror them about `t/2`; the two zero-width markers are at `k*w` and `t - k*w`, and leftover is `t - 2k*w`. Check parallel array lengths and marker count with the independently derived float envelope. These proportional, unit-normalized relations are not absolute-coordinate Orca output fixtures, consistent with ADR-0042. Do not require `bead_widths.len() == requested_count` across decorators. For widening, canonical `WideningBeadingStrategy::compute` (`WideningBeadingStrategy.cpp`) selects the special branch only when `bead_count <= 1 && t < getTransitionThickness(1)`: below `min_input_width` it returns no bead/leftover `t`; at or above that minimum it returns one centered bead `max(t, min_output_width)` with zero leftover. With `bead_count >= 2`, it delegates to the parent even when `t < optimal_width`. Exercise this transition case, not just the locally implemented thickness-only branch. A concrete independently calculated regression uses a distributed parent, `w = 4000` units, `t = 3000` units and requested count 2: canonical delegates and returns two 1500-unit beads, whereas the current local source takes its single-bead branch. Name the new deterministic real-SUT test `widening_two_requested_below_optimal_delegates_to_parent`, establish the pre-fix result by execution, and fix the production branch and caller-correct transition threshold if reproduced. Widening may deliberately make `sum(widths) > t`, so conservation applies only to cases where it is independently valid. Shrink while retaining each branch and its boundary witnesses.

The count-two case is part of the real algorithm, not merely an arbitrary trait input: canonical `SkeletalTrapezoidation::generateSegments` (`SkeletalTrapezoidation.cpp`) walks nodes and, for a positive bead count with nonzero transition ratio, calls the stack at the same thickness for the lower count and the next count. `populate_beading_propagation` (`crates/slicer-core/src/skeletal_trapezoidation/propagation.rs`) contains the corresponding production caller. Add deterministic real-caller regression `widening_transition_propagation_preserves_two_bead_endpoint` under `C`: use a valid bounded two-vertex/twin-edge graph with a noncentral vertex at radius 1500 units, `bead_count = Some(1)`, `transition_ratio = 0.5`, and a real `BeadingStrategyFactory::create_stack` with thin walls enabled, even cap 4, `optimal_width = preferred_bead_width_outer = 4000`, `min_input_width = 1000`, `min_output_width = 3400`, and zero outer offset. Call the actual population pass and inspect that vertex's `beading_propagation` entry. With equal-thickness low/high beadings, canonical `SkeletalTrapezoidation::interpolate` (`SkeletalTrapezoidation.cpp`) preserves the high-count side and blends corresponding widths/locations: expect widths `[2450, 1500]` and locations `[1125, 2250]` units, under the independently derived f64 error envelope. This concrete unit-scale example instantiates the same proportional relation; do not infer a measured incidence rate or require it from every shape.

### H-ARACHNE-GRAPH — real construction and graph relationships

`proptest_arachne_graph_topology` calls actual `SkeletalTrapezoidationGraph::from_polygons` on independently validated small closed outlines, including deterministic positive-area rectangle and holed/concave witnesses within the supported non-touching segment domain. Check every `start_vertex` index, every non-sentinel edge reference, `twin.twin`, `next.prev`, `prev.next`, and the two construction-stage vertex-parallel side-table lengths using an independent indexed relation checker, not the production compactor. Assert a nonempty vertex/edge population on the explicitly documented suitable rectangle witness; empty/tiny cases are separate. If a referenced twin exists, its start vertex resolves the edge endpoint; only check finite/nonnegative distance relationships in a subdomain where both endpoint radii are known and finite. Do not assume all constructed references exist or test an artificially mirrored pipeline graph as the orchestrator's internal graph.

Add deterministic direct calls showing empty input returns `SktError::EmptyInput` and a ring with fewer than three points returns `SktError::DegeneratePolygon`. They are validation-boundary examples, not permission to expect arbitrary invalid rings to be diagnosed. Inject broken reciprocity, out-of-range references and a truncated side table into test-owned copies and prove the independent relation checker rejects each; never feed malformed graphs to production kernels without an explicit rejection contract.

### H-ARACHNE-PIPELINE — output structure and contour roles

`proptest_arachne_pipeline_structure` calls real `run_arachne_pipeline` with bounded `ArachneParams` based on its `Default` via FRU, and the #2 geometry families. Audit source/canonical predicates and derive the separate positive-area, feature-clearance and parameter conditions needed for an output-producing rectangle/wedge; the controlled guaranteed-output mode must actually yield nonempty printable lines, not just `Ok`. Other valid geometry modes may legitimately erase a tiny feature or yield no walls when the audited conditions allow it; record and assert the exact declared outcome rather than silently accepting every error. Include an explicit known sufficient-size square, a tapered witness, an eligible thin-wall case, and a separately encoded collapsed/empty preprocessing case. Do not claim these become canonical exact output goldens.

For returned printable lines, check nonempty junctions and finite bounded coordinates/widths, first-junction marker separation, and the `perimeter_index`/`inset_idx` relation on the verified output domain. The PnP `ExtrusionLine.is_closed` contract requires coincident XY endpoints; assert it on controlled output cases whose stitch closure is independently known to produce an explicit repeat, and preserve legitimate open paths. Canonical `WallToolPaths::stitchToolPaths` (`WallToolPaths.cpp`) can set its closure flag even when a noncoincident endpoint gap does not meet its append condition, so do not call exact endpoint equality a universal upstream guarantee or manufacture closure to satisfy a test. Investigate any conflict with the PnP representation against canonical before generalizing. Never require every inset-zero or odd line to be closed. Include deterministic source-backed open and closed line fixtures as well as whatever the pipeline generates; a pipeline class that is empty must not satisfy an output loop. For `inner_contour`, check the first width is zero and treat it as a marker, not as an extrudable wall. Independent relation controls must reject a changed index, a falsely marked closed line with unequal endpoints in the explicit-repeat domain, and a nonzero-first-width marker. Full containment, a fixed number of walls, a universal two-times-width cap and arbitrary rotation invariance are not asserted.

Audit the real pre-stitch `generate_toolpaths` call to `generate_local_maxima_single_beads` (`crates/slicer-core/src/arachne/generate_toolpaths.rs`). The existing `arachne_local_maxima_single_beads` target uses a small regular-pentagon input and observes the **post-pipeline** result; it does not expose the pre-stitch graph. Construct a bounded valid graph with a noncentral strict maximum and odd populated beading, then call the actual public `generate_toolpaths` to inspect its raw buckets. Canonical `SkeletalTrapezoidation::generateLocalMaximaSingleBeads` (`SkeletalTrapezoidation.cpp`) constructs an odd, six-junction line with `is_closed = false`; it does not append the first junction. The local source currently sets `is_closed = true` and appends it. Add deterministic real-kernel test `arachne_local_maximum_pre_stitch_is_open` under `C`, retain a nonempty actual maximum population, and verify the constructor and caller/stitch behavior before fixing any confirmed discrepancy. Update a conflicting local fixture only to canonical-correct behavior, not to preserve its former closed-loop expectation; test post-stitch behavior separately rather than assuming that an open pre-stitch line must remain open forever.

### M-ARACHNE-CLASSIFY — actual role table

`property_tests::proptest_module_arachne_classify` calls private `classify_line`. Independently tabulate `is_odd`, `inset_idx == 0` and `print_thin_walls`: only odd, zero-inset, thin-enabled becomes `(ExtrusionRole::ThinWall, LoopType::ThinWall)`; all other inset-zero cases become `(OuterWall, Outer)`; every positive inset becomes `(InnerWall, Inner)`, including odd lines. `is_closed` alone changes no classification. Include all Boolean modes and zero/positive inset witnesses; shrink positive insets without losing positivity. Deliberately mapping a deeper odd wall to GapFill is detected. This PnP ThinWall labeling refinement is not asserted as an upstream role identity.

### M-ARACHNE-BUILD — point, width, flag and topology correspondence

`property_tests::proptest_module_arachne_build_walls` calls `ArachnePerimeters::build_walls` directly with constructed `ExtrusionLine`s, a real `SliceRegionViewBuilder`, and `PerimeterSpatialContext::new` from the same declared region data. Use nonempty bounded dyadic coordinates, positive distinct per-junction bead spacings, positive layer height and corresponding valid region shapes. Include both a closed line with an explicit repeated XY endpoint and an open line with distinct endpoints; never synthesize closure from `is_odd` or `inset_idx`. A controlled rectangle and its reversed winding must force both winding/no-winding branches; an asymmetrically placed strictly interior bridge rectangle covers at least one but not all distinct points. Independently predict membership with #2's `point_in_region` or analytical rectangle inequalities away from boundaries, not `PerimeterSpatialContext::is_bridge` or `build_wall_flags`.

For each nonempty input line, exactly one wall preserves `inset_idx` as `perimeter_index` and the independently tabulated role/loop type; an empty line produces no wall. The actual output order may be the source order or a whole-line reversal only where the source/canonical contract permits it. Match each output point to its actual source junction, including the repeated endpoint; its expected width is the independent real-number formula `spacing + height*(1 - π/4)` with the separately derived f32 rounding envelope, and `width_profile.widths[i] == path.points[i].width` exactly. The bridge flag at index `i` must belong to that same point, as must its bridge-flow and any other authored per-point metadata under the selected region; `feature_flags.len() == width_profile.widths.len() == path.points.len()` alone is insufficient. With `LoopType::ThinWall`, every `is_thin_wall` is true and no `is_bridge` is set. Empty bridge/overhang views exercise absence; mixed bridge membership exercises positive and negative flags without relying on a production containment predicate.

`line.is_closed` and output `path.is_closed()` must agree for these valid distinct-endpoint/explicit-repeat fixtures; orientation normalization must not add a closing edge to an open path. Audit canonical treatment of open-path direction before requiring or forbidding reversal: a permissible reversal must reverse the entire point/width/flag association, not just coordinates. Preserve permitted per-point metadata and derive any bridge-flow check from its documented formula, not `bridging_flow` itself. A separate deterministic reverse-trigger fixture uses unequal widths and asymmetric bridge flags; a synthetic points-only reversal must fail the independent comparison. If the actual kernel fails it, reproduce, classify and fix it rather than reducing the property to equal-length arrays.

### M-ARACHNE-SEQUENCE — region-local, lossless commitment

`property_tests::proptest_module_arachne_sequence` calls private `commit_wall_sequence` with a bounded batch carrying unique independently visible wall identities, unequal per-point widths and distinct flag content. In the controlled domain, there is exactly one `Outer` wall at either endpoint and one or more `Inner` walls, with no hidden grouping. Form the expected normalized identity list by leaving an outer-first input unchanged or reversing an outer-last input. `InnerOuter` expects that list, `OuterInner` expects its full reverse, and `InnerOuterInner` expects first inner, outer, remaining inners. Compare complete `WallLoop` values by independent identity mapping, retaining intra-wall point direction and all parallel metadata; assert the output is an exact permutation, with no additions or losses. Empty and singleton input remain unchanged. A batch without a unique endpoint outer is checked only for lossless permutation, not an invented general sandwich model. Existing `wall_sequence_commit_tdd` additionally exercises the real per-region driver, both first-layer and later-layer sandwich behavior, and cross-region precedence; do not claim the private helper itself accepts region identities. This controlled PnP commitment contract is not a claim that two upstream revisions' odd-line region-order policies agree.
