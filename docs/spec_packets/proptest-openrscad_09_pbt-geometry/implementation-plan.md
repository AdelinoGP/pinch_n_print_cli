# Implementation Plan: pbt-geometry

Start direct work only after #1 and #2 are implemented and their exports, registry/context and feature graphs are rechecked against disk. #3/#4 are conditional enrichment, not prerequisites for the direct family. All new targets and tests named here are planned. Each step leaves default and selected enabled targets compiling. The spec defines `C`, `H`, `P`, `S`, baseline commands and the mandatory `target/test-output.log` capture; inspect/archive that log before the next invocation.

## Step 2: Build independent Boolean and full-path clipping checks

- Objective: expose wrong set membership, hole treatment and missing/extra path spans through actual production calls.
- Surface: `proptest_boolean_set_algebra`, `proptest_clip_polylines_full_segments` in new `crates/slicer-core/tests/property_geometry.rs`; `geometry_controls_boolean_and_clip_mutations` and `geometry_controls_vertex_plane_and_hole_witnesses` in new `crates/slicer-core/tests/property_geometry_controls.rs`; `H-BOOL-SET`/`H-BOOL-CLIP` records and charters.
- Approach: use #2 topology cases, `line_segments`, independently checked `point_in_region`, `segment_in_region`, `signed_area2` and `validate_ring`. Pair/translate valid cases with checked arithmetic; preserve the relevant hole/component witness during shrinking. Implement the bounded exact rectangle cell-partition and 1D interval reference locally, with deterministic positive populations. For clipping analytically model the one-unit expanded rectangle/contracted rectangular hole, preserve the documented ±2-unit endpoint tolerance, and test non-axis-aligned paths only beyond the boundary band. Do not use Clipper, self-union, input tags, raw ring ordering, single-midpoint containment or blanket output topology validation as the reference.
- Verify: `C`; after their measured records exist run `cargo xtask test --summary --properties --property H-BOOL-SET --property H-BOOL-CLIP --tier routine`; run the existing `polygon_ops_tdd` and `polygon_ops_clip_batched_tdd` targets with the wrapper.
- Done when: all four Boolean wrappers and actual open clipping run, exact and sampled assertions have nonempty populations, and the specified union, filled-hole, shortcut and dropped-span controls fail the checker. Log bounds, samples, shrink behavior and documented limitations.

## Step 3: Bound offsets and canonical-backed smoothing

- Objective: check preservation only where a mathematical special case proves it.
- Surface: `proptest_offset_rectangular_clearance`, `proptest_smooth_outward_safe_families` and `geometry_controls_offset_and_smooth_mutations` in the new core targets; existing `offset`/`offset2_ex` in `crates/slicer-core/src/polygon_ops.rs` and `smooth_outward_polygon` in `crates/slicer-core/src/smooth_outward.rs`; registry/charter rows `H-OFFSET-MITER` and `H-OFFSET-SMOOTH`.
- Approach: construct axis-aligned whole-mm rectangles/annuli with material and hole clearance surviving both passes; calculate rectangle and hole bounds/area directly, with separately justified f32/f64 and grid conversions. Exercise unequal deltas, both signs and empty/zero; use the one-mm square with −1 mm then +2 mm to distinguish first-pass collapse from reversed order. Surviving axis-aligned passes alone cannot prove order because their bounds depend on the delta sum. Construct convex rings whose edges survive the duplicate prepass and L-notches with sufficient arm/feature clearance; derive 90° chord setback and truncation envelope independently. Keep tiny CW deletion separate. Recheck focused Orca `offset2_ex` (`ClipperUtils.cpp`) and `smooth_outward` (`MutablePolygon.cpp`); preserve the existing DEV-141 far/blocked divergence rather than porting it away.
- Verify: `C`; `cargo xtask test --summary --properties --property H-OFFSET-MITER --property H-OFFSET-SMOOTH --tier routine` after those records exist; existing `offset2_ex_tdd`, `offset2_ex_collapse_tdd`, `polygon_ops_tdd` and core `smooth_outward::tests` with separate capture.
- Done when: wrong sign/order, hole deletion and arm-distance/chord confusion are detected; no asserted universal offset inverse, unconditional smoothing superset or unproved tolerance remains.

## Step 4: Exercise analytical mesh slicing, transforms and queries

- Objective: test real mesh code against dimensions and independent coordinate/ray models rather than a second call to production.
- Surface: `proptest_slice_analytical_solids`, `proptest_mesh_transform_and_aabb`, `geometry_controls_slice_and_query_mutations` and `geometry_controls_vertex_plane_and_hole_witnesses` in the new core targets; `slice_mesh_ex`, `transform_point3`, `AabbTree::{new,bounds,raycast_first_hit,raycast_all_hits}`; `H-MESH-SLICE`/`H-MESH-QUERY` registry/charters.
- Approach: make bounded closed box/vertical right-prism scenes using the spec's XY triangle whose dimensions and sorted planes guarantee finite computations and nonambiguous interior slices; validate indices/finite coordinates/incidence with #2 before slicing. Derive box and prism section geometry from primitive parameters, including separately pinned exact top, bottom and vertex-plane fixtures. Use #2 `analytical_meshes` for bounds and `rigid_transforms` for transform checks, and construct separate ray-friendly boxes because the predecessor's maximum extent does not guarantee a minimum dimension. Sign/swap plus translation is the transform oracle and dimension-derived box face intersections the ray oracle. Keep zero-matrix guard and identity explicit. State mesh-space query ownership and do not claim the tree is called by the pipeline.
- Verify: `C`; `cargo xtask test --summary --properties --property H-MESH-SLICE --property H-MESH-QUERY --tier routine` after those records exist; run existing `triangle_mesh_slicer_tdd` and `aabb_tree_tdd` as specified, separately logged. Verify the named shared-edge and vertex-plane tests execute.
- Done when: required nonempty slice/hit populations exist, missing or filled geometry, transposed transform and wrong hit sets fail their controls, and finite/quantization error proofs are retained. Do not pass unsorted planes or invalid indices to a function that lacks a rejection contract.

## Step 5: Compare helper splitting with a separate face model

- Objective: protect selected real pre-pipeline mesh behavior without asserting repair or decimation preservation.
- Surface: `proptest_helpers_split_components` in `crates/slicer-helpers/tests/property_helpers.rs`; `helper_controls_edge_adjacency_and_singleton_mutations` in its controls target; `split_connected_components` in `crates/slicer-helpers/src/split.rs`; `H-HELPERS-SPLIT` registry/charter and `docs/13_slicer_helpers_crate.md` Splitting behaviour.
- Approach: construct finite meshes with valid indices and distinct position identities; include closed solids, vertex-only contact, reversed/same-direction edges, empty input and singleton fragments. Independently compare every face pair for opposite directed index edges and compute bounded reachability without the production map/DFS. Reconstruct oriented output faces from local vertex indices; compare exact multisets/partitions and first-input-face component ordering. Preserve witnesses during shrinking; assert input/output populations when applicable.
- Verify: `H`; `cargo xtask test --summary --properties --property H-HELPERS-SPLIT --tier routine` after its record exists; existing `cargo test -p slicer-helpers --test split_tdd` with capture.
- Done when: actual output preserves each face exactly once, and vertex-only/same-edge-direction joins and dropped singleton mutations are caught. No general repair property or malformed-index error is claimed.
