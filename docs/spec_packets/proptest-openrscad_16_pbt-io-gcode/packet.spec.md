# H-IO, H-GCODE and the I/O-facing module kernels

## Goal

Complete H-IO and H-GCODE with bounded, independently oracled properties, and add the remaining template, cooling, overhang-speed, skirt/brim and wipe-tower kernel properties, all executed through the opt-in property harness with measured Windows routine and extended profiles.

## Why

The approved source is `docs/specs/proptest-openrscad-adoption.md` §§5–7, 10–13 and queue row 16. The existing bed-placement, loader, emitter, serializer and module examples are useful fixed witnesses, not domain exploration. The source identity is a basename-plus-index UUID rather than a hash whose injectivity can be assumed; placement is a rigid whole-scene translation whose float tolerances must be derived; emission and serialization carry state (tool, E accumulator, layer context) that a single example cannot justify; and the five module kernels are decision/template/interval/containment functions whose branch boundaries are exactly where silent regressions live.

This packet also closes a documentation hazard found during authoring: `docs/02_ir_schemas.md` describes the `[0.05, 5.0]` speed-factor clamp as OrcaSlicer parity, while `docs/08_coordinate_system.md` names the clamp without that parity claim. A delegated read of the available canonical checkout found no such clamp in `GCode::_extrude_piece`, `GCodeWriter::set_speed` or the `GCode/` extrusion path. The clamp is PnP's ADR-0052 contract. The property charter asserts the PnP contract and this packet corrects the provenance wording. Separately, `path_object_id`'s source comment calls its namespace `NS_OID`, but the 16 literal bytes are the RFC 4122 X.500 namespace (`6ba7b814-…`), not the OID namespace (`6ba7b812-…`). The packet's oracle uses the actual bytes, records the misnomer, and corrects the comment/docs (including the misleading baseline commentary in `object_id_is_the_documented_basename_uuid5`) without changing the stable UUID behavior.

## Scope

- In: H-IO source identity and basename collisions; transform-aware world-Z extent; rigid bare-mesh bed placement, relative arrangement and derived float tolerances; H-GCODE feedrate resolution, emission state/sequence, and serializer relative/absolute extrusion semantics; `machine-gcode-emit` placeholder substitution; `part-cooling` layer/event decisions; `overhang-classifier-default` speed sections and interpolation; `skirt-brim` skirt/brim enclosure and loop counts; `wipe-tower` purge-path rectangle and convex-bed containment. All new properties, deterministic controls, shrink/mutation probes, registry records, measured profiles, Windows evidence, focused fixes for confirmed SUT defects and the documentation corrections listed below.
- Out: new IR/WIT/schema fields, schema-version bumps, new shared SDK exports, widening private APIs for tests, arbitrary hash-injectivity claims, concave-bed containment claims, fan monotonicity, route optimality, canonical rectangle/tessellation claims, full OrcaSlicer differential testing, randomized guest/E2E campaigns, new SCAD behavior, scheduler/runtime coverage, and workspace test closure. A larger confirmed defect becomes blocking fix work for the affected family, not a weakened property or an ignored acceptance failure.

### H-IO-ID: basename-plus-index identity, not hash injectivity

Owner: `slicer-model-io`, inline lib test `loader::property_tests::proptest_object_id_and_basename_collisions`, calling the real private `path_object_id` and public `check_basename_collisions`. Domain: bounded ASCII/Unicode basenames without path separators (`max_basename_bytes`), bounded distinct directories, indices `0..=max_index` plus deterministic `0` and a large representable index, empty path list, repeats, and `Path::file_name()` edge cases. Use Rust's actual component semantics: trailing separators are ignored for the final normal component (`/usr/bin/` has `file_name() == Some("bin")`), while `file_name()` is `None` for an empty path, a root path (`/` or `C:\`), `.`, and `..`. Do not classify a trailing-separator path as lacking a file name. Use a construction-first basename strategy; do not build a filter-heavy arbitrary path generator.

Oracle: an independent name constructor `format!("{basename}#{index}")` plus `uuid::Uuid::new_v5` with the exact 16-byte namespace from `path_object_id` (the RFC 4122 X.500 namespace, not `Uuid::NAMESPACE_OID`). For a path with no `file_name`, mirror the documented fallback to the whole `path.to_string_lossy()` text before appending `#<index>`. This shares the `uuid` crate's RFC 4122 implementation but not `path_object_id`'s basename/index/collision logic; record that dependency in the charter. Assert canonical lowercase hyphenated `8-4-4-4-12` syntax, determinism for repeated calls, same basename in different directories gives the same id, a trailing-separator path uses its final normal component as the basename, different indices give different ids on the declared bounded set, and different basenames give different ids on that set. The last two are bounded-domain observations, not a universal injectivity theorem; never assert unequal UUIDs for arbitrary inputs. Add a deterministic control that uses `NAMESPACE_OID` instead of the actual X.500 bytes and must be rejected; this pins the namespace and demonstrates why the source comment is misleading.

Collision oracle: group the generated paths by `file_name()` in input order; a collision exists exactly when a basename group contains two paths that `same_file` does not consider equal. For non-existent generated paths, `same_file` reduces to the production `Path` equality first branch; model that exact predicate rather than raw string inequality. Expect `Ok(())` otherwise; on failure expect `ModelLoadError::DuplicateInputBasename { basename, first, second }` with the first path in input order and the first later distinct path. Include a deterministic temp-file control for `./a/cube.stl` versus an absolute path to the same file, a repeated identical path, distinct basenames, `file_name() == None` paths (empty/root/`.`/`..`, skipped), a trailing-separator path grouped under its final component (not skipped), and a Unicode basename. Shrinking may simplify the directory/basename text but must retain the collision/no-collision mode; use `prop::sample::select(...).no_shrink()` for the mode.

### H-IO-EXTENT: exact affine Z row on a dyadic domain

Owner: `slicer-model-io`, `property_io`, `proptest_object_world_z_extent`, calling the real `object_world_z_extent`. Generate 0..=`max_vertices` vertices with dyadic f32 coordinates in `[-max_abs_mm, max_abs_mm]` and an affine `Transform3d` whose row entries `m[2], m[6], m[10], m[14]` are dyadic in a bounded range. The zero matrix is a separate deterministic identity witness and a separate generated mode selected with `prop::sample::select(...).no_shrink()`; do not rely on random all-zero generation.

Oracle: for the zero matrix, `z_i = v.z`; otherwise compute the exact real value `m[2]*x + m[6]*y + m[10]*z + m[14]` from the f32 inputs in f64. On the declared dyadic bounds (coordinates multiples of `2^-4`, matrix entries multiples of `2^-2`, magnitudes below `2^12`), every product and the four-term sum are exactly representable in f64; cast once to f32, matching the production narrowing point. Assert `Some((min,max))` with exact f32 equality when the resulting `z_max > z_min`, and `None` for empty, degenerate (`z_max <= z_min`) or non-finite reduced extrema cases. Be precise about the non-finite policy: the reduction ignores NaN vertices because the `<`/`>` comparisons are false, while an infinity that reaches an extremum makes the final extent non-finite and returns `None`. The non-finite mode is separately labeled, includes both observations, and is never called a valid printable object. Shrinking removes vertices and reduces magnitudes; it retains the identity/affine/nonfinite/degenerate mode required by the assertion. Deterministic controls reject a missing row term, a non-transform-aware extent, an off-by-one min/max swap, and a false `Some` for a degenerate extent.

### H-IO-PLACEMENT: rigid whole-scene translation with derived tolerances

Owner: `slicer-model-io`, `property_io`, `proptest_place_bare_mesh_on_bed`, calling the real `place_bare_mesh_on_bed`. Generate 0..=`max_objects` objects with 0..=`max_vertices_per_object` dyadic vertices, zero-matrix (identity convention) or a bounded live affine transform selected with `no_shrink()`, and a finite dyadic `bed_center`. Use `analytical_meshes(SolidKind::Box, ...)` or an equivalent construction-first box family for nonempty worlds; include an empty world, one empty object beside a nonempty object, a single object, multiple objects, an already-placed world, and a below-bed/off-centre world.

Oracle: independently compute each object's world AABB using the documented zero-matrix-is-identity convention, union them, and derive `dx = bed_center.0 - (min.x+max.x)/2`, `dy = bed_center.1 - (min.y+max.y)/2`, `dz = -min.z`. Compare the returned `BedPlacement` to that formula on the f32 values. After placement, require: the new world `z_min` is `0` within a derived envelope; the new XY AABB centre is `bed_center` within `2 * ulp(max(|coordinate|, |bed_center|))`; every pair of objects preserves its AABB min/max differences within `4 * EPSILON * max_abs` (the bound covers `fl(a+t) - fl(b+t) - (a-b)`); and no object is individually re-centred or re-dropped. For zero-matrix objects only, assert `mesh.build_volume` equals the union of the shifted raw vertices. For live-transform objects, `build_volume` is currently computed from raw vertices (`compute_bounding_box_union`), not world AABBs; do not assert raw-vertex union equals world union. Record the observed field and classify a confirmed mismatch under the defect policy. `None` is expected when no object yields the function's finite-X AABB gate (an empty or all-nonfinite-X world); non-finite Y/Z are outside the valid domain. Shrinking removes objects/vertices and simplifies transforms; it retains the empty/nonempty, identity/live-transform and placeable/unplaceable modes. Deterministic controls reject per-object centring, a translation-only XY shift without Z drop, a non-rigid per-object scale, and a fabricated placement for an empty world.

### H-GCODE-FEEDRATE: role table, factor clamp, conversion and rounding

Owner: `slicer-gcode`, `property_gcode`, `proptest_feedrate_resolution`, calling the real `DefaultGCodeEmitter::resolve_feedrate`. Generate bounded finite base speeds in `[0, max_base_speed_mm_s]` for every `ExtrusionRole` variant and finite factors spanning `[0, max_factor]`, including `0`, negative values, values below `0.05`, above `5.0`, and exact `0.05`/`5.0`. Build `FeedrateConfig` explicitly; the oracle is an independent decision table, not a call to `role_base_speed_mm_per_s`:

- OuterWall→`outer_wall_speed`; InnerWall→`inner_wall_speed`; ThinWall→`thin_wall_speed`; TopSolidInfill→`top_surface_speed`; BottomSolidInfill→`bottom_surface_speed`; InternalSolidInfill→`sparse_infill_speed`; SparseInfill→`sparse_infill_speed`; BridgeInfill→`bridge_speed`; SupportMaterial→`support_speed`; SupportInterface→`support_interface_speed`; SupportBaseInterface→`support_interface_speed`; Skirt→`skirt_speed`; Brim→`skirt_speed`; WipeTower→`wipe_tower_speed`; PrimeTower→`prime_tower_speed`; GapFill→`gap_infill_speed`; RaftInfill→`outer_wall_speed`; InternalBridgeInfill→`resolve_internal_bridge_speed_mm(internal_bridge_speed, bridge_speed)` — in percent mode `(value as f32 / 100.0) * bridge_speed`, otherwise `value as f32`; Ironing→`filament_ironing_speed` when it is `> 0.0`, else `ironing_speed`; `Custom("Travel")`→`travel_speed`; `Custom("Wipe")`→`wipe_speed`; `Custom("GapInfill")`→`gap_infill_speed`; every other `Custom`→`outer_wall_speed`.

For a finite base and factor, expected `F = round(f64(base) * 60.0 * f64(clamp(factor, 0.05, 5.0)) * 1000.0) / 1000.0` narrowed to f32. State explicitly that Rust `f64::round` is the half-away-from-zero operation and compare the resulting f32 bits. `resolve_feedrate` always returns `Some`; with a zero base speed it returns `Some(0.0)`, not an error and not a fabricated automatic speed. A separate deterministic boundary probe derives `max_finite_base = f32::MAX / (60.0 * 5.0)` and shows that a larger finite base narrows to `f32::INFINITY`; this is an overflow observation, not a valid rate. Non-finite factors are outside the valid domain and are observed separately: `+Infinity`/`-Infinity` **saturate** through `f32::clamp` to 5.0/0.05, while NaN propagates; none is asserted as correct. Shrinking reduces base/factor magnitudes and retains the role and over/under-clamp mode. Deterministic controls reject an omitted 60× conversion, a factor clamp of `[0,1]`, truncation instead of round-to-millidegree, and a role-table swap.

The `[0.05, 5.0]` clamp is PnP ADR-0052, not a canonical OrcaSlicer behavior; see the OrcaSlicer references section. Do not introduce a canonical-parity claim in the charter.

### H-GCODE-EMIT: a small command/state model

Owner: `slicer-gcode`, `property_gcode`, `proptest_emission_state_sequence`, calling the real `emit_gcode` (and `emit_gcode_owned` for the owning path). Domain: 0..=`max_layers` layers, each with 0..=`max_entities_per_layer` entities, dyadic finite points in `[-max_abs_mm, max_abs_mm]`, distinct per-layer `entity_id`s, roles from a bounded set, `order_lock = Some(0)` to bypass simplification (or an explicitly zero `gcode_resolution`/`min_segment_length`), and zero/one tool change at a valid anchor. Keep role base speeds nonzero in the positive domain so `f` follows the explicit `resolve_feedrate` oracle; the zero-base automatic branch is covered only by the negative mode. Include empty layers, a skipped empty layer between nonempty layers, a layer with a side-table entry but no ordered entities (only headers are producible; classify the side-entry observation rather than asserting emission), an empty layer collection, and a layer with a nonempty `RegionKey.variant_chain` whose axes are in #11 `(priority, name)` order.

State oracle: walk the returned `GCodeIR.commands` and compare a test-owned state machine:

- The stream starts with `ExtrusionMode { absolute: !relative }`; `disable_m73 = true`; no M73 commands are expected. Trailing `Raw` filament-statistics comments appended after the layer walk are identified and ignored by the state model (or asserted for their documented content on exact inputs); they are not treated as entity output.
- Every layer with output emits `Raw(";LAYER_CHANGE")`, `Raw(";Z:<...>")`, `Raw(";HEIGHT:<...>")` before its first move; a layer with no output emits nothing and does not increment `metadata.layer_count`. A layer containing only annotations is a no-output layer: annotations are emitted only inside/after an output layer, not as a reason to open one.
- Entity order is preserved unless cross-layer rotation is intentionally exercised; for a one-layer scene, `apply_cross_layer_tool_rotation` is a no-op on the leading tool, so the model can predict entity order. For multi-layer header/role scenes, keep the leading **and ending** tool equal across layers so rotation is a no-op; do not use a multi-layer tool-change scene where rotation would rewrite anchors unless the model explicitly applies the rotation.
- Each entity's first Move has `e = None`; subsequent Moves have `e = Some(cumulative)` for positive-length segments; a zero-length segment has `e = None`. All `Move` x/y/z values equal the original points; the role equals the entity role; `f` is present and equals the feedrate oracle for the selected role/factor.
- After each entity, the sequence is retract(s) → Z-hop up → travel(s) → tool change (with the wipe-tower guard/retract when enabled) → annotation(s) → Z-hop down → unretract(s), matching anchors and declaration order.
- A tool change emits `ToolChange { after_entity_index, from, to }` and resets the next entity's `;TYPE:` label; a layer-boundary tool reset occurs before the first entity when its `tool_index` differs.
- `metadata.filament_used_mm` has length `max_tool + 1`, where `max_tool` is the maximum key actually present in `filament_per_tool`, defaulting to `0` when no key is present (so an empty/no-Move stream still has a single zero entry). A tool that owns any processed `Move` point is present even if its delta is zero: the emitter calls `filament_per_tool.entry(current_tool).or_insert(0.0)` for an entity's first point, so a singleton/non-extruding entity contributes a zero entry. A tool that appears only in `tool_changes` with no `Move` does not extend the vector. Each entry equals the sum of that tool's Move E deltas (zero for a singleton) within a derived f32 accumulation envelope; all values are finite and nonnegative for the positive-flow domain.
- `GCodeIR` has no `RegionKey` field, so the nonempty #11-ordered chain is fixture input only. Assert that replacing it with an empty chain leaves the command stream/order unchanged, or inspect an owner-local layer seam; do not claim output-chain preservation.

Use a separate negative mode for `wipe_tower_enabled = true` with a tool change but no `WipeTower` entity, expecting `GCodeEmitError::MissingToolchangePurge { layer_index, tool_change_index }`; and for a tool index `>= MAX_PLAUSIBLE_TOOLS` (1024) on an extruding entity, expecting `GCodeEmitError::ToolIndexOutOfRange { tool, max }`. Also drive the automatic-volumetric branch with a role whose configured base speed is exactly `0.0` and non-finite width/height/flow/factor, expecting the documented `GCodeEmitError::Emit` messages; do not weaken those finite/positive checks. Shrinking removes layers/entities/points and side entries; it retains the required tool-change/retract/travel/anchor mode and the fixture-only nonempty-chain witness. Deterministic controls reject a missing layer header, a dropped skipped-layer rule, an unretracted tool change, a reordered retract/travel/tool-change sequence, a per-entity rather than whole-scene E accumulator, a dropped zero `filament_used_mm` entry for a singleton/non-extruding entity, and a fabricated entry for a tool that appears only in `tool_changes`.

### H-GCODE-SERIALIZE: independent text and extrusion-state model

Owner: `slicer-gcode`, `property_gcode`, `proptest_serializer_extrusion_state`, calling the real `DefaultGCodeSerializer::serialize_gcode` in relative and absolute modes with the Marlin and RepRapFirmware temperature forms. Domain: 0..=`max_commands` commands built directly as `GCodeIR` (`Move`, `Retract`, `Unretract`, `FanSpeed`, `Temperature`, `ToolChange`, `Comment`, `Raw`, `ExtrusionMode`), with:
- XYZ coordinates on a dyadic grid with at most 3 decimal places;
- absolute E values and retract/unretract lengths on a dyadic grid with at most 5 decimal places;
- integer Celsius values for temperature;
- bounded ASCII text for comments/raw lines, including `G92 E0`, `G92 E1.5`, `G92 X0`, `G92 E` (unparseable), and a non-`G92` line;
- no command with a non-finite numeric field in the generated valid domain.

Oracle: an independent command renderer that implements the documented text contract: `G0` for `Custom("Travel")` otherwise `G1`; `X`/`Y`/`Z` via a test-local 3-decimal (configured `gcode_xy_decimals`) trimmed formatter; `E` as the absolute value in absolute mode and as `current - previous_accumulator` in relative mode; `F` and retract/unretract speeds via an independent 4-decimal trimmed formatter matching `format_coord`'s wire shape. Relative mode: a `Gcode` retract emits `G1 E-<length> F<speed>` and subtracts `length` from the accumulator; an unretract emits `G1 E<length> F<speed>` and adds it. Absolute mode: the documented contract is absolute E positions, so the accumulator tracks the last emitted absolute E (updated by Moves and G92), a `Gcode` retract emits `G1 E<updated_absolute> F<speed>` and updates the accumulator, and an unretract emits `G1 E<updated_absolute> F<speed>` and updates it. A `G92` raw line updates the accumulator only when its first `E`-prefixed token parses as an `f64`; otherwise the accumulator is unchanged. Each generated stream opens with exactly one `ExtrusionMode` matching the serializer's `relative` setting; do not generate conflicting mode switches. A separate deterministic mode-switch probe with G92 resets may exercise text ordering, not E-position policy. The header block and width comments are asserted only for their documented presence/ordering and exact values on dyadic inputs; do not require them to be absent.

The documented absolute-position behavior is the expected contract: absolute mode must emit the updated absolute E position for Gcode retracts/unretracts and keep the accumulator consistent. The current source emits `E-<length>`/`E<length>` without updating the accumulator, so it is a **candidate SUT defect**.
