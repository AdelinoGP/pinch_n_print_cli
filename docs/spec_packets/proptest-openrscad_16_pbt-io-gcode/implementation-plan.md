# Implementation Plan: pbt-io-gcode

Implement only after packets #1, #2 and #6 all have `status: implemented`, and recheck their actual exports, registry/profile behavior and feature graphs. The approved queue authorizes this scope; the queue row's `pending` status is not implementation. All helpers and tests remain private to their owners unless a focused, independently confirmed fix requires an existing production seam. No workspace test is required.

Every plain Cargo test below runs under Bash after `set -o pipefail` and `mkdir -p target`, with the shown `2>&1 | tee target/test-output.log`; inspect and archive the log before the next test. On PowerShell preserve the native `$LASTEXITCODE` across `Tee-Object`. Registry runs use `cargo xtask test` as written, which owns combined logging, context, freshness gates and child status. **Direct `cargo test` invocation of a generative property is invalid**: `PropertyRun::new` requires the foundation's `PNP_PROPERTY_CONTEXT`, which only the registry-backed `cargo xtask test --properties` path supplies, and rejects a missing/mismatched context. Use the exact registry selectors from `packet.spec.md` §Verification for properties; plain Cargo tests are only for the deterministic controls and pre-existing baselines. Registry ID-to-package/target/feature/filter identities are fixed by the table in `packet.spec.md`; do not append ordinary Cargo selectors to property mode.
