# Pure runtime dispatch, modifier transactions and fill partition properties

## Goal

Complete H-RUNTIME with independent semantic-set and small-region models exercising live selection authority, modifier collision/rollback and fill precedence without a new randomized guest campaign.

## Why

The approved source is `docs/specs/proptest-openrscad-adoption.md` §§5–7, §10 and G-FAMILY. #6 deliberately covers only pure modifier-ID construction and explicitly hands actual runtime collision rejection/transactionality to this packet. Properties must exercise the production mutation and publication seams, not infer their behavior from the ID helper or hand-built expected output.

Grounding corrects the old seam name: `module_invocation_allowed_on_layer` no longer exists in `crates/slicer-runtime/src/layer_executor.rs`. Its live semantic predicate is public `paint_allows_layer` in `crates/slicer-wasm-host/src/selection.rs`, called by the committed whole-print selection builder and fed by runtime `build_and_commit_layer_selection_index`. The pure contract and host-wide rollout scope are unchanged; do not restore a deleted helper or add guest randomization to compensate.

## Scope

- In: H-RUNTIME semantic-set invocation, exact-key selection validation/atomic publication, private modifier splitting and public prepass/Tier-2 callers, actual collision/unsupported-parent rejection and rollback, priority/order ownership, full-identity perimeter joins, conditional fill precedence/subset/conservation, aligned internal-bridge metadata, arena versus immutable Blackboard bookkeeping, deterministic oracle controls and relevant existing tests; measured profiles/Windows CI evidence and focused canonical-correct defect fixes with concrete regressions.
- Out: new WIT/IR fields/schema versions, public visibility widened for tests, broad guest/module/E2E property campaigns, support-plan aggregation/clearance algorithms, arbitrary raw invalid-geometry validation, unrestricted hash injectivity, general polygon Boolean correctness, SCAD, changing fill policy or adding a new transaction framework. Large/policy-changing findings block affected coverage rather than becoming passing exclusions.

## Design notes

### Grounded production surface, current call paths and test placement

Extend the existing `slicer_sdk` dev-dependency (package `slicer-sdk`, currently `features = ["test"]`) to `features = ["property_testing"]`, which implies test; leave the normal `slicer-sdk` edge property-free. ### Charter H-RUNTIME-DISPATCH: semantic sets, not paint values or region counts

Independent model: let `S` be the declared semantic set and `L` the set of semantic **names** in every region's ordered `variant_chain` on the selected slice. Allow iff `S` is empty, slice is absent, or `S ∩ L` is nonempty. Compute `L` by independent ordered-set construction; never use `paint_allows_layer` to certify the generator/expectation. Names are case-sensitive strings, including bounded custom names; values (`Flag`, `ToolIndex`, `Custom`) and polygon emptiness do not determine this predicate. Keep scalar values out of valid declared region-split cases; this helper is not their validator.

Generate declared-set insertion permutations, multiple regions/chains, repeated semantic occurrences, unrelated semantics and value changes. Assert exact boolean result and invariance under region order and value-only changes. Deterministic witnesses cover transparent empty set, absent slice (conservative allow), present-empty slice (skip for nonempty S), no match, one matching name amid unrelated entries, matching name only on an empty-geometry region, case mismatch, and `paint_only = false` declaration transparency.

Feed equivalent valid compiled bindings and authoritative RegionMap inputs through real `build_and_commit_layer_selection_index` and inspect each returned selection. Use a neutral module-backed stage such as `Layer::SlicePostProcess` with no fill/support/non-region claims, so independent special claim gates do not change this semantic-only result. All candidate model keys must have real config entries, even in semantic mismatch scenarios, unless the case is explicitly testing failure ordering. Transparent absent/present-empty slice retains `invoke = true` and zero model targets; a nonmatching declaration gives `invoke = false`. For present matching scenes, selected model identities are all candidate regions for that neutral stage, **not only matching regions**: gating is per module × layer, not per region. Preserve the ordered chain in observations; do not sort the production input chain to build expected identities. #7 owns declaration aggregation/paint-only propagation, while this property proves their actual runtime consumption.

### Charter H-RUNTIME-SELECTION: exact authority and atomic publication

Use tiny committed `SliceIR`/`RegionMapIR` scenes and real runtime plan bindings; observe `LayerTargetSource::Model { key, members }`, `targets[*].config`, `invoke`, exact `selection_for` pairs and Blackboard product state. Build expected full keys directly from the fixture's source identity and documented address rule: ordinary empty-chain IDs stay verbatim; painted nonmodifier IDs use source ID divided by `PAINT_VARIANT_REGION_ID_STRIDE` only at the config-map address; modifier IDs stay verbatim; ordered chain/object/layer remain exact. Do not call production `region_map_key_for_sliced_region` as the oracle for its own addressing. Use #6's namespace contract, not an unrestricted ID hash oracle.

Populate unique nondefault config marker values on real interned configs (a declared ordinary key such as `line_width`, with finite compatible values) and the matching filtered invocation view. Compare actual per-target config values against the independently keyed table, not a default/first sibling. Permute map insertion and input binding order; compare selected identities/config associations while preserving committed slice target order. Include sources sharing object/region but differing in ordered chains, different objects with the same numeric region and modifier child identities; no duplicate full source keys in a valid case. Valid marker differences must not depend on differing hashes.

Negative mode removes one exact required RegionKey while leaving default, sibling or reversed-chain entries present. `build_layer_selection_index` must return `LayerSelectionBuildError` with `SelectionError::MissingModelConfig { key }`, responsible stage and module; runtime wrapper must return `LayerStageError::FatalModule` naming that authority and leave `blackboard.layer_selection_index()` absent. Put at least one earlier valid binding/layer before the failing one so success-only/no-partial tests cannot pass on empty work. Invalid raw stage strings go directly to the public pure builder and yield `UnknownLayerStage`; the runtime wrapper filters to its actual roster and is not an unknown-stage validator.

After successful publication, a second runtime publication attempt rejects through the write-once Blackboard seam and preserves the original index `Arc` identity and observations. Do not mutate/rebuild a committed authority as a recovery fallback. This selected pure validation coverage is not a new host permission/guest transport campaign.

### Shared exact small-region oracle and valid domains

Primary geometry domain is bounded orthogonal regions made from even-coordinate axis-aligned rectangles, rectangular holes, concave orthogonal unions and separated components. Use #2 geometry predicates/witness strategies where they match that declared domain; construction of rectangle masks is target-private and does not add another shared generator API. Include nonempty, empty, holed, disconnected, touching-boundary and overlapping-role/footprint scenes deliberately. Invalid geometry is not sent to these APIs with an invented rejection promise. Unique full identities and valid aligned metadata are construction preconditions; separate failures target actual ID/authority validators.

The independent reference is an **exact finite cell labeling model**, not Clipper Boolean output reused as an oracle. Collect input and output orthogonal boundary X/Y coordinates; partition their checked bounding box into elementary open rectangles. Classify a rational midpoint in every cell using independent #2 point membership (doubling coordinates with checked arithmetic permits half-integer midpoints), then evaluate role/ownership truth tables. Including output boundary coordinates prevents a wrong new cut from hiding between sampled input cells. Confirm output edges are orthogonal/on the bounded grid and compare exact area against independently labeled cell sums, using absolute contour/hole double-area rather than contour ordering/winding equality. Check output boundaries cannot hide extra geometry outside the modeled extent. No finite random interior probes alone certify whole-set equality.

Shared predicates must be independent of `slicer_core::polygon_ops::{union,intersection,difference}` used by the SUT. Keep geometric equivalence distinct from byte/metadata rollback equality. Oracle negative controls include a lost sliver, swapped role precedence, cross-hole fill, omitted later footprint and pair-keyed chain mixup; each must be rejected. Rectilinear exact arithmetic needs no ad hoc epsilon. Degenerate boundary-only contact has zero area and is handled explicitly, not counted as positive-area overlap. General oblique Boolean/offset correctness remains #9.

### Charter H-RUNTIME-MODIFIERS: actual ownership, collision rejection and transaction boundaries

Generate ordered parameter-modifier footprints on bounded parents with full identities, object isolation, overlapping higher/lower priority, stable equal-priority document order, empty/disjoint footprints, existing modifier children and paint-chain siblings. A cell belongs to the **first** intersecting footprint in supplied order; later footprints see only the parent's remaining cells. Public prepass order is priority descending then original index. The private splitter itself receives that order and does not sort arbitrary input.

For each split, compare independent cell ownership and conservation/disjointness for `polygons`, `infill_areas`, `bridge_areas`, `bottom_solid_fill`, `top_solid_fill`, `sparse_infill_area`, `internal_solid_fill`, `internal_bridge_areas` and `raft_fill`; initial empty parent infill is restored from its original polygons before successful splitting, so model that documented special case. Parent identity/chain and unaffected metadata persist; children copy parent metadata/chain, clear `segment_annotations`, use modifier namespace IDs decoding to the correct parent, and do not add PerimeterIR walls/entries. `internal_bridge_areas` are split per original polygon, retaining its angle on every resulting piece; test both aligned angle Vec and empty-Vec fallback to `bridge_orientation_deg`. Never union those carriers and lose source-angle association. Keep geometry and metadata observations separate.

Actual rejection mode inserts a preexisting child with the **same** `(object_id, minted region_id, ordered variant_chain)` as a prospective split, or an intersecting unsupported parent derived from #6's representable-parent boundary. Using `modifier_sub_region_id` to construct an adversarial existing-ID stimulus is intentional and does **not** prove hash uniqueness. Force a later failure after another parent/footprint could already have mutated: snapshot the full input before the call, and assert full `SliceIR` equality after `Err`, with `identity collision` / `parent_region_id` and original identity context in the error. An identical numeric ID on a different object/chain is a distinct full identity and must not be rejected merely by numeric equality. No collision search, allocator exhaustion loop or universal hash-injectivity property.

Exercise actual private kernel, `split_modifier_footprints` raw staging and public `split_modifier_sub_regions_for_prepass`, rather than crediting one helper's transactional clone for all callers. Valid prepass mesh cases use small box cross-sections on an interior plane; support enforcer/blocker modifiers must not create parameter children. A consumed raw footprint sentinel disappears only on success; on rejection the original staging/data remain intact. Existing already-materialized children stay unchanged unless their prospective full identity collides. Do not assert arbitrary duplicate raw region records are a geometry validator input.

**Arena boundary:** drive the same rejecting raw-footprint case through `sync_perimeter_infill_areas_into_slice`. It must return `LayerStageError::FatalModule { stage_id: "Layer::Perimeters", module_id: "host:region_partition", message }` and retain the original staged slice (including roles/footprints), not leave `arena.slice() = None` or a partly repartitioned slice. Perimeter data stays unchanged. Source inspection shows the current `take_slice` followed by `split_modifier_footprints(...)?` can abandon the slot on error: reproduce this concrete failure before fixing it. A focused preservation/rollback fix is explicitly in this packet's approved invalid-operation transaction scope. No rollback of an entire earlier perimeter module commit is claimed; the transaction starts at entry to this partition hook. Derived prepared caches may invalidate and recompute, but cannot return stale geometry after success or rejection. Do not expand this into an unrelated arena transaction framework.

### Charter H-RUNTIME-PARTITION: conditional fill rules and full-source joins

Stage a real LayerArena slice/perimeter and call actual `sync_perimeter_infill_areas_into_slice`, also retaining an immutable Blackboard `Arc<Vec<SliceIR>>` original. Perimeter lookup uses exact `(object, source region, ordered chain)`; modifier child lookup decodes only its parent region, preserving object/chain. The effective wall inset is `W = donor.infill_areas ∩ slice_region.polygons`, not the donor's whole object geometry. For nonempty W independently label each cell by the first applicable role `bridge > bottom > top > sparse`: bridge when in original bridge; else bottom when in original bottom; else top when in original top; else sparse. All four outputs are disjoint subsets of W, and their union is W. Compare exact role sets and conservation, not only nonintersection or total area.

**Empty W is conditional**, not a universal subset invariant:

| Condition | Required geometric output |
|---|---|
| W empty and donor has walls | All four canonical fill sets empty: walls consumed the cross-section. |
| W empty and donor has no walls | Preserve original bridge; top is original top minus bridge; bottom and sparse are empty. No false claim that preserved roles are subsets of empty W. |
| Missing donor for ordinary/virtual/modifier region | Region roles stay unchanged and a warning names the object/region (modifier warning also names parent); not a fatal per-region absence. |

The no-wall fallback above is the actual bounded host contract, not the stale comment promising preserved bottom. Nonempty-W clipping matches the inspected `LayerRegion::slices_to_fill_surfaces_clipped` behavior; do not weaken canonical clipping to make a generative test pass. Existing `docs/02_ir_schemas.md` prose still says bridge can always extend beyond inset, missing donors skip silently and all bottom/top/sparse are subsets in every empty case; update it and region_partition's stale Errors/fallback rustdoc to state these **conditional** behaviors, preserving current policy rather than inventing a universal identity.

Role sync leaves unrelated `internal_solid_fill`, aligned internal-bridge fields, raft carrier and metadata unchanged unless the subsequent modifier split explicitly partitions them. For an already-materialized child whose bridge is already contained in W, retain its bridge byte representation as the existing source-preservation branch requires; elsewhere compare geometry semantically, allowing ring start/order differences. No general repeated-call byte-idempotence claim is made: the no-wall bottom behavior and modifier application have explicit domains.

Missing SliceIR is fatal. Missing PerimeterIR is fatal and restores the taken slice; assert actual `FatalModule` stage/module and message fragments `no staged SliceIR` / `no staged PerimeterIR`. Missing individual donor is not that error. Run missing-donor and mismatch cases with another matching region so the population is nonempty and unchanged-on-skip is meaningful. Original Blackboard Arc data and PerimeterIR remain unchanged by successful arena-only partition. Prime/recompute prepared-region views around mutation and compare their geometry to the staged slice so cache invalidation cannot be falsely green.
