# Design: lightning-geometry-portability-gate

## Controlling Code Paths — CURRENT, Not Proof

- `generate_lightning_trees` (`crates/slicer-core/src/algos/lightning/mod.rs`) takes `&[SliceIR]` and `&ResolvedConfig`, returning `Result<Arc<LightningTreeIR>, LightningTreeError>`. It groups `(object_id, region_id)`, pairs island vectors by position, uses print-wide config and clips segments to each region polygon. `algos::lightning` is behind `host-algos`; the feature enables `rayon`/`boostvoronoi`. Do not export this driver as the new kernel.
- `commit_lightning_tree_ir_builtin` (`crates/slicer-runtime/src/builtins/lightning_tree_producer.rs`) calls the host driver. `LightningInfill::run_infill` (`modules/core-modules/lightning-infill/src/lib.rs`) reads already committed `paint.lightning_tree_segments_for`; it does not plan.
- `integrated_parity_lightning_infill` (`crates/slicer-runtime/tests/contract/integrated_parity_lightning_infill_tdd.rs`) injects `LightningTreeIR`, then compares real native/WASM consumers. This is a consumer dispatch precedent, not generator evidence. `lightning_primitives_are_deterministic` (`crates/slicer-core/tests/algo_lightning_tdd.rs`) is repeatability, not canonical evidence.
- The source plan's current-host grouping, future wall-inset availability and paint-preservation concerns are hypotheses to audit. No production fix is smuggled into feasibility work.

## Selected Approach

Keep A and B separate. A reconstructs canonical planning domains from late-PrePass-shaped data and compares them to an independently executed source recorder. B receives the **recorded canonical planning inputs**, not A's candidate output, and executes the owned kernel through isolated ordinary-stage adapters. Thus B may pass while A fails; neither overrides the other. Ordinary fixture verification reads only committed portable files.

### Gate A: independent reference and strategy

NET-NEW recorder tooling lives at `tools/lightning_gate/record.py`, `canonical-recorder.patch`, and `README.md`. `--capture` resolves source provenance at execution, copies/fetches a clean canonical revision into approved disposable storage, applies the checked-in opt-in recorder patch and invokes verified upstream build/slice commands. It records command vectors, tool versions, source URL/revision/dirty-state, patch hash, generated scene/config hashes and recorder artifacts. Never mutate the sibling checkout. `--replay` obtains exactly the recorded source revision/patch/config and verifies normalized output hashes in a separate output directory; missing prerequisites exit nonzero with `inconclusive`, not a synthesized reference. The fixture input description deterministically generates canonical models/configuration; no local PnP output enters expected records.

Recorder checkpoints, keyed by explicit object/local-layer/Z/region/surface identity:

1. `PrintObject::bridge_over_infill` (`src/libslic3r/PrintObject.cpp`): original eligible sparse/internal-void and internal-solid candidates, unsupported intersection, layer grouping and expanded temporary bridge anchors; record immediately before generator creation and after restoration.
2. `Generator::generateInitialInternalOverhangs` and `Generator::generateTrees` (`src/libslic3r/Fill/Lightning/Generator.cpp`): exact accepted `stInternal`/`stInternalVoid` surfaces pooled across regions by object-layer, derived overhangs, parent/child/root graph and boundary grounding before final clipping, top-down order.
3. `group_fills` and `Layer::make_fills` (`src/libslic3r/Fill/Fill.cpp`): caller locals `region_id`, `layerm`, `surface`, `region_config`, `extrusion_role`, grouped `expolygons` and `region_id_group`; make_fills sets `params.config = &region_config`, `f->angle`/`f->fixed_angle` and dispatches `surface_fill.surface` with each `expoly`. Record actual resolved caller policy and grouped geometry with source contributions before dispatch. `region_id_group` is **not** an expolygon-to-region mapping; the representative surface cannot recover original occurrence provenance. Preserve source tokens and transformation operands/events in `group_fills` before grouping/boolean clipping, then use the exact attribution rules below; missing original evidence is inconclusive, not repaired from the representative surface.
4. `Filler::_fill_surface_single` (`src/libslic3r/Fill/FillLightning.cpp`) actually receives `(const FillParams&, unsigned int, const std::pair<float, Point>&, ExPolygon, Polylines&)`, not a region/variant accessor. NET-NEW `ProbeFillContext` / `ScopedProbeFillContext` are declared in passA's existing budgeted Generator.hpp and implemented in Generator.cpp with opt-in `extern thread_local` state. PassB's Fill.cpp includes Lightning/Generator.hpp under the recorder build guard; FillLightning.cpp uses its existing Generator.hpp include (extend only this named file if the guard requires it). In Fill.cpp, each dispatch installs fresh object/layer/caller-region/config-hash/dispatch-token, full final source contributors and manifest variant-crosswalk context immediately around the fill call; scope destruction restores prior context on normal/cancel/error exits. Same-thread callee observer verifies context/polygon/dispatch identity and records clipping. No changed virtual signature/FillParams field or extra header; ordinals are dispatch handles, never original surface identity.

Canonical caller code has no PnP paint-variant label. Recorder scene construction supplies a NET-NEW immutable scene volume/modifier→canonical object/region/config mapping and ordered typed PnP paint chains, checked against actual grouped contributions and resolved configuration hashes. Store this crosswalk and complete grouped-source sets in the three fixture files; never pretend an existing RegionKey/variant getter exists. Ambiguous crosswalk/grouped surface provenance prevents a verified oracle. Faithful clipping and wrong-domain direct replay use the **same saved caller-context/final-expolygon sequence**, so neither grouping nor bridge mutation is rerun for the control.

Record raw object slice outlines and shell/bridge classification inputs separately from wall-inset fill surfaces. Each input geometry has `origin_phase` and `available_before_layer` metadata in the fixture manifest. A must reject any candidate input populated from the recorded final-fill/planning expectation, or any future Layer-produced wall inset masquerading as a PrePass field. The recorder may inspect both phases, but the candidate receives only the audited earlier geometry/configuration. A mismatch caused by unavailable inset fidelity is an explicit failed strategy, not permission to substitute canonical expected polygons as its input.

The expected relationship is specified before recording tolerances: temporary anchors can remove sparse planning area/alter grounding while final-fill surfaces are restored; final clipping constrains emission but does not prove the same plan. The negative `final_domain_only` strategy drops temporary edits and uses restored final-fill areas. It must have positive polygon symmetric-difference area and a differing **pre-clip** root/connectivity/grounding predicate on `anchor_bridge`. A domain difference alone, or a visual difference alone, is insufficient. If the generated model does not exercise the discriminator, change the recorder fixture scene within Step2's file cap and record again; never invent a positive expected value. An unresolved discriminator makes A inconclusive.

Record the negative control independently too, with **mutation-free direct planner replay**, not a second call through `PrintObject::bridge_over_infill`. No existing replay API is claimed. NET-NEW C++ `run_lightning_planner_fixture(const LightningPlannerSnapshot&, FixtureDomainSelector) -> LightningPlannerFixtureResult` and a snapshot-taking `Generator` overload are introduced only in `tools/lightning_gate/canonical-recorder.patch`, applied to the disposable canonical build. `FixtureDomainSelector` has `faithful_planning`/`final_domain_only`; `LightningPlannerSnapshot` owns immutable ordered layer domains, complete boundary/source/operation tables, final expolygons/caller contexts, identity/config/scalar/seed-policy copies; the result contains full node/edge/root-witness/provenance records and sampled/clipped lines. They factor current input extraction from `Generator::Generator`, `generateInitialInternalOverhangs` and `generateTrees` so real production and fixture entry points share planning code, not a mirrored test planner. Attribute modified C++ functions and translated Rust files. External passA touches exactly Generator.cpp/Generator.hpp/PrintObject.cpp; passB exactly Lightning/Layer.cpp, Fill/Fill.cpp and Fill/FillLightning.cpp. PassA declares all shared probe DTOs/context in its named header; passB needs no fourth-file re-edit. Neither pass mutates the user's read-only canonical checkout; all instrumentation is opt-in on the disposable clone.

The faithful source slice captures immutable deep copies at the `prepare_lightning_infill_data` seam after temporary anchor edits and before restoration: ordered object-layer internal/void polygons, complete region identities/order, first-region resolved scalars, max nozzle/object width/height, computed distances, final expolygons and source provenance. Subsequent faithful clipping records supply final domains without altering the saved planning snapshot. `run_lightning_planner_fixture` creates fresh graph/distance-field/cache state, takes const snapshots plus a no-op cancellation callback, and cannot access or mutate PrintObject. First prove faithful snapshot replay matches the independently recorded production graph; only then run `final_domain_only`, replacing the domain array alone with the saved final expolygons. No expansion/reclassification/restoration is re-executed. Run both selectors with independent fresh state and hash each immutable snapshot/config before and after both calls; compare hashes for accidental mutation. Cache outputs cannot be reused between selectors.

Canonical planning has no external seed: `Node::convertToPolylines` (`src/libslic3r/Fill/Lightning/TreeNode.cpp`) seeds its generator from `PointHash{}(m_p)`. Both replays use that same seed **policy** with fresh per-root streams; a changed root caused by domain substitution legitimately changes its derived stream. `Generator::Generator` (`src/libslic3r/Fill/Lightning/Generator.cpp`)'s time-based diagnostic SVG naming is excluded from semantic records. Persist `seed_policy = root_point_hash`, algorithm/build identity and any explicit external random state (required absent here); do not force identical derived root seeds when roots differ. Apply the same faithful final expolygons, normalization and canonical `intersection_pl` clipping operation in `Filler::_fill_surface_single` (`src/libslic3r/Fill/FillLightning.cpp`) to both resulting sampled outputs. Domain mismatch and nonempty preclip graph/root-grounding disagreement must exist independently of sampling randomness; otherwise the control is inconclusive. Wrong-selector records are explicitly labeled, never substituted for faithful expected data.

Grounding provenance comes from a NET-NEW fixture-only observer of `Layer::getBestGroundingLocation` and `Layer::attach` (`src/libslic3r/Fill/Lightning/Layer.cpp`): record the selected boundary point/winning edge or selected anchor node alongside the existing comparison, without altering selection. Existing return values do not already expose a contour/segment identity. The observer binds the winning boundary edge to the immutable normalized snapshot; a boundary introduced by temporary bridge geometry is labeled TemporaryAnchor, otherwise Boundary. A selected tree-node anchor appears as the actual parent→child connection to that node, not a fabricated root-boundary witness or a conflation with temporary solid anchors. Capture final root/parent topology after pruning/reconnection; record absent grounding only when the canonical graph actually has it. Failure to identify an unambiguous winning boundary witness is inconclusive, not nearest-edge guesswork used as canonical truth.

Selected candidate `build_planning_domain`: accept only `GateASourceInput`, the restricted earlier-source DTO below, and derive its own domains, contributor lineage, fill policies and constructor scalars. No canonical planning layers, final-fill records, resolved policy references or expected graph/grounding can reach this API—even as unused fields. Do not consume final sparse_infill_area as if available before perimeters. Missing earlier source/configuration evidence is fail/inconclusive, not permission to fall back to the broad B input or oracle. A's output is compared only after construction returns; no comparison callback or reference loader is passed to construction.

Required shell/solid-angle input derivation is explicit, not a presumed guest field. NET-NEW `FillPolicyInput` in isolated model.rs stores `infill_direction_deg: f64`, `sparse_rotate_template: String`, `solid_infill_direction_deg: f64`, `solid_rotate_template: String`, `top_layer_direction_deg: f64`, `bottom_layer_direction_deg: f64`, `align_to_model: bool`, `model_alignment_offset_rad: f64`, `resolved_sparse_angle_rad: f64`, `resolved_solid_angle_rad: f64`, `resolved_top_angle_rad: Option<f64>`, `resolved_bottom_angle_rad: Option<f64>`, `is_bridge: bool`, `bridge_angle_rad: Option<f64>`. Raw fields come from independently recorded earlier effective configuration/object transform and layer schedule; resolved fields come from recording the actual branch/template selection in `group_fills`/`Layer::make_fills` (Fill.cpp), with explicit units/selected template entry in manifest. `group_fills` consumes `infill_direction`/`sparse_infill_rotate_template`, solid `solid_infill_direction`/`solid_infill_rotate_template`, top/bottom overrides `top_layer_direction`/`bottom_layer_direction` and `align_infill_direction_to_model`; `params.bridge_angle` copies `surface.bridge_angle`. Lightning's `_fill_surface_single` does not consume `direction` or that bridge angle, so do not claim otherwise. These policies protect shell/solid/bridge source classification/attribution; generator scalars remain separately first-region sourced.

A derives resolved policy/fixed direction from restricted raw config, earlier geometry/classification and transform/schedule, then returns it in GateAConstruction. A separate comparator checks against canonical resolved-policy references; those references are not input to either the source extractor or builder. EarlierSurface has no solid_angle oracle field; solid/top/bottom angles are computed from raw policy and classification. A detected bridge angle is permitted only as an independently recorded EarlierClassification measurement with audited pre-Layer provenance, never copied from a later fill observer. Missing shell geometry, raw template, applicable earlier bridge measurement, unit evidence or transform is RequiredSourceInputUnavailable (inconclusive); measured policy mismatch is RequiredSourceInputMismatch (fail). No zero/default or presumed host/guest accessor repairs missing data; future source exposure remains a migration requirement and no draft03–06 contract is consumed.

FillPolicyInput also requires `fixed_angle: bool`, independently recorded from `surface_fill.params.fixed_angle` → `f->fixed_angle` in Layer::make_fills (Fill.cpp); `Fill::fixed_angle` is bool in `src/libslic3r/Fill/FillBase.hpp`, separate from the numeric params.angle → f->angle assignment. Record/derive this fixed-absolute-direction policy along with the numeric selected angle, not as an inferred or default boolean. FillBase.hpp is delegated read-only type authority, not a seventh instrumented file.

### Fixture identity and discriminating coverage

NET-NEW `crates/slicer-wasm-host/tests/fixtures/lightning_gate/{inputs.json,canonical.json,manifest.json}` remain the three portable files. inputs.json has strict `GateInputsFile { schema_version: u32, cases: Vec<GateInputCase> }`, where each `GateInputCase { case_id: String, wall_strategy: WallStrategy, a_source: GateASourceInput, b_input: Option<KernelInput> }` separates source-only A bytes from optional independently recorded B domains/scalars/final clipping inputs. WallStrategy is the closed Classic/Arachne enum. canonical.json separately has `GateOracleFile { schema_version: u32, cases: Vec<GateOracleCase> }`, with `GateOracleCase { case_id: String, wall_strategy: WallStrategy, reference: GateReference }`; GateReference contains independently recorded planning layers, resolved policy/constructor scalars, caller/final-fill checkpoints, complete graph/grounding/sampled/clipped expectations and faithful/wrong-domain replay records. No expected graph/output data enters b_input, and **no** reference fields enter a_source. Missing b_input/reference is allowed only for A isolation execution, not normal complete gate acceptance.

`extract_gate_a_source(source_bytes: &[u8]) -> Result<GateASourceInput, KernelError>` is NET-NEW host support in `crates/slicer-wasm-host/tests/integration/lightning_gate_support.rs`: given only the isolated serialized a_source subtree, strictly deserialize/validate it without oracle/manifest/B handles. The fixture loader selects the `a_source` subtree by this exact key and serializes it unchanged before the extractor call; it never merges fields from b_input/reference. For the poison control, select a_source from a cloned outer JSON envelope while other branches are opaque arbitrary JSON, allowing invalid/missing reference/B branches without parsing them before A extraction. Normal B/oracle validation occurs later through separate loaders; source-only fixture execution has no reference dependency. Record separate `a_source_sha256`, `a_raw_config_sha256`, `a_earlier_provenance_sha256`, `b_input_sha256` and `reference_sha256` in manifest/evidence (missing optional branches have explicit absent identities). A's raw config/provenance hashes derive exclusively from A's typed source fields, never from the full envelope/manifest/reference digest. The recorder independently populates source/reference provenance; normal acceptance validates both after A construction. Small explicit fixtures only; oversized captures require separately scoped partition steps, not a new implicit fixture file.

The host's test-only in-memory `GateFixtureView` assembles exactly `{ case_id, wall_strategy, a_source, b_input?, reference? }` from the matching raw input/oracle case objects without parsing either non-source branch. No fourth fixture file is created. `project_gate_a(view: &serde_json::Value) -> Result<GateASourceInput, KernelError>` in the same support file selects/serializes only the required `a_source` key and calls extract_gate_a_source; this is the real A driver entry used for ordinary and poison runs. Absence/invalid values in b_input/reference cannot prevent projection/construction. Normal whole-fixture validators subsequently reject incomplete/tampered required evidence without changing the previously computed A result. Whitelist/schema checks apply recursively to the a_source subtree; broad opaque values exist only outside the candidate's typed input and never cross its API boundary.

Use canonical serialized a_source-subtree bytes (not a hash of the surrounding case/file) for a_source_sha256. Compute a_raw_config_sha256 from only typed object_config plus full-identity-keyed raw region configs, and a_earlier_provenance_sha256 from only typed earlier-origin/occurrence associations; normalizations are deterministic and recorded in the manifest. Reference poisoning changes only reference_sha256, and B poisoning only b_input_sha256. These source hashes are audit identities, not lookup handles to reference data; construction has no hash-indexed oracle access. The dynamic test compares the actual projected source bytes/fields and complete output, in addition to these independently scoped hashes.

- Case IDs: `anchor_bridge`, `pooled_regions`, `hole_void`, `island_split_merge`, `paint_modifier_config`. Each records Classic and Arachne wall generation (serialized canonical spelling is read from the source config at recording, never assumed from PnP).

If the chosen case has unchanged tree output, add a discriminating recorded angle/width companion and fail coverage until the expected relation is independently established.

Canonical production scalar policy is **first canonical object region**, as read from `Generator::Generator`, not per-region reconciliation. Record `canonical_region_order`, `scalar_source_region`, nozzle and resolved extrusion width, multiline, density normalization, layer height and all three angles per object. Full region effective config remains separately keyed; do not reproduce last-variant-wins delivery. A supported mixed-config policy is the canonical policy plus explicit attribution, not a claim that every region has an independent tree generator.

### Gate B: same owned kernel, real current adapters

NET-NEW standalone library crate `lightning-feasibility-kernel` is owned under `modules/core-modules/lightning-infill/feasibility-kernel/`; its empty `[workspace]` sentinel and rlib-only library keep it outside production linking and guest discovery. It owns `src/{lib,model,domain,polygon,distance_field,tree,planner}.rs`. Future translation preserves canonical algorithms rather than blindly relocating the current host adapter. Dependencies are `slicer-ir`, serde/serde_json and direct portable polygon math (`clipper2-rust` resolved from the real root dependency declaration); no `slicer-runtime`, host driver, gated Lightning module, `rayon` or `boostvoronoi`. Source-level absence is a guard, not the proof; actual wasm32 execution is required.

NET-NEW `crates/slicer-wasm-host/test-guests/lightning-portability-guest/{Cargo.toml,src/lib.rs}` uses current `#[slicer_module] impl LayerModule for LightningPortabilityGuest`, implementing the existing `run_infill` signature. It declares `cdylib` and `rlib`, `wit-bindgen`, direct `serde_json` decoding, SDK/IR/schema path dependencies and the owned kernel path dependency; use an isolated workspace sentinel. Its generated `__slicer_native_entry() -> NativeStageEntry` is the native adapter for exactly the same body. New host dev-dependencies enable native guest/kernel linking, SDK `test` fixture bases, serde/serde_json fixture/evidence decoding and SHA-256 validation via `sha2`; resolve/pin dependency versions at implementation rather than inventing an existing host re-export.

The test-only config strings `probe_input_json` and `probe_output` (`planned` or `clipped`) transport input-only `KernelInput` and output mode through current config resources (`ConfigViewData.fields` uses `ConfigValueStorage::Str(String)`). `ConfigView::get_string` reads them. Each fresh adapter call decodes those bytes and executes the same `plan_lightning`. `planned` emits lossless tagged graph records described below, not a mere unlabelled edge list. `clipped` calls `clip_lightning` with independently recorded final domains and emits actual sampled/clipped segment paths. Both use existing `InfillOutputBuilder` path operations and full origin tagging; neither is production preparation or visual-debug integration. Expected/provenance files never enter the guest or adapter inputs.

### Test-only directed-graph transport and independent reconstruction

Use only current `ExtrusionPath3D.points` and each `Point3WithWidth`'s x/y/z/width/flow_factor fields. Never use `dist_to_top_mm` (the generated SDK WIT drain resets it), tool index or an invented output field for metadata. Every planned record is one six-point SparseInfill path with finite coordinates, all point Z values equal to the actual layer Z, width from the positive fixture width, flow_factor1 and speed_factor1. No implicit XY geometry claim attaches to metadata points. Compact positive node/edge IDs and all metadata integers must be exactly representable in f32 (`< 1 << 24`); zero encodes absent parent/witness fields. Grounded surface/ring/segment IDs are one-based; region dictionary indices are zero-based. Reject overflow/nonintegral values instead of narrowing. Geometric XY alone passes through mm/unit conversion with the pre-recorded transport budget.

Define three record tags, with ordered point `(x,y)` pairs:

- Node, tag1: `[(1,node_id), (point_x_mm,point_y_mm), (parent_id_or_0,root_id), (ground_kind,origin_region_index), (surface_id,ring_id), (segment_id,0)]`. Every node is emitted, including isolated roots and coincident-but-distinct nodes. Nonroot witness slots are zero. Ground kinds are0 ungrounded/no witness,1 planning boundary,2 temporary anchor; grounded roots identify normalized source surface/ring/segment and use the root point as grounding position.
- Edge, tag2: `[(2,edge_id), (parent_id,child_id), (parent_x_mm,parent_y_mm), (child_x_mm,child_y_mm), (root_id,origin_region_index), (0,0)]`. Every directed parent→child edge occurrence is emitted independently; repeated geometry is not deduplicated.
- Provenance, tag3: `[(3,chunk_index), (byte_len,chunk_count), (b0,b1), (b2,b3), (b4,b5), (b6,b7)]`. Serialize the entire layer's `GraphProvenance` DTO as canonical UTF-8 JSON; split into eight-byte chunks, zero-pad only the last chunk, and use zero-based contiguous chunk indices. Byte values are exact integers0–255; byte_len/chunk_count obey the same exact-f32 bound. These are six-point metadata paths with normal layer Z/width/flow, not geometric lines. Each chunk has an explicit origin equal to the first canonical pooled source region, solely a transport envelope; contributor identities are in the payload and never replaced by that envelope. Emit exactly one complete DTO per object/layer including empty boundary collections where canonical requires them. Reject missing/extra/duplicate/reordered indices, inconsistent lengths/counts, nonzero padding, invalid UTF-8, unknown JSON fields, omitted required fields or multiple DTOs. The decoder parses into the typed records below, checks geometry/operation/source references and complete canonical correspondence, not just the bytes or an echoed hash. This adds no WIT field, SDK API or fourth codec file.

`origin_region_index` resolves through input `canonical_region_order` to the complete `RegionIdentity`. Before **every** path, SDK `begin_region` installs its explicit Some origin. Generated `__slicer_drain_infill` sends those Some values via `set_current_origin`; the current boundary has no clear-origin call, so a None path following Some can inherit stale origin. The probe forbids all None origins. SDK drain also degrades `PaintValue::Custom` to ToolIndex0; reject Custom probe inputs before dispatch and record them as unsupported, without changing SDK. Use actual WIT-supported variants for the required material fixtures. The driver validates every returned object/u64 region/ordered chain against its dictionary and encoded index, never current-region fallback. Each request is explicitly scoped to one object/layer, while planning pools all its regions. `clipped` records have exactly two actual geometric points and the full final-fill origin; compare oriented segment **multisets**, not sets or containment alone.

Exact current drains: native `NativeLayerResponse.infill.as_ref()` exposes `InfillOutputBuilder::sparse_paths()` and `sparse_path_origins()` (optional `RegionOrigin` with object/region/variant chain); raw `HostExecutionContext::infill_output()` exposes `sparse_paths` and `sparse_path_origins` (optional `OriginId`). Assert equal path/origin vector lengths **before** zip so extra outputs cannot be silently truncated; require every origin Some and normalize only lossless supported variants. Both drains preserve x/y/z/width/flow. Inspect actual outputs, not a hand-built graph passed to the comparator. The raw driver checks both trap/result layers, all collected records and origin cardinality, because generated drain calls may ignore builder errors; missing/corrupt output must fail independently even if a call returns Ok.

Decoder reconstructs distinct nodes keyed by `(object_id,global_layer_index,node_id)` and edge occurrences by their own edge IDs. Reject duplicate IDs, unknown tags/origins, missing endpoint/parent/root nodes, inconsistent endpoint coordinates, mismatched root IDs or witness slots, cycles and disconnected nodes that cannot reach their recorded root. Roots are exactly nodes with absent parent and `root_id == node_id`; preserve isolated roots and ungrounded roots if canonical records them. Reconstruct parent incidence and edge multiplicity without welding coincident points. Native builder drain and raw host output both feed this same decoder; compare each decoded result independently to canonical.json, not to each other.

Canonical pooled nodes do not already have production region-origin fields. Recorder/probe origin tags are explicit NET-NEW attribution metadata: resolve the root's observed boundary address through `PlanningLayer.boundary_provenance`, then assign it to the earliest contributing region in `canonical_region_order`; an ungrounded root uses the first contributing pooled region. Descendants/edge occurrences inherit the root tag without splitting pooled planning. Keep the **complete** contributor multiset and source checkpoints in the tag3 DTO even when one region wins that transport-origin tie. Source identity must first resolve independently; ordering cannot repair an unidentified/ambiguous source. Final clipped origins come from the caller's explicit final surface/region crosswalk, not inherited root tags or polygon-vector positions.

The canonical comparator establishes a full node bijection preserving point coordinates within the locked conversion budget, origin identity, parent/root relations and root ground-kind/source-boundary witness. Local integer IDs may be bijectively relabeled, but distinct nodes/root identities may not be merged. Under that bijection, require equality of complete directed edge-occurrence multisets, all isolated nodes/roots, and all grounding labels; missing/extra nodes/edges/roots and changed multiplicities are errors. Check boundary/anchor witness point membership against independently recorded domains. Clipped comparisons similarly require full missing/extra segment equality per full region identity, plus containment; a containment-only assertion is insufficient. Independent canonical node/edge/root populations must be nonempty on discriminating cases. Negative controls remove/add records, reverse an edge, duplicate an occurrence, disconnect a parent or corrupt a root witness—including the same corruption on both adapters—so each claimed predicate can fail.

Complete normalized boundary comparison is additionally mandatory: construct a bijection of boundary addresses by domain kind, normalized surface/ring geometry and directed atomic segment endpoints, preserving holes and temporary-anchor classifications. Compare every source reference, checkpoint, direct-overlap interval or generated-operation lineage and contributor multiplicity under that correspondence, including boundaries never used by a root. Resolve node witness addresses against the **returned** tag3 table, not just the input table, and verify its complete correspondence with independent canonical records.
