# Packet Contract: 207-paint-segmentation-per-region-shell-config

## Goal

Replace `execute_paint_segmentation`'s `match region_map.configs.first()` shell-parameter block (`crates/slicer-core/src/algos/paint_segmentation/mod.rs`) with **per-`variant_chain`** resolution through `RegionMapIR::config_for`, by re-keying `painted_subsets` on `(object_id, semantic_name, value)` and resolving each subset against the `RegionKey` whose `object_id` matches and whose `variant_chain == vec![(semantic_name, value)]` — the same `chain_key` the function already builds in its Phase 6/7 loop — so each `propagate_top_bottom` call carries that painted chain's own `top_shell_layers` / `bottom_shell_layers` / line width / layer height including any `paint_config:<semantic>:<key>` overlay, and build that call's `RoleWidthContext` from the resolved config instead of a hardcoded nozzle diameter and a zero `outer_wall_line_width`.

## Scope Boundaries

This packet owns the shell-parameter resolution site inside `execute_paint_segmentation` and the `painted_subsets` key that makes per-`(object, chain)` resolution possible; the `propagate_top_bottom` call moves from one whole-stack invocation per `(semantic, value)` to one per `(object, semantic, value)`. Granularity is **per painted `variant_chain`, per object** — the finest granularity `RegionMapIR` actually expresses for this data, because `execute_region_mapping_inner` (`crates/slicer-core/src/algos/region_mapping.rs`) writes one `entries` row per `(layer, object, region, chain)`, keyed by a `RegionKey` carrying that `variant_chain`, after applying the chain's paint overlay via `overlay_resolved`. The distinction lives in `entries`, **not** in the `configs` pool: `intern_config` is a linear-scan dedup on `ResolvedConfig`'s `PartialEq`, so chains that resolve to equal configs share one `ConfigId`. That is precisely why the resolver must key on `RegionKey.variant_chain` and read through `config_for`. It does not change `propagate_top_bottom`'s internal shell math (`shell_step`, the `0.5 * width` opening radius), does not touch packet 128's per-object shell-index propagation block or its `assert_per_object_shell_index_invariant`, and does not touch the seam-annotation writer packet 206 adds to the same function.
