# Packet Contract: 306-interlocking-beams-slice-postprocess

## Goal

Make all six `interlocking_*` queue keys drive a real beam-interlocking structure at parity with canonical `InterlockingGenerator::generate_interlocking_structure` (`Feature/Interlocking/InterlockingGenerator.cpp`) and its supporting `VoxelUtils` grid walk, split along the seam the algorithm already has: a host **analysis** prepass `host:interlocking_lattice` on a new host-only stage `PrePass::InterlockingLattice` voxelises the shells of each pair of differently-toned regions across all layers and commits the surviving cell set as a new `InterlockingLatticeIR`, and a new guest module **`interlocking-beams` on `Layer::SlicePostProcess`** stamps the beam microstructure into its own layer and returns the rewritten outlines as `polygon_updates`.

## Scope Boundaries

This packet carries **six** queue keys, not three: the P89 trio (`interlocking_beam`, `interlocking_beam_layer_count`, `interlocking_beam_width`) plus the P90 trio (`interlocking_depth`, `interlocking_orientation`, `interlocking_boundary_avoidance`), because canonical's enabling gate reads four of the six in one condition and `interlocking_depth` — a P90 key — is one of them. Wayfinder ticket 97 is dissolved into this packet on the ticket-31 (P24) precedent. **Ticket 04's owner — `new interlocking module` — is held, not corrected**: the microstructure and the outline rewrite live in a guest module on `Layer::SlicePostProcess`, which becomes that stage's first production occupant and answers the question ticket 148 asks about what the seam is for. Only the voxel **analysis** is host-side, because the shell walk XORs each layer against the one below and so cannot be expressed per layer; that is the same global-prepass-IR-consumed-by-a-per-layer-module shape `LightningTreeIR` and `lightning-infill` already use. One of the six keys, `interlocking_beam`, is **partially live in this tree under a PnP-invented name** — `mmu_segmented_region_interlocking_beam` (`crates/slicer-ir/src/resolved_config.rs`), a spelling canonical does not have — so the packet renames it and preserves its existing Phase-5 suppression read site. Rule 4 fires *for* this design, not against it: the beam pattern is the swappable part, so it lives in the module where a community fork can replace it, rather than being frozen in host code. Canonical's `min` / `max` on five of the six are GUI hints and this packet adopts none of them (ticket 113). Queue count unchanged at 409.
