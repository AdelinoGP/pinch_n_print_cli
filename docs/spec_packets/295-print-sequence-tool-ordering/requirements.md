## Problem Statement

Canonical `ToolOrdering` lets a profile fix the per-layer tool visitation order: one list for the first layer, one list plus a repeat count for later layers. This port has no such input — per-layer tool order is whatever the emission stage happens to walk — so Orca profiles carrying these keys lose their ordering intent silently on ingest (unknown keys fall into `extensions`). The three keys are one coherent slice (same canonical file, same ordering subject, same host seam) and fit one Tier B packet under the 12-key ceiling.

## In Scope

- `first_layer_print_sequence` (canonical `coInts`, default `{0}`): scalar-global ordered tool-index list; stable-sorts layer-0's tools by sequence position; ignored when shorter than the layer's distinct tool set (ported ignore-condition, defaults inert).
- `other_layers_print_sequence` (canonical `coInts`, default `{0}`): scalar-global ordered tool-index list for post-first layers; ignored when empty.
- `other_layers_print_sequence_nums` (canonical `coInt`, default `0`): repeat-cycle count; `0` disables the other-layer override (defaults inert); `N > 0` covers the first `N` full cycles of `len(seq)` layers after layer 0.
- Three scalar-global `ResolvedConfig` fields (two `Vec<f64>` float-lists with round-to-index + non-negative validation, one scalar count), host-only omitted from the CONFIG_BLOCK (packet-287/288 precedent; canonical spelling rides ticket 132; no padding-table edit).
- Sequence-driven stable re-sort in the host emitter (`crates/slicer-gcode`), applied after `apply_cross_layer_tool_rotation` so explicit user order is authoritative over the port-internal rotation; pure reorder, geometry untouched; locked-tagged entities (`entity.path.order_lock.is_some()`) pinned at authored positions (ADR-0062 conformance).
- DEV-187 row with (a)+(b)+(c)+(d) clauses; 04 owner correction (`tool-ordering` → `crates/slicer-gcode` emission stage); 05 P66 annotation (3 in at 295).

## Out of Scope

- Per-object first-layer area ordering (`generate_first_layer_tool_order`'s contour-area base) — named non-borrow, DEV-187(c); the base order is the existing emission order.
- Grouping-record layer ranges and flush-optimisation override (`get_recommended_filament_maps` / `reorder_extruders_for_minimum_flush_volume` record machinery) — named non-borrow, DEV-187(b); the port has no grouping engine (tickets 136/142/143 subject) and no ordering optimisation to override.
- A per-tool/per-extruder vector model for these keys (ticket 125) — explicitly not this packet's axis: canonical declares plain global lists, verified `coInts`/`coInt`.
- An `int-list` schema/WIT type — deliberately not built; the port reuses `float-list` with rounding (dragon-curve precedent), DEV-187(a).
- CONFIG_BLOCK spelling for the three keys — rides ticket 132; this packet makes no padding-table edit (AC-N1 pins honest absence).
- Sequential printing (`print_sequence == ByObject`, ticket 124) — different key, different feature; no interaction (these sequences order tools *within* by-layer emission).
