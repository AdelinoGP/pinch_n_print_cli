# Design: preparation-runtime-lifecycle

## Controlling Code Paths

- Existing `run_slice`/`run_slice_with_collector` (`crates/slicer-runtime/src/run.rs`) load through `load_live_modules_for_plan_manifest_first` (`crates/slicer-wasm-host/src/execution_plan_live.rs`), build the real dispatchers and call the pipeline. Integrated provenance supplies native entries; external same-ID override supplies WASM. No automatic preparation exists today.
- Existing `run_pipeline_core` (`crates/slicer-runtime/src/pipeline.rs`) currently brackets PrePass, dumps products, promotes global layers, checks cancellation and starts `execute_per_layer_with_committed_anchored_events_instrumented`. Add the preparation closure after **all** final committed prepass products/global-layer promotion and before ending the PrePass bracket or starting any Layer/anchored consumer. Do not use a guessed enum stage or alter `STAGE_ORDER`.
- Public `run_pipeline*` entry points include a separately spelled execution path in `pipeline.rs`; normalize all variants to the same private core, keeping raw config, config expansion authority, output config block, progress/instrumentation choices and support tools intact. No preparation helper may be dead from production or used only by capture.
- Existing `execute_single_layer_inner`, `hydrate_slice_arena`, `prepare_dispatch_region_views` (`crates/slicer-runtime/src/layer_executor.rs`) are the ordinary per-layer consumer path. Arena region preparation is lazy and is **not** whole-print plan preparation.
- Actual selected `Layer::AnchoredEvents` module invocation is in the **ordinary** `execute_single_layer_inner` stage loop (`crates/slicer-runtime/src/layer_executor.rs`) calling `LayerStageRunner::run_stage`. `WasmRuntimeDispatcher::run_stage` / `dispatch_layer_call` (`crates/slicer-wasm-host/src/dispatch.rs`) reach the module's WIT `call_run`; `deconstruct_layer_ctx` yields `LayerStageCommit::AnchoredEvents`. This path can consume a prepared plan once the new forwarding adapter is wired.
- By contrast, `execute_anchored_event_collections_with_mode_and_feedrate` (`crates/slicer-runtime/src/layer_executor.rs`) clones supplied entities and applies synthetic `Anchored::Event` / `host:anchored-events` commits without a module config, dispatcher or prepared-plan read. The combined `execute_per_layer_with_committed_anchored_events_instrumented` path and later `synthesize_anchored_rows` do not prove additional anchored-module dispatch. Preserve those builtin semantics; retain the private print scope until that host closure also finishes. Extensions' `anchored_entities` feed only that unchanged host work, not eligibility for an invented later module call.
- Existing `run_slice_api_tdd::run_slice_against_wedge_returns_nonempty_gcode` (`crates/slicer-runtime/tests/e2e/run_slice_api_tdd.rs`) proves the e2e binary can run a full slice. New lifecycle tests register in `tests/e2e/main.rs`. Runtime default is `report`; neither e2e target nor aggregator is feature-gated. Runtime enables `slicer-core/host-algos` unconditionally. Embedded readiness tests use the existing runtime library target.

## Architecture Constraints

- Lifecycle is a late **PrePass closure**, not another ordinary module stage or barrier. Ordinary `from_config`, instance pool mode, serial-module constraints, arena run-to-completion and existing anchored capability-derived host closure stay authoritative. No synthetic entity commit is converted into module dispatch.
- Avoid widening existing `SliceRunOptions`, `SliceOutcome`, `PipelineConfig`, `PipelineOutput`, `PrepassContext`, `LiveModuleBinding`, `LoadedModule`, `CompiledModuleStatic`, `NativeStageEntry`, `PreparationExportSchema`, IR/config/WIT envelopes or ProgressEvent. New sidecars/private companions and forwarding functions contain this packet's blast radius.
- New `PipelineError::Preparation { module_id: ModuleId, failure: Arc<PreparationFailure> }` preserves failure identity and conveys **required dependency abort**. Existing exhaustive `PipelineError` handling is `fmt::Display` in `crates/slicer-runtime/src/pipeline.rs`; surveyed tests in `tests/integration/pipeline_tdd.rs` have catch-all arms. Add variant and Display together. Cancellation keeps the existing `PipelineError::LayerExecution(LayerExecutionError::Cancelled)` path. Do not repair the documented ordinary nonfatal mapping limitation.
- No existing struct field, config contract, WIT signature or schema-version bump is planned. Adding any would violate the bounded steps: first rederive complete literal sites, version-assertion fallout and cross-boundary SDK/macros/native/WASM/build consumers, split the <=3-edit steps, and reapprove scope. New watched test structs use FRU or justified exhaustive waiver; fixture-only config keys are snake_case. Existing manifest spelling is not mass-renamed.
<!-- snippet: wasm-staleness -->
- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and inspect its exit code: exit 0 means fresh, non-zero means stale (a distinct exit code signals `wasm-tools` is unavailable). Never use `rg -q 'STALE:'` — a `wasm-tools`-missing infrastructure error prints no `STALE:` and would read as fresh. If stale, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.
<!-- snippet: coord-system -->
- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.

## Code Change Surface

Pass it explicitly through new internal forwarding paths rather than global/TLS lifecycle state or fields on existing public structs. Native call-local plan binding remains #03's unwind-safe scoped facade, not a new global owner registry. All net-new public shapes are specified only in `packet.spec.md`.

### Binding capture and eligibility

1. Existing search-root/manifest-first loader decides provenance and version. Parse the selected manifest with #03's `parse_preparation_declaration`; do not search a second capability catalog. Freeze the **same** loaded engine/component or paired native entry. Native prepared registrations cannot override a selected external component or repair a declared-but-missing capability.
2. Carry version and deterministic opaque artifact identity derived from the actual selected artifact in the private companion. Owner sorting compares complete module/version/stage/artifact identities in stable bytewise order, not HashMap order or module basename. Within one print, deduplicate one frozen owner, not `(owner, region)` or `(owner, layer)`.
3. After final prepass and global-layer promotion, build #04 `CommittedPreparationInputs` using existing committed Blackboard Arc products. Missing required input is #04's failure; optional absent versus present-empty remains distinct. Construct each `PreparationSelectionContext` from the frozen module's stage/claims/paint declarations and declared-key-filtered invocation config.
4. For each promoted layer and selected ordinary module stage, including actual `Layer::AnchoredEvents`, call #01 public projection directly on final committed products to decide participation **before owner creation**. Participation is projection `invoke && targets.nonempty`; combine selected targets over the print without merging different variant keys/members/provenance or dropping held roles. Only after an eligible owner exists does #04 `from_committed` create its checked typed input facade using that same projection authority. Non-region targets use the filtered invocation config, never fabricate RegionKey. Committed model/perimeter-source selection is not a prediction of eventual Perimeter/Infill output. At the ordinary boundary reuse #01 on actual available views; prepared no-work calls skip, plain `invoke=true` empty calls remain unchanged. Supplied synthetic anchored entities never add module targets or module preparation owners.
5. Actual `Layer::AnchoredEvents` calls have #01 AnchoredStage context and remain meaningful independently of empty/nonempty output. Their prepared read uses the ordinary selected module dispatcher, not the capability-derived synthetic host collection builder, an event-kind roster, row lowering or guessed later calls. Preserve the print scope through all real module calls and the applicable builtin anchored closure; that outer scope retention does not invent a #03 read guard inside synthetic work.

### Production forwarding driver

NET-NEW private `PreparedLayerStageRunner` / `PrintPreparationScope` have the concrete constructor/trait contract in packet.spec. `run_slice` constructs the wrapper at its real layer dispatcher assembly, supplies it in the existing pipeline runner slot, and existing `execute_single_layer_inner` calls its unchanged `run_stage` trait signature. It delegates plain entries unchanged and selected eligible prepared entries to the host's new `run_prepared_stage`; that same route handles `Layer::AnchoredEvents`. It supplies call guards/fresh resources, not a new stage enumeration. `execute_anchored_event_collections_with_mode_and_feedrate` remains entirely synthetic host work. The separate observer hook wraps entry and return/unwind only, and print-scope cleanup follows host-closure completion as well as module-call joins. No later anchored-module dispatch path is assumed or authored.

### Ready, resources and cleanup

For each eligible owner, create it in a new `PreparedOwnerStore::new()` for that print, call the frozen binding with `PreparationInputData::from_committed`, then verify `current` succeeds. NoWork observations name selected declared owners with zero targets without creating/preparing/calling a plan owner. Publish Ready only after #03's atomic transaction finish; success without Ready is required failure. All participating owners must be Ready before consumers are admitted.

Use fresh #03 adapters per ordinary/anchored call. Call guards own only checked store/owner access and release at return/unwind; immutable owner pieces have cursorless reads. Do not hold a guest Store/instance, a strong payload-owning stale handle, or unfinished LayerArena across calls. Respect existing serialized module pools and finalization constraints; immutable plan access does not make a non-parallel-safe module parallel.

The private print scope joins all scheduled Rayon work and active module calls, and completes/unwinds the applicable synthetic anchored-host closure on success/failure/cancel, then disposes each owner/store. #03 disposal returns `Busy` while actual preparation/read guards are active; the store itself never waits. The runtime caller establishes quiescence at joins/guard completion, then calls disposal without spin/forced revocation. An outer runtime print scope retains the store during synthetic work; it must not claim synthetic work creates a producer read guard or prepared read. In-flight preparation is cooperative: check cancellation before/after each owner and use `prepare_with_publication` with a validation closure checking the flag before atomic publication. If set, record a private `cancelled_at_publication` decision and reject with `PublicationRejected { detail: "preparation cancelled before publication" }`; translate the recorded host decision, not a message match, to Cancelled. Let the active call return and abort staging before consumers. Original module/trap failure takes precedence over writer poison or publication-cancel rejection and retains original fields.

Runtime logical retention is the checked sum of #03 `retained_payload_bytes` and `retained_name_bytes`. Capture snapshots these gauges and `returned_read_bytes` through metadata accessors before disposal, then reports post-cleanup retained zero. `transferred_bytes` is the checked successful production prepared-piece read total (`returned_read_bytes`), excluding requested bytes, puts, typed input/metadata traffic and any allocator overhead. Capture does not open/read/copy opaque pieces, so an isolated preparation-only fixture with no piece reads reports transfer zero even when stored piece length is nonzero. Metadata/typed selected targets remain usable after disposal without owning payloads or plan handles. Module-owned ordinary reads/outputs separately prove semantics. Q17/ADR-0066 permit diagnostics, not an opaque host export/decoder; #06 alone adds opt-in atomic typed diagnostic snapshots. No raw opaque payload in capture/observer/CLI/DAG, and no allocator highwater claim.

### Fixture and observation design

The new SDK fixture mirrors existing `SdkLayerPathoptGuest::run_path_optimization` (`crates/slicer-wasm-host/test-guests/sdk-layer-pathopt-guest/src/lib.rs`): real `LayerModule` signature, `from_config` per call and `GcodeOutputBuilder::push_comment`. Extend it via the #02 preparation macro; read #04 typed selected targets/configs and put `probe`, not controlled `read-fixture`. Its exact `[preparation].input_reads` are `layer_plan`, `slices`, `region_map`, `mesh`, `selected_targets`, `surface_classification_optional`, `seam_plan_optional`, `support_analysis_optional`, `support_geometry_optional`, `support_plan_optional`; `interface = "slicer:layer-preparation/prepare@1.0.0"`, `views = []`. These are #04's existing planned tokens, not invented permission spellings. Fixture-only manifest-declared snake_case string keys `preparation_probe_mode` (default `ready`) and `preparation_probe_token` (default `probe`) select ready-empty, required-decoder, duplicate-put, panic/trap and module-error modes. The independent malformed decoder pin is code **57403**, message **lifecycle fixture malformed payload**; native/component normal markers are different literal comments. No production config schema changes.

e2e fixtures drive actual loading and ordinary adapters through `run_slice_with_runtime_extensions`; ordinary `run_slice` is independently exercised for default activation. External fixture manifests are staged with their actual generated component; fail loudly if any artifact/input is absent. Reuse #02's schema-derived prepared/plain artifact inputs and schema authority, with independent literal expected deliveries, not a local resolver or the same production projection for both sides. Reuse #04's produced `whole-print-input-{path,perimeters,infill,support,anchored}` dual-target fixture artifacts/native libraries for their real stage entry families; add their native dev-dependencies within the existing runtime Cargo step, never alter producer fixtures or route every target-kind case through the PathOptimization entry. Include nonempty controls for model paint/modifier, perimeter members, support/raft and **actual** anchored module calls. A missing-Ready embedded library fixture deliberately supplies an unready owner to the same guard used by the production closure; it cannot stand in for the separate full-driver activation proofs.

The separately owned `preparation-lifecycle-anchored-guest` is necessary because input-observation fixtures are not evidence of ordinary module-owned prepared reads. Its real SDK method is `LayerModule::run_anchored_events(&self, layer_index: u32, regions: &[SliceRegionView], collection: &mut LayerCollectionBuilder, config: &ConfigView) -> Result<(), ModuleError>` (`crates/slicer-sdk/src/traits.rs`). Its preparation puts a four-byte `probe`; its ordinary call uses `PreparedPlanView::require("probe")`, module-owned decoding and `LayerCollectionBuilder::set_anchored_event_collection(OrderedEventCollection) -> Result<(), String>` (`crates/slicer-sdk/src/layer_collection_builder.rs`). Emit a nonempty planar path with independently pinned native X 3→4 mm or WASM X 5→6 mm from that piece; changing the fixture's preparation token changes emitted geometry. Use real `AnchoredEntity`/`OrderedEventCollection` fields from `crates/slicer-ir/src/slice_ir.rs`, existing coordinate conversions and exhaustive production literals. Tests observe actual G-code/committed module output, actual read counters and ordinary dispatch traces. Separately supplied synthetic host entities use different coordinates and create no plan read/call evidence; block their separate trace hook to prove outer print retention until host Finished without inventing a Busy read guard.

Observers receive typed lifecycle records on success and error. They contain module/version/artifact, lifecycle phase separate from ordinary stage, actual optional layer/anchor index, exact status and names/lengths only. The observer's default `on_layer_arena` hook records real executor creation/commit/drop boundaries through a drop guard; failure/cancel without commit still reports Dropped after active calls. This explicitly authored production-used hook supplies the previously absent arena lifetime witness without exporting or retaining arena contents. Duration clocks are used only under existing instrument/report opt-in; no synthetic zero measurement is emitted in noninstrumented records. Static capability/DAG descriptions remain #02's capability metadata and existing `record_edges`, never a claim preparation executed. Do not change ProgressEvent or schema constants. Use monotonic trace order and call/arena event assertions; no wall-clock sleeps, allocator peak assertions or guessed latency thresholds.

## Data and Contract Notes

No WIT/IR/version changes. All new metadata-only public shapes and private forwarding-driver shape belong to packet.spec. Existing struct literal blast radius is empty by design; new types have no prior sites. `PipelineError` Display is in the same edit step as its new variant. The production schema dependency move, both fixture dev-dependencies and guest manifests are explicitly inventoried; no reliance on dev-feature unification. Config keys remain snake_case.

## Locked Assumptions and Invariants

Same selected artifact for preparation/ordinary calls; owner immutable and print-private; all Ready before required consumers; no prepare/call for prepared no-work; plain empty-target semantics unchanged; final committed inputs only; no stage barrier; selected Layer::AnchoredEvents reads differ from synthetic host commits; print scope outlives both paths; caller joins before Busy-free disposal; original ModuleError preserved; decoder stays module-owned; capture is metadata-only with actual production read accounting; #06 alone owns typed diagnostic snapshots; legacy lightning unchanged.

## Risks and Tradeoffs

Factoring existing pipeline variants must preserve raw config/instrumentation differences. Nondefault/non-region ownership can be lost through fill-only keys. Names/lengths/typed selection diagnostics must never expose opaque bytes or let the host infer plan semantics; ordinary module outputs provide that independent proof. Synthetic commits are lifetime controls, never prepared-consumer evidence. Embedded missing-Ready testing is narrower than activation proof. Aggregate M requires bounded step contracts.

## Context Cost Estimate

Aggregate M; largest step M. Highest-risk dispatch: actual consumer/anchored routing and no duplicated eligibility, LOCATIONS <=20 plus independent SUMMARY <=200 words.
