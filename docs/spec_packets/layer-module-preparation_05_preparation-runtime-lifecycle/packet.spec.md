# Packet Contract: preparation-runtime-lifecycle

## Goal

Automatically prepare exactly the eligible frozen module owners from final committed PrePass products, enforce readiness before their ordinary/anchored consumers, and dispose print-private plans after all calls complete.

## Scope Boundaries

Own production activation, deterministic selected-owner capture, whole-print lifetime, failure/cancellation/cleanup, truthful lifecycle observations and a preparation-only runtime capture seam for #06. Preserve plain-module semantics, per-call `from_config`, selected external override precedence, and run-to-completion Layer arenas. No algorithm migration, between-stage barrier, visual-debug schema or general ordinary error-policy repair.

## Prerequisites and Blockers

- **FORWARD-DEP** on generated **draft, NOT IMPLEMENTED** `layer-module-preparation_03_preparation-contract-transport` and `layer-module-preparation_04_whole-print-input-views`; #01 `layer-module-preparation_01_shared-selection-prerequisite` and #02 `layer-module-preparation_02_preparation-capability-pilot` are transitive generated-draft dependencies. Generation preflight of #03/#04 is not an executable capability gate.
- Activation/implementation is blocked until #01–#04 implementation and their executable narrow acceptance gates pass, including #02's native/WASM capability pilot. Every AC below consumes these forward contracts and runs only after that gate; none is claimed passing today.
- Unblocks queue #06 / TASK-575's preparation-only capture integration using the exports below. Queue #08's lightning migration blockers are independent; retain host legacy lightning throughout this packet.

## Net-New Public Runtime Exports for #06

**NET-NEW**, all in `slicer_runtime::preparation_lifecycle` (`crates/slicer-runtime/src/preparation_lifecycle.rs`), root re-exported from `crates/slicer-runtime/src/lib.rs`. They introduce no visual schema or WIT types:

- `SliceRuntimeExtensions` has private fields; `new(integrated: Vec<slicer_scheduler::IntegratedModuleRegistration>, prepared_native: Vec<(ModuleId, slicer_sdk::native::NativePreparedStageEntry, slicer_schema::PreparationExportSchema)>, anchored_entities: Vec<slicer_ir::AnchoredEntity>, observer: Option<Arc<dyn PreparationLifecycleObserver>>) -> Self`; `Default` supplies empty extensions. Registration supplies artifacts, **never Ready plans**. Manifest-first discovery/override precedence still decides whether those artifacts are selected. Native ordinary registration comes from the paired entry's `stage`; external selection always suppresses that native pair.
- `run_slice_with_runtime_extensions(opts: SliceRunOptions, extensions: SliceRuntimeExtensions) -> Result<SliceOutcome, SliceRunError>` and `run_slice_preparation_capture(opts: SliceRunOptions, extensions: SliceRuntimeExtensions) -> Result<PreparationCapture, SliceRunError>`, implemented in `crates/slicer-runtime/src/run.rs`. Ordinary `run_slice` forwards through the same closure with default extensions. Capture runs the same startup validation and final committed prepass/preparation prefix, snapshots only metadata/typed selection, then disposes before any LayerArena, selected Layer module or synthetic anchored-host closure. It never reads/copies opaque pieces or decodes their format; it must not substitute the narrower `prepare_prepass_context` setup.
- `PreparationCapture { owners: Vec<PreparationOwnerCapture>, lifecycle: Vec<PreparationLifecycleRecord>, retained_bytes: u64, transferred_bytes: u64 }`.
- `PreparationOwnerCapture { module_id: ModuleId, module_version: String, artifact_identity: String, consumer_stage: StageId, selected_targets: Vec<slicer_sdk::preparation::PreparationSelectedTarget>, pieces: Vec<PreparationPieceMetadata>, accounting_before_disposal: PreparationAccountingSnapshot }`; `PreparationPieceMetadata { name: String, length: u64 }`; `PreparationAccountingSnapshot { retained_payload_bytes: u64, retained_name_bytes: u64, returned_read_bytes: u64 }`. These are metadata-only snapshots of #03's read-only accounting before disposal. Capture `retained_bytes` is the checked post-cleanup total retained payload/name bytes (zero); `transferred_bytes` is the checked sum of **production** `returned_read_bytes` observed before disposal, not metadata size, requested bytes, stored piece lengths or captured raw copies. Metadata-only capture performs no piece reads, so its isolated no-consumer fixture has transfer total zero despite a nonempty stored piece. #06 alone owns opt-in atomic typed diagnostic snapshots via #03's publication hook; no raw opaque payload is exposed through capture, observer, CLI or DAG.
- `PreparationLifecycleObserver: Send + Sync { fn on_preparation_lifecycle(&self, record: &PreparationLifecycleRecord); fn on_layer_arena(&self, global_layer_index: u32, status: LayerArenaLifecycleStatus) {} fn on_anchored_host_closure(&self, status: AnchoredHostClosureStatus) {} }`. Default hooks observe ownership boundaries without exporting IR/payload. `LayerArenaLifecycleStatus::{Created, Committed, Dropped}` and `AnchoredHostClosureStatus::{Start, Finished}` are runtime trace enums, not visual/IR schemas. Host-closure Finished denotes return/unwind, not success; it is never a prepared module-call/read observation.
- `PreparationLifecyclePhase::{Preparation, Consumption, Disposal}` and `PreparationLifecycleStatus::{Start, Ready, NoWork, Failure, Cancelled, Disposed}`.
- `PreparationLifecycleRecord { module_id: ModuleId, module_version: String, artifact_identity: String, consumer_stage: StageId, global_layer_index: Option<u32>, lifecycle_phase: PreparationLifecyclePhase, status: PreparationLifecycleStatus, pieces: Vec<(String, u64)>, retained_bytes: u64, transferred_bytes: u64, elapsed: Option<std::time::Duration>, failure: Option<Arc<slicer_wasm_host::preparation::PreparationFailure>> }`. Whole-print prepare/dispose has no layer index; actual ordinary/anchored calls carry their real anchor/layer index. `elapsed` is `None` unless existing instrumentation is enabled; failure retains original typed module fields. Records never carry piece bytes. These are typed observer/capture records, **not new ProgressEvent JSONL fields or a schema-version bump**; existing instrumented stage/module brackets remain separate.
- NET-NEW host adapter method, separate crate to avoid a dependency cycle: `slicer_wasm_host::WasmRuntimeDispatcher::run_prepared_stage(&self, stage_id: &StageId, layer: &GlobalLayer, module: &CompiledModuleLive<'_>, input: LayerStageInput<'_>, binding: &FrozenPreparationBinding, owner: &PreparationOwner) -> Result<Option<slicer_ir::LayerStageCommit>, slicer_ir::LayerStageError>` in `crates/slicer-wasm-host/src/dispatch.rs`. It reuses ordinary call marshalling/delivery and #03 fresh native/WASM scopes; it is not another selection resolver. Actual selected `Layer::AnchoredEvents` is an ordinary Layer module invocation and uses this same method. Synthetic `Anchored::Event` / `host:anchored-events` commits never call it or read plans.

### NET-NEW Private Production Forwarding Driver

`slicer_runtime::preparation_lifecycle::PreparedLayerStageRunner` is a private-field runtime companion implementing the existing `slicer_wasm_host::LayerStageRunner`. Its private `new(plain: Box<dyn LayerStageRunner + Send + Sync>, prepared_dispatcher: WasmRuntimeDispatcher, lifecycle: Arc<PrintPreparationScope>) -> Self` takes the ordinary runner, real prepared dispatcher and NET-NEW private print scope. Its `run_stage` retains the existing trait signature, uses #01 selection/all-Ready gates, forwards eligible prepared modules to `run_prepared_stage`, and delegates plain modules unchanged. Forward all runner sampling/audit/log/profile accessors to the dispatcher used by the call; wrapper defaults must not silently erase existing observations. Construct it where `run_slice` creates the real layer dispatcher and pass it as the pipeline's layer runner; the existing `execute_single_layer_inner` ordinary stage loop then reaches it, including selected `Layer::AnchoredEvents`. No new anchored stage/dispatch architecture is introduced. `execute_anchored_event_collections_with_mode_and_feedrate` remains clone/synthetic-commit host work; only print-scope retention and the separate host-closure trace hook surround it.

The future runtime `Cargo.toml` step explicitly moves `slicer-schema = { path = "../slicer-schema" }` from dev-only to `[dependencies]`, retaining fixture libraries in `[dev-dependencies]`. A transitive dependency does not authorize a direct production type path. Grounded production graph: runtime → schema; schema's manifest has no dependencies and therefore no back edge/cycle. This is a planned dependency edit, not a dependency added during generation.
