# Design: 283-printer-timing-emitter

## Controlling Code Paths

- Primary code path: `estimate_command_deltas` (`crates/slicer-gcode/src/estimator.rs`) — the `GCodeCommand::ToolChange { to, .. }` arm (today: `toolchange_count += 1`, zero seconds) — plus `filament_stats_comment_block` (`crates/slicer-gcode/src/m73.rs`) for the cost footer line.
- Neighboring tests/fixtures: `crates/slicer-gcode/tests/estimator.rs` (estimator pins), `crates/slicer-gcode/tests/m73.rs` (M73 + footer precedent), `docs/config/host-keys.toml` `[resolved_config]` shape, `host_keys_doc_lock_tdd` (runtime lock test asserting the TOML mirrors live Rust defaults, with per-key match arms to extend).
- OrcaSlicer comparison: see `requirements.md` §OrcaSlicer Reference Obligations; do not repeat delegation rules.

## Architecture Constraints

- Host-emitter ownership stands (ticket-27 hazard checked): canonical's reads are all `GCodeProcessor` time estimation and `GCode` statistics accumulation — emission/statistics-time, not placeholder publication — so `machine-gcode-emit`'s generic `[key]` sweep is the wrong seam. No manifest declaration (host-only keys; P35 `enable_pressure_advance` precedent omits module manifests).
- `Option<f32> = None` machine-key shape (not the 282 plain-`f32` shape): the adjacent `machine_max_*` fields are `cli_opt @printer` Options omitted from `to_config_map` when unset, which keeps the CONFIG_BLOCK byte-stable at defaults without a padding twin. The `0.0`-vs-`None` distinction buys nothing (canonical default `0.0` is itself identity), so the mirror + lock test pin the *effective* default `0.0` via `unwrap_or(0.0)` arms.
- Ticket-113 conformance: canonical min-0 is a GUI hint (`PrintConfig.cpp` spinner only; `Config.cpp` never enforces). Enforcing it here is a deliberate divergence recorded in DEV-175(c), not parity.
- No `ORCA_CONFIG_PADDING` edit (Authoring rule 2). Unset keys never reach the serializer (omitted from the resolved map); AC-N3 pins honest absence.
- Scalar-global is parity, not divergence: canonical declares all four scalar (`coFloat` × 4), so no vector DEV and no ticket-125 engagement.

## Code Change Surface

- Selected approach: four scalar-global `ResolvedConfig` fields (`machine_load_filament_time` / `machine_unload_filament_time` / `machine_tool_change_time` / `time_cost`: `Option<f32> = None`, `extract_float_or_first` ingest, `unwrap_or(0.0)` at use) + `to_config_map` Option-loop extension + `[resolved_config]` mirror rows + lock-test arms + a per-`ToolChange` seconds charge in `estimate_command_deltas` + a gated `; printer cost` footer line + emitter-side negative rejection + DEV-175 row + `gen-config-docs` regen + one new test file.
- Exact functions, traits, manifests, tests, and fixtures:
  - `crates/slicer-ir/src/resolved_config.rs` — `declare_resolved_config!` invocation (4 new `cli_opt @printer` field lines; overlay arms generated by the macro per ticket-126 — no hand-written composition edit) + `to_config_map` Option-field emission loop (4 new entries).
  - `crates/slicer-gcode/src/estimator.rs` — `estimate_command_deltas` (`ToolChange` arm: add `load + unload + tool_change` seconds into `elapsed_deltas_s[command_index]`) + a small `TimingCosts` view (or direct `ResolvedConfig` reads) threaded from `estimate_print_with_elapsed`'s call chain.
  - `crates/slicer-gcode/src/emit.rs` — validation before estimating (negative timing/cost → stable rejection) + cost value threaded into the footer call.
  - `crates/slicer-gcode/src/m73.rs` — `filament_stats_comment_block` (new optional `; printer cost = {v:.2}` line, present only when `time_cost > 0`).
  - `docs/config/host-keys.toml` — 4 `[resolved_config]` rows (`default = 0.0`, `>= 0` ranges, canonical provenance notes).
  - `crates/slicer-runtime/tests/unit/host_keys_doc_lock_tdd.rs` — 4 new `resolved_num` match arms (`unwrap_or(0.0)`).
  - `docs/DEVIATION_LOG.md` — DEV-175 row (4 clauses below).
  - `docs/15_config_keys_reference.md` — regenerated (no hand edit).
  - `crates/slicer-gcode/tests/printer_timing_stats_tdd.rs` — NEW (auto-discovered; schema + 5 behaviour + 2 negative tests).
- Rejected alternatives and reasons:
  - Plain `f32 = 0.0` (282 shape): rejected — always-emitted fields would add 4 CONFIG_BLOCK lines at defaults with no padding twin to shadow; the adjacent machine keys already prove the `None`-omitted shape.
  - `FeedrateConfig`/`SPEED_KEYS` membership: rejected — these are estimate additions on toolchange events, not base speeds; `read_speed`/`resolve_feedrate` is the wrong home.
  - Module-manifest declaration: rejected — no module reads these keys; `ConfigView::from_declared` whitelisting would make manifest rows dead (ticket-34 shape).
  - Conditional per-change composition (canonical first-change/same-extruder table): rejected — no extruder/nozzle model exists in tree to condition on; recorded in DEV-175(a).
  - Full `; total filament cost` line: rejected — needs Tier D `filament_cost` vectors with no in-tree source; recorded in DEV-175(d).
  - Widening to per-filament vectors now: rejected — canonical is scalar; ticket-125 owns no model here.

Canonical blocks ported (verbatim grounding):

```cpp
extra_time += filament_load_time;
extra_time += tool_change_time;
```

```cpp
total_cost += config.time_cost.getFloat() * (normal_print_time/3600.0);
```

Port mapping: canonical's conditional table (initial selection = load only; same-extruder swap = unload + load; extruder switch = tool-change + conditional load/unload; multi-nozzle overload likewise) collapses to a uniform per-`ToolChange` charge of `load + unload + tool_change` (DEV-175(a)); the printer-cost formula ports verbatim with `total_time_s` as `normal_print_time` (DEV-175(b) covers the label only, not the arithmetic); `filament_cost`-driven lines are not ported (DEV-175(d)).

DEV-175 (single row, four clauses): (a) plain-sum simplification — no extruder/nozzle model to condition on. (b) `; printer cost` label is PnP-invented — canonical prices the hour into the stats-dialog total, which the port lacks; the port's stats surface is the footer block. (c) negative/min enforcement — canonical declares GUI min 0 and never enforces (`Config.cpp` ignores min/max); the port rejects negatives (ticket-113 class). (d) filament-cost total omitted — `filament_cost` is Tier D deferred; printer-hour only.

## Data and Contract Notes

- IR/manifest contracts: none — host-only keys add no Slice IR field, no manifest schema, no `CONFIG_SCHEMA_WIRE_VERSION` bump, no guest rebuild.
- WIT boundary: none — estimator-internal charge + footer text; no WIT accessor, no `SliceRegionView` metadata.
- Determinism/scheduler constraints: pure function of (ToolChange count/positions, 4 config values); no RNG, no ordering effects; all-unset → byte-identical (AC-2).

## Locked Assumptions and Invariants

- Effective defaults locked to canonical (`0.0` × 4 via `None`-omission).
- Every `ToolChange` command charges the full plain sum regardless of `to` vs current tool (no first-change exception — the port's stream has no initial-selection event to exempt).
- Cost line appears iff `time_cost > 0`; value is exactly `time_cost * total_time_s / 3600.0` at two decimals.
- Change is reversible via defaults: all-unset restores HEAD estimate, footer, and CONFIG_BLOCK bytes exactly.

## Risks and Tradeoffs

- `f32` seconds vs canonical `float`: same width; accumulated in `f64` estimator totals like existing segment times; AC-3 asserts exact `10.0` delta on round inputs to prevent precision drift.
- Cost uses post-charge total (toolchange seconds included): matches canonical, where the printer-cost term prices `normal_print_time` inclusive of change times; pin by computing the expected value from the measured total in-test rather than a hardcoded constant.
- DEV-171–174 collision lesson: drafts 276/277/281/282 already propose DEV-171/172/173/174 while only DEV-171 has landed in LOG; this packet takes DEV-175 as first collision-free — implementer must re-derive `max(DEV-*)` over LOG + `docs/spec_packets/*/` before writing the row.
