# Packet Contract: 232-freshness-gate-docs

## Goal

Restate the guest-freshness contract as artifact-verified everywhere it is currently written as mtime-based — `CLAUDE.md`, `docs/03_wit_and_manifest.md`, `docs/05_module_sdk.md`, `docs/07_implementation_status.md`, ADR-0014, ADR-0045, `CONTEXT.md`, the `wasm-staleness` authoring snippet and `.claude/skills/spec-review/SKILL.md` — and make CI actually run the verifier by adding `cargo test -p xtask` to the `test` job with real-artifact tests that fail rather than skip.

## Scope Boundaries

This packet is documentation, one authoring snippet, one skill bullet, one CI workflow edit, and — only where a test would otherwise be vacuously green in CI — a hardening edit to `xtask/src/wit_verify.rs`'s test skip-guards. It changes no freshness logic, no fingerprint content, no closure walk and no exit code; every behaviour it describes is shipped by packets 229, 230 and 231. It edits no other packet directory, explicitly including the six whose acceptance criteria use the grep form of the freshness check (`206`, `207`, `209`, `210a`, `210b`, `211`, `212`), which are left untouched by user ruling of 2026-08-19.

## Prerequisites and Blockers

- Depends on: `docs/spec_packets/230-output-based-guest-freshness` and `docs/spec_packets/231-guest-closure-fingerprint`, both `status: draft` at authoring time — these are **FORWARD-DEPs**, not satisfied dependencies. The prose this packet writes describes their shipped behaviour: from 230, artifact decoding in `--check`, the `EXIT_FRESH` / `EXIT_STALE` / `EXIT_INFRA_ERROR` contract and the `v2-` fingerprint; from 231, the per-guest dependency-closure input set and the deletion of `compute_shared_freshness` and `stage_wit_snapshot`.
- Unblocks: nothing. This is the final packet of the queue in `docs/specs/guest-freshness-artifact-verification-plan.md`.
- Activation blockers: packets 230 and 231 not yet `status: implemented`. Writing this prose before they land would document behaviour that does not exist.
