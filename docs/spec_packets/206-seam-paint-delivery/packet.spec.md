# Packet Contract: 206-seam-paint-delivery

## Goal

Deliver seam paint to the seam placer end-to-end: add a seam-annotation writer module (`crates/slicer-core/src/algos/paint_segmentation/seam_annotations.rs`) wired into `execute_paint_segmentation` so `SlicedRegion.segment_annotations` carries `PaintSemantic::Custom("seam_enforcer")` / `Custom("seam_blocker")` on every return path including the seam-only short-circuit (DEV-123 open half), replace `paint_marker`'s substring test in `paint_annotation_type` (`modules/core-modules/seam-planner-default/src/visibility.rs`) with exact seam-semantic matching so support paint stops reading as seam intent (DEV-133), and promote `seam_paint_boxes` into `slicer_core::perimeter_utils` so `modules/core-modules/arachne-perimeters/src/lib.rs` gains the `apply_seam_paint_bias` call it lacks (DEV-134).

## Scope Boundaries

This packet owns the seam-paint **delivery** path only: the new writer module `crates/slicer-core/src/algos/paint_segmentation/seam_annotations.rs` and its call sites in `execute_paint_segmentation`, the `seam_paint_boxes`/`seam_paint_box` promotion into `crates/slicer-core/src/perimeter_utils.rs` with both perimeter generators rewired onto it, and the `paint_annotation_type` discriminator in `seam-planner-default`. The encoding change forces one existing test to be re-expressed against the production encoding: `paint_annotations_set_point_type` (`modules/core-modules/seam-planner-default/tests/seam_canonical_visibility_tdd.rs`) currently encodes seam intent as `PaintSemantic::Custom("seam")` + `PaintValue::Custom("enforced"/"blocked")`, which exact matching no longer classifies; it is rewritten to the two production semantic keys with `PaintValue::Flag(true)`, keeping **all six** of its assertions — four `point_type` equality checks (`layer[0]` → `Enforced`, `layer[1]` → `Enforced`, `layer[2]` → `Blocked`, `layer[3]` → `Neutral`) and two `central_enforcer` checks (`assert!(layer[0].central_enforcer)`, `assert!(!layer[1].central_enforcer)`). Dropping either `central_enforcer` assertion is a weakening, not a re-expression. It does **not** re-specify the DEV-123 region-split filter (`is_seam_paint_semantic` already landed and stays untouched), does not change any IR field, WIT record, or schema version, and does not touch shell-parameter resolution in `execute_paint_segmentation` (that is packet 207 / DEV-122).

## Prerequisites and Blockers

- Depends on: nothing. The DEV-123 region-split filter (`is_seam_paint_semantic`) and packet 108's reader (`apply_seam_paint_bias`) are already in the tree.
- Unblocks: packet 207 (`207-paint-segmentation-per-region-shell-config`) edits the same function, `execute_paint_segmentation`, and must rebase onto this packet's landed writer call.
- Activation blockers: none.
