# Packet Contract: 210a-support-planner-coord-t

> **SUPERSEDED 2026-08-12 by the support-families and anchored-entities sequence** (`docs/specs/support-families-anchored-entities-plan.md`). The single `support-planner` is split and renamed into `tree-support-planner` (packet 221), which rewrites the planner with distributed contacts and radius-aware collision; DEV-128's scaled-integer geometry work is absorbed there only where it remains valid inside the new tree family, and the structural `SupportPlanIR` migration (packet 220) supersedes the branch-path schema this packet's emission boundary assumed. Directory retained intact for provenance; do not implement as-is.

## Goal

Migrate `support-planner`'s branch-node geometry from `f32` millimetres to scaled-integer `i64` internal units (DEV-128): `PlannedSupportNode` position, the Prim MST edge weights, the move-pass step cap, the avoidance clamp, the exact polygon-membership test, and the 100-iteration Laplacian smoother — converting to `f32` mm only at the `Point3WithWidth` emission boundary. As part of the one and only rewrite of `smooth_branches`, extract its inlined sub-chain gap walk into `split_column_into_chains` so that packet `210b`'s bottom-interface pass consumes a chain definition that already exists rather than re-deriving one.

**Why the extraction lives here.** `smooth_branches` is the seam where the 2026-08-07 merge of packets 210 and 211 was originally motivated: half A retypes the gap walk to an integer squared-unit comparison, half B needs the same walk as a reusable helper. Both are edits to the same twenty lines. This packet performs that rewrite exactly once (Step 3) and ships the helper; `210b` adds only a second *caller*. Under this ordering the collision cannot recur, and `210b` never reopens `smooth_branches`.

## Scope Boundaries

In scope: `modules/core-modules/support-planner/src/lib.rs` — the node-geometry retype (struct, MST, distances, aggregation, clamp, membership test, scan-line emitter parameters, `first_point_xyw`), the one-time `smooth_branches` rewrite, and the net-new private `split_column_into_chains`; `modules/core-modules/support-planner/tests/multi_neighbour_mst_tdd.rs` (rewritten to integer units); the in-file `#[cfg(test)]` module; and both frozen-golden fixture pairs under `resources/golden/` if and only if the canonical-correct output moves them.

Also out of scope: the WIT/IR wire format — `record point3-with-width` (`crates/slicer-schema/wit/deps/types.wit`) and `slicer_ir::Point3WithWidth` stay `f32` mm, so no guest/host marshal signature changes; mm-valued flow/width quantities (`width`, `flow_factor`, `MAX_BRANCH_RADIUS_MM`, `tapered_radius`); mesh-vertex-space helpers (`point_in_polygon`, `detect_overhang_facets`, `collect_paint_blocker_polygons`); and every other core module.

## Exports Consumed by 210b (contract, not advice)

These shapes are `210b`'s preconditions. Changing any of them after this packet closes breaks `210b`'s plan:

- `fn split_column_into_chains(entries: &[SupportPlanEntry], column: &[usize]) -> Vec<(usize, usize)>` — private, half-open ranges into `column`, returns **every** range including those shorter than 3.
- `fn point_in_any_expoly(polygons: &[ExPolygon], p: Point2) -> bool` — **this is the helper `210b` consumes for its model-landing test**, because `LayerCollisionCache.collision_polys` is `Vec<ExPolygon>`, not `Vec<Point2>`. It is **hole-honouring**: a point inside a hole of an `ExPolygon` is NOT inside that `ExPolygon`. On support geometry that is not a nicety — dropping it would let `210b` place a floor band, and let this packet's own avoidance clamp place a branch, inside a model hole.
- `fn point_in_polygon_units(poly: &[Point2], p: Point2) -> bool` — exact `i128` cross-product ray cast over a **single ring**. It is the ring-level primitive `point_in_any_expoly` is composed from (contour ring, then each hole ring); it is not itself an `ExPolygon` test and `210b` does not call it directly.
- `fn first_point_xyw(entry: &SupportPlanEntry) -> Option<(Point2, f32)>` — position in units, width in mm, **no `z`**.
- `fn push_interface_scan_lines(out, centre: Point2, z: f32, half_units: i64, width_mm: f32, spacing_units: i64, parity: i32, avoidance_polys, collision_polys)`.
- `LayerCollisionCache` keeps both `collision_polys` and `avoidance_polys` on the **same** struct; there is no separate avoidance cache.
