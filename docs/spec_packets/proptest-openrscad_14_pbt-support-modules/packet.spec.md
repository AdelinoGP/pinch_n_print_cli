# Independently checked support planner and renderer properties

## Goal

Exercise the selected traditional/tree support planner and renderer kernels and support-surface ironing with bounded, independently modeled properties, meaningful failure controls and measured Windows profiles.

## Why

The approved source is `docs/specs/proptest-openrscad-adoption.md` §§3–7 and 11–13, queue row 14. These five module owners contain different raster, tree, path and metadata behavior; existing examples do not prove arbitrary generated cases or independent whole-segment containment. A successful empty result cannot certify a productive scene, while some empty, blocked and degraded outcomes are legitimate. This packet owns the module kernels, not the host support prepass or a general support-routing proof.

## Scope

- In: `traditional-support-planner` rasterization, one-pass hole fill, block-local grid/extraction and planner territory; `tree-support-planner` node smoothing, collision carve, role construction and its actual batched emit path; `traditional-support` and `tree-support` fill/walls; `support-surface-ironing` fill. Include independently checked small models, required positive and negative scenes, shrink and mutation controls, registry/CI integration, measured Windows routine/extended execution and focused fixes plus concrete regressions for **confirmed** SUT defects.
- Out: a general planner-routing/complete-connectivity claim, unconditional nonempty output or cross-layer area monotonicity; proving the host prepass, host aggregation, final G-code or a new randomized guest/E2E campaign; organic-engine parity, new IR/WIT/schema fields or shared SDK support APIs; OpenRSCAD; changing the source plan, queue or another packet. A larger real defect blocks the affected coverage instead of being hidden or waived.

### Test homes and common discipline

All five named packages are root workspace members and have lib targets; Cargo metadata at authoring shows no owner features or required-feature test targets. Add a new empty default-off `property_testing = []` feature in each owner manifest, extend its existing `slicer-sdk` **dev-dependency** with #1's `property_testing` alongside `test`, and add workspace Proptest as a dev-dependency. Do not enable either test feature on normal/guest edges. `requires_host_algos = false` in the registry means these are not host-algos-gated core targets; the native SDK dev graph may still unify `slicer-core/host-algos`. Recheck actual Cargo metadata/graphs after predecessors land.

Add one new private `src/property_tests.rs` per owner, declared in that owner's `src/lib.rs` with separate stacked `#[cfg(test)]` and `#[cfg(feature = "property_testing")]`; all tests below have the exact `property_tests::` libtest prefix. This preserves access to private parent kernels without changing production visibility. Test-local references, scenes, controls and helpers are private; no new consumable Rust symbol is exported. Register only tests that actually exist. Recheck feature-enabled exact libtest discovery and require nonzero execution.

`collect_enforced_files` and `LiteralVisitor::visit_item_mod` (`xtask/src/check_literals.rs`) do not scan `modules/core-modules/*/src/**` or follow an out-of-line module; stacked attributes do not cure that blind spot. `collect_enforced_files` (`xtask/src/check_test_quality.rs`) also omits module `src/**`. Re-derive the watched-type set, manually inspect **every** watched literal in all five new source test files and touched source tests, use a valid fixture/FRU or properly placed `// exhaustive: <reason>`, and record sites/waivers in evidence. Manually review `docs/22_test_quality.md` as well. Run both gates, but never claim that their clean output scanned these files.

Every registered callback uses #1's `PropertyRun::{new,bound,check}` and its per-invocation `CaseGuard`; deterministic SUT witnesses and controls that use SDK host state also use a fresh `CaseGuard`. `docs/testing/properties.md` records every source-plan §5 charter field: ID, owner/target/SUT, contract, domain, strategy/witness, oracle and dependencies, exact/tolerance proof, shrink behavior, measured execution, failure/replay and acceptance. Use #2's actual documented exports only; module-local rectangle, raster, flood, graph and scene builders stay local, never promoted into an invented SDK API.

Choose semantic modes using Proptest 1.11 `prop::sample::select(...).no_shrink()` or an equivalent demonstrably nonshrinking selector. Do **not** use `prop_oneof![Just(...), ...]` for a mode whose witness must survive: a union can switch arms. Parameters may shrink within the selected valid, holed, blocked, territory or feasible mode. Each owner has a deterministic `Strategy::new_tree` probe of actual `ValueTree::{current,simplify,complicate}`, including failed transitions and repeated complicate; independently validate every exposed value and its selected mode, begin nonminimally and demonstrate a permitted real reduction. An impossible bound, narrowing conversion, exhausted generation or lost witness is a failure, not a rejection that becomes a pass.

Each property independently executes its deterministic positive fixture plus its distinct empty/degraded controls; random sampling alone must not supply rare topology. Maintain **per-property, per-required-positive-subcase** local in-process counters of actual checked output cells, nodes, roles, intervals, walls or segments; after `PropertyRun::check`, require the appropriate counters positive. The relevant positive subcase must be constructed in the callback rather than depend on a random mode being chosen. Use in-process profiles (`timeout_ms = 0`) so callback counters are observable; the deterministic controls use the **same checker** with exact wrong outputs, not a second oracle. Never classify a SUT failure as `Reject` or accept an empty loop as evidence.

### Property charters

**`M-SUPPORT-RASTER`**: call real `rasterize_polygons` on small bounded, well-wound orthogonal rectangles, a notch and a rectangular hole, with vertices strictly away from pixel-grid lines/corners; include partial-cell coverage and negative translated origin. Independently enumerate each cell's intersection with analytically described material rectangles/notches/holes using exact interval/set arithmetic, not production edge rasterization or Clipper. Compare the entire row-major 0/1 buffer and its size; explicitly include a cell whose center is outside but which has positive material coverage and a hole-interior cell that stays unset. Keep grid dimensions, products and origin arithmetic checked. Empty/short rings and zero-sized grid are separate no-work cases. Avoid claiming this restricted open-interior model resolves coincident-boundary raster conventions.

**`M-SUPPORT-HOLES`**: compare `fill_grid_holes` to an independent simultaneous relation on the **original** 0/1 grid: an interior cell is set if it was set or has both horizontal or both vertical neighbors set; the outer ring is unchanged. Tiny/short-buffer inputs return unchanged as source specifies. Required cascading control is a 5×5 zero grid with set cells `(column,row) = (1,1), (3,2), (1,3)`: `(1,2)` becomes set and `(2,2)` stays unset. An in-place left-to-right fill would wrongly set the latter. Include a two-cell gap and do not claim general enclosed-hole filling or idempotence.

**`M-SUPPORT-GRID`**: exercise `SupportGrid::new` and `grid` on bounded multi-block scenes, plus `for_test`, extraction and sample filtering on explicitly constructed interior cell islands. Independently model the 3×3 all-set **erosion** mask and use a queue-based four-neighbor flood fill *only* on a proven subdomain: within each block the unmasked traversable cells form one axis-aligned rectangle, with nonempty seeds inside it, or no usable seed. Original masked seeds remain present but cannot propagate. On that subdomain the two source sweeps reach the full rectangle; prove the equivalence from the rectangular shape and verify every block separately. Do **not** compare arbitrary masked mazes to a flood-to-fixpoint model: `seed_fill_block` deliberately does only two sweeps. Deterministically check blocked source and destination, neighboring macro-block isolation, empty mask and a prevalidated empty outer ring. `seed_fill_block` returns early on zero size/stride but, for positive size/stride, asserts equal mask/grid lengths; test the mismatch as the specified panic, not an unchanged-result guarantee. For tiny/short extraction buffers use a valid offset and assert the actual empty result; an invalid offset has its separate assertion guard.

For extraction use analytic single-cell/rectangular islands separated by at least one pixel and legal `offset_in_grid` checked with the source's strict in-cell bound. Compare geometric sets at test-owned interior sample points and explicitly derived rectangle limits, not contour start/order; verify trim subtraction, samples selecting only their own island, hole exclusion, no samples → no selected islands, and the legal-boundary/invalid-offset guard. `SupportGrid::extract_islands` may return islands before selection. Check an AGG macro-block halo witness against the block-local extent, not against the original polygon subset. Do not mistake the seed-fill model for the separate one-pass `fill_grid_holes` contract.

**`M-SUPPORT-TERRITORY`**: call actual `SupportPlanner::clip_to_territory` with fresh test-local `SupportAnalysisView` fixtures and exact full-source chains. For controlled axis-aligned input and rectangular territory, independently classify cells using rectangle intersection for own territory or input minus the positive-line-width expanded foreign rectangle for a base region. Include no partition, another object/layer, chain-distinct sources, own and foreign positive populations, and an empty/fully removed case. Assert actual surviving cells and clearance; a removed foreign bar or wrong chain fails. This is the planner-local application of the PnP rule, not #11's host territory proof or canonical routing.

**`M-TREE-SMOOTH`**: construct private `NodeArena`, `LayerRecord` and valid parent/child/active links, including a nonminimal bent chain with at least three nodes, a merge node, a polygon-typed child and a shorter-than-three-node chain. Inspect all references before/after. The kernel indexes its arena directly: an out-of-range ID is a checker-only mutation, not an invalid SUT input or a promised validation error. For the simple single-chain subdomain, fixed endpoints remain fixed, short chains retain position/radius/movement, and committed interior positions stay inside the coordinate-wise bounds of the original chain, allowing only the independently derived final integer rounding. Use a straight equally spaced positive witness and a bent witness; check the source-backed merged-parent `need_extra_wall` trigger separately. The width-derived half-line value is a **signed component threshold for a flag**, not a cap on `movement` or a guarantee about `max_move_dist`; do not assert either. Preserve `DEV-143` and do not use another 100-pass copy as the expected output.

**`M-TREE-ROLES`**: call `carve_emitted_regions`, `build_roles` and the production `build_roles_batched` on bounded, non-simplifying, axis-aligned rectangle scenes. Independently partition at every input/output X/Y edge and label open cells from the source rectangles: per input region subtract collision and retain the uniquely larger surviving rectangle where the cut splits it; then form the declared body/interface sets, subtract each interface from body, and for the batched own-territory mode intersect each role with own territory. Check actual collision exclusion, role membership, role order `SupportBody`, `TopInterface`, `BaseInterface`, `BottomInterface` with absent empty roles omitted, and body-versus-each-interface disjointness. Interface roles need not be pairwise disjoint outside this intentionally disjoint fixture. Include positive body and interface cells, a fully swallowed region, no collision, and own territory; validate batched input/output association with two distinguishable inputs. Test a disjoint bbox-gated region as geometric-set identity; do not compare normalized vertex order or use serial output as the batched oracle. Distinct-point skeleton segments are not assumed to create role polygons. The actual larger production routing/aggregation is outside this kernel claim.

**`M-TRADITIONAL-SCAN`**: call private `TraditionalSupport::fill_expolygon` with finite positive inputs and independently validated rectangles, concave notch and hole. For angle zero derive the complete half-open rows and input-defined horizontal material intervals by rectangle arithmetic; for controlled rotated cases test all resulting segments against the independently derived region/rounding envelope. Check `SupportMaterial`, supplied Z, speed and path width, flow `1.0`, and unset tool/order fields; the caller, not this kernel, changes interface roles. Require a hole-split row and the exact hole-crossing negative below. Check nonpositive spacing/degenerate input as the actual empty kernel outcome. For a valid narrow region only assert a fallback under its documented actual preconditions, not for every narrow shape. A deterministic candidate is the diamond `(5,4.5), (5.5,5), (5,5.5), (4.5,5)` mm at angle zero and 2 mm pitch: the first row is a zero-length tip, and any center fallback must span `(4.5,5) → (5.5,5)`. The live centroid branch omits the bbox-center translation used by the main branch, while the deviation record says the fallback was removed. This is a **source-inspected candidate**, not a confirmed regression: reproduce and reconcile whether the fallback itself is required before demanding nonempty output or making a focused fix. Any output must still satisfy the applicable containment contract; do not accept outside-region paths as a new oracle.

**`M-TREE-SCAN`**: call `scan_fill_region` on axis-aligned rectangle/notch/hole domains in horizontal and vertical modes. Independently derive complete intervals at `scan_min + spacing/2 + n*spacing` while below `scan_max`, with a separate mid-scan fallback only when no ordinary line is emitted. Assert whole segments, role/width/flow/Z/speed, and hole exclusions; use positive dyadic dimensions/spacing and a separate nonpositive/degenerate empty mode. A required exact vertical witness has outer rectangle `[0,10] × [0,20]` mm, spacing `2.5` mm and no holes: four vertical strokes at x `1.25, 3.75, 6.25, 8.75` must each span y `[0,20]`. The live source compares these vertical crossing values to X bounds; this is a candidate discrepancy, not an executed failure. Classify/reproduce before any fix or concrete regression. A valid 0.5 mm square with 2 mm pitch tests the separate center-line fallback, not a universal tiny-tip guarantee.

**`M-TREE-RENDER`**: call `render_polygon_with_wall_count` on sufficiently roomy axis-aligned rectangles and a holed rectangle with line width `0.5` mm. Independently expect two distinct closed wall-center bands `[0.25,9.75]` and `[0.75,9.25]` for a 10 mm square with two walls; the fill centerlines lie in `[1,9]²`. For a hole, account for outward hole expansion and check every wall/fill segment against the relevant analytically inset region. Include a private-kernel zero-wall mode and a production-supported positive-wall mode; `from_config` clamps configured wall count, so do not claim zero passes through the entrypoint. Offset-collapse/small-tip cases are explicit possibly-empty outcomes; require nonempty output only in the independently feasible roomy scenes. Check extents with a proven conversion allowance, not output captured from `offset_polygons` as its own expected answer.

**`M-SUPPORT-IRONING`**: call `SupportSurfaceIroning::fill_expolygon` with independently valid rectangle, notch and rectangular-hole shapes and positive configured spacing. Compare complete half-open horizontal rows/material intervals, whole strokes and hole exclusions against input arithmetic; inspect each `Ironing` path's supplied Z/speed, configured line width and `flow_factor` from the explicitly supplied valid config value. This is a metadata propagation contract, not a claim that the manifest default's numeric value represents an independently verified physical percentage. Nonpositive spacing/degenerate geometry may return empty. A holed `[0,10]²` mm fixture with hole `[4,6]²` and 1 mm spacing has nonempty material intervals on both sides at an interior hole row.

For all three fill checkers use a separate exact false-acceptance control: outer `[0,10]²` mm, hole `[2,3] × [4,6]` mm, segment `(1,5) → (9,5)` mm. Both endpoints and the midpoint are material but the segment crosses the hole; the independent whole-segment checker must reject it. Include an analogous U-notch chord, dropped expected row and false all-empty result. These are synthetic controls, not claims of an observed production failure.

### Outcomes, profiles and evidence

Exercise real planner entrypoints with **bounded named fixtures**, not a general routing theorem. The traditional planner's all-layer occupancy fixture in `agg_path_still_declines_no_route_when_occupancy_closes_every_layer` (`modules/core-modules/traditional-support-planner/tests/agg_rasterizer_tdd.rs`) supports `NoRoute` and warning `1203` for default, `agg`, and `legacy_semantic` modes when the whole candidate and halo are blocked. Also retain its local-blocker distinction `agg_does_not_decline_no_route_where_legacy_semantic_does`; AGG success there is not a defect. Exercise a real blocked tree candidate yielding `SupportPlanDeclineReason::Blocked`, and disabled tree planning yielding no entries, using the existing `disabled_and_declined` fixture (`modules/core-modules/tree-support-planner/tests/tree_family_tdd.rs`). A directly constructed declined entry is not evidence that the planner produced a decline. Retain renderer `declined_or_empty_plan_has_no_fallback_paths` (`modules/core-modules/tree-support/tests/tree_family_tdd.rs`) as the separate no-fallback boundary. No successful nonempty output is required for every candidate.

For every observed failure retain input/context first, reproduce, and classify SUT versus generator/oracle/contract. Only a **confirmed** SUT defect receives a focused canonical-correct fix and a named concrete regression containing the root cause and previously failing input, runnable without RNG or `PNP_PROPERTY_CONTEXT`; #2's formatter only accepts its documented `ConcreteInput` variants. If no defect is confirmed, say so. If a fix changes a documented contract rather than restoring it, stop for the proper decision; do not weaken assertions, add ignores, fabricate a regression or rebaseline unrelated tests.
