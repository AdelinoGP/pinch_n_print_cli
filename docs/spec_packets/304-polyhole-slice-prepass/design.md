## Architecture Constraints

- **The pass is cross-layer, and that is what fixes the seam.** Canonical accepts a hole only when a matching hole exists on a contiguous neighbouring layer, and indexes the twist rotation by the absolute layer index. `Layer::SlicePostProcess` is dispatched one layer at a time, and the executor is layer-major — `execute_per_layer*` iterates layers in the outer loop and `plan.per_layer_stages` in the inner (`crates/slicer-runtime/src/layer_executor.rs`) — so a module there can never see the neighbour, and there is no barrier between per-layer stages where a host pass could stand in. The prepass seam, which owns whole `Vec<SliceIR>` at once, is the only one that can serve this pass. `PrePass::ShellClassification` proves the shape works: `commit_shell_classification_builtin` (`crates/slicer-runtime/src/slice_postprocess_prepass.rs`) clones the committed `Vec<SliceIR>`, walks per-`(object_id, region_id)` timelines built by `build_region_timelines`, mutates across layers, and writes back.
- **Rule 4 does not fire.** The four keys are scalar parameters of one geometric pass, not an enum selecting between competing algorithms that would have to live in separate modules. No claim is minted and no `*_holder` key is introduced. The map's trigger test (cross-module algorithm selection) is not met.
- **A new `STAGE_ORDER` entry has a bounded, fully enumerated blast radius — and it is bounded only because the stage is host-only.** Required: the `STAGE_ORDER` entry itself (`crates/slicer-scheduler/src/execution_plan.rs`), the `HOST_ONLY_STAGES` entry that keeps `host_only_stages_partition_stage_order_into_valid_stages` green (`crates/slicer-scheduler/tests/contract/stage_list_consistency_tdd.rs`), one `required_slots` arm (`crates/slicer-runtime/src/prepass.rs`), one `run_builtin_stage` call, one `PrepassExecutionError` variant, and the two stage lists in `docs/04_host_scheduler.md` and `docs/01_system_architecture.md`. Deliberately **not** required, because the stage is not module-targetable: `slicer_schema::VALID_STAGES`, `slicer_schema::STAGES`, the `StageGlueKind` match in `crates/slicer-macros/src/lib.rs`, the `LayerStageCommit` match in `crates/slicer-ir/src/stage_io.rs`, and the scaffold arm in `crates/pnp-cli/src/module_new.rs`. `phase_from_stage` (`crates/slicer-runtime/src/progress_instrumentation.rs`) keys on the `PrePass::` prefix and needs no edit — a test named `phase_from_stage_uses_prefix` in that file locks the prefix behaviour. Two neighbouring assertions were checked at authoring and both stay green **only under this design**: `crates/slicer-scheduler/tests/integration/dag_cli_integration.rs` asserts *containment* of a six-stage built-in list, not equality, so a new stage does not disturb it; and `crates/slicer-runtime/tests/unit/builtin_producers_tdd.rs` asserts a **producer count of 7**, which stays 7 only because this built-in registers through `run_builtin_stage` without registering a `Producer` — the `PrePass::PaintSegmentation` shape, and the reason that stage is deliberately excluded from the `dag_cli_integration.rs` list. If the implementer ever registers a `Producer` for this stage, that count assertion must move in the same step.

- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.
- **No reusable `SCALED_EPSILON`.** Canonical floors `max_variation` at `SCALED_EPSILON`. This tree's only symbol of that name is a file-private `const SCALED_EPSILON: i128 = 1;` in `crates/slicer-core/src/smooth_outward.rs` — not `pub`, a different type, a different magnitude. The siblings `SCALED_EPSILON_MM` (`crates/slicer-core/src/algos/bridge_over_infill.rs`) and `SCALED_EPSILON_SQ` (`crates/slicer-core/src/medial_axis.rs`) are likewise file-private. `polyhole.rs` declares its **own** file-private epsilon in this tree's units, documents the canonical value it stands in for, and neither imports nor widens the visibility of any existing one. Packet 303 hit this exact trap during its preflight.
- **The kernel is ungated and must stay ungated.** `crates/slicer-core/src/algos/mod.rs` gates every module except `bridge_over_infill` behind `#[cfg(feature = "host-algos")]`. `polyhole` joins `bridge_over_infill` ungated — not because a guest links it (none does), but because an ungated module and an ungated test target remove the CLAUDE.md silent-zero-tests hazard entirely: a bare `cargo test -p slicer-core` compiles and runs the suite. The kernel therefore may not use `rayon`, may not touch anything behind the feature, and its test target may not carry `required-features`.
- **No guest WASM in the change surface.** No `modules/` path and no manifest is touched, so the guest-staleness gate is not a per-step obligation here. The `wasm-staleness` snippet is deliberately omitted; if any step later adds a `modules/` path, that omission becomes wrong and the step must add the gate.
- Schema/version constants and event-specific locking: **not applicable** — no `PROGRESS_EVENT_SCHEMA_VERSION` or other public version constant is bumped. `SliceIR`'s schema is unchanged: hole point vectors are mutated in place and no field is added.
- **ADR conformance (no amendment).** `docs/adr/0062-order-lock-for-print-order-sensitive-extrusion-sequences.md` and `docs/adr/0063-sequence-locked-paths-may-occupy-neighboring-fill-domains.md` govern extrusion-path ordering. Neither is contradicted: this pass runs inside the prepass, long before any extrusion path exists. No ADR is authored and no slot is allocated.

## Code Change Surface

- **Selected approach.** Split the pass into a pure kernel over `&mut [SliceIR]` and a thin `Blackboard` bridge, mirroring `PrePass::ShellClassification`'s split. Every geometric decision — candidacy, the two spread tests, grouping, edge count, rotation — lives in the kernel and is testable natively with hand-built `SliceIR` fixtures and no scheduler, no blackboard and no WASM. The producer holds only config resolution and the clone/write-back, which is the part that cannot be unit-tested in isolation anyway.
- **The per-region config gate is resolved, not flattened.** Canonical reads `hole_to_polyhole` from `region().config()`, so two regions on one layer can disagree. The producer builds a `RegionKey { global_layer_index, object_id, region_id, variant_chain }` per region and resolves it through `RegionMapIR::config_for` (`crates/slicer-ir/src/slice_ir.rs`), which returns that region's interned `ResolvedConfig`. `nozzle_diameter` is read from the same `ResolvedConfig`'s `extensions` map, the pattern `crates/slicer-runtime/src/builtins/support_analysis_producer.rs` already uses. The resolved per-region values become the `region_params[slice_index][region_index]` matrix the kernel consumes, so the kernel never sees a `ResolvedConfig`.
- **Exact functions, traits, manifests, tests, and fixtures.**
  - NEW `crates/slicer-core/src/algos/polyhole.rs` — `pub fn create_polyholes(center: Point2, radius: i64, nozzle_diameter: i64, twisted: bool, max_edges: u32) -> Vec<Polygon>`; `pub struct PolyholeParams { pub enabled: bool, pub threshold: ResolvedFloatOrPercent, pub twisted: bool, pub max_edges: u32, pub nozzle_diameter_units: i64, pub filament_id: u32 }`; `pub fn transform_holes_to_polyholes(slices: &mut [SliceIR], region_params: &[Vec<Option<PolyholeParams>>]) -> usize`. File-private helpers for centroid, vertex-radius statistics, line-midpoint statistics, the convexity predicate, and the file-private epsilon. Opens with the standard porting header naming `src/libslic3r/PrintObject.cpp`.
  - EDIT `crates/slicer-core/src/algos/mod.rs` — one ungated `pub mod polyhole;` line beside `bridge_over_infill`.
  - NEW `crates/slicer-runtime/src/builtins/polyhole_producer.rs` — `pub fn commit_polyhole_builtin(blackboard: &mut Blackboard) -> Result<(), PolyholeBuiltinError>` with `MissingSliceIr` / `MissingRegionMap` / `Blackboard` variants, mirroring `ShellClassificationError`'s shape; declared in `crates/slicer-runtime/src/builtins/mod.rs`.
  - EDIT `crates/slicer-runtime/src/prepass.rs` — one `PrepassExecutionError::Polyhole { source }` variant, one `run_builtin_stage` call between the `PrePass::Slice` and `PrePass::OverhangAnnotation` registrations, and one `required_slots` arm returning `LayerPlan`, `RegionMap`, `SliceIR`.
  - EDIT `crates/slicer-scheduler/src/execution_plan.rs` — one `STAGE_ORDER` entry.
  - EDIT `crates/slicer-scheduler/tests/contract/stage_list_consistency_tdd.rs` — one `HOST_ONLY_STAGES` entry with a comment naming the producer file, matching the existing `PrePass::LightningTreeGen` comment style.
  - EDIT `crates/slicer-ir/src/resolved_config.rs` — four `cli` rows and four `to_config_map` emissions (macro arms only).
  - NEW `crates/slicer-core/tests/algo_polyhole_tdd.rs`, `crates/slicer-ir/tests/resolved_config_polyhole_tdd.rs`, `crates/slicer-runtime/tests/executor/prepass_polyhole_stage_order_tdd.rs` + one `mod` line in `crates/slicer-runtime/tests/executor/main.rs`.
- **Rejected alternatives and reasons.**
  - *A guest module on `Layer::SlicePostProcess`* (the tier table's owner). Rejected: the stage is dispatched per layer inside a layer-major executor, so the grouping step's neighbour read is unserviceable. This is the ticket-27 owner correction, and it is the same reasoning packet 297 used.
  - *Splitting detection into a prepass and replacement into a per-layer module.* Rejected: canonical identifies the hole to replace by pointer identity into the layer's own surfaces; a split would have to re-match by centre and radius after another pass may have moved them, which is strictly more divergence than doing the whole pass at one seam.
  - *Reusing `PrePass::Slice`'s stage id for the built-in instead of adding a stage.* Rejected: it would misattribute this pass's timing to the slicer in `pnp_cli dag`, the HTML report and every instrumentation consumer, for the sake of avoiding two one-line edits. Every existing built-in owns a distinct stage id.
  - *Making the stage module-targetable* (`VALID_STAGES` + a `STAGES` row + WIT + SDK trait). Rejected: it multiplies the blast radius across `slicer-schema`, `slicer-macros`, `stage_io.rs` and `module_new.rs` to expose a seam nothing asks for. A fork replacing this pass edits the built-in.
  - *Hardcoding `max_edges = 50` and leaving the fourth key out.* Rejected: map rule 4 forbids hardcoded constants where the architecture has a place for the decision, and the key is one `cli` row.
  - *Adopting canonical's `min = 3` on `hole_to_polyhole_max_edges` as validation.* Rejected under ticket 113 — canonical never enforces it, and the kernel's `max(3, ..)` already makes a smaller value harmless.

## Data and Contract Notes

- IR/manifest contracts: `SliceIR` is mutated in place — a hole's `Polygon.points` vector is replaced; no field is added, no schema version moves, and no manifest exists for this pass. The kernel must never touch `ExPolygon.contour`, only `ExPolygon.holes`; AC-3 asserts that directly.
- WIT boundary: none. The stage is host-only and no guest sees it.
- Determinism/scheduler constraints: the pass is deterministic and single-threaded. Canonical parallelises its detection sweep with TBB and then does the grouping serially; this port does the whole pass serially, because the grouping consumes candidates from a shared structure and the region axis in this tree is degenerate for typical prints (`build_region_timelines` keys on `(object_id, region_id)`, which is one timeline for a single-material single-object print — measured and recorded in `slice_postprocess_prepass.rs`). Iteration order is slice index ascending, then region index, then hole index, so the output is reproducible.
- **Deviation row (re-derive the next free `DEV-###` at write time; `DEV-198` was next-free at authoring and packet 303 also intends to file one).** Three clauses:
  - **(a) Ordering against elephant-foot.** Canonical runs `elephant_foot_compensation` inside `slice_volumes` and `_transform_hole_to_polyholes` afterwards, so a first-layer hole reaches the polyhole pass already grown by the compensation — which is why canonical carries a lone-first-layer rescue in its grouping rule at all ("cause of first layer compensation", in its own comment). Packet 303 places elephant-foot on `Layer::SlicePostProcess`, after every prepass stage, so in this port the order is inverted: polyhole converts the circular hole first and elephant-foot then resamples and offsets an already-faceted polygon. Observable only when **both** features are enabled — `hole_to_polyhole` defaults `false` and `elefant_foot_compensation` defaults `0` — and only on the first `elefant_foot_compensation_layers` layers. Recorded, not resolved: neither packet may amend the other, and if the seam question later resolves toward a prepass elephant-foot, the fix here is the position of one `run_builtin_stage` call.
  - **(b) Serial where canonical is parallel.** Canonical's detection sweep is a `tbb::parallel_for` over layers; this port sweeps serially. Results are identical; only wall time differs.
  - **(c) Single mutation target.** Canonical replaces the hole's points in both the region's `slices.surfaces` and the layer's `lslices`, which are two containers holding the same hole. This tree has one — `SlicedRegion.polygons` — so the second write has no counterpart and no divergence follows; recorded so a future reader does not go looking for the missing store.

## Locked Assumptions and Invariants

- **`PrePass::PolyholeTransform` is host-only, permanently.** Adding it to `VALID_STAGES` later would require a WIT world, an SDK trait and a `STAGES` row; that is a different packet, not a follow-up edit.
- **The stage's position is a contract, not a preference.** It must stay after `PrePass::Slice` (it needs committed slices) and before `PrePass::OverhangAnnotation` and `PrePass::ShellClassification` (both derive from footprints this pass changes — canonical's `detect_overhangs_for_lift` and `detect_surfaces_type` likewise run after `PrintObject::slice`). AC-9 and AC-10 pin both ends.
- **The kernel stays ungated.** Reversible in principle, but a regression is silent: gating it turns the test binary into zero tests that print `ok`.
- Otherwise reversible via existing config defaults — all four keys default to canonical values, and at those defaults the pass is a no-op returning `0`.

## Risks and Tradeoffs

- **First occupant of a new prepass stage.** Nothing has been registered between `PrePass::Slice` and `PrePass::OverhangAnnotation` before. Treat ordering, instrumentation and `pnp_cli dag` surprises as expected discovery rather than a defect in this design; AC-9 and AC-10 are the guards.
- **Hole identity is by geometry, not by pointer.** Canonical holds raw `Polygon*` into the layer's surfaces and mutates through them. This port must index holes by `(slice_index, region_index, hole_index)` instead. The risk is an index invalidated by a concurrent mutation; mitigated by the pass owning the whole `Vec<SliceIR>` for its duration and never inserting or removing a hole, only replacing point vectors.
- **The threshold's percent base is easy to get wrong.** Canonical resolves the percentage against the **mean** vertex radius (`diameter_sum / n_points`), not the max and not the diameter. AC-5 pins the absolute case; the implementer must not substitute `diameter_max`.
- **`filament_id` participates in canonical's hole identity** and this tree's per-role filament selection is not identical to canonical's `outer_wall_filament_id`. On a single-filament print the field is constant and the risk is nil; on a multi-filament print a mismatch would merge or split groups. The producer reads whatever this tree's region config exposes for the outer-wall role and the kernel treats it as an opaque grouping token, which is the faithful behaviour regardless of how the id is spelled.
- **Convexity on a clockwise ring.** Holes are wound clockwise in this tree (`ExPolygon.holes`, documented on the type) as in canonical, so the convexity predicate's sign convention must be written for a clockwise ring. Getting the sign backwards silently accepts exactly the wrong holes; AC-N1 is the guard.
