# Packet Contract: lightning-migration

## Goal

Move lightning planning out of the host PrePass and into the selected `com.core.lightning-infill` artifact. The planner and its two plan types relocate into the module (`modules/core-modules/lightning-infill/src/kernel/`), a NET-NEW module-side adapter builds the planner's inputs from typed preparation data, preparation plans the trees from those committed inputs, fresh ordinary `Layer::Infill` calls consume module-private pieces, a typed `planning_geometry` projection publishes the final plan, and the legacy host producer, public `LightningTreeIR`/`LightningTreeEntry`/`PrePass::LightningTreeGen`, the `lightning-tree-segments` accessor and the `slicer:lightning-queries` WIT package are deleted. Correctness is **recorded behavioural equivalence to the live producer, captured before removal**: this packet moves ownership and changes no output.

## Scope Boundaries

This is a **behaviour-preserving ownership migration**, not a planning improvement. The planning algorithm itself is relocated, not rewritten: the code that `crates/slicer-core/src/algos/lightning/` executes today moves into the module's kernel, with **planning numeric logic frozen** — `generator.rs`, `layer.rs`, `tree_node.rs`, `distance_field.rs`, `error.rs` and the computation in `mod.rs` keep every decision (layer iteration order, domain/parameter derivation, grounding, clipping, the `sparse_fill_holder` branch). The permitted differences are enumerated and mechanical: file location, the plan-type import (the two types' home becomes `kernel/plan.rs`), `crate::` → `slicer_core::` on the ungated helper paths the relocated bodies already call, the error type's path, a NET-NEW additive input adapter that supplies the planner's inputs without touching arithmetic, and doc comments that named the moved types now naming `KernelPlan`/`PlanEntry` (AC-5 greps the module's own `src/` as a public-name leak check, so comment text must follow the rename). AC-2/AC-3 prove that list was respected. The equivalence oracle is the current producer's own output. Every acceptance criterion below is therefore falsifiable today, without a scientific gate. The module's private plan type is `KernelPlan`/`PlanEntry`, relocated from the host algorithm into `kernel/plan.rs` with no `serde`, no `schema_version` field and no schema-version constant — a private module type, never a public IR — and AC-5's absence list names only **public-contract** symbols (`slicer-ir`, `slicer-runtime`, `slicer-wasm-host`, `slicer-sdk`, `slicer-macros`, `slicer-scheduler`, WIT, with the module's own `src/` grepped solely as a leak check for those public names); the module's own private types are exempt by construction.

The only module behaviour this packet adds beyond the move is the D6 diagnostic publication mode: a manifest-declared, advanced, default-`none` enum that stages named failure outputs **after** planning. It cannot reach the kernel, cannot change a planning scalar, and is inert on the `none` path; AC-2/AC-3 run with the default. It exists because the module owns the decoder and `require` path that AC-N2 protects, and no host surface can hand the real consumer a missing, malformed or stale-version piece without faking that boundary.

The ADR conflict this creates is resolved by [ADR-0074](../../adr/0074-lightning-migration-on-recorded-equivalence.md), the accepted decision record that supersedes ADR-0029's host-ownership decision and amends ADR-0066's retirement precondition; the two dated `## Amendment — 2026-10-20` sections in those ADRs carry the clause-by-clause replacement in place, ADR-0074 quotes the contested clauses by text and slot, and it separates *ownership move* from *strategy change*. Its registered deviations are `D-LMP08-ADR-0066-RETIREMENT-PRECONDITION` and `D-LMP08-ADR-0029-HOST-OWNERSHIP` in `docs/DEVIATION_LOG.md`. ADR-0029's Future-Reviewer Note is **not** superseded: preparation is whole-print, before any per-layer sampling, so this is not the per-layer approximation that note retires.

Two consequences are load-bearing and must not be elided:

- **No new parity claim.** Equivalence preserves whatever the live producer does, including any existing deviation from OrcaSlicer. A green equivalence run says "ownership changed, output did not", never "the plan is canonical". Row 07's recorded `Gate A outcome: fail` and row 09's unexecuted Gate B remain recorded as-is; this packet neither resolves nor re-litigates them.
- **Strategy work is out of scope.** Replacing the current strategy with a gate-verified one is row 09/07 forward work. Nothing here is evidence about it.

The packet supersedes a blocked-draft revision: the earlier revision of this directory made Gate A `pass` and Gate B `pass` entry conditions, which was unsatisfiable (Gate A is recorded `fail`, Gate B has no planner to run). That premise is withdrawn. See `design.md` `## Decisions That Replace the Former Blockers` (D1–D5) and ADR-0074 for the replacement authorization.

## Completion Semantics

This packet is **not** a record-only investigation like rows 07/09. Its deliverable is a migration, so:

- A recorded **equivalence `fail` blocks retirement** (Steps 10a–13c). AC-2/AC-3 are hard gates on deletion, because deleting a producer whose replacement differs silently would ship a behaviour change disguised as a refactor. Report the divergence, keep the packet open, do not proceed to deletion.
- A recorded **equivalence `pass` plus every negative control** is required before deletion starts; the packet then closes when AC-5/AC-N4 document that nothing host-owned remains.
- Equivalence `pass` is **not** a parity claim and must not be written up as one. The source-plan record and the `docs/07` note must both say so.
- Gate A/B status is neither improved nor worsened by this packet.
