## Architecture Constraints

- Same selected artifact and frozen module/version/artifact/stage identity own preparation and consumers. Host owns transport/access/lifetime only; decode, pooling, source conversion, planning and clipping remain in module/kernel code. No native surrogate for an externally selected WASM artifact.
- Late preparation uses final committed PrePass products and all eligible full targets. Eligibility is shared `invoke && !targets.is_empty()`; plain dispatch's empty-target behavior remains distinct. No algorithm-named host activation branch.
- No LayerArena survives preparation; no extra stage barrier/live guest/unfinished layer is retained. `Busy` disposal is a nonwaiting producer result; runtime joins actual calls before cleanup. Selected `Layer::AnchoredEvents` uses the generic prepared stage adapter if selected; synthetic `Anchored::Event`/`host:anchored-events` work only extends print-scope retention and is never a lightning consumer/read witness.
- Native SDK's legitimate `host-algos` dependency is allowed. The owned kernel and WASM guest closure must exclude host-algos and callable host lightning production/fallback. A native feature graph alone is not portability failure or success.
<!-- snippet: wasm-staleness -->
- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and inspect its exit code: exit 0 means fresh, non-zero means stale (a distinct exit code signals `wasm-tools` is unavailable). Never use `rg -q 'STALE:'` — a `wasm-tools`-missing infrastructure error prints no `STALE:` and would read as fresh. If stale, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.
<!-- snippet: coord-system -->
- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.
- No speculative public version bump. WIT accessor removal is an affected-contract change, not silently compatible merely because the export signature stays unchanged. B4 must select its supported compatibility/version/rebuild treatment and inventory all old-value assertion and literal/exhaustive-match fallout before any type change. Existing ProgressEvent and row06 visual schema remain untouched.
- New translated Rust files carry the exact standard porting header from `docs/ORCASLICER_ATTRIBUTION.md`, with actual canonical file provenance. No copied placeholder source path.
