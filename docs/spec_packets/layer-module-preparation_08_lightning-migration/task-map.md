## Dependency Change From the Previous Revisions

Two earlier revisions of this crosswalk were unusable, for different reasons.

The first required "independently verified actual executed Gate A/B outcomes recorded in the source plan" before any step could run. That was unsatisfiable (row 07 records `Gate A outcome: fail`; row 09's kernel had empty `planner.rs`/`tree.rs` stubs, so Gate B never had a planner) and tested a property this packet does not claim.

The second replaced that gate with recorded equivalence but left a compile-fatal hole: the planner's return type *is* the public plan IR, which the same plan deleted, while the algorithm directory was declared out of bounds. That is closed by moving the planner and the plan types together into the module's kernel (`kernel/plan.rs`), narrowing the constraint to "planning **numeric** logic frozen" with an enumerated list of permitted mechanical deltas, and deleting the public IR only after its last consumer is gone.

What this packet requires is: rows 01–06 implemented (re-derive each packet's `status:` frontmatter; do not quote this line), the baseline recorded deterministically, AC-2/AC-3 green **before deletion begins**, and ADR-0074 present with its two registered deviations. Gate A/B stay recorded exactly as they are and are neither consumed nor updated here.

`TASK-572`–`TASK-576` remain predecessor-owned and are not absorbed or marked complete. The only ledger edits this packet authorizes are **confirming** the existing row-08 re-scope note in `docs/specs/layer-module-preparation-plan.md` (plus making the paragraph under it agree with it) and the `TASK-577` line in `docs/07_implementation_status.md`, both in Step 16 and both re-derived at edit time. ADR-0074, the two ADR amendment sections and the two deviation rows were recorded during authoring, not as an implementation step.
