# Packet Contract: preparation-contract-transport

## Goal

Normalize the proven preparation capability into declaration-validated, same-artifact native/WASM adapters and production owner-private immutable named-piece storage with checked transport and atomic publication.

## Scope Boundaries

Queue row 03 of the approved eight-row `docs/specs/layer-module-preparation-plan.md` owns declarations, frozen capability adapters, serialized transport, and storage/disposal APIs. It does not schedule preparation, select modules, resolve final whole-print inputs, release storage from the pipeline, or interpret opaque payloads or diagnostic geometry. Authoring creates only this packet's five files; this is draft work, not implementation or permission to execute.

- Draft contract only; implementation, activation and commit require separate authorization.

## Forward Export Summary — concrete contracts, NET-NEW or FORWARD-DEP

**Unchanged producer contracts, FORWARD-DEP on row 02:** `slicer:layer-preparation@1.0.0` at canonical `crates/slicer-schema/wit/deps/layer-preparation/layer-preparation.wit`; imported `preparation-types` defines `print-preparation-input`, `prepared-plan-output`, `prepared-plan-view`, `prepared-piece`, and `preparation-error`. `prepare.prepare-print(input: print-preparation-input, output: prepared-plan-output) -> result<_, slicer:common/module-errors.module-error>`; `output.put(name, bytes)`; `plan-access.current()`; `view.open(name)` returning an optional piece; `piece.len()`; `piece.read(offset: u64, max-bytes: u64)` remain exactly the pilot seams. `input.read-fixture` is controlled-only, not the final whole-print projection.

SDK `slicer_sdk::preparation::LayerPreparation::prepare_print(&PrintPreparationInput, &mut PreparedPlanOutput) -> Result<(), ModuleError>`, `#[slicer_module(preparation)]`, `T::__slicer_prepared_native_entry()`, and `slicer_sdk::native::NativePreparedStageEntry { stage: NativeStageEntry, prepare: fn(&PrintPreparationInput, &mut PreparedPlanOutput) -> Result<(), ModuleError> }` remain unchanged. `PreparationExportSchema` remains a separate `slicer-schema` sidecar. Plain stage worlds/signatures, `from_config`, and existing envelopes do not widen.

**Row 03 NET-NEW exports (full definitions in design):**
- `slicer_schema::preparation::{PreparationDeclaration, PreparationDeclarationError, PreparationTransportError}`; private-field declaration accessors `interface()`, `input_reads()`, `views()`; transport variants `NotReady`, `InvalidName`, `DuplicateName`, `PoisonedOutput`, `RangeError`, `ArithmeticOverflow`, `AccessDenied`, matching the pilot's seven WIT variants. Add `PreparationExportSchema::qualified_export()` without adding a field.
- `slicer_scheduler::preparation::{parse_preparation_declaration, PreparationManifest}`: `parse_preparation_declaration(&str) -> Result<Option<PreparationDeclaration>, PreparationDeclarationError>`; companion storage `PreparationManifest::new(LoadedModule, Option<PreparationDeclaration>)`. `[preparation]` requires `interface = "slicer:layer-preparation/prepare@1.0.0"` and `input_reads: array<string>`; optional `views: array<string>` defaults to empty. Ordinary `ir_access` grants nothing here.
- `slicer_wasm_host::preparation::{FrozenPreparationBinding, NativePreparationArtifact, PreparationFailure}`: `freeze_native(module_id: ModuleId, declaration: Option<PreparationDeclaration>, artifact: NativePreparationArtifact)` and `freeze_wasm(module_id: ModuleId, declaration: Option<PreparationDeclaration>, engine: Engine, component: Component, stage_id: StageId)` return `Result<FrozenPreparationBinding, PreparationFailure>`. A native prepared artifact contains the **paired** entry and schema; a WASM binding retains one component, never a preparation companion artifact or live store.
- `slicer_wasm_host::preparation::{PreparedOwnerStore, PreparationOwner, PreparationTransaction, PreparedPlanHandle, PreparedPieceHandle, StagedPreparation, PreparedPlanMetadata}`. `PreparedOwnerStore::new()` creates one print scope; `create_owner(&FrozenPreparationBinding)`, `begin(&PreparationOwner)`, `current(&PreparationOwner)`, `dispose_owner(&PreparationOwner)`, and `dispose()` are checked APIs. Transactions `put(&str, &[u8])` and `finish(result, validate)` publish once; `validate: FnOnce(&StagedPreparation) -> Result<(), PreparationFailure>` is row 06's extensible, geometry-free atomic-publication seam. Read handles expose `open(&str)`, `len() -> u64`, and `read(u64, u64)` without a provider-id argument or shared cursor.
- `FrozenPreparationBinding::prepare(&PreparationOwner, PreparationInputData)` and `prepare_with_publication(&PreparationOwner, PreparationInputData, validate)` return `Result<(), PreparationFailure>`; fresh consumer scopes use `with_native_plan(owner, call)` and `with_wasm_plan(owner, ordinary_context, call)`. These explicit adapters are not scheduling/autoselection. Row 04 extends `PreparationInputData` with typed input projections; row 06 extends private staging with validated diagnostic attachments, not a host plan decoder.
- SDK host callback/read-facade constructors and `PreparedPlanView::require(&str) -> Result<PreparedPiece, ModuleError>` are additive. Missing required piece is fatal code `57401`; a module's own malformed decoder is still its responsibility. Host-only NET-NEW feature `slicer-wasm-host/preparation-test-fixtures` permits controlled input fixtures; it does not substitute a test transport for production resources.
