# Design: preparation-contract-transport

## Controlling Code Paths — verified existing tree

- `ingest_manifest_text` and `LoadedModuleBuilder` (`crates/slicer-scheduler/src/manifest.rs`) are the existing ingestion authority. The text function is **pub(crate)**, not a public external parser API; this packet does not call it from another crate or create a second ingestion model.
- `StageSpec`, `STAGES`, `SlicerModuleSchema`, `qualified_export_for_stage_id` (`crates/slicer-schema/src/lib.rs`) are scheduled-stage authority, not preparation storage.
- `NativeStageEntry`, `NativeLayerRequest`, `NativeLayerResponse` (`crates/slicer-sdk/src/native.rs`) and `LayerModule::run_path_optimization` (`crates/slicer-sdk/src/traits.rs`) are the ordinary native seam. The latter receives layer index, perimeter regions, G-code output, collection and config; no prepared-plan parameter is added.
- `HostExecutionContext::table`, `host::layer_perimeters` and its `with` mappings (`crates/slicer-wasm-host/src/host.rs`) supply the resource table and canonical ordinary imported identities. The table is crate-private and can be reused by a new wrapper in this crate. `HostExecutionContextBuilder`, `gcode_output`, and `push_gcode_output_builder` are real driver surfaces.
- `LiveModuleBinding`/`load_live_modules_for_plan_manifest_first` (`crates/slicer-wasm-host/src/execution_plan_live.rs`) and native/WASM branches in `crates/slicer-wasm-host/src/dispatch.rs` are **read-only row-05 context**, not edited here.
- `production_classic_perimeters_instantiates_with_layer_linker` (`crates/slicer-wasm-host/tests/contract/production_guest_smoke_tdd.rs`) uses an actual component, `LayerModule::add_to_linker`, `HostExecutionContextBuilder`, Store and typed instantiate. New tests use this kind of driver, never `run_slice` or a fictitious unit-test driver.
- Cargo metadata confirms existing `contract`, SDK `layer_module_tdd` (feature `test`), macro `slicer_module_tdd`/`binding_surface_tdd`/`postpass_text_glue_tdd`, and schema/scheduler library test targets. New contract files require explicit `mod` registration in `tests/contract/main.rs`.

## Architecture Constraints

- Conform to ADR-0066 owner-private pieces/atomic success, ADR-0045 independently versioned typed capability and imported resource identity, and ADR-0056 same-source native/WASM inside one module model. There is no alternate selection/override path or ADR rewrite.
- Row 02's forward contracts are now shipped types: its executable pilot gate was re-derived green (freshness exit 0, 11/11 pilot tests, archived old artifact hash matched) and this packet is active. Two shapes still need care against disk: `PreparationExportSchema` already has a `pub qualified_export` field (add the method, change no field), and `__slicer_prepared_native_entry` is macro-emitted, not SDK-declared.
- No plain-world, stage-signature, existing public-field, IR-version or stage-table changes. Preparation is not an extra scheduled stage. The agreed new preparation package version is not a future IR version pin.

- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. ## Data and Contract Notes

### Declaration and metadata

`PreparationDeclaration` stores private `interface: String`, `input_reads: Vec<String>`, `views: Vec<String>` with read-only accessors. Parser requires `[preparation].interface` equal to `slicer:layer-preparation/prepare@1.0.0`, requires `input_reads` even when empty, and defaults missing `views` to empty. Both arrays contain nonempty exact UTF-8 strings without duplicates; names are not normalized. Unknown keys are errors. Row 04 supplies supported typed input projection names/operation validation; row 06 supplies projection validation, not this parser. Controlled fixture permission is exactly `fixture` and is not a final production projection identifier.

This exact external spelling is a deliberate, narrowly scoped authority amendment: docs/04 “Manifest ↔ Runtime Naming Map (Normative)” currently states manifest keys are kebab-case. Add a following explicit exception and the subsection `#### Preparation metadata naming exception (Normative)` for new `[preparation]` metadata only, mapping external `interface`, `input_reads`, `views` to the companion's Rust `interface()`, `input_reads()`, `views()`. Include exactly `Only new [preparation] metadata keys use snake_case; legacy manifest/config naming remains unchanged.` Existing legacy mapping rows, `[ir-access]`, `[compatibility]` and config naming policy remain intact; this does not rename existing manifest keys or authorize snake_case aliases elsewhere. The new `input-reads` alias is UnknownKey. AC-9 tests actual parsing/accessors plus legacy ingestion, not source-text behavior.

`PreparationManifest` privately stores the existing `LoadedModule` plus optional declaration, constructed by `new(LoadedModule, Option<PreparationDeclaration>)` and exposed by `module()`/`preparation()`. It does not replace existing ingestion. Row 05 composes the new parser with the same source already used for external/integrated ingestion and stores the companion alongside the frozen selected binding.

`PreparationExportSchema::qualified_export() -> &'static str` exposes the producer sidecar's stored qualified capability export, `slicer:layer-preparation/prepare@1.0.0#prepare-print`; it is a method addition, not a field addition. Compare the declaration's interface plus `#prepare-print` to metadata and to actual typed WASM exports. Do not confuse an interface name with a world name or a scheduled stage.

`PreparationDeclarationError` variants: `InvalidTable`, `MissingInterface`, `UnsupportedInterface`, `MissingInputReads`, `InvalidInputRead`, `DuplicateInputRead`, `InvalidViewName`, `DuplicateViewName`, `UnknownKey`, `MissingExport`, `IncompatibleExport`, `UndeclaredExport`, `UnsupportedStage`. Errors carry module/field or expected/actual interface detail through diagnostics, not an opaque success fallback. Missing table/plain artifact is legal; either-sided opt-in without its counterpart is rejected.

Exact rejection mapping: a non-table preparation value is `InvalidTable`; absent interface is `MissingInterface`, wrong interface type/value/qualification/version is `UnsupportedInterface`; absent input_reads is `MissingInputReads`, wrong array/entry type or empty entry is `InvalidInputRead`, repeated entry is `DuplicateInputRead`. Wrong views array/entry type or empty name is `InvalidViewName`, repeated exact name is `DuplicateViewName`; any other key is `UnknownKey`. A declared but absent capability is `MissingExport`, capability without declaration is `UndeclaredExport`, wrong compiled capability metadata/version/signature/resource identity is `IncompatibleExport`, and a capability paired with a non-Layer family/stage is `UnsupportedStage`. Fixtures assert each variant rather than just is_err().

### Shared errors and SDK facades

`slicer_schema::preparation::PreparationTransportError` has exactly `NotReady`, `InvalidName`, `DuplicateName`, `PoisonedOutput`, `RangeError`, `ArithmeticOverflow`, `AccessDenied`, mapped one-to-one to WIT `not-ready`, `invalid-name`, `duplicate-name`, `poisoned-output`, `range-error`, `arithmetic-overflow`, `access-denied`. No new WIT variant or version is necessary.

Host `PreparationFailure` variants are `Declaration(PreparationDeclarationError)`, `Transport(PreparationTransportError)`, `Module(ModuleError)`, `Trap { detail: String }`, `Disposed`, `Busy`, `InvalidOwner`, `AlreadyStarted`, `PublicationRejected { detail: String }`. Native preserves the original `ModuleError` object; WASM reconstructs its exact `code: u32`, `message: String`, `fatal: bool` fields using the canonical imported module-error identity. Required preparation treats every returned module error as failure without modifying those fields. Native panic/guest trap preserve detail and publish nothing. Lifecycle/foreign-owner errors map to `AccessDenied` at fallible WIT resource operations. Infallible `piece.len()` returns captured length metadata even after disposal; subsequent reads are denied and handles retain no payload bytes.

Add native-only facade traits in SDK preparation module: `PreparedPlanRead::open(&self, &str) -> Result<Option<Arc<dyn PreparedPieceRead + Send + Sync>>, PreparationTransportError>` and `PreparedPieceRead::{len(&self) -> u64, read(&self, u64, u64) -> Result<Vec<u8>, PreparationTransportError>}`. `PrintPreparationInput::from_host_reader(Arc<dyn Fn(u64,u64) -> Result<Vec<u8>, PreparationTransportError> + Send + Sync>)`, `PreparedPlanOutput::from_host_writer(Arc<dyn Fn(&str,&[u8]) -> Result<(), PreparationTransportError> + Send + Sync>)`, and `PreparedPlanView::from_host_view(Arc<dyn PreparedPlanRead + Send + Sync>)` are additive non-WASM constructors; wrappers' private representations may normalize without touching their pilot public methods. `with_prepared_plan` **already exists** in the SDK with a different first argument (`impl Fn() -> Result<PreparedPlanCallbacks, PreparationError> + 'static`) and is already unwind-safe and restoring through its own scope guard. Step 3 must **not** change that public signature — Step 3's own exit condition fails on a changed plain ABI, and design.md's "wrappers' private representations may normalize without touching their pilot public methods" endorses leaving it alone. The new `Arc<dyn PreparedPlanRead + Send + Sync>` scope is therefore added under the distinct name `with_prepared_plan_view<R>(view: Arc<dyn PreparedPlanRead + Send + Sync>, call: impl FnOnce() -> R) -> R` with the same unwind-safe restore-any-prior-binding semantics; the pre-existing `with_prepared_plan` stays byte-for-byte untouched and gains a regression test instead. `PreparedPlanView::require(&str)` maps optional absence to `ModuleError::fatal(57401, "required preparation piece missing: <name>")`, but does not decode payloads.

### Print store, immutable pieces and accounting

`PreparedOwnerStore`, `PreparationOwner`, transaction/plan/piece handles and `StagedPreparation` have private fields and constructor/accessor APIs. A new store is one print identity; owner tokens additionally bind the frozen artifact identity/module id. No caller supplies a provider id to `open/read`. Wrong-store/foreign owner yields `InvalidOwner` or boundary `AccessDenied`; no lookup/fallback catalog exists.

`create_owner(&FrozenPreparationBinding) -> Result<PreparationOwner, PreparationFailure>`, `begin(&PreparationOwner) -> Result<PreparationTransaction, PreparationFailure>`, `current(&PreparationOwner) -> Result<PreparedPlanHandle, PreparationFailure>`, `dispose_owner(&PreparationOwner) -> Result<(), PreparationFailure>` and `dispose() -> Result<(), PreparationFailure>` are exact API shapes. Beginning an already active/ready owner is `AlreadyStarted`; dropped/failed staging returns to unready, not ready. Disposal while active preparation/read call guards exist is `Busy`; row 05 waits/unwinds then calls it. Disposal drops name and payload storage, and revokes old handles. Handles retain metadata and weak store/owner references, not strong payload copies. Returned byte vectors belong to callers and are not retained-store accounting.

`PreparationTransaction::put(&mut self, &str, &[u8]) -> Result<(), PreparationTransportError>` validates only nonempty UTF-8 name identity, uniqueness, checked lengths and accounting before retaining the entire piece once. Every failed put poisons the transaction permanently. No append/replace API exists. Successful immutable storage is owner-wide, not region/layer restricted.

`finish(self, result: Result<(), PreparationFailure>, validate: impl FnOnce(&StagedPreparation) -> Result<(), PreparationFailure>) -> Result<PreparedPlanHandle, PreparationFailure>` prioritizes an original module/trap failure over poison while recording the writer fault, otherwise rejects poisoned output, runs validation before publication, then atomically publishes collection plus ready marker. Empty success is ready. Validation cannot observe a ready plan or mutate published bytes. RAII abort clears unfinished staging. `StagedPreparation` exposes owner, declared views, piece count and names/lengths; its private representation can later gain diagnostic attachments. Row 06 validates those attachments before the same ready transition; this packet defines no geometric type or interpretation.

`PreparedPlanHandle::open(&str) -> Result<Option<PreparedPieceHandle>, PreparationTransportError>` distinguishes missing optional from unready. `PreparedPieceHandle::len() -> u64`; `read(offset: u64, max_bytes: u64) -> Result<Vec<u8>, PreparationTransportError>` first rejects `offset > length` as RangeError, then computes `remaining = length.checked_sub(offset)` and `take = min(max_bytes, remaining)`. Only the clipped take is converted to usize and used for a checked bounded end/index before allocation. Never compute offset plus the unbounded requested maximum. Valid oversized requests clip: for `[3,5,11,17]`, `(1,u64::MAX)` returns `[5,11,17]`, while `(u64::MAX,1)` is RangeError. Offset equal to length (including a maximum request) and zero-sized reads are valid empty reads. Checked length conversion, bounded indexing or accounting failures remain ArithmeticOverflow. Calls have no mutable/shared cursor and fresh adapters see the same owner-wide immutable data.

All counters/lengths use checked conversion/addition and commit updates as a group. `read_calls`/`put_calls` count successful transfers/accepted complete puts; failed operations do not partially advance accounting. `requested_read_bytes` accounts the original request, `returned_read_bytes` the clipped transfer; accumulating a maximum request into a nonzero requested-byte counter may independently fail ArithmeticOverflow. AC-4 uses fresh/nonoverflowing counter state per boundary case; AC-N5 separately forces real production counters to their limits and verifies no partial mutation. `prepare_invocations` counts calls at the actual adapter boundary. `PreparedPlanMetadata` has private fields/read-only accessors and a redacted Debug formatter: `module_id`, `phase` (`unready|staging|ready|disposed`), `ready`, `pieces` (name/length only), `retained_payload_bytes`, `retained_name_bytes`, `staged_payload_bytes`, `staged_name_bytes`, `put_calls`, `read_calls`, `requested_read_bytes`, `returned_read_bytes`, `prepare_invocations`. UTF-8 name bytes are counted separately. No raw payload field, debug dump of store internals, quota/spill/cache, allocator-overhead or peak-memory estimate is added.

### Frozen adapters and resource identity

`NativePreparationArtifact::Plain(NativeStageEntry)` or `Prepared { entry: NativePreparedStageEntry, schema: PreparationExportSchema }` makes the paired entry the only native prepared source. Do not accept a separate ordinary pointer and independently chosen preparation pointer. `FrozenPreparationBinding` has private immutable source/declaration/ordinary-entry identity; WASM additionally retains its selected stage id, one Engine/Component and typed indices, never a Store/module instance. The precise freeze APIs are published in packet.spec.md. Unsupported non-Layer capability is rejected using schema stage authority and the native entry family. Existing ordinary native manifest/schema validation remains the common ingestion authority; this capability adapter does not invent a new ordinary stage-validation model.

`prepare(owner: &PreparationOwner, input: PreparationInputData) -> Result<(), PreparationFailure>` delegates to `prepare_with_publication(owner, input, validate)` with a no-op validator. Both begin a real store transaction, bind real input/output resources or SDK callbacks, invoke the frozen preparation function, drop the call-local store/value, and only then finalize through the same transaction. `with_native_plan<R>(owner, call: impl FnOnce(NativeStageEntry) -> Result<R, ModuleError>) -> Result<R, PreparationFailure>` supplies the paired ordinary entry under a fresh native read facade. `with_wasm_plan<R>(owner, ordinary_context: HostExecutionContext, call: impl FnOnce(&Component, &mut Store<PreparedHostState>) -> wasmtime::Result<R>) -> Result<R, PreparationFailure>` creates a fresh store and passes only the frozen component. Both maintain active-call guards and owner checks. They expose mechanisms, not when/which modules execute.

`PreparedHostState` privately wraps `ordinary: HostExecutionContext` plus call-local preparation context. Its preparation resources use `ordinary.table`; ordinary resource structs and their identities remain unchanged. Register ordinary imports through the selected existing stage's `add_to_linker` with a context projection to `&mut state.ordinary` (`HasSelf<HostExecutionContext>` data), then register only the new preparation-types/plan-access imports against the wrapper. Do not call two whole-world import helpers that register common interfaces twice. New composed bindgen worlds alias ordinary shared types through `host::layer_perimeters`; one prepared binding is the preparation resource identity root and others alias it. Typed composed instantiate validates actual exported prepare and ordinary selected stage against the **same component** before execution. Compile coverage derives supported Layer entries from `STAGES` with nonempty package, not a maintained count/roster.

Production `PreparationInputData`, `PreparationOutputData`, `PreparedPlanViewData`, `PreparedPieceData` normalize/promote the pilot backings rather than keeping them in tests. Their fields are private. `PreparationInputData::for_owner(&PreparationOwner)` is production deny-by-default until row 04 extends it; `controlled_fixture(&PreparationOwner, Arc<[u8]>)` is available only under the NET-NEW host test-fixture feature. `read-fixture` additionally requires exact preparation permission `fixture` and owner match; production mode always denies it. These are real imported resource implementations, not guest-exported resource definitions.

### Fixture and driver

NET-NEW `TransportPathModule` uses the exact PathOptimization trait signature verified above and `#[slicer_module(preparation)]`; Cargo is dual `rlib`/`cdylib` and follows the existing SDK/IR/schema/wit-bindgen guest pattern. **Correction, measured on this tree:** this fixture is also a path dev-dependency of `slicer-wasm-host`, so its `Cargo.toml` must **not** carry a `[workspace]` sentinel and must **not** carry its own `Cargo.lock`. The driver registers in the real contract binary and creates real HostExecutionContext/linker/store calls using production frozen adapters/backings. It may create malformed component witnesses for missing/version/signature/resource identity tests with the existing `wat`/`wit-parser` dev tools, but cannot implement storage or Host traits itself. Native literals are independently pinned, not generated by the decoder being tested. The old-artifact test loads and verifies the row-02 archive/provenance at `target/preparation-pilot/plain-before.component.wasm`, fails loudly if absent, and does not replace it with a current guest. Static schema-derived compiled coverage is explicitly distinct from the two-leg behavioral PathOptimization fixture; do not claim every stage executes from a count-only test.

### Independent review findings (2026-10-14) — `CHANGES REQUESTED`

A full adversarial `spec-review` of the partial state found the following **beyond** the disclosed AC-N2 / AC-N1 / AC-8 gaps. Each is source-confirmed and **none has a passing witness**. Fix these before closing the packet or letting a dependent row consume this surface. Recorded here so a fresh session cannot re-derive them from scratch or, worse, miss them.

1. **HIGH — owned-output lifecycle conflict in WASM finalization.** `prepare-print` takes an **owned** `prepared-plan-output`; the generated guest glue (`build_preparation_glue`, `crates/slicer-macros/src/lib.rs`) captures it inside `PreparedPlanOutput`'s callback storage, so normal scope destruction drops the owned imported resource. `HostPreparedPlanOutput::drop` (`crates/slicer-wasm-host/src/preparation_host.rs`) then deletes `PreparationOutputData`, which owns the unfinished transaction, and `PreparationTransaction::drop` (`crates/slicer-wasm-host/src/preparation_store.rs`) aborts staging. `FrozenPreparationBinding::prepare_wasm` afterwards tries to delete the same output rep to recover and finalize it. This threatens publication outright and can replace an original returned `ModuleError` with the later resource-table deletion error. Runtime reproduction is unverified because no existing witness invokes the path.
2. **HIGH — `prepare_invocations` is permanently zero.** The field is initialised to zero and has an accessor, but neither adapter increments it (`prepare_with_publication` in `crates/slicer-wasm-host/src/preparation_native.rs`, `prepare_wasm` in `crates/slicer-wasm-host/src/preparation_host.rs`). This violates this design's "counts calls at the actual adapter boundary".
3. **HIGH — native `current()` falsely succeeds on an unprepared owner.** `with_native_plan` installs `with_prepared_plan_view`, whose `current` callback unconditionally returns `Ok(host_plan_callbacks(...))`; readiness is checked only when `NativePlan::open` runs. WASM `plan_access::Host::current` **does** return `NotReady`. This contradicts AC-5's native/WASM readiness parity.
4. **HIGH — caught writer faults classify as `Module`, not `Transport(PoisonedOutput)`.** SDK `PreparedPlanOutput::put`/`complete` convert caught faults into a synthetic `ModuleError` carrying `POISONED_PREPARATION_CODE`; the native path maps that to `PreparationFailure::Module`, and `PreparationTransaction::finish` prioritises module errors over transport poison. Publication is still blocked, but AC-N3's promised error classification is not implemented, and `writer_fault` cannot record SDK-local rejections that never reach `transaction.put`.
5. **Contract drift.** SDK `validate_name` rejects control characters while `PreparationTransaction::put` rejects only empty names, so a nonempty UTF-8 key containing a newline or tab behaves differently across the facade and the raw store surface. `PreparationInputData::for_owner`, promised by this design, does not exist — only `default()` and `controlled_fixture` were implemented. The transport fixture reads the **entire** piece and emits both comments on every call instead of consuming separate `(0,2)` and `(2,2)` ranges as AC-2 specifies (`TransportPathModule::run_path_optimization`, `crates/slicer-wasm-host/test-guests/preparation-transport-path/src/lib.rs`).
6. **Tests that endorse or misdescribe the defects.** `prepare_reads_bound_fixture_and_rejects_publication_atomically` (`crates/slicer-wasm-host/src/preparation_native.rs`) reads a fixture successfully using a declaration with **empty** `input_reads`, which positively endorses the missing native permission check. `ordinary_ir_reads_do_not_grant_preparation_access` (`crates/slicer-wasm-host/src/preparation_host.rs`) sets `input_reads` to `SliceIR`, proving rejection of another *preparation* permission string rather than the ordinary-IR authority separation its name claims. `read_fixture_denied_in_production_mode` leaves `fixture_permission` false, so it cannot distinguish production-input denial from ordinary missing-grant denial. `plain_artifact_and_stage_bindings` hard-pins `stages.len() == 9` instead of asserting a nonempty schema-derived population, with no wire-format waiver. The mechanical `check-test-quality --report` gate returns 0 findings and does **not** clear any of these semantic coverage defects.
7. **AC-N2 qualification — the reviewer refuted the privacy claim.** The WASM imported-resource boundary **is** protected: `PreparedHostState::for_binding` derives its permission by exact equality with `fixture`, and `HostPrintPreparationInput::read_fixture` additionally gates execution on the feature.
