# Packet Contract: fuzzy-skin-noise-modules

# Goal

Turn OrcaSlicer's `fuzzy_skin_noise_type` enum into this port's claim-holder mechanism and make its three parameter keys drive the generators. A new `claim:fuzzy-skin-generator` is held by six modules — one per canonical noise type — selected by `fuzzy_skin_noise_type` read from the raw config at module-load dedup time, exactly as `wall_generator` already selects between `classic-perimeters` and `arachne-perimeters`. The shared gate, mode switch, and resampling logic move into a `fuzzy-skin-core` library crate the six modules reuse, so each module contributes only its noise function. `fuzzy_skin_scale`, `fuzzy_skin_octaves`, and `fuzzy_skin_persistence` become live parameters of the coherent-noise generators, honouring canonical's rule that each type ignores the parameters it does not use.

## Scope Boundaries

The packet creates a `fuzzy-skin-core` library crate and five new core-module crates (`perlin-fuzzy-skin`, `billow-fuzzy-skin`, `ridged-multi-fuzzy-skin`, `voronoi-fuzzy-skin`, `ripple-fuzzy-skin`), converts the existing `fuzzy-skin` module into the `classic` holder, adds `claim:fuzzy-skin-generator` to `docs/03_wit_and_manifest.md` § Known claim IDs, generalizes `dedup_same_claim_modules_with_wall_generator` (`crates/slicer-scheduler/src/execution_plan.rs`) so a second claim can be resolved from a raw-config key, and registers the five modules in the root `Cargo.toml`, the integrated registry, and `crates/pnp-cli/Cargo.toml`. It does **not** add a WIT interface, bump an IR schema, or add a `ResolvedConfig` field — the selection key is read from the raw config source before `ResolvedConfig` exists, which is precisely why the `wall_generator` precedent exists. It does not touch `ORCA_CONFIG_PADDING`, does not re-specify the gate or mode keys (packet **259a**'s scope), and does not vendor libnoise — the four coherent generators are ported to Rust in-tree.

**Key-list note (requires a ticket update):** `ripple` is driven by three keys that are **not** in ticket 14's list — `fuzzy_skin_ripples_per_layer`, `fuzzy_skin_ripple_offset`, `fuzzy_skin_layers_between_ripple_offset`. Shipping the `ripple` value requires adding them to ticket 14. This packet declares and wires them; the ticket/map update is reported, not applied.

## Prerequisites and Blockers

It builds the `should_fuzzify` gate and the `fuzzy_skin_mode` switch that this packet extracts into `fuzzy-skin-core`. **259a carries an open `[BLOCK]` (its BLOCK-1, an IR schema change); this packet cannot start until 259a is `implemented`.** Name/shape reconciliation: 259a leaves the single noise sample in `apply_fuzzy_skin` as `rng.next_f32() * fuzzy_skin_thickness`; this packet replaces that one expression with a generator call and moves the surrounding function into the shared crate unchanged.
- Ordering, not gating: packets 253–258 precede this packet in the queue and touch different modules.
- Unblocks: wayfinder ticket 14's resolution (jointly with 259a).
- Activation blockers: none of its own. No `[BLOCK]` in this packet's `design.md`; it is gated only by 259a's.
