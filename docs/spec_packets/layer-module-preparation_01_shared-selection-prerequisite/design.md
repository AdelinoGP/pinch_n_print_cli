# Design: shared-selection-prerequisite

## Corrected premise and controlling paths

The former design-choice blocker is falsified. Absolute workspace-root rechecks verified these PREEXISTING symbols; there is no producer-config inheritance decision to make:

- `bind_module_config_view` (`crates/slicer-scheduler/src/execution_plan.rs`) freezes the fully resolved config filtered to the module's declared schema keys. This is explicit invocation-effective authority for genuinely non-region work.
- `WasmRuntimeDispatcher::dispatch_layer_call` (`crates/slicer-wasm-host/src/dispatch.rs`), `Layer::AnchoredEvents` arm, already installs region fields plus invocation-default fields and passes effective config to the actual module export. In contrast, `execute_anchored_event_collections_with_mode_and_feedrate` (`crates/slicer-runtime/src/layer_executor.rs`) commits a synthetic host closure with `config_view: None` and does not invoke a module there. Do not conflate them.
- `build_paint_layer_data_with_plan` (`crates/slicer-wasm-host/src/dispatch.rs`) uses explicit `GlobalLayer.is_raft`; raft plan is print-wide and deliberately has no support-entry anchor filter.
- `support_carrier_regions` (`crates/slicer-wasm-host/src/dispatch.rs`) creates chain-empty compatibility handles when a support entry identity is absent from the slice. `SupportPlanEntry` has no variant/config binding. These facts require explicit non-region context and an invocation config channel, not new bindings.
- `AuthoredColoringContext::{granted_regions, allows}` (`crates/slicer-wasm-host/src/marshal/out.rs`) is pair-keyed. Its grant construction and commit enforcement must become full-origin authority in this prerequisite.

The mechanical missing channels are: pair-keyed delivery maps; chain-blind claim resolution; native views attaching only module config; carrier views omitted when native input has no slice; coarse grant keys; native conversion passing no coloring context; and separate runtime/dispatcher/native eligibility/source reconstruction. Repair those channels, not the producer contracts.

## Architecture constraints

- **Complexity-contract conformance (`resolve_active_regions` Complexity Contract, `docs/04_host_scheduler.md`).** Build full-identity selection ONCE at the late-bind seam, after `promote_global_layers` (`crates/slicer-runtime/src/layer_executor.rs`) finalizes `plan.global_layers` and all late-PrePass products are committed. Per-layer eligibility is O(1) lookup by `(global_layer_index, module_id)` into the precomputed `LayerSelectionIndex`; neither runtime nor dispatcher reconstructs candidates/config/claims or rescans support entries per invocation. Filtering and held-claim resolution occur only during whole-print construction. A NEW index is required: `ExecutionPlan::module_region_index` (`crates/slicer-scheduler/src/execution_plan.rs`) stores `ActiveRegion` values, whose config is backfilled by `backfill_active_region_configs` through `config_for_region_smallest_chain` (`crates/slicer-runtime/src/layer_executor.rs`), with no `variant_chain` or held-claim results. Reusing it would re-canonize the identity loss this packet repairs. The new index conforms to the normative lookup contract; it is NOT an exception or deviation. Transport may traverse already selected targets and current delivered geometry, but never repeat activation/config/claim selection.
- Shared selection is host-side Rust only. ONE existing wasm-host field addition, `LayerStageInput.selection`, and ONE Blackboard product are required. No IR, WIT, manifest, SDK request/response, runner-trait signature, `CompiledModuleStatic`, `CompiledModuleLive` or schema/version changes. The exact existing input-literal inventory and bounded migration steps are below.
- The schema-roster channel is `pub use slicer_schema::{StageSpec, STAGES};` in `crates/slicer-wasm-host/src/selection.rs`; runtime supplies `slicer_wasm_host::selection::STAGES` and never names `slicer_schema` directly. No runtime manifest/dependency edit is required. Every direct `run_stage` caller supplies `Some`; `None` is confined to non-dispatching direct builder/accessor fixtures and the AC-N1 rejection control, not a legacy dispatcher exemption.
- Use PREEXISTING `OriginId` (`crates/slicer-wasm-host/src/marshal/origin.rs`), with unmodified ordered `variant_chain`, for call-local model delivery/grants. Resolve config with PREEXISTING `RegionKey`, including global layer index, before converting to call-local origin. Never sort chain elements, regenerate IDs, or stringify paint values.
- Production selection/configuration is provenance-independent (ADR-0056). Both dispatch legs consume the same precomputed call-local selection through `input.selection`. `bind_module_config_view` remains the only live binding construction path; no alternate scope-stack resolution here. For module-backed Layer stages bound to the index, `LayerSelection`'s build-time exact-key configs supersede the Packet 51 **Layer Stage Dispatch ConfigView Sourcing** per-invocation `RegionPlan.config` reconstruction; the new normative section must state that supersession explicitly and retain the Packet 51 rule for stages outside the indexed contract.
- True model config is exact `entries.get(&key)` presence check followed by `config_for(&key)` interner access (the only supported production read path per `docs/02_ir_schemas.md` Config Interner Contract); a missing entry/map is `MissingModelConfig`, not default authority. This local routing-contract error maps to the existing fatal module boundary; the broader ordinary nonfatal/fatal error policy is untouched.
- Non-region targets use `invocation_config` explicitly, already resolved and filtered. Do not create model keys, attach demand-scope inheritance, or use a sibling/model-first/`ResolvedConfig::default()` source for them. Carrier wire handles may retain their existing object/region/empty chain for compatibility, but the tagged projection records their non-region source.
- Snippets for WASM-source staleness, coordinates and Orca delegation are absent: no guest source, geometry algorithm/conversion or Orca port changes. Real guest tests still require the ordinary artifact freshness gate before attribution. No accelerated-artifact claim is made.

## Selected approach and exact semantics

The public NET-NEW seam and full shapes are summarized in `packet.spec.md`: `build_layer_selection_index(LayerSelectionIndexInput<'_>) -> Result<LayerSelectionIndex, LayerSelectionBuildError>`, `LayerSelectionIndex::selection_for`, `LayerSelectionModuleInput`, and unchanged `LayerSelection`/target/inner-error/presence shapes. `pub struct LayerSelectionBuildError { pub error: SelectionError, pub stage_id: String, pub module_id: String }` is NET-NEW in `crates/slicer-wasm-host/src/selection.rs`; it carries the failing input module/stage identity without changing `SelectionError::{UnknownLayerStage { stage_id: String }, MissingModelConfig { key: RegionKey }}`. Implementation belongs to that selection module, not a per-call config helper or preparation API. The numbered rules below run at BUILD time, once for every bound module-backed Layer module and every committed global layer; a private per-layer routine is permitted only inside the whole-print builder.

`LayerSelectionIndexInput.stage_roster` borrows the schema's `StageSpec` roster through the public `StageSpec`/`STAGES` re-export in `crates/slicer-wasm-host/src/selection.rs`. Production and test runtime callers pass `slicer_wasm_host::selection::STAGES`; schema validation inside wasm-host retains its existing schema dependency. No second roster or runtime production dependency is introduced.

Runtime adds NET-NEW `pub fn build_and_commit_layer_selection_index(plan: &ExecutionPlan, blackboard: &mut Blackboard) -> Result<(), LayerStageError>` in `crates/slicer-runtime/src/layer_executor.rs`. Both `promote_global_layers` caller paths in `crates/slicer-runtime/src/pipeline.rs` and `prepare_prepass_context` in `crates/slicer-runtime/src/run.rs` call it immediately after promotion, before per-layer execution or returning the prepared context. It is public so runtime fixtures driving executor entry points directly provision through this same production channel. Plan compilation is too early: production supplies empty global layers/region plans to `build_execution_plan` (`crates/slicer-scheduler/src/execution_plan.rs`), before slices/region map/support products exist. Keep `promote_global_layers`'s existing signature; this adjacent fallible build/commit path consumes committed products and the finalized plan.

Storage is ONE immutable `Option<Arc<LayerSelectionIndex>>` product on `Blackboard` (`crates/slicer-runtime/src/blackboard.rs`), initialized to `None` by `Blackboard::new`, with NET-NEW `layer_selection_index` accessor and `commit_layer_selection_index` write-once commit path. Duplicate commit uses a runtime-local error mapped to the existing fatal boundary, NOT a new `BlackboardPrepassSlot`/`BlackboardError` variant (`crates/slicer-ir/src/stage_io.rs`); the existing `commit_prepass` helper cannot label this host-only product without an out-of-scope IR change. Runtime can name both IR and wasm-host types; scheduler `ExecutionPlan` cannot name wasm-host `OriginId` and is not extended. The builder receives all committed layers' slices, exact region map, optional support plan and available committed perimeter products, plus schema roster/static module metadata/config. Resolve exact model/perimeter authority via `entries.get(&key)` then `config_for(&key)` during BUILD, not Layer dispatch. Missing authority returns inner `MissingModelConfig` in `LayerSelectionBuildError`; stage/module context is carried by the wrapper, never recovered by rerunning selection. The runtime late-bind build site maps ANY `LayerSelectionBuildError` to `LayerStageError::FatalModule { stage_id, module_id, message }` (`crates/slicer-ir/src/stage_io.rs`), preserving the wrapper's stage/module identity and including the inner error rendering in `message` (the exact `RegionKey` for `MissingModelConfig`), before any Layer invocation. Commit only a fully successful index; never expose a partial index.

Every bound `(layer.index, module_id)` has an entry, even if `invoke = false` or targets are empty. Missing index, missing bound pair, or absent `input.selection` on production module dispatch is an internal-consistency fatal, never a fallback resolver. Later-produced perimeter geometry uses prevalidated full-origin authority from model/source keys and available committed perimeter keys; no later per-call config resolution is permitted. The index stores selected source descriptions/configs, not predictions of future geometry; current committed products still travel through the existing input fields.

This storage/borrow contract also governs fixtures: every direct `run_stage` caller holds an indexed entry and supplies `Some`. `None` is legal only in non-dispatching direct builder/accessor fixtures and the AC-N1 rejection control; it never requests reconstruction or grants test-only dispatcher permission.

The index is SELECTION METADATA ONLY: selected full identities, exact-key configs, held claims, merged membership, carrier/raft/anchored contexts and support presence are computed once. Payload GEOMETRY is always the CURRENT call-local product: the arena slice for the current layer (including earlier same-layer commits, notably `LayerStageCommit::Perimeters` in `crates/slicer-runtime/src/layer_executor.rs` calling `sync_perimeter_infill_areas_into_slice` in `crates/slicer-runtime/src/region_partition.rs`), current support-plan roles and current perimeter products, associated to indexed identities by full `RegionKey`/`OriginId`. Dispatch uses the index to decide WHICH identities/configs/claims to deliver, never re-derives selection, and never substitutes the build-time snapshot for current geometry. A selected identity absent from current products is delivered in its current (possibly empty) state, not as stale bytes.

1. Validate stage through `slicer_schema::{STAGES, stage_by_id, TIER_LAYER}` and `StageSpec.wit_export`. Reject unknown, non-Layer and host-only stages. Use the returned stage identity for ordinary dispatch; derive the supported set from schema rather than maintaining a second roster.
2. Apply the existing paint gate when `paint_semantics = Some`: empty declared set is transparent; absent slice conservatively allows; otherwise at least one chain semantic must match. Runtime supplies this metadata to the whole-print builder; dispatcher does not supply metadata or rerun the gate. Gate failure yields `invoke = false`, no targets/views, explicit support presence, and an unchanged invocation config. No model config is demanded for work that is not selected.
3. Construct candidate model sources from current slice. Only `Layer::Perimeters` uses existing `perimeter_source_regions`; all other stages use ordinary slices as today. Reuse that geometry implementation rather than duplicating its unions/angle pairing. Record exact matching modifier/base membership separately in `Model.members`, excluding footprint-only sources as that helper does. Include the base itself. The merged source's config and held roles come from its base key, not a child's config or first member. Future consumers can inspect membership without predicting later geometry.
4. For each candidate, require full-key config and use it for both filtering and claims. Preserve the existing support-family matcher (`module_claims_match_active_region` in `crates/slicer-scheduler/src/execution_plan.rs`) semantics, including compatibility `support_generator`/`support_type` mapping, but apply it to this exact resolved model config rather than choosing a chain-less active-region config. A temporary `ActiveRegion` adapter may carry that resolved config to the existing matcher; it does not create a non-region key. Preserve `resolve_held_claims`/`FillHolders` (`crates/slicer-scheduler/src/validation.rs`); retain every held role, not one winner. Filter the config map through `ConfigView::from_declared` using invocation view keys, including resolved extensions. Memoize repeated `ConfigId` conversions; never memoize identity/claims solely by object/base pair. Capture the candidate's non-negative resolved `extensions["extruder"]` tool as `SelectedLayerTarget::resolved_role_tool` at BUILD time (host tool authority; never surfaced through a module config view) so ordinary tool attribution consumes indexed authority instead of re-reading the live `RegionMapIR` during invocation.
5. Support carriers apply only where ordinary `Layer::Support` currently delivers them: held-family match, `entry.global_layer_index == layer.index as i32`, `decline_reason = None`, nonempty role geometry, and identity absent from slice regardless of polygon emptiness. This is the actual predicate in `support_carrier_regions` (`crates/slicer-wasm-host/src/dispatch.rs`); `anchor_layer_index` is preserved provenance, not carrier eligibility. At selected layer 7, global 7/anchor 3 selects, while global 3/anchor 7 does not. Move/reuse the existing carrier helper in the shared module; keep a delegating compatibility wrapper if old callers require it. Preserve body/demand IDs, family and anchor in `SupportCarrier` context. Multiple eligible entries remain distinct targets even if one transport carrier is deduplicated by object/region; provenance must not disappear. Derived carrier geometry handles use invocation config/held non-fill claims and no coloring grant. They must be delivered even with `slice = None`; prepared-region data must not be indexed into a carrier using a model index.
6. On explicit raft layers, record `Raft` only for stages that currently consume the raft paint view (`Layer::Infill`, `Layer::Support`), with invocation config and module claims. Do not filter print-wide raft plan by support entry anchor, infer raft from index, or turn raft into a model `RegionKey`. Optional plan absence is recorded, never filled by a fabricated raft plan. Existing raft/model view coexistence remains possible.
7. Actual `Layer::AnchoredEvents` records one `AnchoredStage` invocation context with the physical layer index and invocation config, even without slice targets. This describes scheduled module generation, not entities later scheduled by `ExecutionPlan::anchored_invocation`. Existing entities/capabilities/provenance validation and synthetic closure config are unchanged.
8. `support_plan_presence` is `Absent` for `None`, `Present` for `Some`, even if empty. Support-family eligibility requires a selected model matching family, a qualifying carrier, or applicable raft work; none means `invoke = false`. Paint-transparent non-support stages retain invocation with an empty target list. Thus `invoke` is not defined as `!targets.is_empty()`. Successful empty output remains ordinary `Ok(None)`, not a preparation ready state.
9. At BUILD time populate `perimeter_configs` from exact full keys for committed perimeter products available in the snapshot and from the selected model/perimeter-source identities whose perimeter geometry can arrive later through the existing input channel, filtered identically. A missing exact perimeter key is also `MissingModelConfig` and fails before any Layer invocation. Later committed geometry is marshalled with these prevalidated full-origin configs, not by consulting the region map again; an unexpected delivered identity without indexed authority is an internal-consistency fatal, not default config. This transport config map predicts neither geometry nor preparation targets. Model and carrier contexts sharing a legacy wire origin are forbidden by carrier absence rules; check this rather than overwriting a model entry. Raft/anchored config remains request-wide.

10. **RegionMap key space and painted-id inversion.** `RegionMapIR.entries` keys painted variants by their BASE region id plus the ordered chain, and modifier children by their modifier sub-id plus chain (`execute_region_mapping_inner` in `crates/slicer-core/src/algos/region_mapping.rs`). Post-paint `SliceIR`/`PerimeterIR` ids for non-modifier chained regions are DERIVED: `paint_variant_region_id` in `crates/slicer-core/src/algos/paint_segmentation/mod.rs` mints `base * PAINT_VARIANT_REGION_ID_STRIDE + h`, with `h in [1, 999_999]`; modifier-child ids use the flagged namespace (`modifier_sub_region_id` / `modifier_base_region_id` in `crates/slicer-ir/src/slice_ir.rs`). The whole-print builder's `key_for` in `crates/slicer-wasm-host/src/selection.rs` must resolve every model/perimeter candidate into the map key space before its single exact `entries.get`: modifier-namespace ids stay verbatim; non-modifier nonempty-chain ids invert exactly by `id / PAINT_VARIANT_REGION_ID_STRIDE`; empty chains stay verbatim. This is an addressing translation of ONE identity and the exact inverse of the documented minting: it regenerates no identity and is NOT config-authority fallback. Direct-id tolerance/fallback is forbidden; `MissingModelConfig` carries the map-space key. Modifier-child membership compares `modifier_base_region_id(child_region_id)` with the parent's RAW derived id, while the parent's indexed key carries the base id. Fixtures must be canonical: chained non-modifier slice/perimeter ids are derived from their base; map keys carry the base id plus the same chain. The normative section in `docs/04_host_scheduler.md` owned by Step 11 must state this encoding rule.
   Provenance: added during implementation after the measured production mismatch between base-keyed `RegionMapIR.entries` and derived `SliceIR` ids.

### Ordinary production consumers

- Runtime test-side migration uses selection-aware direct-dispatch helpers in `crates/slicer-runtime/tests/common/mod.rs`: accept stage/layer/module identity, claims, invocation config and static paint metadata, build entries ONLY through public `build_layer_selection_index`, and hold the returned index across the borrowed input and `run_stage` call. No second resolver, implicit missing-map seeding or fabricated `LayerSelection` is permitted. Every runtime direct-dispatch fixture obtains selection through these helpers; `run_layer_and_commit_with_bundle` supplies the bundle's static metadata internally. The separate executor-driven fixture class (Steps 2U–2X) must call public production `build_and_commit_layer_selection_index` (`crates/slicer-runtime/src/layer_executor.rs`) after seeding `slice_ir` and any exact map data and before direct `execute_per_layer`/capture entry points; no test-local gathering that could drift. Audit seeded slices for candidate regions of bound module stages and add only minimal exact committed `RegionKey` map entries aligned with intended config, preserving every assertion; slices with no regions need no entries. Production-driver fixtures still exercise the real late-bind build/commit seam, never substitute test-helper selection for AC-B4. The fourteen parity files obtain theirs in/through `run_integrated_parity`'s closure or an equivalent shared harness addition (`crates/slicer-runtime/tests/common/integrated_parity_harness.rs`); today its closure exposes live modules but not static metadata and its `CompiledModuleBuilder` omits `region_split_semantics`. The harness addition must retain manifest-derived static paint metadata for both bindings and expose it to the common helper, without changing production module shapes or introducing a test-local roster/resolver.
- `execute_single_layer_inner` and the capture-path eligibility call site in `execute_captured_stages_with_support_tools` (`crates/slicer-runtime/src/layer_executor.rs`) consume the Blackboard index with O(1) `selection_for(layer.index, module_id)` lookups and use `invoke`. Remove their independent paint/family/carrier gating. At both production input constructions set `selection: Some(selection)` to the borrowed indexed entry. Keep PREEXISTING public `module_invocation_allowed_on_layer` as a compatibility wrapper over NET-NEW public `selection::paint_allows_layer`, not a second implementation. Preserve scheduling, instrumentation boundaries and synthetic anchored handling. No runner-trait signature changes.
- `WasmRuntimeDispatcher::run_stage` (`crates/slicer-wasm-host/src/dispatch.rs`) receives `input.selection: Option<&LayerSelection>`; if it is `None` for a module scheduled on the current layer, this internal-consistency violation returns `LayerStageError::FatalModule` naming the scheduled stage/module, and neither the native entry nor the WASM guest is invoked or commits output. With a selection, both legs return without invoking when `invoke = false` and never recompute selection. Remove pair-key/first-match/default config and claim authority; do not refilter/rederive carriers. Build transport maps solely from selected targets/perimeter configs; invocation fields are only for invocation reads and explicitly tagged non-region handles. Coloring grants derive from selected model full origins.
- `dispatch_layer_call`, `push_slice_regions` (`crates/slicer-wasm-host/src/dispatch.rs`), and native production construction (`crates/slicer-wasm-host/src/marshal/native.rs`) consume indexed target membership/config/claims with CURRENT call-local geometry, never the `slice_regions` build-time snapshot as payload. Associate current model/member geometry by full `RegionKey`/`OriginId`; use stored merged membership to assemble current member geometry without repeating selection or rediscovering membership. Current support roles and perimeter products supply their geometry under indexed authority; an absent selected identity has its current possibly empty state. Neither leg refilters or rederives carriers independently. Prepared data must remain associated with source identity; filtering/merging must not shift index-based annotations onto another source. AC-B4 witnesses post-Perimeters fill-mask delivery to same-layer Infill with the original indexed configs/claims.
- Add NET-NEW `marshal::native::build_native_layer_request_from_selection(stage_export: &'static str, layer_index: u32, input: &LayerStageInput<'_>, module: &CompiledModuleLive<'_>, selection: &LayerSelection, is_raft: bool) -> NativeLayerRequest`. Production `run_stage` calls it. Retain existing direct-builder signatures for legacy transport tests only; factor common marshalling, do not leave a second live config authority. Old builders are not forward-dependency exports and must not be called by production dispatch after this packet.
- `HostExecutionContext` changes existing claim/config maps to `HashMap<OriginId, ...>`, both setters/readers to full-origin lookup. Slice/perimeter accessors parse canonical numeric IDs and convert full paint values using existing `parse_canonical_region_id` and `marshal::leaf::convert_paint_value`. Resource state/origin output side effects remain unchanged. Exact missing model resources must not read `default_config_fields`; projection prevalidates live resources, accessors reject absent full-origin entries. Invocation-default fields remain for actual invocation config resources; map entries explicitly carry carrier config. Malformed `"01"` fails with the existing canonical-ID error.
- Coloring grants become `HashSet<OriginId>`. `allows` takes a complete origin and checks range plus grant. `enforce_authored_coloring` constructs that origin from committed region chain. Keep the existing two-sided `authored_coloring_granted` predicate and stripping semantics. Add NET-NEW `commit_native_layer_response_with_authored(response: &NativeLayerResponse, stage_export: &str, layer_index: u32, support_plan: Option<&SupportPlanIR>, authored: Option<&AuthoredColoringContext>)` with the existing return type. Production dispatch supplies projection-derived context; old `commit_native_layer_response` remains a deny-by-default wrapper for direct callers. No SDK envelope changes.

Rejected: first-match/default model authority; a prepared-only unused index; producer inheritance/WIT bindings; treating carrier handles as model keys; using synthetic anchored commits as module eligibility evidence; a new stage roster; independent native/WASM selection algorithms.
