# Design: whole-print-input-views

## Controlling Code Paths

Existing facts: `PrepassStageInput` (`crates/slicer-wasm-host/src/binding.rs`) contains mesh, optional layer_plan/slice_ir/region_map/support_analysis/support_geometry and a lifetime anchor; no surface classification. `SurfaceClassificationIR`, `SlicedRegion`, `RegionMapIR`, `RegionKey`, `GlobalLayer`, seam/support IRs are in `crates/slicer-ir/src/slice_ir.rs`. Existing `slice-region-view` (`crates/slicer-schema/wit/deps/ir-types.wit`) has shell/internal-bridge/sparse accessors, but is an ordinary resource with infallible read methods, not this capability's permission-checked input contract. Existing `mesh-object-view` (`prepass-types.wit`) is a value record, not a batched resource. Do not silently reuse either as if it supplied this contract.

FORWARD-DEP #03 owns `preparation.rs`, `preparation_host.rs`, `preparation_bindings.rs`, `preparation_native.rs`, `preparation_wasm.rs`, SDK preparation facade and canonical layer-preparation package. FORWARD-DEP #01 owns the selection seam; full shapes appear in packet.spec and producer's public exports. Neither is currently implemented.

## Architecture Constraints

- ADR-0066: same-module owner-private preparation, completed PrePass input and separate selected targets, no unfinished arenas/provider catalog. ADR-0045/0056: imported typed identity, independently versioned capability, one native/WASM selection model. No amendment or new ADR.
- No change to IR field layouts or schema constants; no guessed future schema version. Extend only the draft preparation capability before its production release, keeping row 03's qualified `interface()` identity. Plain old ordinary artifacts retain their worlds/imports/signatures.

## Typed Fields and Mapping — all algorithm-consumable views

Types below are NET-NEW SDK DTOs in `slicer_sdk::preparation`, not additions to `slicer_ir` or imports from `slicer_schema`. Native DTO geometry/config values use `slicer_ir` types (also available through existing `slicer_sdk::ir`), but paint values/chains/keys use the capability-owned DTOs below. Guest conversions materialize declared-key-filtered owned `slicer_ir::ConfigView`, following existing SDK conversion patterns, not a raw resolved config. Each listed snake_case field becomes the same kebab-case WIT field; preparation keys use `global-layer-index` (not the ordinary `region-key.layer-index` spelling), and RegionId's u64 maps to canonical decimal string (no leading zeros). No JSON/opaque-byte input encoding.

### Capability-Owned Lossless Paint Identity

Disk authority is `slicer_ir::PaintValue` (`crates/slicer-ir/src/slice_ir.rs`): `Flag(bool)`, `Scalar(f32)`, `ToolIndex(u32)`, **`Custom(String)`**. Existing ordinary WIT `paint-value` and prepass `paint-value-view` omit Custom. Do not widen either shared package, reject valid Custom keys, or encode Custom as a different native variant.

- NET-NEW `slicer_sdk::preparation::PreparationPaintValue::{Flag(bool),Scalar(f32),ToolIndex(u32),Custom(String)}` maps exhaustively and bidirectionally to native PaintValue without normalization, string parsing or fallback. Preserve exact UTF-8 strings and finite f32 bit identity including signed zero. Native PaintValue documentation forbids constructing NaN; that existing invariant does not justify rejecting Custom.
- NET-NEW `PreparationVariantChain = Vec<(String, PreparationPaintValue)>`; retain semantic names, exact value variants and element order. WIT `preparation-paint-value` is `variant { flag(bool), scalar(f32), tool-index(u32), custom(string) }`; `preparation-variant-chain` is `list<tuple<string, preparation-paint-value>>`.
- NET-NEW `PreparationRegionKey { global_layer_index: u32, object_id: String, region_id: u64, variant_chain: PreparationVariantChain }`; WIT `preparation-region-key` fields `global-layer-index:u32, object-id:string, region-id:string, variant-chain:preparation-variant-chain`. Use this key for region config keys, seam keys and selected Model `key`/`members`; #01's imported native RegionKey shape remains unchanged and converts losslessly at the capability boundary. PreparationRegion.variant_chain uses PreparationVariantChain.
- NET-NEW SDK implementations `From<&slicer_ir::PaintValue> for PreparationPaintValue`, `From<&PreparationPaintValue> for slicer_ir::PaintValue`, `From<&slicer_ir::RegionKey> for PreparationRegionKey`, `From<&PreparationRegionKey> for slicer_ir::RegionKey` define concrete bidirectional conversion seams. Chain elements convert individually in order; do not attempt an orphan impl on the Vec alias or change #01's key type.
- NET-NEW `PreparationPaintStroke { triangles: Vec<Point3>, semantic: String, value: PreparationPaintValue }` and `PreparationPaintLayer { semantic: String, facet_values: Vec<Option<PreparationPaintValue>>, strokes: Vec<PreparationPaintStroke> }` map to `preparation-paint-stroke`/`preparation-paint-layer` with identical kebab-case field names. Mesh paint must not route through the smaller ordinary/prepass value variants.
- PreparationRegion.segment_annotations is `HashMap<PaintSemantic, Vec<Vec<Option<PreparationPaintValue>>>>` natively. NET-NEW WIT `preparation-segment-annotations-polygon { values:list<option<preparation-paint-value>> }` and `preparation-segment-annotations-entry { semantic:paint-semantic, polygons:list<preparation-segment-annotations-polygon> }` reuse only the existing complete paint-semantic identity, including custom(string), not its incomplete paint-value records.

Do not derive a different order from serialized display strings. Reverse conversion preserves exact identity rather than reconstructing a key by first match.

### WIT Shape and SDK Method Results

Extend imported `print-preparation-input` in its existing `preparation-types` interface. Define NET-NEW records/variants from the table and lossless paint inventory in that same interface; import existing `slicer:types/geometry`, `slicer:config/config-types.config-view`, and `slicer:ir-handles/ir-handles.{paint-semantic,surface-group,quartile-band,seam-position}` by exact identity. Do **not** import ordinary region-key/paint-value/segment-annotations-entry or prepass paint-layer-view for preparation identities/paint: use capability-owned preparation-region-key/preparation-paint-value/annotation/mesh-paint records. Define local preparation facet/bridge/overhang/support/query/source records where existing smaller producer proposals cannot express all fields. Never invent an existing `surface-classification-view` resource.

`layer-count: func() -> result<u64,preparation-input-error>`; batch methods use `offset:u64,max-items:u64`, plus `layer-index:u32` for layer-scoped methods or `object-id:string` for mesh buffers. Required results: `layers -> list<preparation-layer>`, `regions -> list<preparation-region>`, `region-configs -> list<preparation-region-config>`, `mesh-objects -> list<preparation-mesh-object>`, `mesh-vertices -> list<point3>`, `mesh-triangles -> list<tuple<u32,u32,u32>>`, `selected-targets -> list<preparation-selected-target>`, `mesh-queries(requests:list<preparation-mesh-query>) -> list<preparation-mesh-query-result>`. Optional-capable results: `surface-objects -> option<list<preparation-surface-object>>`, `surface-layers -> option<list<preparation-surface-layer>>`, `seams -> option<list<preparation-seam>>`, and support methods each `option<preparation-...-batch>`. All are wrapped in `result<value,preparation-input-error>`. Native facade returns the identical SDK DTO shape with Vec/Option and errors, not borrowed host IR references.

For support-analysis, offset/count applies independently to each canonically sorted collection in the batch (candidates, four keyed geometry maps and family assignments); settings/envelope are invariant metadata. Document this explicitly; no zip-induced record loss. For support geometry/plan it applies to entries. Snapshot indices avoid rescanning/copying the entire print; bounded output copies only requested records, metadata retained in shared backing. Mesh query request/result order is caller order.

NET-NEW SDK native trait `slicer_sdk::preparation::PrintPreparationRead: Send + Sync` has the exact PrintPreparationInput method signatures/result types enumerated in packet.spec and this section, with `&self` receivers. Add `PrintPreparationInput::from_host_input(reader: Arc<dyn PrintPreparationRead + Send + Sync>) -> Self`; keep #03's controlled-fixture `from_host_reader` constructor unchanged. One production host implementation wraps owner plus indexed Arc backing, and both native facade and WASM handlers call it. WIT input-error variant names are `access-denied`, `range-error`, `arithmetic-overflow`, `missing-required(string)`, `unsupported-read(string)`, `invalid-input(string)`, `unknown-object(string)`, `selection-rejected(string)`; SDK/schema named-field enum variants map to these string payloads without losing diagnostic text.

Reuse `raycast_z_down_against(&ObjectMesh,f32,f32,f32)->Option<f32>`, `surface_normal_at_against(&ObjectMesh,f32,f32,f32)->Option<Point3>` and `transform_mesh_point` from `crates/slicer-wasm-host/src/host.rs` by making them crate-visible. Extract NET-NEW `object_bounds_against(&ObjectMesh)->Option<BoundingBox3>` from `object_bounds_mesh_query`; existing ordinary helper preserves its current empty-object error, while preparation returns InvalidInput naming empty mesh bounds. Permission and object lookup stay outside these pure geometric helpers; preparation must never rely on ordinary ir-access to grant its own query permission. Empty mesh objects expose optional bounds: `PreparationMeshObject.bounds: Option<BoundingBox3>`; ObjectBounds query on that empty object is InvalidInput. No mesh-query algorithm is changed.

### Permissions and Availability

Production typed `[preparation].input_reads` vocabulary is exactly `layer_plan`, `slices`, `region_map`, `mesh`, `selected_targets`, `surface_classification`, `surface_classification_optional`, `seam_plan`, `seam_plan_optional`, `support_analysis`, `support_analysis_optional`, `support_geometry`, `support_geometry_optional`, `support_plan`, `support_plan_optional`. Required/optional alternatives for the same product are mutually exclusive (`InvalidInput` naming conflicting tokens). Unknown strings are `UnsupportedRead`. Preserve #03's separate recognized pilot token `fixture` syntactically so its existing production-mode AccessDenied test still reaches the actual read; it has no production prerequisite/grant effect and enables reads only through #03's feature-gated controlled input mode. `.views()` is diagnostic metadata owned elsewhere, not permission vocabulary.

| --- | --- | --- |
| layer_count, layers | layer_plan / none | committed LayerPlanIR |
| regions | slices / none | slices for every schedule index |
| region_configs | region_map / none | exact authoritative map/config indices |
| mesh_* | mesh / none | committed MeshIR |
| selected_targets | selected_targets / none | shared projection inputs and matching frozen owner |
| surface_objects, surface_layers | surface_classification / surface_classification_optional | product exists if required |
| seams | seam_plan / seam_plan_optional | product exists if required |
| support_analysis | support_analysis / support_analysis_optional | product exists if required |
| support_geometry | support_geometry / support_geometry_optional | product exists if required |
| support_plan | support_plan / support_plan_optional | product exists if required |

Grant checked before existence/range lookup. Undeclared => AccessDenied even for absent product. Granted optional absent => Ok(None); granted present empty => Ok(Some(empty)). Required absence is MissingRequired at `from_committed`, before native/guest invocation or output transaction starts. An explicit empty product is available, not missing. Owner mismatch/disposed resource => AccessDenied, no argument can name another provider. No method exposes PerimeterIR/InfillIR/SupportIR/LayerCollectionIR or any plan provider id. Ordinary host-services imports must not bypass this: preparation-call mesh service adapters gate `mesh` identically, preserving ordinary-call behavior.

Failure phase is explicit. Constructor/from_committed rejection (unsupported token, malformed snapshot, missing required product, shared selection error) has zero invocation markers and no output transaction. Handler rejection (undeclared/foreign/disposed resource, bad range, unknown query object or checked handler overflow) requires an already-entered fixture invocation: markers are nonzero and the exact PreparationInputError is recorded. A read error never poisons PreparedPlanOutput. A fixture mode that catches it may continue and publish success; a separate mode returns a ModuleError after staging a valid piece, so #03's existing transaction finalization publishes nothing and current() stays NotReady. Do not assert PoisonedOutput for arbitrary reads; that is exclusively the existing output-writer fault contract.

Shared observation fixtures emit an invocation log marker before reading and log the actual typed Result error, rather than a predetermined expected string, before their deliberate ModuleError return. The production driver captures those native/guest logs. Failed publication is verified through owner current(); do not attempt to read discarded staging to obtain the error witness. Successful caught-read controls may encode their actual read error in the published observations piece. Constructor failures emit no marker because fixture code was never entered.

### Shared Selection, Ordering and Validation

Construct inputs once from committed products. Validate unique increasing finite GlobalLayer indices/Z, per-schedule SliceIR index/Z match (including empty raft slice), duplicate full keys, config pool indices, finite geometry/query parameters and index-aligned internal bridge angle/skeleton wall-count arrays. Missing off-schedule support rows are legal and retain signed indices; they do not add fabricated GlobalLayers. Empty angle vector keeps existing fallback convention. Unknown mesh object => UnknownObject; malformed metadata => InvalidInput with named field. Checked u64 conversions/counters => ArithmeticOverflow.

Call #01 `project_layer_selection` for each canonical layer with `paint_semantics: Some(...)` and frozen module/stage/claims/config, `slice: Some(committed layer)`, `region_map: Some(authoritative map)`, actual optional support plan, **`perimeter: None`**. Consume `invoke` and all selected source fields, not `slice_regions` as future final geometry. Keep empty source lists legal; this transport does not schedule or skip a preparation. InfillPostProcess and other downstream stage model source context remains current committed model identity/config with explicit absence of future outputs; perimeter-stage merged members come from the shared source projection, not reconstituted hypothetical walls. Carrier entry_index stays tied to retained input order; canonical presentation sorting must never renumber that reference.

Store canonical schedule order (increasing index, preserve exact supplied Z), then full key `(global_layer_index,object_id,region_id,variant_chain)` using existing PaintValue total order (never reorder elements within a chain). Sort object maps by object id, support keyed maps by full key, seam entries by full RegionKey, support entry presentation by signed global index/object/region/family with original index as deterministic tie-breaker. Selected Model targets by full key; non-model targets by explicit source tag and provenance/index, not polygon position. Batch offset is ordinal in this stable presentation; unknown layer index => RangeError. Clip count to remaining records before checked conversion/end math; offset==len valid empty, offset>len RangeError. No cursor.
