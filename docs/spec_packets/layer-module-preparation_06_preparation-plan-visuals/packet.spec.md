# Packet Contract: preparation-plan-visuals

## Goal

Publish optional owner-private typed XY diagnostic snapshots atomically with prepared plans, and render them through the existing visual-debug bundle path with truthful execution evidence.

## Scope Boundaries

Two internal gates remain distinct: A is generic projection transport, validation and atomic ownership; B is visual-debug selection, production-prefix capture, rendering and bundle compatibility. This is framework work, not lightning visualization or an opaque payload decoder. Authoring produced a draft; implementation and acceptance are recorded in this packet.

## Implementation Deviations (recorded at implementation closure)

These are implemented facts that differ from an earlier design/plan sentence; each was verified against the tree and the acceptance matrix. None changes an AC's given/when/then.

- **Postpass taps fail closed.** A preparation visual request that also names `PostPass::LayerFinalization`/`PostPass::GCodeEmit` returns the named `Slice` rejection `"preparation visual postpass tap closure is not forwarded: <tap>"` instead of running ADR-0040's whole-print closure. The visual path disposes the print scope after preparation, so a truncated postpass capture would fabricate whole-print execution evidence. AC-5/AC-6 exercise `Layer::PathOptimization` (per-layer), not postpass. This is an explicit open scope limitation, not a silent success.
- **Fixture workspace form.** The generated fixture is a root-workspace member with no `[workspace]` sentinel, matching every shipped dual native/WASM producer fixture (`preparation-lifecycle-guest`, `preparation-transport-path`, `preparation-pilot-*`, `whole-print-input-*`). A standalone sentinel makes the required path dev-dependency fail with "multiple workspace roots".
- **Empty-scene Z.** `CommittedPreparationProjection::layer_z` carries the whole committed schedule, not only primitive-referenced layers. An explicitly completed empty scene has no primitives but still needs the real schedule Z for every rendered layer (AC-6); the host remains the sole schedule-Z authority.
- **Out-of-surface additive edits.** `crates/slicer-wasm-host/src/preparation_input.rs` gained the non-counting `schedule_snapshot`; `crates/slicer-wasm-host/tests/contract/preparation_pilot_host.rs` gained the Host-trait methods forced by the WIT addition. Both are additive/compile fallout, not design changes.
- **Owner-state coverage.** `PreparationUnsupportedOwner`/`InactivePreparationOwner` are mapped exactly and pinned by the production-unit `preparation_visual_error_mapping_is_exact_for_every_variant`, but the single always-invoked preparation fixture cannot reach those runtime states end-to-end (a non-preparation module is `UnknownPreparationOwner`; the fixture participates on every layer). The runtime validation sites are `freeze_selected_preparation_bindings` and `resolve_preparation_visual_request`. AC-N2's command runs that unit test plus `pre_execution_rejections_never_invoke_preparation`, which pins no preparation `Start` record for unknown owner/view/layer.
- **Counted-once accounting.** `capture_visual_and_dispose` pushes one `diagnostic_accounting` entry per owner/view outside the rendered-layer loop; the `multi_layer_capture_shares_one_scene_and_one_accounting_entry` runtime test asserts one entry and `Arc::ptr_eq` across two rendered layers.
- **Layer-error name.** The CLI maps the runtime `UnknownLayer` rejection to the AC-N2 name `NoApplicableLayer` (the preparation-specific `PreparationNoApplicableLayer` variant was removed to keep the named surface exact).
- **Review follow-up (2026-10-18).** The closure review's non-blocking coverage notes were addressed without behavior changes: AC-5 now asserts the execution identity/run-once record, AC-6's command includes the multi-layer Arc/accounting test, AC-7 adds repeat-run byte determinism, AC-8 asserts normative-section content, and AC-N1/N2 commands include the overflow/error-mapping/pre-execution unit tests. `docs/19` now discloses the preparation+postpass fail-closed limitation, and the packet's authoring-status prose was corrected.
