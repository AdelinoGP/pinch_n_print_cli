## Problem Statement

OrcaSlicer's `make_overhang_printable` family reshapes sliced layers so steep overhangs print as self-supporting conical slopes instead of mid-air extrusion. This port slices the mesh once in `PrePass::Slice` and never revisits the footprints, so enabling the keys is impossible: the three spellings occur nowhere under `crates/`/`modules/`/`xtask/` (claim-time grep: 20 doc-only hits, 0 code hits) and no `apply_conical_overhang` analog exists. The neighbouring `PrePass::OverhangAnnotation` stage only *classifies* overhang from the slices; nothing *grows* the slices. This packet builds the missing mutation as one coherent host-prepass slice: three config fields plus a pure kernel plus a thin builtin, ordered between slicing and every slice-differ.

## In Scope

- Three `ResolvedConfig` fields at canonical defaults: `make_overhang_printable: bool = false`, `make_overhang_printable_angle: f32 = 55.0` (degrees), `make_overhang_printable_hole_size: f32 = 0.0` (mm²); `to_config_map` emission and `apply_cli_key` round-trip for each.
- Pure kernel `slicer_core::algos::conical_overhang::apply_conical_overhang` mirroring `PrintObject::apply_conical_overhang`: per-object bottom-up sweep over `(global_layer_index, footprint)` pairs; per-layer enable check; `== 90.0` early-return; `max_dist = tan(angle_rad) * layer_h` offset of the upper footprint; small-covered-hole cut from the upper layer before offset; union into the current layer. Per-object isolation preserved (an object's layers mutate only from that object's footprints).
- Thin builtin `commit_conical_overhang_builtin` beside `commit_overhang_annotation_builtin`: reads the three keys from the raw config source (sibling convention) with canonical defaults as fallback, derives per-object footprints from committed `SliceIR` exactly like the sibling, and writes back via `replace_slice_ir`. `MissingSliceIr` ordering guard when no `SliceIR` is committed.
- Stage registration via `run_builtin_stage` strictly after `PrePass::Slice` and before `PrePass::OverhangAnnotation`.
- Tests: `ResolvedConfig` schema/defaults test (new, `slicer-ir`); kernel behaviour tests incl. default identity, angle-45 growth, angle-90 no-op, hole preservation, disabled-with-angle-set no-op (new, `slicer-core`); stage-order + raw-source-reaches-consumer + refuses-without-slices tests (new, `slicer-runtime` executor bucket with `main.rs` registration).
- Key disposition table (map Authoring-rule gate (a): zero declaration-only keys):

| `make_overhang_printable_hole_size` | wired — area threshold preserving small fully-covered base holes |

Canonical behaviour per key (claim-time delegation, ticket 78 grounding):

- `make_overhang_printable` (`PrintConfig.cpp`, coBool default `false`): master switch. Read twice in `PrintObject::apply_conical_overhang` (`PrintObjectSlice.cpp`) — a whole layer is skipped when every region disables it, and skipped per-region when the upper layer's region disables it. `false` makes the pass a no-op.
- `make_overhang_printable_angle` (`PrintConfig.cpp`, coFloat default `55.0`, domain 0–90 degrees): slope steepness. Read once in `PrintObject::apply_conical_overhang`: `== 90.0` returns early (no geometry change); otherwise radians conversion, `tan(angle) * layer_height` yields `max_dist_from_lower_layer`, the XY offset applied to the upper layer before unioning it into the current layer.
- `make_overhang_printable_hole_size` (`PrintConfig.cpp`, coFloat default `0.0` mm²): hole guard. Read once in `PrintObject::apply_conical_overhang`: scaled to area; when `> 0`, holes in the current layer smaller than this that are fully covered by the layer above are cut from the upper layer before offset/union, so recessed base holes are not closed up. `0` fills all base holes.
