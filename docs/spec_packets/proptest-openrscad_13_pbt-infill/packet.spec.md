# Independent properties for infill, linking, waves and ironing

## Goal

Exercise the five PBT-INFILL owners with bounded, independently checked whole-path or whole-footprint properties, nonvacuous witnesses, mutation controls, reproducible shrinking and measured Windows profiles.

## Why

Queue row 13 and `docs/specs/proptest-openrscad-adoption.md` §§5–7, 11–13 require real kernel coverage, valid spacing and gyroid phase domains, and source-backed coverage rather than successful random calls. The emitter/linker boundary matters: `GyroidInfill::fill_expolygon` deliberately emits **raw unclipped** waves; ADR-0025 assigns clipping and connecting to the linker. An oracle that requires raw gyroid waves to be inside a holed polygon would test the wrong contract. Conversely, checking only each pair of ironing scan endpoints misses the extruded segments between pairs in the returned polyline.

The live `adjust_solid_spacing` has the recorded open `D-209-ADJUST-SOLID-SPACING-DIVERGENCE`; a delegated read of `Fill::_adjust_solid_spacing` (`src/libslic3r/Fill/FillBase.cpp`) independently verified the upstream over-cap rule. Do not bless the current result as correct or weaken a canonical-backed boundary to make it pass. The current ironing implementation also concatenates separated scan intervals into one path; whether an actual whole-path witness fails is an **unexecuted candidate**, not an authoring-time test result.

## Scope

- In: rectilinear `scan_expolygon` and `adjust_solid_spacing`; gyroid `gyroid_f`, `align_to_grid`, `fill_expolygon` and its real native clipping primitive; linker `connect_infill`, `chain_or_connect_infill`, boundary graph/connector helpers and the actual `orchestrate_infill` identity/compatibility seam; wave `generate`; top-surface `generate_zigzag_strokes_for_polygon`. Add owner-local native properties, independent checkers, deterministic positive/empty/negative witnesses, measured Windows routine/extended profiles and focused fixes plus concrete named regressions **only for confirmed SUT defects**.
- Out: lightning generation or additional lightning property IDs: #11 owns `H-LIGHTNING-SEEDS`/`H-LIGHTNING-TREES` and its module-kernel credit. Also out: changes to other packets or the queue, a shared SDK infill API, new WIT/IR/config contracts, production visibility changes, general guest/E2E randomization, scripted/SCAD prerequisites, a live Orca differential harness, arbitrary rotational symmetry, universal nonempty output or unconditional coverage/area monotonicity. A larger confirmed defect blocks affected coverage rather than being ignored or recast as a weaker property.

- `docs/spec_packets/proptest-openrscad_02_pbt-domains/` (**draft at authoring**): its planned SDK `domains::{DomainError, GeometryBounds, GeometryDomain, GeometryCase, TopologyClass, BoundaryRule, geometry_cases, geometry_complexity}`, `oracles::{validate_geometry, point_in_region, segment_in_region, segment_relation, signed_area2}` and `regression::{ConcreteInput, format_regression_fixture}` are the exact shared test-only surface; they are **not live exports yet**. Whole-segment checking partitions all boundary intersections, not only endpoints or a midpoint.

Its optional scripted enrichment is not required here.

### Shared property discipline

Every registry callback uses `PropertyRun::new`, `bound`, `check` and a fresh `CaseGuard`, including each shrink attempt. The charter for each ID in `docs/testing/properties.md` records all source-plan §5 fields: owner/SUT, bounded domain, preconditions, real oracle dependencies, expected output, tolerance proof, mandatory witness, shrink protocol, execution profile, failure artifact/replay and concrete-regression home. #2's `validate_geometry` checks inputs; it is not a blanket output-topology assertion. Reference models must not invoke the SUT's scanner, graph projections, Boolean/offset engine, clipping routine or production validator to manufacture expected results.

Select semantic modes with `prop::sample::select(...).no_shrink()`; for a topology-to-strategy mapping use a prevalidated selector plus `prop_ind_flat_map` or equivalent with the same nonshrinking guarantee. Never use `prop_oneof![Just(...), ...]` for a mode whose witness must persist: Proptest unions can switch arms during shrinking. Preserve selected ring/hole/component, phase branch, anchor/compatibility, fallback/trim and empty-versus-positive modes. Checked owner-local builders reject missing, zero where positive is required, impossible or narrowing/overflowing profile bounds before sampling. SUT-output failures are `TestCaseError::fail`, not `Reject`, `prop_filter`, or a silent return.

Each property runs its deterministic witness independently of random selection. Construct a positive subcase when a nonempty output is mathematically/source justified, and separately exercise legitimate empty/tiny cases. Maintain per-property, per-required-positive-subcase local in-process counters of actual paths, segments, scan intervals, graph connections, sampled cells or footprints; assert the relevant count is positive after `check` succeeds. Do not rely on a random mode being selected, a loop over empty output, or a counter shared by unrelated modes. Fresh samples are still required. Deterministic controls call the **same** checker with explicitly wrong outputs and establish exact rejection; they are not SUT regressions.

For every owner, a deterministic `TestRunner::deterministic` / `Strategy::new_tree` probe drives `ValueTree::{current,simplify,complicate}`, including false-return and repeated-complicate states, for each relevant mode/class. Independently revalidate every exposed input and retained witness, exercise a nonminimal starting value and require at least one permitted structural or ordinary-parameter reduction. A false-only probe, exhausted generation, lost mode, absent context, unchecked narrowing or zero selected property is failure. If a selected profile cannot admit all mandatory inputs and a real reduction, fix the profile/strategy before accepting it.

### Property charters

**`M-RECTILINEAR-SCAN`.** Generate bounded, independently validated axis-aligned rectangles, L/U notches and rectangular-hole regions, including negative XY and a valid sub-spacing rectangle; restrict the exact sparse interval model to `cos_a = 1`, `sin_a = 0`, `x_shift = 0`, `adjust_for_solid = false`, positive `line_spacing` and finite metadata. Independently enumerate rows from the input bbox on the half-open grid and derive rectangle/notch/hole interior X intervals by arithmetic on fixture edges, not the scan implementation. For solid cases calculate expected adjusted spacing from the independently verified `M-RECTILINEAR-SPACING` reference, not from a call to the SUT. Compare the complete multiset of actual row intervals including omitted spans, check **every** actual segment with #2's boundary-inclusive `segment_in_region`, and inspect role, two endpoints, Z, width, flow, speed and `None` tool/lock. Tangential/zero-length and degenerate/empty/nonpositive-spacing modes are separate; a row count is not a segment count for a concavity. A positive sub-spacing rectangle with a positive minimum-boundary interval has one row, not a blanket zero or blanket nonempty rule. For shifted output, separately compare an integer `x_shift` to a correspondingly translated expected region; do not assert it remains inside the unshifted polygon. A removed interval, filled hole and a shortcut whose endpoints/midpoint hide an outside subinterval must fail the checker. One exact hole control uses outer `[0,10] × [0,10]` mm, hole `[2,3] × [4,6]` mm, and the mutated segment `(1,5) → (9,5)` mm: both endpoints and midpoint lie in material, but an open interval crosses the hole.

**`M-RECTILINEAR-SPACING`.** Call `adjust_solid_spacing` only with positive `distance`, nonnegative bounded width and checked arithmetic; test zero/too-large profile bounds at the test-domain builder, not division by zero in this nonvalidating kernel. Compare independently calculated interval/cap behavior to the delegated `Fill::_adjust_solid_spacing` source on explicitly representable physical domains; include width below distance, exact interval boundaries, rounding boundaries and over-cap cases. The deterministic over-cap witness is width 1.5 mm / distance 1.0 mm: the source-backed cap is 1.2 mm, not a reset to 1.0 mm. `D-209-ADJUST-SOLID-SPACING-DIVERGENCE` also records epsilon and integer-conversion differences: derive them at the selected canonical source revision and grid before asserting additional exact cases. Execute the witness before diagnosing; if the discrepancy is reproduced, fix the smallest canonical-correct owner seam and add a named concrete regression with this input and root cause. If resolution is larger or the independent canonical conversion cannot be justified, leave the family blocked, not green by encoding the current fallback. Do not claim the last scan row must touch the far boundary.

**`M-GYROID-PHASE`.** Use bounded finite `x` and phase `z`, derive `z_sin`/`z_cos` from the **same** phase and choose `vertical = abs(z_sin) <= abs(z_cos)` as the real fill caller does. Exercise both reachable orientation and flip branches, including non-singular positive/negative phases and explicit near-singular controls. Assert finite `gyroid_f` output and the mathematically derived branch ranges, plus periodic observations only where a documented f64 error envelope and distance from unstable/clamped boundaries justify them. For `align_to_grid`, use finite positive grids and safe ratios, exact dyadic witnesses on both sides of zero: e.g. grid 2, values −3, −2 and +3 map to −4, −2 and +2. Compare to an independent integer-quotient/floor interval model, including grid multiples, adjacent negative values and checked translation by whole periods. A truncation-toward-zero mutant must fail. Do not apply the implicit-surface residual to the wrong swapped/offset/clamped coordinate system; derive the exact phase/axis mapping and sampling error first, and record whether a meaningful residual subdomain is proved.

**`M-GYROID-CLIP`.** On valid finite `0 < density <= 1`, positive finite width, bounded finite Z and controlled angles, call real `fill_expolygon`; it emits raw waves, not region-clipped paths, and can extend beyond the outline. Require a deterministic nonempty rectangular wave witness and inspect every raw segment for finite coordinates, copied Z/speed and source-backed metadata, without asserting hole exclusion on raw output or mistaking the passed spacing width for the currently stamped `self.line_width`. Convert the actual paths to integer subjects and pass them through `PreparedPolylineClip::new(...).clip_batched(...)` (`crates/slicer-core/src/polygon_ops.rs`), the actual batch clipping seam used by the linker's `link_paths_without_offset`, against a controlled axis-aligned rectangle with a rectangular hole. Use its per-subject results; do not assume a flat output order. Compare **every retained and missing subinterval** against an independent rational segment-versus-expanded-rectangle/contracted-hole interval model accounting for the one-unit inflation and proved endpoint/quantization allowance; require nonempty interior observations and a hole-crossing split witness. Check all surviving segments, not just vertices. A false all-empty clip, dropped interior span or segment crossing the hole beyond the boundary band fails. The separate linker property below calls the real orchestration seam; this primitive composition alone is not a claim of end-to-end dispatch. Empty contour, nonpositive density/width and a legitimate empty clipped result are separate modes.

**`M-LINKER-GRAPH`.** Use rectangles, a concave notch, a rectangular hole and two separated components with endpoints constructed **on** known ring edges. Independently compute rectangle perimeter, ring identity, shortest forward/backward arc and expected intermediate corner positions from fixture dimensions; compare to actual `BoundaryInfillGraph`, `BoundaryRing::directed_distance`, `contour_connector` and `contour_stub` outputs, including a strictly shorter arc and a tie. Verify every connector/stub segment lies on the correct ring, including corner traversal, with checked grid-to-f32 error. Mutations replacing a concave contour walk with a chord or changing its ring must fail. Empty graph is a distinct mode. Do not use `project`, `directed_distance` or the SUT's walk to compute expected arcs.

**`M-LINKER-CONNECT`.** Construct distinguishable, nonzero paths with at least two points and endpoints on known rings. Compare each original path's ordered point/metadata sequence, possibly reversed, as a contiguous subsequence of exactly one output; independently identify added connector/stub edges and verify their entire ring walks. For controlled two-path fixtures the independent compatibility predicate is equal `role`, bit-equal `speed_factor`, equal `tool_index`, and both corresponding first/last endpoint width differences at most `0.000001` mm. Check compatible merging and each individual role/speed/tool/width mismatch, including opposite sides of the width boundary; path order alone is not a merge. Prove an outer-to-hole and a disconnected-ring pair actually project to different rings and are never extruded together; use nonvacuous output and source-path counters. `connect_infill` discards paths shorter than two points only in its connecting branch, whereas its `dont_connect` early return preserves its input: exercise those separately. Do not treat arbitrary interior endpoints as unanchorable: live `boundary_position` selects the nearest ring for ordinary interior points. Restrict exact ring-walk claims to constructed on-ring endpoints. `DEV-110` remains a separately recorded stub residual.

**`M-LINKER-CHAIN`.** Drive `chain_or_connect_infill` with nonempty, at-least-two-point paths, independent original-path multiset/metadata coverage and both sides of `AnchorParams::dont_connect`; in chain-only mode paths may reorder/reverse but must acquire no connector geometry. Do not equate adjacency in the returned list with extrusion between paths or assert a globally optimal route. Also call actual `orchestrate_infill` with full `(object_id, region_id, ordered variant_chain)` identities, same-object/same-wall-group and separate-region/tool/role/width fixtures; compare output origins and original-path provenance to an independent compatibility/ownership table. Include a legal priority/name-ordered `material` then `fuzzy_skin` chain and a distinct chain, plus a deliberately mismatched/reversed lookup as a negative exact-identity input. A missing exact view passes the prior bucket through; an empty chain is not a wildcard. Preserve region tool versus authored path tool as separate checks. `order_lock` is not an argument to the direct connector compatibility predicate: use unlocked direct inputs and test the orchestrator's locked-path bypass separately. For any majority-owner assertion construct unequal independently measured source lengths and a separate tied case; do not infer ownership from the first point.

**`M-WAVE-TRIM`.** Call actual `generate` on a controlled axis-aligned bridge rectangle with analytically specified supporting bands, zero perimeter overlap, no narrow split, finite positive spacing/width/flow and enough trim clearance for the first deposited-half-width inset to survive. Start from the real `seam_fixture` / `wave_bead_footprint_stays_inside_trim_boundary` and `waves_cover_domain_without_seam_gap` (`modules/core-modules/wave-overhangs/tests/wave_overhangs_tdd.rs`), adapt their dimensions/parameters into a direct kernel fixture, and establish by execution a nonempty no-fallback witness before generalizing a bounded neighborhood. For identical inputs call `generate` twice and compare every path point, filled contour/hole and fallback in order; mark this as the `docs/22_test_quality.md` determinism-pin exception, not an independent correctness oracle.

Define `P` as the independently derived original rectangular wave piece **before** the first trim, after any cover construction; it is neither the trim itself nor necessarily the entire raw infill envelope. For this positive-flow domain let deposited radius `r = (flow_width * flow_ratio) / 2` and require `r >= EPSILON_MM`, so the actual first-trim guard `max(EPSILON_MM, r)` is `r`. Define the centerline trim `T = P ⊖ disk(r)`; require it to be nonempty. Independently require every output segment's centerline endpoints to lie in `T`, and its **whole deposited capsule**, including both endcaps, to lie in `P` — never require the capsule to lie in `T`. Because rectangular `T` is convex, endpoint containment proves the entire straight centerline lies in `T`, and the radius-`r` capsule then lies in `P`. Derive and record linear grid/float/clip allowances for these two boundaries; do not apply radius clearance a second time.

`property_tests::wave_controls` must use the same checker for an exact, unrounded **double-inset false-rejection regression**: `P = [0,10] × [0,10]` mm, `r = 1` mm, `T = [1,9] × [1,9]` mm, and centerline `(1,2) → (1,8)` mm. Its endpoints lie in `T` and its entire capsule lies in `P`, touching `P` at `x = 0`, so accept it even though the capsule is not contained in `T`. A separate nominal-width mutation uses the same `P`, nominal width `1` mm, `flow_ratio = 2`, and centerline `(0.75,2) → (0.75,8)` mm: the actual radius is `1` mm, so its capsule reaches `x = −0.25` mm and must be rejected; incorrectly using the nominal radius `0.5` mm would accept it. Derive any production-output allowance independently and keep it too small to mask this exact negative control.

For coverage, use an independently computed point-to-segment/capsule-distance grid and boundary-connected empty-cell model over a declared finite interior lattice, with grid resolution and threshold derived from the existing seam fixture; label it sampled coverage, not a proof of arbitrary continuous area. Require positive interior samples and a deletion mutation that creates a detectable interior gap. Deterministic fallback inputs include empty `infill_area` → `NoOverhang` with no paths/filled; a 1 mm square with `min_length` greater than its 4 mm outer perimeter → `MinLengthFiltered` and no output; an unsupported rectangle with no lower support → `MissingAnchors` and no paths; and the positive seed scene with `max_iterations = 1` → `IterationResidual` once actual first-iteration progress is witnessed. `paths`, `filled` and `fallbacks` can coexist, and fallback is not universally empty. Do not apply the full-width containment assertion when the generator takes either narrower trim fallback, or assume `filled` is a swept footprint: its regularization can grow it. No arbitrary rotation or layer-to-layer monotonicity claim.

**`M-IRONING-ZIGZAG`.** On independently validated axis-aligned rectangle, notch and rectangular-hole fixtures with finite positive spacing and bounded row count, derive the complete expected horizontal scan interval set from input rectangle arithmetic and the half-open Y domain. Compare all expected intervals to output geometry, check planar Z and `ExtrusionRole::Ironing`, input flow/speed and source width/tool/lock fields. Independently check **every consecutive segment of every returned `ExtrusionPath3D`**, including between intervals and between rows, with #2's boundary-inclusive full-segment oracle; evaluating only `chunks(2)` is forbidden. Boundary rows are centerline contracts, not a promise that a half-width bead stays inside. Deterministic 8 mm square with hole `[3,5] × [2,6]` mm and 1 mm row spacing must have nonempty rows on both sides of the hole and no extruded segment through its interior; a U-notch must likewise retain both arms. Current source concatenates intervals, so record the actual red/green outcome and classify it before any production fix. A confirmed crossing gets a focused correct fix that may emit multiple paths and a named concrete regression; do not pin the current one-path count. Empty/degenerate bbox, nonpositive spacing and tiny zero-span inputs are legitimate empty modes. Mutation controls inject a hole-crossing between paired intervals, a dropped row and a false all-empty output.
