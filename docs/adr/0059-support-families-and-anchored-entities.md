# Support Families Plan Geometry Before Anchored Layer Execution

Status: accepted

Support generation is split into host-owned analysis, a selected strategy planner, and a matching layer renderer. `PrePass::SupportAnalysis` produces strategy-neutral support candidates, model occupancy, authored constraints, eligible termination surfaces, and a baseline feasible envelope; family planners selected per region consume that analysis and exact-Z cached host geometry queries, then emit one universal `SupportPlanIR` containing semantic `ExPolygon` body/interface regions, optional structural skeletons, stable cross-layer body and demand identities, declined-candidate reasons, and anchored planar entities. A support family is an atomic planner-renderer pair identified through role and `support-family:<id>` claims; missing or mismatched pairs fail before slicing, while unroutable candidates and invalid or overlapping bodies are dropped as degraded success with structured diagnostics. The host aggregates planner output, assigns deterministic routing cells, rejects positive-area cross-family overlap, and dispatches validated per-family plan entries to renderers; renderers generate nozzle-width paths into structured, attributed `SupportIR` entries. This decision amends ADR-0009's single-writer clause (line 71: "`support-planner` keeps sole ownership of `SupportPlanIR` (single-writer rule preserved)"): the host aggregator is the sole writer of the aggregated `SupportPlanIR`, and family planners emit only family-scoped entries for host aggregation.

Independent support heights use generic anchored entities without replacing global-layer ordering. A planar entity between model planes is anchored to the upper global layer, executes in ascending Z before that layer's ordinary model event, and is optimized and cooling-accounted independently; same-Z support joins the ordinary model event. A future atomic Z-spanning entity may extend outside its anchor layer's Z interval while still executing at that layer's normal position. Global layers remain the parallel worker and ordering barrier, each worker returns ordered event collections, and path validation follows each entity's declared planar or Z-spanning contract instead of the model-layer Z envelope. Rafts remain signed negative global-layer prefix entries rather than anchored entities. This design preserves layer-parallel generation, permits external support families without host algorithm changes, and avoids embedding traditional or tree propagation policy in generic analysis.

## Amendments

Ruling 1: `family_assignments` are minted per `RegionMap` region. Candidate-less regions receive their config-resolved family assignment. Emission semantics for candidate-less regions are deferred to planner-fidelity packets.

Ruling 2: (2026-09-04, packet `241b-support-plan-ownership-seam`) the decision clause "assigns deterministic routing cells" is superseded. The bbox-centroid routing-cell mechanism (`RoutingCell`, `routing_cell`, `ROUTING_CELL_SIZE`) is deleted; the constant survives renamed as `MAX_BODY_EXTENT_UNITS` (same `1 << 20`) backing a pure max-body-extent bound. Host aggregation (`union_same_family_entries` / `check_ownership`, `crates/slicer-wasm-host/src/support_aggregation.rs`) now keys merges on declared identity `(family_id, global_layer_index, object_id, region_id, anchor_z)` and enforces ownership default-deny: an entry is retained only if `SupportAnalysisIR::family_assignments[(object_id, region_id)]` equals the entry's `family_id` AND the producing module's manifest claims hold `support-family:<family_id>`; otherwise it is dropped with Warn code `1206`. Arrival-order arbitration is removed, so aggregation results are plan-order independent by construction. §6 invariant 15 therefore holds in full: every region that requires support has exactly one attributed plan entry, and regions that require no support carry a structured no-work/declined record — the emission semantics of that second half for candidate-less regions remain deferred by Ruling 1 above.
