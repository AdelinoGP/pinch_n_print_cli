# Packet Contract: 185-arachne-width-bridge-parity

## Goal

Bring role-aware flow/width resolution to OrcaSlicer parity by adding a shared context-aware resolver `resolve_role_width` in `crates/slicer-core/src/flow.rs`, consumed by all five width-consuming core modules, with percent/`FloatOrPercent` config transport through `ResolvedConfig.extensions` and the canonical key rename `first_layer_line_width` → `initial_layer_line_width`.

## Scope Boundaries

One shared geometric width resolver keyed by explicit canonical `ExtrusionRole` plus first-layer/bridge context, wired into classic-perimeters, arachne-perimeters, rectilinear-infill, gyroid-infill, and lightning-infill, together with the config transport (percent preservation, key rename with legacy alias, auto-0 defaults) that makes it reachable on a live slice. Geometric widths and spacing only: canonical top/bottom/internal-solid flow-**ratio** controls are deferred to new deviation DEV-102. Classic-perimeters also receives its two residual parity fixes (canonical final-infill-boundary inset; threshold-aware topmost `only_one_wall_top`) and canonical overlap-key selection. The Arachne wall-width type/default change explicitly amends ADR-0043 through `D-185-ADR-0043-AMENDED`; the stale ADR-0014 `slicer-core` freshness exclusion is amended through `D-185-ADR-0014-AMENDED`. No central config-schema contract, no `schema_imports` mechanism, no host injection — flow keys stay module-owned in each manifest.

## Prerequisites and Blockers

- Depends on: packet 184 (`184-classic-perimeter-flow-parity`, status implemented); existing fns `line_width_to_spacing`, `flow_to_width`, `bridging_flow` in `crates/slicer-core/src/flow.rs`.
- Unblocks: DEV-102 (material-volume flow-ratio parity) follow-up; full D-105-FLOW-NOT-WIRED and D-164-WALL-WIDTH-KEYS-NOT-FLOAT-OR-PERCENT residual closure; TASK-212b part-level width-key metadata reaching live slices.
- Activation blockers: none beyond the mandatory guest freshness gate (`cargo xtask build-guests --check`) before any guest/module-dispatch test result is attributed.
