## Problem Statement

Packets 186 and 187 close the placeholder-engine half of `custom-G-code injection deviation` and the layer-scoped injection points. Six canonical points remain that PnP's pipeline **can** reach, and five that it **cannot**. This packet lands the six and files the five as residuals with measured evidence, so `custom-G-code injection deviation` closes honestly rather than by declaring a feature complete that is not.

**Reachability was determined against this tree, point by point, before this packet was written.** The evidence is recorded here so a reviewer does not have to re-derive it:

**Restructure note, stated plainly.** The plan's decomposition put `file_start_gcode` in packet 187 and `time_lapse_gcode` in this packet. The resulting split is layer-scoped (187) versus toolchange- and role-scoped (188), which is the seam the code actually has.

## In Scope

- Extend packet 187's `InjectionSite` enum with the variants the toolchange and role sites need, and grow `INJECTION_POINTS` from five to eleven entries. **Extend, never fork:** a second table or a parallel dispatch path would defeat the registry 187 exists to establish.
- Toolchange sites, keyed off `GCodeCommand::ToolChange { from, to, .. }`: emit `filament_end_gcode` then `change_filament_gcode` immediately **before** the command, and `filament_start_gcode` immediately **after** it, so the tool-select sits between `change_filament_gcode` and `filament_start_gcode` exactly as in canonical `GCode::set_extruder`.
- Extrusion-role sites, keyed off a `Raw` whose text begins `;TYPE:`: emit `change_extrusion_role_gcode`, `filament_change_extrusion_role_gcode` and `process_change_extrusion_role_gcode`, in that order, immediately **before** the marker.
- Per-site variables, transcribed per option from canonical `s_CustomGcodeSpecificPlaceholders` rather than unioned — **names and values both**. Role sites get `{layer_num, layer_z, extrusion_role, last_extrusion_role}` and **not** `max_layer_z`; and their `layer_num` is **N+1**, from `GCode::_extrude`'s `m_layer_index + 1`, whereas every other site in this packet and in 187 resolves it to **N**. Reusing 187's `LayerContext` unchanged at the role family would union the value semantics while the names stayed correct — AC-19 pins the contrast. **The N invariant is positional, not expressional: port the value, never the expression.** `before_layer_change_gcode` also textually reads `m_layer_index + 1` and still resolves to **N**, because it runs *before* `GCode::change_layer`, which holds the sole `++m_layer_index`; the role block reads the identical expression and gets **N+1** only because it runs *after* it. And `change_layer` increments only under `if (m_layer_count > 0)`, so canonical `set_extruder` calls during start G-code legitimately observe `layer_num == -1` — the toolchange sites must tolerate "no layer has begun"; `change_filament_gcode` gets `{layer_num, layer_z, max_layer_z, previous_extruder, next_extruder, toolchange_count}`; `filament_end_gcode` gets `{layer_num, layer_z, max_layer_z, filament_extruder_id}` where `filament_extruder_id` is the **old** tool — canonical uses `int(get_extruder_id(old_filament_id))` there, an **extruder** id, whereas at `filament_start_gcode` it uses raw `int(new_filament_id)`, a **filament** id. PnP has one id space and cannot reproduce that asymmetry; it ports the old/new direction and records the id-space difference as a residual; `filament_start_gcode` gets `{layer_num, layer_z, max_layer_z, filament_extruder_id}` with `filament_extruder_id` bound to the **new** tool. **The three layer variables are deliberately included even though `s_CustomGcodeSpecificPlaceholders` lists only `filament_extruder_id` for that option** — this is a third drift in that table (alongside the omitted `wrapping_detection_gcode` and the `timelapse_gcode` vs `time_lapse_gcode` key mismatch). Measured: the runtime `DynamicConfig` at the `placeholder_parser_process("filament_start_gcode", …)` site in `GCode::set_extruder` sets `layer_num`, `layer_z` and `max_layer_z` as well. Transcribing the table literally would leave `[layer_num]` verbatim and warn under packet 186's rule, which AC-20 prevents.
- `extrusion_role` substitutes the marker text **with the `;TYPE:` prefix stripped**. `orca_type_label` (`crates/slicer-gcode/src/emit.rs`) returns `";TYPE:Outer wall"` — prefix included — and the emitter pushes that whole string as the `Raw` text, so the module must strip it. The remainder is already the string OrcaSlicer's viewer parses. `last_extrusion_role` substitutes the previous marker's stripped label, or the empty string before any role has been seen.
- `toolchange_count` is 1-based and increments across the whole print, matching canonical `m_toolchange_count`.
- Declare the six new keys in `modules/core-modules/machine-gcode-emit/machine-gcode-emit.toml`, each `type = "string"`, `default = ""`, `group = "Machine G-code"`.

## Out of Scope

- **The five unreachable points.** `file_start_gcode`, `wrapping_detection_gcode`, `machine_pause_gcode`, `template_custom_gcode` and `printing_by_object_gcode` must **not** be declared in the manifest and must **not** appear in `INJECTION_POINTS`. AC-N3 enforces this. In particular, emitting `file_start_gcode` after `; HEADER_BLOCK_END` because that is where a postpass module can reach would be a fake, not a partial implementation: canonical's contract is "before the header", and a point that lands somewhere else is worse than an absent one.
- **Any host crate change.** `crates/slicer-gcode/src/emit.rs`, `crates/slicer-gcode/src/serialize.rs` and `crates/slicer-gcode/tests/golden_emit_tdd.rs` must be byte-identical at closure (AC-12 guards this). `serialize.rs` is listed explicitly because it is the file a future `file_start_gcode` packet needs, and pre-emptively touching it here would blur the seam this packet is drawing.
- **Per-filament (`coStrings`) resolution.** Canonical registers `filament_start_gcode`, `filament_end_gcode` and `filament_change_extrusion_role_gcode` as per-filament vectors resolved with `get_at(filament_id)`; PnP declares them as scalar strings applied to every filament. Recorded in a residual row, not implemented.
- **Canonical's `change_filament_gcode` flush/travel/temperature variable group** (`first_flush_volume`, `second_flush_volume`, `flush_length_1`..`flush_length_4`, `new_filament_temp`, `old_filament_temp`, `new_retract_length`, `old_retract_length`, `travel_point_1_x`..`travel_point_3_y`, `x_after_toolchange`, `y_after_toolchange`, `z_after_toolchange`, `toolchange_z`, `relative_e_axis`, `fan_speed`). PnP does not model these at this stage; under packet 186's warn-and-pass rule, using any of them leaves the placeholder verbatim, returns `Ok`, and emits one warning naming the key and site. Recorded in the same residual row.
- **Canonical's two toolchange suppressions.** (a) `custom_gcode_changes_tool`: `m_writer.toolchange` is always invoked and only its emitted text is dropped, and only when a matching `T<id>` is found inside the parsed `change_filament_gcode`. (b) `manual_filament_change`: `GCode::set_extruder` skips **`change_filament_gcode` itself** — the whole template, not just the tool select — when `m_config.manual_filament_change` is set and `m_toolchange_count == 1`, so the first toolchange of a manual-change print emits no `change_filament_gcode` at all. PnP models neither and must not invent either: the `ToolChange` command is always re-emitted and the template fires at every toolchange including the first. (b) is recorded as clause (f) of AC-16's residual row; PnP has no `manual_filament_change` option.
- **A `{…}` expression syntax**, an escape for literal square brackets, or any behavior beyond packet 186's warn-and-pass unresolved-placeholder rule.
- **`docs/ORCA_CONFIG_REFERENCE.md`** — no edit (see `packet.spec.md` §Doc Impact Statement).
