## Problem Statement

Three open deviations describe the same organ — `classic-perimeters`' width-and-spacing arithmetic — from three angles, and they are ordered by data dependency, not by convenience.

1. **`D-164-WALL-WIDTH-KEYS-NOT-FLOAT-OR-PERCENT`.** Canonical `PrintConfig.cpp::PrintConfigDef::init_fff_params` declares `outer_wall_line_width` and `inner_wall_line_width` as `coFloatOrPercent` with `ratio_over = "nozzle_diameter"`, `min = 0`, and `set_default_value(new ConfigOptionFloatOrPercent(0., false))`. PnP's classic manifest declares both as plain `float`, `min = 0.1`, and `run_perimeters` reads them with a raw `match _config.get(key) { Some(ConfigValue::Float(w)) => …, _ => legacy_line_width }`. A percent-valued profile is therefore not even *expressible*, and the `0` auto sentinel is rejected by the `min = 0.1` range check.
2. **`D-105-FLOW-NOT-WIRED` (classic half; roadmap task `T-052-WIRE-FLOW`).** `slicer_core::flow::line_width_to_spacing` (`crates/slicer-core/src/flow.rs`) implements canonical's rounded-cross-section `spacing = width - layer_height * (1 - PI/4)` and has been unit-tested and unused by classic since packet 105. `emit_walls` instead computes the wall gap as the width-average `(outer_wall_line_width + inner_wall_line_width) / 2.0` and uses a raw `-inner_wall_line_width` for every inset at `i >= 2`. At the 0.4 mm / 0.2 mm defaults the true spacing is `0.35708` against the `0.4` used today — a ~10.7 % inset error compounding across every inner wall. The arachne half landed — `modules/core-modules/arachne-perimeters/src/lib.rs` calls `line_width_to_spacing` — under the packet now archived at `.ralph/specs/_OLD/150-arachne-flow-and-percent-config.md` (no `.ralph/specs/150*/` directory exists; cite the code). Classic never followed.
3. **`D-152-CLASSIC-MIN-WIDTH-TOP-SURFACE-REMAINDER`.** `run_perimeters` reads `min_width_top_surface`, `debug_assert!`s it, and then discards it with a literal `let _ = min_width_top_surface;`. Neither `only_one_wall_top` collapse site consults it. The arachne half landed — `emit_only_one_wall_top_second_pass` exists in `modules/core-modules/arachne-perimeters/src/lib.rs` — under the packet archived at `.ralph/specs/_OLD/152-arachne-topmost-layer-behavior.md` (no `.ralph/specs/152*/` directory exists; cite the code). Because that work also retyped arachne's `[config.schema.min_width_top_surface]` to `float_or_percent` / `"0.0"` while classic's stayed `float` / `1.2`, the two modules today resolve the *same config key* by different rules — a divergence `docs/15_config_keys_reference.md` records explicitly.

The ordering is forced: D-164 defines what the resolved wall widths *are*, and D-105's `line_width_to_spacing` consumes exactly those widths. Doing D-105 first would wire the spacing formula to values that D-164 then redefines, re-blessing the byte-identical golden twice.

Two plan-level claims were falsified during grounding and must not be reintroduced. There are **no** functions named `inset_polygons` or `emit_gap_fill` — both behaviours are inlined inside the method `ClassicPerimeters::emit_walls`. And packet 177 (commit `77f15d48`) deleted every `expected_perimeter_ir.json` oracle and all eleven `#[ignore]`d `record_*` recorder functions, so there is **no re-record mechanism** for perimeter or arachne parity today; the only bless flow left in the repo is `BLESS_GOLDEN=1` against the byte-identical G-code golden.

## In Scope

- Retype `[config.schema.outer_wall_line_width]` and `[config.schema.inner_wall_line_width]` in `modules/core-modules/classic-perimeters/classic-perimeters.toml` to `type = "float_or_percent"`, `min = 0.0`, `max = 2.0`, `unit = "mm"`, `default = 0.4` (value deliberately unchanged), each with a `description` citing canonical's `coFloatOrPercent` declaration with `ratio_over = "nozzle_diameter"` and upstream default `0`.
- Rewrite classic's wall-width resolution in `run_perimeters` to `_config.get_abs_value(key, nozzle_diameter)` with three arms: `Some(v) if v > 0.0` → `v as f32`; `Some(_)` (an explicit `0`, i.e. canonical's auto sentinel) → `1.125 * nozzle_diameter`; `None` (key absent) → `legacy_line_width`.
- Reorder the R2 config-read block so `nozzle_diameter` is resolved **before** the two wall widths. Today `nozzle_diameter` falls back to `inner_wall_line_width`, which is read earlier; making width resolution depend on `nozzle_diameter` would create a read cycle. `nozzle_diameter`'s fallback becomes `legacy_line_width` (itself `0.4` when `line_width` is absent), preserving the empty-config effective value of `0.4` that `manifest_default_reconcile_tdd`'s `nozzle_diameter` row asserts.
- Wire `slicer_core::flow::line_width_to_spacing` into `emit_walls`: hoist `ext_perimeter_spacing` and `perimeter_spacing` above the inset loop, compute `ext_perimeter_spacing2` as `0.5 * (ext_perimeter_spacing + perimeter_spacing)` in the **non-precise** branch (the precise branch's mean-of-widths is already canonical-correct and stays), use `perimeter_spacing` for the `i >= 2` inset, and correct the gap-fill bounds to canonical's `min = 0.2 * min(perimeter_width, ext_perimeter_width) * (1 - INSET_OVERLAP_TOLERANCE)` and `max = 2 * perimeter_spacing`. **`INSET_OVERLAP_TOLERANCE` is an OrcaSlicer-side name with no in-tree constant** — it appears in this repo only inside a comment in `modules/core-modules/classic-perimeters/src/lib.rs`. Port its canonical value as the literal **`0.4`**; do not `use` or introduce a const by that name.

  > **Correction (2026-07-31).** Earlier revisions of this packet's requirements, design, and implementation plan all instructed porting this tolerance as two tenths. That was **wrong**. The constant's sole declaration is `static constexpr double INSET_OVERLAP_TOLERANCE = 0.4;` in OrcaSlicer's `libslic3r/libslic3r.h` (verified twice by independent dispatch). The wrong value originated from a pre-existing false comment in `modules/core-modules/classic-perimeters/src/lib.rs`, which asserted the tolerance was two tenths and described it as the "OrcaSlicer default" with "no matching const in repo"; that comment has been corrected in code. The implementation shipped canonical `0.4`, so `min = 0.2 * min(perimeter_width, ext_perimeter_width) * (1 - 0.4)`. Note the leading `0.2` in that expression is a **separate** canonical coefficient and is unrelated to the tolerance — do not conflate them.
- Add an `ERR_NEGATIVE_SPACING: u32 = 1` constant to `modules/core-modules/classic-perimeters/src/lib.rs` — the same value and shape `arachne-perimeters` already uses — and map `NegativeSpacingError` through `ModuleError::fatal(ERR_NEGATIVE_SPACING, e.to_string())`.
- Gate both `only_one_wall_top` sites on `min_width_top_surface`, mirroring arachne's `emit_only_one_wall_top_second_pass`: resolve via `get_abs_value("min_width_top_surface", perimeter_width_mm)`, `retain` top sub-areas at or above it, then `offset2_ex(&top_area, -min_width_top, min_width_top + 0.85 * perimeter_width_mm, OffsetJoinType::Miter, 3.0)` with the empty-result fallback. Apply the gate **at the call site**, not inside `slicer_core::top_surface_split::split_top_surfaces`.
- Retype `[config.schema.min_width_top_surface]` to `float_or_percent` / `default = "0.0"` to match arachne, and update the `CLASSIC_FALLBACKS` row in `crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs` from `Float(1.2)` to `Str("0.0")`.
- Update `crates/slicer-runtime/tests/integration/outer_inner_width_and_spacing_tdd.rs` so its expectations are **derived by calling `line_width_to_spacing`**, not transcribed as decimals, and add a negative test asserting `ModuleError::fatal(ERR_NEGATIVE_SPACING, …)` on a non-positive-spacing config.
- Add two new test files to the `integration` binary (registered in `crates/slicer-runtime/tests/integration/main.rs`): `crates/slicer-runtime/tests/integration/classic_wall_width_resolution_tdd.rs` (D-164 behaviour) and `crates/slicer-runtime/tests/integration/classic_min_width_top_surface_tdd.rs` (D-152 gate).
- Re-bless `crates/slicer-runtime/tests/fixtures/golden/precision_legacy_20mmbox.gcode`. This golden is produced by **classic** and this packet moves it.
- Regenerate `docs/15_config_keys_reference.md`'s generated blocks with `cargo xtask gen-config-docs`, hand-correct its per-key narrative outside the markers, flip the three deviation rows, file the new residual-gap deviation row (ID derived at the point of use), add the `TASK-303` row to `docs/07_implementation_status.md`, and run `cargo xtask check-deviations`.

## Out of Scope

- **Config ingestion of a real percent value.** Nothing on the live slice path ever *produces* a `ConfigValue::Percent` or `FloatOrPercent`, so the retype makes the percent form *declarable and validated* but a real slice still cannot carry one end-to-end — `get_abs_value` on a live slice hits the `Float(f) => Some(*f)` arm and passes the value through unscaled. The barrier is the **parser**, not `ResolvedConfig::to_config_map`; `design.md` §Architecture Constraints states the corrected mechanism, and any new deviation row must be worded about the parser. Closing that half means teaching config ingestion to parse and carry a percent, which reaches `ResolvedConfig`'s declared-field surface and stales the guest WASMs (cf. `docs/07_implementation_status.md` TASK-301/TASK-302). Filed as a residual deviation, not fixed here.
- **Changing the absent-key default to canonical's auto.** Canonical's default is `0` → `1.125 × nozzle_diameter` = `0.45` mm at a 0.4 mm nozzle. Adopting it widens every default wall from 0.4 to 0.45 mm, moves every wall-bearing fixture and the byte-identical golden, and desynchronises the live `0.4` fallbacks in `ClassicPerimeters::run_perimeters`' `legacy_line_width` binding (`modules/core-modules/classic-perimeters/src/lib.rs`) and `resolve_line_width_mm` (`crates/slicer-runtime/src/builtins/overhang_annotation_producer.rs`), whose doc comment pins itself to "the guest-side default used by `classic-perimeters`/`arachne-perimeters`". It would also contradict the `; outer_wall_line_width = 0.4` header default **already landed by packet 182** (`status: implemented`, commit `5478d7a0`): `crates/slicer-gcode/src/serialize.rs` assigns `0.4` and the golden header reads `; outer_wall_line_width = 0.4`. Recorded as the residual gap; reversing this decision is a one-line change in the same step (`design.md` §Open Questions `[FWD-1]`).
- **`arachne-perimeters`.** This packet reads arachne's code as a shape reference and edits nothing in it. **Anchor the "already landed" claims on the code, not on packet numbers** — the packets in question are archived as flat files under `.ralph/specs/_OLD/` (`150-arachne-flow-and-percent-config.md`, `151-arachne-winding-wallcount-dispatch.md`, `152-arachne-topmost-layer-behavior.md`), not live directories under `.ralph/specs/`, so a reader looking for `.ralph/specs/150*/` will find nothing. Verify by symbol instead:
  - **D-105 arachne half — landed.** `modules/core-modules/arachne-perimeters/src/lib.rs` calls `line_width_to_spacing` (`rg -c 'line_width_to_spacing' modules/core-modules/arachne-perimeters/src/lib.rs`).
  - **D-152 arachne half — landed.** `emit_only_one_wall_top_second_pass` exists in `modules/core-modules/arachne-perimeters/src/lib.rs`, and `[config.schema.min_width_top_surface]` in `modules/core-modules/arachne-perimeters/arachne-perimeters.toml` declares `type = "float_or_percent"` / `default = "0.0"`.
  - **D-164 arachne half — NOT landed; do not claim it is.** `[config.schema.outer_wall_line_width]` in `modules/core-modules/arachne-perimeters/arachne-perimeters.toml` is still `type = "float"`, `min = 0.1`. Retyping it is sibling packet `185-arachne-width-bridge-parity`'s work, which is also why 185 is the one that amends ADR-0043. This packet mirrors arachne's *shape* for D-105 and D-152; for D-164 it goes first and 185 follows.
- **Changing `slicer_core::top_surface_split::split_top_surfaces`' signature.** It is a free function taking `(region_polygons, top_solid_fill)` with no threshold parameter, and `classic-perimeters` reuses it for a *second, non-top* purpose with `region.overhang_areas()` as the mask. Adding an erosion parameter would break that second call site. The gate goes at the call site.
- **The `emit_nonplanar_shells` path.** It receives both wall widths but generates shell walls, not perimeters; canonical has no corresponding flow. Untouched.
- **Re-recording any perimeter or arachne IR oracle.** None exist — packet 177 deleted them all along with their recorder functions. Any plan text implying a re-record step is stale.
- **`crates/slicer-gcode`.** The serializer's header defaults were packet 182's subject, and **that packet has landed** (`status: implemented`, commit `5478d7a0`): `crates/slicer-gcode/src/serialize.rs` assigns `0.4` today. This packet's `0.4` preservation is therefore *consistent with* the landed header rather than a bet on a future one. Note the two packets nonetheless collide on `precision_legacy_20mmbox.gcode` (see Cross-packet impact below); "out of scope" here means the serializer source, not the shared golden.

## Step Completion Expectations

- **Step order is a data dependency, not a preference.** D-164 (Steps 1-2) defines the resolved wall widths that D-105 (Steps 3-4) feeds into `line_width_to_spacing`. Running them out of order re-blesses the golden twice and makes the intermediate spacing numbers meaningless.
- **`cargo xtask build-guests --check` after every step that edits `modules/core-modules/classic-perimeters/src/**` or its `.toml`.** Those paths feed the guest WASM build. A stale guest produces failures in the `e2e`, `perimeter_parity`, and `arachne_structural_invariants` surfaces that look unrelated to the edit but are caused by it. Rebuild without `--check` before drawing any conclusion.
- **`cargo build --workspace` before the golden re-bless.** `legacy_zero_matches_golden` locates and executes a `pnp_cli` binary on disk; `crates/slicer-runtime` does not depend on the CLI crate, so `cargo test` alone will not rebuild it and a re-bless against a stale binary silently re-records the pre-fix geometry. `cargo check` is insufficient — it produces no executable.
- **The `BLESS_GOLDEN=1 … --test slicing_precision_integration_tdd` hint written inside `crates/slicer-runtime/tests/e2e/slicing_precision_integration_tdd.rs` is stale and names a cargo target that does not exist.** The real invocation is `BLESS_GOLDEN=1 cargo test -p slicer-runtime --test e2e -- legacy_zero_matches_golden --nocapture`.
- **`ERR_NEGATIVE_SPACING` shares a numeric value with arachne's constant by design.** Module error codes are module-local; using `1` in both keeps the two perimeter modules' failure surface identical for the same underlying `NegativeSpacingError`. Any deviation from `1` must be justified in the step that introduces it.
- **Never weaken an assertion to obtain a pass.** `COVERAGE_THRESHOLD`, the `0.005` spacing tolerances, and `legacy_zero_matches_golden`'s byte-identity comparison are all fixed. Re-bless *data*; never relax a comparison.
