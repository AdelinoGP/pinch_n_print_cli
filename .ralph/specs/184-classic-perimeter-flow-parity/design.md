# Design: 184-classic-perimeter-flow-parity

## Controlling Code Paths

- Primary code path: `ClassicPerimeters::run_perimeters` and `ClassicPerimeters::emit_walls` (`modules/core-modules/classic-perimeters/src/lib.rs`; long — ranged reads only). `run_perimeters` owns the R2 per-invocation config-read block (widths, `wall_sequence`, `precise_outer_wall`, `nozzle_diameter`, `layer_height`, `min_width_top_surface`) and both `only_one_wall_top` branches; `emit_walls` owns the inset loop and the gap-fill width-band filter. **Neither `inset_polygons` nor `emit_gap_fill` exists** — `rg` returns zero hits **in source**; both behaviours are inlined inside `emit_walls`. (The two names do survive in prose, in `docs/specs/deviation-backlog-remediation-plan.md`'s D-105 entry. That doc hit is the origin of the fiction and must not be read as evidence the functions exist.)
- Manifest: `modules/core-modules/classic-perimeters/classic-perimeters.toml` — `[config.schema.outer_wall_line_width]`, `[config.schema.inner_wall_line_width]`, `[config.schema.min_width_top_surface]`.
- Host/SDK API surface consumed: `slicer_core::flow::line_width_to_spacing` and `flow_to_width` (`crates/slicer-core/src/flow.rs`); `slicer_ir::ConfigView::get_abs_value` (`crates/slicer-ir/src/slice_ir.rs`); `slicer_sdk::error::ModuleError::fatal` (`crates/slicer-sdk/src/error.rs`); `slicer_core::top_surface_split::split_top_surfaces` and `slicer_core::polygon_ops::{offset2_ex, OffsetJoinType}`.
- Neighbouring tests/fixtures: `crates/slicer-runtime/tests/integration/{outer_inner_width_and_spacing_tdd,precise_outer_wall_tdd,gap_fill_emission_tdd,manifest_default_reconcile_tdd,perimeter_parity}.rs` (all registered as `mod` in `crates/slicer-runtime/tests/integration/main.rs`); `crates/slicer-runtime/tests/{arachne_parity,arachne_structural_invariants}.rs` (standalone binaries); `legacy_zero_matches_golden` in `crates/slicer-runtime/tests/e2e/slicing_precision_integration_tdd.rs` against `crates/slicer-runtime/tests/fixtures/golden/precision_legacy_20mmbox.gcode`.

## Architecture Constraints

<!-- snippet: coord-system -->
- Coordinate units: **1 unit = 100 nm** (10⁻⁴ mm), NOT 1 nm like OrcaSlicer. Divide OrcaSlicer constants by 100. Use `Point2::from_mm(x, y)` or `mm_to_units()` at every mm↔unit boundary. Full porting checklist in `docs/08_coordinate_system.md`.

<!-- snippet: wasm-staleness -->
- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and, if `STALE:` is reported, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.

- **This packet's arithmetic is mm-domain throughout.** `line_width_to_spacing`, `flow_to_width`, `get_abs_value`, `offset`, and `offset2_ex` all take and return millimetres; the coord-system bullet above applies only if an implementer reaches for `Point2`/`mm_to_units` (e.g. to compute a bounding-box width for the D-152 gate, where `ex_polygon_min_width_mm` uses `units_to_mm` on raw `Point2` coordinates). Canonical's `min_width_top_surface` floor of `ext_perimeter_spacing / 2. + 10` uses OrcaSlicer's scaled coordinates; the `10` there is 10 upstream units = **0.1 PnP units**, i.e. numerically negligible at PnP's scale — do not port it as a literal `10`.
- **Config key strings are snake_case, always.** `outer_wall_line_width`, `inner_wall_line_width`, `min_width_top_surface`, `nozzle_diameter`, `layer_height`. No hyphens (CLAUDE.md §Config Key Naming Convention).
- **`nozzle_diameter` must be read before the wall widths.** Today `nozzle_diameter` falls back to `inner_wall_line_width`, which is read earlier. Making width resolution depend on `nozzle_diameter` creates a read cycle. The R2 block must be reordered so `legacy_line_width` → `nozzle_diameter` (fallback `legacy_line_width`) → wall widths.
- **Range checks compare percents as raw magnitudes.** `is_numeric_field_type` / `check_scalar` (`crates/slicer-scheduler/src/config_resolution.rs`) validate a `float_or_percent` field's `min`/`max` against the *unresolved* number, so the existing `min = 0.1` would reject the canonical `0` auto sentinel. The retype must lower `min` to `0.0`.
- **Manifest default syntax for `float_or_percent`.** `parse_config_field_entry` / `parse_percent_default` (`crates/slicer-scheduler/src/manifest.rs`) accept a `"<n>%"` string (percent), a bare numeric string `"0.0"` (absolute), or a bare TOML float/int. `type = "percent"` would *require* a `"<n>%"` default — which is why the wall-width keys use `float_or_percent`, not `percent`. Precedent already in-tree: `overhang_reverse_threshold` and `min_width_top_surface` in `modules/core-modules/arachne-perimeters/arachne-perimeters.toml`.
- **The reconcile guard reads raw TOML, not the resolved schema.** `assert_exhaustive_reconcile` (`crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs`) parses the manifest's own `default` value and compares it to a transcribed `CodeFallback`. Keeping `default = 0.4` as a bare TOML float means the two wall-width rows stay `Float(0.4)` and need no edit; retyping `min_width_top_surface` to `default = "0.0"` means its row must change `Float(1.2)` → `Str("0.0")`, and that row and the `.toml` must land in the **same step** or the test goes red.
- **No `emit_walls` signature change.** `layer_height`, `precise_outer_wall`, `wall_sequence`, and both widths are already among its 26 parameters. Computing spacings inside `emit_walls` keeps all five call sites untouched — and is also *more correct*, because the outer width `emit_walls` receives is `region_outer_wall_line_width` (the narrow-island override from `classify_narrow_island`), not the raw config value. Hoisting spacing computation into `run_perimeters` would silently derive the outer spacing from the un-overridden width.
- **No live-path *producer* of a `ConfigValue::Percent`/`FloatOrPercent` exists — and the barrier is the parser, not `ResolvedConfig::to_config_map`.** `to_config_map` (`crates/slicer-ir/src/resolved_config.rs`) is **not** restricted to `Bool`/`Int`/`Float`/`String`: it also emits a `ConfigValue::List` (the `filament_density` arm) and ends with `for (k, v) in &self.extensions { m.insert(k.clone(), v.clone()); }`, a verbatim pass-through of a `BTreeMap<String, ConfigValue>` that can carry **any** variant. `outer_wall_line_width` is not a declared `ResolvedConfig` field, so it routes through exactly that pass-through. The load-bearing conclusion survives for a different reason: the only non-test code that *originates* a `Percent`/`FloatOrPercent` is `parse_percent_default` (`crates/slicer-scheduler/src/manifest.rs`), and both of its call sites inside `parse_config_field_entry` invoke it as a bare validation statement and **discard** the returned `ConfigValue` (the manifest's `default` is retained only as a `String`). Every other in-tree `Percent` arm — the generated WIT conversion in `crates/slicer-macros/src/lib.rs`, `config_value_to_storage` in `crates/slicer-wasm-host/src/host.rs`, and the formatter in `crates/slicer-gcode/src/serialize.rs` — merely re-encodes a variant something upstream must already have produced. With no producer, `get_abs_value` on the live path always hits its `Float(f) => Some(*f)` arm and passes the value through unscaled. The retype is therefore a *capability and validation* change, not an end-to-end percent path. **Note the favourable direction:** because `extensions` is a transparent channel, this retype becomes transportable the moment config ingestion learns to parse a percent — no `ResolvedConfig` field addition is required for the wall-width keys specifically. Out of scope here, filed as a residual deviation worded about the parser.
- **`slicer-core`'s default feature set is empty** (`default = []`; `host-algos` is opt-in) and `pub mod flow;` is unconditional. `classic-perimeters` depends on `slicer-core` without `default-features = false` while `arachne-perimeters` pins it off — **verified equivalent**, since the default set is empty. No `Cargo.toml` change is needed and no new guest-build risk is introduced by calling into `slicer_core::flow`.

## Code Change Surface

- Selected approach — three ordered moves, each RED-then-GREEN, with the recorded-output fallout as its own step:

  1. **D-164 (Steps 1-2).** Manifest: `outer_wall_line_width` / `inner_wall_line_width` → `type = "float_or_percent"`, `min = 0.0`, `max = 2.0`, `unit = "mm"`, `default = 0.4` (unchanged), plus a `description` naming canonical `PrintConfig.cpp`'s `coFloatOrPercent` declaration with `ratio_over = "nozzle_diameter"` and upstream default `0`. Code: reorder `nozzle_diameter` above the width reads with fallback `legacy_line_width`; resolve each width as `_config.get_abs_value(key, nozzle_diameter as f64)` with `Some(v) if v > 0.0 => v as f32`, `Some(_) => 1.125 * nozzle_diameter` (canonical `Flow.cpp::auto_extrusion_width`), `None => legacy_line_width`.
  2. **D-105 (Steps 3-5).** Inside `emit_walls`, hoist above the inset loop:
     `ext_perimeter_spacing = line_width_to_spacing(outer_wall_line_width, layer_height)?`,
     `perimeter_spacing = line_width_to_spacing(inner_wall_line_width, layer_height)?`,
     `ext_perimeter_spacing2 = if precise_outer_wall { 0.5 * (outer_wall_line_width + inner_wall_line_width) } else { 0.5 * (ext_perimeter_spacing + perimeter_spacing) }`.
     Inset deltas become `i == 0` → `-ext_perimeter_spacing2` when precise, else `-(outer_wall_line_width / 2.0)` (canonical `ext_perimeter_width / 2`, already correct); `i == 1` → `-ext_perimeter_spacing2`; `i >= 2` → `-perimeter_spacing`. Gap-fill bounds become `min = 0.2 * outer_wall_line_width.min(inner_wall_line_width) * (1.0 - 0.4)` and `max = 2.0 * perimeter_spacing` — the trailing `0.4` is `INSET_OVERLAP_TOLERANCE` (**corrected 2026-07-31**; an earlier revision of this line said `0.2`, which was wrong — the constant's sole declaration is `static constexpr double INSET_OVERLAP_TOLERANCE = 0.4;` in OrcaSlicer's `libslic3r/libslic3r.h`, verified twice by independent dispatch. The leading `0.2` is a separate canonical coefficient; do not conflate them). Both `?` sites map through a new module-local `ERR_NEGATIVE_SPACING: u32 = 1`.
  3. **D-152 (Steps 6-7).** Manifest: `min_width_top_surface` → `type = "float_or_percent"`, `default = "0.0"`, `unit = "%"`, `min = 0.0`, matching arachne verbatim. Code: replace the read-and-discard with `let min_width_top = _config.get_abs_value("min_width_top_surface", perimeter_width_mm).unwrap_or(0.0);`, then at both `only_one_wall_top` sites apply the arachne-shaped gate to the top portion — `retain` sub-areas whose minimum bounding-box extent is `>= min_width_top`, then `offset2_ex(&top_area, -min_width_top, min_width_top + 0.85 * perimeter_width_mm, OffsetJoinType::Miter, 3.0)` with the empty-result fallback to the unexpanded set. Dropped sub-areas fall through to the full-`layer_wall_count` path.

- Exact functions, manifests, tests, and fixtures:
  - `ClassicPerimeters::run_perimeters` — R2 read-order change, width resolution, `min_width_top_surface` resolution, both `only_one_wall_top` sites.
  - `ClassicPerimeters::emit_walls` — hoisted spacings, inset deltas, gap-fill bounds. **No signature change.**
  - New module-local `const ERR_NEGATIVE_SPACING: u32 = 1;` and a new `use slicer_core::flow::line_width_to_spacing;` (the file already has `use slicer_core::flow::bridging_flow;`).
  - New free fn for the D-152 minimum-extent test, mirroring arachne's `ex_polygon_min_width_mm` (min of bbox width and height via `units_to_mm`).
  - `modules/core-modules/classic-perimeters/classic-perimeters.toml` — three `[config.schema]` entries.
  - `crates/slicer-runtime/tests/integration/outer_inner_width_and_spacing_tdd.rs` — expectations derived from `line_width_to_spacing`; new negative test `negative_spacing_config_is_a_fatal_module_error`.
  - New `crates/slicer-runtime/tests/integration/classic_wall_width_resolution_tdd.rs` and `crates/slicer-runtime/tests/integration/classic_min_width_top_surface_tdd.rs`, both registered in `crates/slicer-runtime/tests/integration/main.rs`.
  - `crates/slicer-runtime/tests/integration/manifest_default_reconcile_tdd.rs` — `min_width_top_surface` row `Float(1.2)` → `Str("0.0")`; the `nozzle_diameter` row's explanatory comment updated (its `Float(0.4)` value is unchanged, because `legacy_line_width` still bottoms out at `0.4`).
  - `crates/slicer-runtime/tests/fixtures/golden/precision_legacy_20mmbox.gcode` — re-blessed.

- Rejected alternatives and reasons:
  - **Adopt canonical's default (`"0.0"` in the manifest, code fallback `1.125 × nozzle`).** Faithful, but widens default walls 0.4 → 0.45 mm, moves every wall-bearing fixture and the byte-identical golden, desynchronises the two live `0.4` fallbacks (`legacy_line_width` in `ClassicPerimeters::run_perimeters`, `modules/core-modules/classic-perimeters/src/lib.rs`; and `resolve_line_width_mm`, `crates/slicer-runtime/src/builtins/overhang_annotation_producer.rs`), and would contradict the `; outer_wall_line_width = 0.4` header default **already landed by packet 182** (`status: implemented`, commit `5478d7a0`; `crates/slicer-gcode/src/serialize.rs` assigns `0.4` and the golden header reads `0.4`). Rejected; recorded as `[FWD-1]` and as a residual deviation. Reversing it is a one-line change in Step 2.
  - **Add a threshold parameter to `slicer_core::top_surface_split::split_top_surfaces`.** It is a free fn taking only `(region_polygons, top_solid_fill)` with a private `MIN_AREA_UNITS_SQ` sliver filter and no offset call at all — and `classic-perimeters` reuses it for a **second, non-top** purpose with `region.overhang_areas()` as the mask. Changing its signature would silently impose a top-surface erosion on the overhang split. Rejected in favour of the call-site gate, which is also exactly what arachne does.
  - **Hoist spacing computation into `run_perimeters` and pass it into `emit_walls`.** Would grow a 26-parameter function to 28 and touch five call sites, and would derive the outer spacing from the raw config width rather than the narrow-island-overridden `region_outer_wall_line_width` actually used for the inset. Rejected on both counts.
  - **Port canonical's `std::max(ext_perimeter_spacing / 2. + 10, …)` floor for `min_width_top_surface`.** The `10` is 10 upstream scaled units (1 nm each) = 0.1 PnP units — numerically irrelevant — and the `ext_perimeter_spacing / 2` floor would make the gate fire even at the `0.0` default, changing default geometry and moving the golden a second time for a D-152 reason. Rejected; the gate stays disabled at the `0.0` default, matching arachne. Noted as `[FWD-2]`.
  - **Retype the wall-width keys as `type = "percent"`.** `parse_percent_default` requires a `"<n>%"` default for that type, forcing a percent-shaped default the code fallback cannot state. Rejected.
  - **Re-record perimeter parity goldens.** There are none — packet 177 (commit `77f15d48`) deleted every `expected_perimeter_ir.json` and all eleven `#[ignore]`d `record_*` functions. The only bless flow in the repo is `BLESS_GOLDEN=1` against the G-code golden.

## Risks and Tradeoffs

- **The `nozzle_diameter` fallback reorder is a real behaviour change in one corner.** Today `nozzle_diameter` falls back to `inner_wall_line_width`; after the reorder it falls back to `legacy_line_width`. These differ only when `inner_wall_line_width` is set explicitly while both `nozzle_diameter` and `line_width` are absent — in which case the R4 thin-wall threshold and `bridging_flow` see `0.4` instead of the configured inner width. All in-repo classic tests set `inner_wall_line_width` to `0.4` or leave it absent, so none observe the difference, but a downstream profile could. Verify by running the full classic-touching test set, not by inspection.
- **The gap-fill band narrows.** Canonical's `min` uses `min(perimeter_width, ext_perimeter_width)`; with `outer = 0.5`, `inner = 0.4` the two agree, but with `outer < inner` the band's lower bound drops and more slivers reach the medial axis. `gap_fill_emission_tdd` asserts no spacing numerics but *is* sensitive to whether a `GapFill` loop is emitted at all — treat a change there as a real signal.
- **`arachne_structural_invariants` is a two-sided ratio and both T2 packets move it.** A green run before the sibling packet lands does not survive it. Re-run, never assume; and never lower `COVERAGE_THRESHOLD`.
- **Re-blessing a byte-identity golden is a blunt instrument.** After Step 5, inspect the diff: it should show coordinate drift on wall moves and nothing structural (no changed layer count, no changed `;TYPE:` sequence, no changed header keys). A blind re-bless would silently absorb unrelated drift — including, in the worst case, a stale-`pnp_cli` re-record of the *pre-fix* geometry.
- **Three deviations in one packet is a context risk.** Mitigated by strict step ordering, per-step file budgets of at most three, and a recorded-output step that is separate from the code step that causes it.

## Open Questions

- **`[FWD-1]` — the default-value decision (implementer-resolvable; already decided, recorded for reversibility).** Canonical declares both wall-width keys with `set_default_value(new ConfigOptionFloatOrPercent(0., false))`, i.e. auto → `1.125 × nozzle_diameter` → `0.45` mm at a 0.4 mm nozzle.
