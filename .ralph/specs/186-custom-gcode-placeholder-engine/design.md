# Design: 186-custom-gcode-placeholder-engine

## Controlling Code Paths

- Primary code path: `substitute_placeholders` and `run_gcode_postprocess` in `modules/core-modules/machine-gcode-emit/src/lib.rs` (the `#[slicer_module] impl PostpassModule for MachineGcodeEmit` block). `run_gcode_postprocess` reads the two templates, builds a `HashMap<String, String>` lookup seeded with `bed_temperature_initial_layer_single` / `nozzle_temperature_initial_layer` and then swept over `config.keys()`, substitutes both templates, and frames the re-emitted command stream with `push_raw`.
- Config surface: `modules/core-modules/machine-gcode-emit/machine-gcode-emit.toml` `[config.schema]` — four declared keys today.
- Neighboring tests/fixtures: `modules/core-modules/machine-gcode-emit/tests/machine_gcode_emit_tdd.rs` (top-level `#[test]` fns, driven through `slicer_sdk::test_prelude::config_with`, which builds a `ConfigView` containing **exactly** the supplied pairs — so a unit test controls the placeholder domain precisely); `modules/core-modules/machine-gcode-emit/tests/slicer_module_binding_tdd.rs` (`binding_surface_matches_gcode_postprocess_stage`); `crates/slicer-runtime/tests/integration/machine_start_end_gcode_emission_tdd.rs` (real WASM component, real pipeline, via `slice_with_raw` → `run_pipeline_with_raw_config`).
- OrcaSlicer comparison: see `requirements.md` §OrcaSlicer Reference Obligations; do not repeat delegation rules.

## Architecture Constraints

<!-- snippet: wasm-staleness -->
- Guest WASM is **not** rebuilt by `cargo build` or `cargo test`. After editing any path in this packet's change surface that feeds the guest build (see `CLAUDE.md` §"Guest WASM Staleness"), the implementer MUST run `cargo xtask build-guests --check` and, if `STALE:` is reported, rebuild without `--check` before re-running the failing test. Stale-guest failures look unrelated to the change but are caused by it.

- Config key strings must be snake_case in Rust and in the manifest. `nozzle_diameter` already satisfies this; do not introduce a kebab-case variant anywhere.
- `ConfigView::keys` (`crates/slicer-ir/src/slice_ir.rs`) returns **every key in its own `fields` map**, sorted — it enforces no manifest scoping itself. The scoping to manifest-declared keys happens when the host **constructs** the view, so "the placeholder domain is the module's manifest" is true of the live pipeline but is *not* a property of `keys()`. Stating it as a property of the function is wrong and misleads anyone reading the accessor. This is the single fact that makes the placeholder domain a manifest question rather than a code question: the `for key in config.keys()` sweep already present in `run_gcode_postprocess` is not dead code to delete, it is the mechanism by which AC-8 works once `nozzle_diameter` is declared. Keep it.
- **The observable error chain, verified end to end. Do not paraphrase it from memory — the format literal was wrong in an earlier draft of this packet and the error was unfalsifiable because this section also forbade reading the file that carries it.** A guest `ModuleError` returned from `run_gcode_postprocess` becomes `DispatchError.reason`, formatted in `crates/slicer-wasm-host/src/dispatch.rs` as `"module error (code={}, fatal={}): {}"` (five occurrences of that literal in that file; the workspace has **zero** occurrences of any `code={}, n={}` form). `PostpassStageRunner::run_gcode_postprocess` wraps it as `slicer_ir::PostpassError::FatalModule { message }`; `Display for PostpassError` (`crates/slicer-ir/src/stage_io.rs`) renders that variant as `"fatal postpass module failure in {stage_id} for {module_id}: {message}"`; `crates/slicer-runtime/src/postpass.rs` returns it unchanged from `execute_postpass`; and `crates/slicer-runtime/src/pipeline.rs` renders the whole thing as `"postpass failed: {e}"`. Both the numeric code and the message text are therefore observable from a pipeline `Err` — AC-N2 depends on this and must not be weakened to an `is_err()`-only assertion. **AC-N2's assertion deliberately stops at the `module error (code=` prefix plus the key name `no_such_key`** — it asserts neither the `fatal={}` field nor the numeric code — so neither a future change to that field nor a change to `ERR_UNRESOLVED_PLACEHOLDER`'s value can make a correct implementation fail the criterion. The numeric code is *deliberately absent* from AC-N2: `crates/slicer-runtime` cannot name the constant (see §Decisions of Record).
- No geometry, no millimetre/internal-unit conversion, and no coordinate arithmetic occurs in this packet, so the `coord-system` constraint does not apply. `nozzle_diameter` is carried as a plain-mm scalar for text substitution only and must **not** be passed through `mm_to_units`.

## Code Change Surface

- **Selected approach.** `substitute_placeholders` keeps its byte-oriented scan but changes shape twice.
  - *Literal runs.* Track the start index of the current literal run and, on reaching a `[` or the end of input, emit `out.push_str(&template[run_start..i])`. Because `[` is ASCII and UTF-8 is self-synchronising, `i` is always at a char boundary when a `[` is found, so slicing is safe and the `bytes[i] as char` cast disappears. The existing `std::str::from_utf8(...).unwrap_or("")` calls on the key and passthrough paths should also become direct `&template[..]` slices for the same reason; `unwrap_or("")` silently discarding a UTF-8 error is a defect of the same family.
  - *Unresolved keys.* Return `(String, Vec<String>)` — the rendered text and the sorted, deduplicated list of bracketed keys that had no entry in `lookup`. The rendered text keeps the verbatim `[key]` for an unresolved key so a future inline-marker rendering is still possible, but under this packet that text never reaches the output because the caller fails first.
  - *Caller.* `run_gcode_postprocess` substitutes both templates, unions the two unresolved lists into a `BTreeSet<String>` (sorted, deduplicated), and — if it is non-empty — returns `Err(ModuleError::fatal(ERR_UNRESOLVED_PLACEHOLDER, …))` **before** emitting anything. The message must name every unresolved key and every injection point that contributed one, and should name the resolvable key set so the user can act. Failing before emission (rather than after) is deliberate: partially-substituted G-code must never reach `GcodeOutputBuilder`.
- **Placeholder aliases.** A `const PLACEHOLDER_ALIASES: &[(&str, &str)]` table with the single entry `("first_layer_temperature", "nozzle_temperature_initial_layer")`. Applied **after** the `config.keys()` sweep so a real config key of the same name would win if one ever appeared. This is a port, not a convenience: `GCode::update_placeholder_parser_with_variant_params` sets the name unconditionally under the comment `// first_layer_temperature is a legacy alias of nozzle_temperature_initial_layer`. It must not become a second manifest key — canonical models it as a parser alias, and two config keys for one value can disagree.
- **Why fatal rather than warn-and-pass.** *(Rationale for a decision recorded in `docs/adr/0050-custom-gcode-architecture.md`, not a decision taken here — see §Decisions of Record.)* Canonical errors: `MyContext::legacy_variable_expansion` throws `"Variable does not exist"` for an undefined `[key]`, and the failure is recorded by `GCode::placeholder_parser_process` and rethrown by `GCode::check_placeholder_parser_failed`, aborting the export. `slicer_sdk::host::log_warn` exists and would be the warn-and-pass mechanism, but a host log line is not observable in a module integration test and does not stop bracketed literal text from reaching a printer, which is the harm `DEV-085` names. The collect-all-then-fail-once shape is copied from canonical's deferral rather than failing on the first key, so a user with three bad macros fixes them in one pass. **One deliberate departure, stated rather than adopted silently: canonical is deferred-collect-then-throw, and it keeps emitting in between.** `GCode::placeholder_parser_process` catches the parser exception, records the template into `PlaceholderParserIntegration::failed_templates`, and splices a `!!!!! Failed to process the custom G-code template …` marker into the G-code — **export continues** — and only `GCode::check_placeholder_parser_failed`, later, throws one aggregated `PlaceholderParserError` (deduped by template name, first message wins). PnP adopts the aggregation but **fails before emitting anything**, so no partially-substituted text ever reaches `GcodeOutputBuilder`. The observable end state is the same (a failed export), and the difference is confined to a marker comment inside output that is discarded either way; PnP's ordering is chosen because a WASM postpass module has no equivalent of a half-built export to salvage. Record this in the residual row alongside the domain asymmetry — do not let it pass as accidental parity. **The known cost is stated, not hidden, and it is wider than "the whole config":** PnP's placeholder domain is one module's manifest (five keys plus one alias after this packet). Canonical's local `DynamicConfig` is only an *override* layered over a persistent parser — `ppi.parser.process(templ, current_filament_id, config_override, &ppi.output_config, &ppi.context)` — beneath which sit the full print config (so any real option name resolves inside any custom G-code) and **119** explicit `placeholder_parser().set(...)` global assignments (counted by execution: 110 via `this->placeholder_parser().set(`, 9 via `gcodegen.placeholder_parser().set(`; no `set_multiple` or `m_placeholder_parser.set` variants exist). A template canonical accepts can therefore now fail a PnP slice by a wide margin. That asymmetry is exactly what the residual `DEV-###` row records, and it is a visible failure rather than a silent one.
- **Exact functions, manifests, tests, and fixtures.**
  - `substitute_placeholders` — signature `(&str, &HashMap<String, String>) -> (String, Vec<String>)`; literal-run slicing; no `as char`.
  - `run_gcode_postprocess` — union the unresolved lists, fail with `ERR_UNRESOLVED_PLACEHOLDER` before Step 4's `push_raw`.
  - New module-level **`pub const ERR_UNRESOLVED_PLACEHOLDER: u32 = 20;`** — chosen above the file's existing 1-11 range so it cannot collide with the push-failure codes. **`pub` is load-bearing, not stylistic.** `modules/core-modules/machine-gcode-emit/tests/machine_gcode_emit_tdd.rs` is an integration-test target: it is a *separate crate* that links `machine-gcode-emit` as a library, so it can only name items the library exports. Today the crate's sole exported item is `pub struct MachineGcodeEmit` (verified: it is the only `pub` at the top level of `modules/core-modules/machine-gcode-emit/src/lib.rs`). A private `const` would make AC-N1's `code == ERR_UNRESOLVED_PLACEHOLDER` assertion fail to compile, and the only way to keep the test would be to hardcode the digit — which is precisely what §Decisions of Record says the packet must not do.
  - `machine-gcode-emit.toml` — one new `[config.schema.nozzle_diameter]` block copied field-for-field from `modules/core-modules/classic-perimeters/classic-perimeters.toml`'s block (`type = "float"`, `default = 0.4`, `min = 0.1`, `max = 2.0`, `unit = "mm"`), with a `display` and a `group = "Machine G-code"` of its own.
  - `machine_gcode_emit_tdd.rs` — rewrite `unknown_placeholder_passes_through_verbatim` → `unknown_placeholder_is_a_fatal_module_error`; add `non_ascii_template_text_survives_substitution`, `every_unresolved_placeholder_is_reported_in_one_error`, and `first_layer_temperature_alias_resolves_to_nozzle_temperature_initial_layer` (AC-15). **All three are required**: the §Context Discipline Note makes this section the authoritative files-in-scope and change list, so a test omitted here is a test the implementer never writes — an earlier draft listed only the first two and AC-15's test would have been silently dropped.
  - `machine_start_end_gcode_emission_tdd.rs` — add `try_slice_with_raw(raw) -> Result<String, _>` and re-express `slice_with_raw` as `try_slice_with_raw(raw).expect("pipeline must succeed")`; rewrite `unknown_placeholder_passes_through_verbatim` → `unknown_placeholder_is_a_fatal_slice_error`; add `nozzle_diameter_macro_resolves_end_to_end`.
- **Rejected alternatives.**
  - *Warn and pass through* (`slicer_sdk::host::log_warn`): rejected — not observable in a test, does not stop the literal text, and diverges from canonical in the direction `DEV-085` argues against.
  - *Substitute unknown keys with the empty string*: rejected — turns `M104 S[first_layer_temperature]` into `M104 S`, which is a worse printer command than the bracketed form and is silent.
  - *Inline `!!!!! Failed to process the custom G-code template` marker instead of failing*: rejected as the sole behaviour — canonical emits the marker **and** fails. Emitting only the marker would ship a comment to the printer and continue.
  - *A `strict_placeholders` opt-out config key*: rejected — canonical has no such toggle, and adding one makes the silent-passthrough path permanently reachable, which is the state this packet exists to end. **This rejection is ADR-0050's, not this packet's**; reinstating a toggle requires amending that ADR.
  - *Declaring `[bed_temperature]`, `[layer_count]`, `[x_max]` … as manifest keys so they resolve*: rejected — none is an OrcaSlicer config key (`layer_count`, `x_max`, `y_max`, `z_max`, `tool_count`, `print_time_estimate_s` are computed print values whose canonical placeholder names are `total_layer_count`, `print_bed_max`, `max_layer_z`, `num_extruders`, `print_time_sec`; `bed_temperature` is not an OrcaSlicer option under that name; `filament_type` is a canonical option with zero occurrences anywhere in this workspace). Declaring them would be inventing config keys, which `requirements.md` §Out of Scope forbids. **`[first_layer_temperature]` is deliberately not in that list any more**: it is adopted, but as a `PLACEHOLDER_ALIASES` entry rather than a manifest key, exactly as canonical models it (see the alias bullet above and AC-15). Adding it as a sixth `[config.schema]` key remains rejected — two config keys for one value can be set to different numbers.

## Decisions of Record (ADR-0050) and Packet-Local Invariants

**The three architectural decisions this packet implements are not this packet's to make, and are no longer carried here as "Locked Assumptions".** They are recorded in **`docs/adr/0050-custom-gcode-architecture.md`** (authored by a separate workstream; do **not** author or edit it from this packet). This packet *implements* them and must not restate, re-litigate, or silently diverge from them:

- **Unknown-key policy — ADR-0050.** An unresolved `[key]` fails the slice; there is no escape syntax and no opt-out config key. This packet supplies the mechanism (`ERR_UNRESOLVED_PLACEHOLDER`, collect-all-then-fail-once, fail-before-emit); the *policy* is ADR-0050's. If a future packet wants an escape or a `strict_placeholders` toggle, it amends the ADR — a packet-local "Locked Assumption" was never the right home for a user-visible, irreversible contract.
- **Placeholder domain — ADR-0050.** The domain is exactly *one module's* manifest-declared key set plus the `PLACEHOLDER_ALIASES` table. Nothing may widen it by reading outside `ConfigView` at this stage. The wide asymmetry against canonical's persistent parser is a consequence of that decision and is recorded both in ADR-0050 and in this packet's residual `DEV-###` row.
- **Engine ownership — ADR-0050.** `substitute_placeholders`, `PLACEHOLDER_ALIASES` and the error constant stay **private to `machine-gcode-emit`**; the engine is not promoted to `slicer-sdk`, `slicer-ir` or the host. The single exception is `ERR_UNRESOLVED_PLACEHOLDER`'s `pub`, which exists only so the crate's own integration-test target can name it (see §Code Change Surface) — that is crate-level export, not cross-crate ownership.

Packet-local invariants (this packet's to keep):

- Not locked: `ERR_UNRESOLVED_PLACEHOLDER`'s numeric value (`20`) is an implementation detail. **AC-N1 asserts the constant symbolically** — it lives in `modules/core-modules/machine-gcode-emit/tests/`, links the module crate, and can name the `pub const`. **AC-N2 does not assert the value at all.** `crates/slicer-runtime`'s `Cargo.toml` has **zero** reference to `machine-gcode-emit` in either `[dependencies]` or `[dev-dependencies]` (verified against the tree; the module dev-dependencies enrolled there are the fill modules, `classic-perimeters`, `arachne-perimeters` and `seam-placer`), so a test in that crate cannot name the constant and could only hardcode `20`. Rather than lock the value to keep a redundant assertion, **AC-N2 drops the code clause** and asserts only the `module error (code=` prefix and `no_such_key`. It remains fully discriminating: on the unfixed tree that slice succeeds and produces G-code, so there is no `Err` and no `module error (code=` anywhere in the result. Adding a `machine-gcode-emit` dev-dependency to `slicer-runtime` purely to share a digit was rejected — it would couple the host crate to a guest module for a value ADR-0050 leaves free.
- Not locked: `substitute_placeholders`' `(String, Vec<String>)` return shape may become a small struct in packet 187 when per-site context arrives; that is an anticipated, in-family change.

## Risks and Tradeoffs

- **A template canonical accepts can now fail a PnP slice.** Accepted and recorded in the residual `DEV-###` row; the alternative is shipping bracketed literal text to a printer, which `DEV-085` identifies as the harm.
- **No escape for a literal `[foo]`.** A start-G-code line that legitimately contains square brackets around a non-key word will now fail. **"No escape syntax" is an ADR-0050 decision**, accepted here rather than re-argued. Canonical has no escape for the legacy form either. Low likelihood — Marlin and Klipper G-code do not use `[...]` in command syntax — and the failure is loud. Documented in `docs/15`.
- **Two test files must move in lockstep with the engine.** Mitigated by putting them in the same step (Step 2) rather than deferring to a follow-up `cargo check`.
- **Guest staleness.** Every `--test integration` result in this packet is meaningless until `cargo xtask build-guests --check` is clean. Called out in `requirements.md` §Step Completion Expectations and in every affected step's verification list.
