# Packet Contract: 186-custom-gcode-placeholder-engine

## Goal

Make the `[key]` placeholder engine in `modules/core-modules/machine-gcode-emit/src/lib.rs` correct and honest before any new injection point is added: replace `substitute_placeholders`' `out.push(bytes[i] as char)` literal-text path with a char-boundary-correct slice copy, replace its silent unknown-key passthrough with canonical `PlaceholderParser`'s fail-the-template behaviour (collect every unresolved key across every template, then return one fatal `ModuleError`), declare `nozzle_diameter` so the last config-valued macro `docs/15_config_keys_reference.md` ever advertised actually resolves, and rewrite that doc section to state the resolvable set and the new failure policy.

## Scope Boundaries

Touches the substitution engine and the two config-value reads that feed it — `substitute_placeholders` and `run_gcode_postprocess` in `modules/core-modules/machine-gcode-emit/src/lib.rs`, one new `[config.schema.nozzle_diameter]` block in `modules/core-modules/machine-gcode-emit/machine-gcode-emit.toml`, and the two test files that pin the old passthrough rule. No new injection point is added here: `machine_start_gcode` and `machine_end_gcode` remain the only two sites, and the registry that generalises them is packet 187. Of the ten macros the pre-correction `docs/15` list advertised but never delivered, **two are recovered here and eight are not**. `[nozzle_diameter]` is recovered as a real config key. `[first_layer_temperature]` is recovered as a **placeholder alias** of the already-declared `nozzle_temperature_initial_layer` — not a new config key — because canonical does exactly that: `GCode::update_placeholder_parser_with_variant_params` sets it **unconditionally** under the verbatim comment `// first_layer_temperature is a legacy alias of nozzle_temperature_initial_layer` (see AC-15). The remaining **eight** (`[bed_temperature]`, `[filament_type]`, `[tool_count]`, `[layer_count]`, `[print_time_estimate_s]`, `[x_max]`, `[y_max]`, `[z_max]`) are **not** implemented — none is a PnP config key and none has a canonical alias PnP can honour — and each is recorded in one residual deviation row with its measured canonical counterpart.

## Prerequisites and Blockers

- Depends on: none.
- Unblocks: `187-custom-gcode-injection-registry` (TASK-306) and, transitively, `188-custom-gcode-conditional-points` (TASK-307). Both add injection points whose templates run through this engine; 187's registry is what supplies the computed variables (`layer_num`, `layer_z`, `max_layer_z`) that several of the eight residual macros map onto, so the residual row filed here must not be closed by 187 without re-checking each entry.
- Activation blockers: none technical. `140_lightning-module-rewrite` is the only `active` packet; this stays `draft` until that clears. **Packets 181-185 are all `status: draft`** — nothing they file has landed, so no claim here may cite them as done.

## Acceptance Criteria

**Mandatory conventions for every `cargo test` command below — both are measured, not stylistic:**

1. **`rg "^test result:"` — the colon is load-bearing.** Unanchored `^test result` also matches libtest's per-test NAME lines, so a green run whose test names begin with `result` trips a `0 failed`-style guard.
2. **Filter resolution differs between the two test binaries used here, and both forms were measured on this tree.** `modules/core-modules/machine-gcode-emit/tests/machine_gcode_emit_tdd.rs` is its own Cargo integration binary with top-level `#[test]` fns, so a **bare** name plus `--exact` resolves (measured: `-- unknown_placeholder_passes_through_verbatim --exact` → `1 passed; 8 filtered out`). `crates/slicer-runtime/tests/integration/machine_start_end_gcode_emission_tdd.rs` is mounted as `mod machine_start_end_gcode_emission_tdd;` in `crates/slicer-runtime/tests/integration/main.rs`, so `--exact` needs the **module-qualified** path (measured: `-- machine_start_end_gcode_emission_tdd::start_gcode_default_substitutes --exact` → `1 passed; 246 filtered out`). A bare name with `--exact` against the `integration` binary selects nothing forever.

Every `cargo test` command in this packet selects exactly **one** test binary (`--test machine_gcode_emit_tdd` or `--test integration`) and therefore emits exactly one `^test result:` line, so all of them take the **single-result-line** guard form: `… 2>&1 | rg "^test result:" | rg -q "^test result: ok\. The `[1-9]` rejects a filtered-to-zero run as well as a partial failure. `rg -v "0 passed"` and `rg -v "0 failed"` are **banned**: the first reports success on `test result: FAILED. 3 passed; 4 failed;`, the second reports success on a run that selected zero tests.
